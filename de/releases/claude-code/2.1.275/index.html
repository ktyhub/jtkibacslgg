claude-code v2.1.275

Patch Veröffentlicht17. Sept. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.275

Was hat sich geändert?

– Das angemeldete Konto wurde zur Claude-Apps-Gateway-Anmeldung hinzugefügt: Wenn das Gateway es benennt, bestätigen Sie es, bevor die Anmeldeinformationen gespeichert werden, und /status zeigt es an – Es wurde eine „Jetzt senden“-Taste (Strg+Enter oder Strg+x Strg+s) hinzugefügt, die die aktuelle Runde unterbricht und alle in der Warteschlange befindlichen Nachrichten auf einmal sendet; Gesendete und in der Warteschlange befindliche Nachrichten werden grau angezeigt, bis das Modell sie empfängt – Es wurde eine Startwarnung hinzugefügt, wenn ein konfiguriertes otelHeadersHelper ausfällt, sodass Sitzungen bemerkt werden, die stillschweigend keine Telemetrie exportieren

  • Synchronisierung der in Ihrem claude.ai-Konto aktivierten Fähigkeiten und Plugins mit damit angemeldeten Terminalsitzungen hinzugefügt; Opt-out mit syncClaudeAiSkills: false oder syncClaudeAiPlugins: false
  • /plugin install <plugin> --marketplace <source> hinzugefügt, das anbietet, den Marktplatz vor der Installation des Plugins hinzuzufügen – Es wurde behoben, dass sich der Altershinweis einer wiederhergestellten Speicherdatei zwischen Anfragen nach einer Komprimierung oder einem Fortsetzen änderte, was zu Fehlern im Prompt-Cache führte – Problem behoben, bei dem die --forward-subagent-text-Stream-json- und SDK-Ausgabe die Nachrichten von Subagenten, die von einem context: fork-Skill erzeugt wurden, und von gespaltenen Skills, die von einem Subagenten oder einem anderen gespaltenen Skill aufgerufen wurden, fallen ließ – Problem behoben, bei dem @-Erwähnungsdateivorschläge unter den MCP-Ressourcen verborgen blieben, wenn ein benutzerdefinierter fileSuggestion-Befehl verwendet oder @./@./ eingegeben wurde
  • Im Vollbildmodus wurden Benachrichtigungen über den Abschluss von Aufgaben im Hintergrund unter der eingeblendeten Werkzeugzeile einer langen Kurve platziert, anstatt dort, wo sie angekommen sind. Jeder Hinweis schließt nun die offene Zeile – Problem behoben, bei dem claude plugin marketplace update die lokale Kopie eines GitHub-Marktplatzes löschte, wenn der Abruf fehlschlug und der Marktplatz nach seinem Repository benannt wurde
  • Plugin- und Marktplatz-Meldungen, Protokolle und claude plugin marketplace list, die ein in einer Git-, SSH- oder Marktplatz-URL gespeichertes Passwort oder Token anzeigen, wurden korrigiert – Es wurde ein Problem behoben, bei dem eine fortgesetzte Cloud-Sitzung eine unbeantwortete Frage im Transkript offen ließ, nachdem sie durch eine Nachricht in der Warteschlange ersetzt wurde
  • Im Vim-Modus wurde der Cursor ein Zeichen direkt nach einem durch einen Punkt wiederholten „!“ platziert. oder ein schnell getipptes „i!“ hat eine nicht leere Eingabeaufforderung in den Shell-Modus versetzt
  • Das Einfrieren oder Ausblenden des Vollbildmodus für mehrere Sekunden beim Scrollen über einen großen Dateiunterschied hinaus wurde behoben – Es wurde ein verirrter schließender Tag im </ccmemory>-Stil behoben, der gelegentlich in Antworten auftrat
  • Plugin-Meldungen, Protokolle und der VS-Code-Plugin-Dialog behoben, der für einige Git-Adressen den falschen Server anzeigte – Es wurde ein Terminal API Error: 400 bei jedem Zug für Benutzer hinter einem Netzwerk-Gateway behoben, das API-Fehlerantworten neu schreibt, wenn ein Beta-Anfrage-Header abgelehnt wird – Sandbox-Bash-Befehle unter Linux behoben, die den Exit-Code 0 für fehlgeschlagene Befehle meldeten, wenn die Shell zsh ist – Das Lese-Tool wurde behoben, das hängen blieb, anstatt einen Fehler zu melden, wenn ein Teil einer großen Datei aufgrund von Speicherauslastung nicht dekodiert werden konnte – Problem behoben, bei dem --resume, die Vorschau der Lebenslaufauswahl, fortgesetzte Hintergrundagenten und die Transkriptansicht bei einer Sitzung fehlschlugen, deren gespeicherter Verlauf eine fehlerhafte Aufgabenerinnerung oder einen @-Dateianhangeintrag enthielt – Ein Absturz beim Fortsetzen einer Konversation, deren Transkript einen fehlerhaften Nachrichteneintrag enthielt, sowie ein Absturz im Vollbildmodus, wenn in einer solchen Konversation neue Nachrichten empfangen wurden, während nach oben gescrollt wurde, wurden behoben – Es wurde ein Problem behoben, bei dem Sitzungen nicht fortgesetzt oder gestartet werden konnten, wenn ihr gespeichertes Transkript einen fehlerhaften Nachrichteninhaltsblock enthielt
  • Behoben: Grep-, Glob- und @-Datei-Vorschläge, die bei Suchvorgängen über der Ausgabeobergrenze von 20 MB hängen blieben oder nicht mehr über genügend Speicher verfügten, und dass System-Ripgrep nach einer Flut von Warnungen „keine Übereinstimmungen“ statt eines Fehlers meldete – Problem mit /rewind in einer gespaltenen oder Hintergrundsitzung behoben, bei dem eine mit Nullen gefüllte oder abgeschnittene Datei wiederhergestellt wurde, wenn die Dateiverlaufssicherungen der Sitzung nicht vollständig kopiert werden konnten – Es wurde ein Problem behoben, bei dem Vollbildsitzungen manchmal mit der Meldung „Claude Code wurde nach einem nicht behebbaren Schnittstellenfehler beendet“ beendet wurden, wenn man schnell tippte oder eine Taste gedrückt hielt, während das Schrägstrich-Befehls-Dropdown-Menü geöffnet war – Problem behoben, bei dem Hintergrundsitzungen abstürzten und ihren Worker neu starteten, wenn ein über stdin eingegebener Befehl auf einem Computer ausgeführt wurde, auf dem keine Dateideskriptoren mehr vorhanden waren – Absturz beim Start behoben, wenn ~/.claude.json einen fehlerhaften mcpNeedsAuthNoticed-Wert enthält – Behoben: --resume und --continue ließen das frühere Denken einer Konversation fallen, wenn ein integriertes Tool, mit dem sie begann, inzwischen durch ein serverseitiges Flag ausgeschaltet wurde – Problem behoben, bei dem mit der Maus in der Vollbild-claude --resume-Sitzungsauswahl ausgewählter Text nie das clipboard erreichte – Problem behoben, bei dem die Plugin-Neuladevorschau die extrahierten Plugin-Dateien einer laufenden Sitzung ersetzte, wenn das Plugin aus einem --plugin-dir- oder --plugin-url-Archiv geladen wurde – Problem behoben, bei dem selbst gehostete Läufer mit --drain-wait-sec das Endergebnis einer Runde verloren, die während eines SIGTERM-Abzugs endete; Der Läufer wartet nun kurz auf die Meldung der Wende – SubagentStop-Hooks mit einem bestimmten matcher, der für jeden stoppenden Subagenten ausgelöst wurde, dessen Agententyp leer war, wurden behoben – Behoben: Sandbox-Bash-Befehle konnten nicht in Projektverzeichnisse mit den Namen hooks/ oder config/ schreiben – Es wurde behoben, dass Artefaktaktualisierungen mit der Meldung „Datei nicht gefunden“ fehlschlugen, nachdem eine Sitzung auf einem anderen Computer fortgesetzt oder ihr Notizblock gelöscht wurde: Die letzte veröffentlichte Version der Seite wird wiederhergestellt – Problem behoben, bei dem /update-config anstelle von Edit(path)-Regeln Write(path)-Berechtigungsregeln schrieb, mit denen Dateiberechtigungsprüfungen nicht übereinstimmen – Vier tote Dokumentations-URLs (Preise, Computernutzung, Fähigkeiten, CLI) in der Live-Quellentabelle des gebündelten Claude-api-Skills behoben
  • Verbessertes Zwischenspeichern von Eingabeaufforderungen für einen --system-prompt, der eine __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__-Zeile enthält: Der Text darüber wird jetzt global zwischengespeichert, wie dies bereits bei der Array-Form des SDK der Fall ist – Der Fehler /desktop, wenn Claude Desktop nicht geöffnet wird, wurde verbessert: Es wird jetzt angezeigt, warum und was als nächstes zu tun ist
  • Die Veröffentlichungs- und Leseergebnisse des Artifact-Tools wurden verbessert: Sie sagen jetzt, wer die Seite öffnen kann und was das Teilen-Menü des Eigentümers bietet – Verbesserte Veröffentlichungsergebnisse für Artefakte: Sie benennen das gesendete Tab-Symbol, warnen, wenn die Seite ein NUL-Byte enthält, und versuchen nach einer veralteten Veröffentlichung einen fehlerhaften Abruf der neueren Seite zum Zusammenführen erneut
  • Verbesserte eingefügte und angehängte Bilder: Sie werden jetzt dort gespeichert, wo Claude sie ohne Erlaubnisaufforderung als Dateien öffnen kann, auch in Desktop und VS Code – Die Anleitung des Artefakt-Tools wurde verbessert, sodass Claude ein freigegebenes Artefakt an Ort und Stelle aktualisiert, wenn Sie Bearbeitungszugriff darauf erhalten, anstatt eine separate Kopie zu veröffentlichen – Verbesserte Plannutzungs-Lesevorgänge: Editorfenster und nicht interaktive Sitzungen auf einem Computer teilen sich jetzt einen Lesevorgang, der in der letzten Minute durchgeführt wurde, anstatt dass jeder den Nutzungsendpunkt aufruft
  • Die Beschreibung des ListPlugins-Tools wurde verbessert, sodass Claude weiß, dass in Ihrem claude.ai-Konto aktivierte Plugins aufgelistet werden, nicht lokal mit /plugin installierte Plugins
  • Verbesserte Reaktionsfähigkeit, wenn das Terminal langsam ist oder pausiert: Die Ausgabe fällt nicht mehr weiter zurück, während das Terminal aufholt
  • Verbesserte Schreib- und Bearbeitungsergebnisse für Dateien im synchronisierten Account-Skills-Ordner: Jetzt wird angezeigt, dass die Änderung nicht in Ihrem Konto gespeichert wurde und wie Sie sie speichern können – /logout für Claude-Apps-Gateway-Anmeldungen aktualisiert, um die Sitzung auch auf Gateways zu beenden, die den Token-Widerruf ankündigen – Gehostete Sitzungen wurden so geändert, dass nach einem Neustart des Containers eine unbeantwortete Berechtigungsabfrage angezeigt bleibt, anstatt erneut zu fragen – Das Artefakt-Tool wurde so geändert, dass es bei der ersten Veröffentlichung nach einem Ein-Wort-Tab-Symbol anstelle eines Emoji-Favicons fragt – Claude in Chrome im automatischen Modus geändert, um die pro-Site-Überprüfung der Erweiterung auf vom Klassifikator genehmigte Aufrufe zu überspringen, wie dies im Bypass-Modus der Fall ist, und browser_batch „Berechtigung verweigert“ nach einer Weiterleitung behoben – Von einer NPM-Quelle installierte Plugins wurden so geändert, dass sie mit npm pack --ignore-scripts abgerufen und auf Integrität überprüft werden, sodass die Installationsskripte eines Pakets nicht mehr ausgeführt werden
  • Geplante und „Jetzt ausführen“-Routinenläufe zum Speichern von Daten und zum erneuten Veröffentlichen der Seite eines Artefakts, das Sie ohne Nachfrage bearbeiten können, wurden geändert. Öffentliche Artefakte, Erstveröffentlichungen und Löschungen fragen immer noch – Die Startbenachrichtigung, die Ihnen mitteilte, dass seit Ihrer letzten Sitzung eine einmalige geplante Routine ausgeführt wurde, wurde entfernt
  • [VSCode] Anzeige, Bearbeitung und Löschen eines gespeicherten Speichers im Speicherdialog hinzugefügt
  • [VSCode] Das Senden eines angehängten Bildes ohne Eingabe von Text wurde hinzugefügt – [VSCode] Dem MCP-Serverdialog wurde ein Link „Wiederholen“ hinzugefügt, wenn die Serverliste nicht geladen werden kann
  • [VSCode] Unter jeder Änderung in der Registerkarte „Änderungsvorschlag“ wurden Schaltflächen zum Akzeptieren und Ablehnen hinzugefügt, sodass eine Bearbeitung Änderung für Änderung überprüft werden kann – [VSCode] Problem behoben, bei dem das Transkript in kleinen Schritten nach unten schlich, während eine Berechtigungskarte wartete und weiterhin Inhalte eintrafen
  • [VSCode] Behoben: Zurückgespulte und gespaltene Konversationen behalten nicht den Berechtigungsmodus bei, den Sie für die ursprüngliche Konversation ausgewählt haben – [VSCode] Ein leerer CLAUDE_CONFIG_DIR-Eintrag in der environmentVariables-Einstellung wurde behoben, der dazu führte, dass Claude Code seine Dateien im Arbeitsbereich behielt – [VSCode] Plugin-Installationslinks, die das Dialogfeld „Plugins verwalten“ für Plugin-Namen und Marktplatzadressen öffnen, die nicht in einem Link verwendet werden können, wurden korrigiert
  • [VSCode] Problem behoben, bei dem die Fernbedienung nach einem Ausschalten, das Claude Code als fehlgeschlagen gemeldet hatte, weiterhin als verbunden angezeigt blieb; es wird jetzt als ausgeschaltet angezeigt
  • [VSCode] Das Scrollen nach unten beim Senden wurde behoben, das kurz vor der Antwort anhielt, wenn die Antwort während des Scrollens eintraf – [VSCode] Die Agentenübersicht wurde korrigiert und zeigte Agenten an, dass ein Absturz unvollendet blieb und als gestoppt statt als fehlgeschlagen galt, sobald die Sitzung erneut geöffnet wurde – [VSCode] Problem behoben, bei dem der Hinweis „Schritt wird fortgesetzt“ nicht angezeigt wurde und das Fortsetzungslimit nach einem Neuladen nach einem Absturz mit noch laufenden Hintergrundaufgaben nicht zurückgesetzt wurde – [VSCode] Die Sitzungsliste wurde korrigiert und zeigte an, wann eine Sitzung zuletzt erneut geöffnet wurde, z. B. nach einem Neuladen des Fensters, und nicht, wann die letzte Nachricht gesendet wurde
  • [VSCode] Das Problem, dass „Konversation von hier aus forkieren“ bei der Nachricht fehlschlug, direkt nachdem eine gesendet wurde, während Claude arbeitete, wurde behoben – [VSCode] Problem behoben, bei dem die Cache-Uhr der Eingabeaufforderung nach dem erneuten Öffnen einer Sitzung mit einer Nachricht, die während Claudes Arbeit gesendet wurde, zu wenige Minuten anzeigte – [VSCode] Ein Hintergrundagent wurde behoben, der beendet wurde, während Claude ein Tool ausführte, und nach einem Neuladen des Fensters seine Abschlussbenachrichtigung und sein Ergebnis auf der Agentenkarte verlor – [VSCode] Es wurde ein seltener Fall behoben, bei dem in einer von Git ignorierten Datei ausgewählter Text an Claude gesendet werden konnte, nachdem die Erweiterung mehrere Sekunden lang nicht reagierte
  • [VSCode] Problem behoben, bei dem das Umbenennen einer laufenden Sitzung auf den generierten Namen zurückgesetzt wurde (Regression in 2.1.269) – [VSCode] Einige claude.ai/code-Sitzungen wurden behoben, die in VS Code als leere Konversation ohne Nachrichten geöffnet wurden – [VSCode] Problem behoben, bei dem Slash-Befehle, die eingegeben wurden, während Claude antwortet, als Text an das Modell gesendet wurden, anstatt ausgeführt zu werden, sobald die Antwort abgeschlossen ist
  • [VSCode] Unlesbarer Code in der Planvorschau und den Dialogen zu Hooks und Berechtigungsregeln mit dem Design „High Contrast Light“ wurde behoben
  • [VSCode] Problem behoben, bei dem /remote-control ignoriert wurde, während die Fernbedienung noch eine Verbindung herstellte: Durch erneutes Ausführen wird die Fernbedienung jetzt sofort ausgeschaltet – [VSCode] Behoben, dass die Konversation Sie nach unten zog, während eine Antwort nach dem Scrollen nach oben gestreamt wurde, und eine claudeCode.scrollToBottomOnSend-Einstellung hinzugefügt, um den Sprung beim Senden zu deaktivieren – [VSCode] Das Dialogfeld „Plugins verwalten“ wurde korrigiert und zeigte ein Passwort oder einen Token an, das in eine Marktplatz-URL eingegeben wurde
  • [VSCode] Die Agentenkarte wurde verbessert: Die Pille zählt laufende Agenten und wird nach einem Fehler rot, der Hauptagent bleibt sichtbar, während die Karte scrollt, und Agenten werden nach Status und dann nach Endzeit sortiert – [VSCode] Neue Sitzung in einem Claude-Editor-Tab so geändert, dass sie in der Seitenleiste geöffnet wird, wenn „Bevorzugter Speicherort“ auf „Seitenleiste“ eingestellt ist, anstatt immer einen anderen Tab zu öffnen – [VSCode] Eine Nachricht, die gesendet wurde, während Claude arbeitet, wurde geändert, sodass am Ende der Konversation gewartet wird, bis Claude damit beginnt
  • [Claude Code im Web] Der Seite, die angezeigt wird, wenn ein Routinenlink nicht mehr aufgelöst wird, wurde neben dem Link zurück zu Ihrer Routinenliste eine Schaltfläche „Neue Routine“ hinzugefügt
  • [Claude Code im Internet] Problem behoben, bei dem routinemäßige Benachrichtigungen über „Pause“ und „In der Warteschleife“ mitten im Satz abgeschnitten wurden; In der Mitteilung über die Unterbrechung des Abonnements heißt es nun, dass Sie die Routine wieder auf sich selbst zurückführen sollen
  • [Claude Code im Web] Behoben: Cloud-Umgebungen mit einer sehr langen Liste zulässiger Domänen konnten problemlos gespeichert werden und schlugen dann bei jedem Sitzungsstart fehl; Das Speichern schlägt jetzt fehl und zeigt an, wie viel gekürzt werden muss
  • [Claude Code im Web] Claudes Anleitung korrigiert, wenn einer Cloud-Sitzung auf einem persönlichen Konto der GitHub-Zugriff verweigert wird: Es wird jetzt auf claude.ai/connect-github statt auf eine Seite mit Administratoreinstellungen verwiesen
  • [Claude Code im Web] Die Anweisungen von Claude, wenn Sie aufgefordert werden, eine nicht von ihm erstellte Routine zu bearbeiten, zu löschen oder auszuführen, wurden verbessert: Sie verweisen jetzt auf die Seite der Routine, sodass Sie dies selbst tun können
  • [Claude Tag] Anhängebedingungen für Zugriffspakete in den Claude Tag-Einstellungen hinzugefügt: Ein Eigentümer kann zulassen, dass ein Paket auch in Kanälen mit Gästen oder Slack Connect-Kanälen gilt, nicht nur für Mitglieder
  • [Claude Tag] Voreinstellungen für Amazon CloudWatch, CloudWatch Logs, Amazon SNS, Google Cloud Monitoring und Cloud Logging zur Registerkarte „Anmeldeinformationen“ eines Zugriffspakets in den Claude Tag-Administratoreinstellungen hinzugefügt
  • [Claude Tag] Datadog-Voreinstellungen für die Standorte US3, AP1, AP2 und US1-FED hinzugefügt; Neue Datadog-Verbindungen sind jetzt auf die Lese- und Abfragerouten API von Datadog beschränkt – [Claude Tag] Problem behoben, bei dem S3-Uploads von aktuellen AWS-Versionen CLI und SDK mit einem 502-Fehler fehlschlugen, wenn sie über eine AWS-Verbindung gesendet wurden
  • [Claude Tag] Problem behoben, bei dem Claude einen Kanal als inaktiv behandelte und Nachrichten ohne Tags dort übersprang, während er noch aus einer Routine oder einem Thread in diesem Kanal postete
  • [Claude Tag] Problem behoben, bei dem der Anzeigename „Claude [Aufgabe]“ eines Threads auf „Claude“ zurückgesetzt wurde, nachdem die Sitzung hinter diesem Thread aktualisiert oder neu gestartet wurde
  • [Claude Tag] Das Modell, zu dem Sie in einem Slack-Thread gewechselt haben, wurde behoben und kehrte stillschweigend zur Standardeinstellung des Kanals zurück, nachdem die Sitzung dieses Threads neu gestartet oder aktualisiert wurde
  • [Claude Tag] Problem behoben, bei dem Claude manchmal zweimal antwortete, wenn eine andere App oder ein Bot es in einer Kanalnachricht der obersten Ebene @erwähnte
  • [Claude Tag] Claudes Hinweise in Enterprise Grid-Kanälen, die über Arbeitsbereiche hinweg geteilt werden, wurden verbessert: Sie sagen jetzt, wenn noch kein Arbeitsbereich eingerichtet ist oder warum nur die Standardeinstellungen der Organisation gelten
  • [Codeüberprüfung] Behoben: Bei Überprüfungen wurde gelegentlich ein Teil der Analyse gelöscht, wenn einer der überprüfenden Agenten seine Ergebnisse in einem unerwarteten Format zurückgab
  • [Codeüberprüfung] Problem behoben, bei dem Pull-Anfragen mit mehr als 100 Claude-Überprüfungen bei jeder sauberen Zusammenführung aus dem Basiszweig eine vollständige erneute Überprüfung erhielten, anstatt der leichteren, auf die Zusammenführung ausgerichteten Überprüfung
