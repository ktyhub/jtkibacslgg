claude-code v2.1.277

Claude-Code v2.1.277

Was hat sich geändert?

  • Unterstützung für AGENTS.md hinzugefügt: In einem Projekt ohne CLAUDE.md liest Claude Code stattdessen AGENTS.md; Ändern Sie es unter „Projektanweisungen“ in /config (noch nicht auf Bedrock, Vertex oder Foundry) – CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1 für Claude-Apps-Gateways hinzugefügt, deren einziger Ausgang ein Forward-Proxy ist: Jede ausgehende Anfrage übergibt dem Proxy den Hostnamen, anstatt ihn lokal aufzulösen – Eine optionale headers:-Karte für Claude-Apps-Gateway-Upstreams hinzugefügt, um statische Header an einen Proxy zu senden, den Sie vor einem Anbieter ausführen – Es wurde eine Zeile hinzugefügt, die besagt, dass die Aktualisierung einer Hintergrundaufgabe wartet, wenn sie abgeschlossen ist, während ein Panel wie /tasks geöffnet ist – claude -p- und Agent SDK-Sitzungen behoben, die nach einem internen Fehler ohne Ergebnis hängen bleiben konnten; Sie melden nun den Fehler und beenden den Vorgang mit Code 1 – Behoben: Konversationen scheiterten bei jeder Anfrage mit „Textinhaltsblöcke dürfen nicht leer sein“, wenn ein früherer Assistent an der Reihe war und einen leeren Textblock neben anderen Inhalten hielt, auch nach --resume – Es wurde ein Problem behoben, bei dem es zu einer unerwarteten Abmeldung kam, wenn ein älterer Claude Code-Build (z. B. das gebündelte CLI einer IDE-Erweiterung) auf demselben Computer wie der aktuelle ausgeführt wurde – Das Problem, dass der interaktive Start hängen bleibt oder für ANTHROPIC_API_KEY-Benutzer einen Fehler anzeigt, wenn ~/.claude.json einen fehlerhaften customApiKeyResponses-Wert enthält, wurde behoben – Es wurde behoben, dass Update-Prüfungen alle 30 Minuten fehlerhaft waren und claude update hängen blieb, wenn eine minimale oder maximale Version festgelegt wurde und ein Proxy eine ungültige Version zurückgab; ein fehlerhaftes minimumVersion wird jetzt ignoriert – claude update bei Winget- oder APK-verwalteten Installationen behoben, die „aktuell“ meldeten, wenn die Versionssuche fehlschlug – Behoben, dass claude plugin install manchmal fehlschlug und die installierte Kopie beschädigte, wenn eine Plugin-Version neu installiert wurde, die eine Sitzung oder ein anderes Programm verwendete; eine unveränderte Kopie bleibt nun in Ruhe – Problem behoben, bei dem Grep und Glob keine Übereinstimmungen meldeten, wenn die Suche nicht gestartet werden konnte, weil das System nicht über genügend Prozesse, Speicher oder Dateihandles verfügte; Sie geben jetzt eine entsprechende Fehlermeldung zurück – Problem behoben, bei dem das Schreibtool den Turn stillschweigend als declined-Berechtigung beendete, wenn der Zielpfad ein vorhandenes Verzeichnis ist; es meldet jetzt einen eindeutigen Fehler – Das Bearbeitungstool hat einen maskierten Backslash gefolgt von uXXXX-Text als \uXXXX-Escape behandelt, was dazu führen konnte, dass bei der Bearbeitung eines Nicht-ASCII-Zeichens stattdessen eine maskierte Backslash-Sequenz neu geschrieben wurde – Problem behoben, bei dem das Bearbeitungstool „Ungültiger regulärer Ausdruck: regulärer Ausdruck zu groß“ anstelle von „Zeichenfolge nicht in Datei gefunden“ meldete, wenn eine sehr große Bearbeitung mit Nicht-ASCII-Text nicht mit der Datei übereinstimmte – Es wurde ein Fehler behoben, der vorzeitig mit „Pfad enthält Null-Bytes“ endete, wenn der Dateipfad eines Tool-Aufrufs \u0000 als Escape-Sequenz geschrieben enthielt; Escape-Steuerzeichen bleiben jetzt als wörtlicher Text – Behoben, dass Hintergrundsitzungen (claude --bg) beendet wurden, wenn der LSP-Server eines Plugins beendet oder seinen Standardwert geschlossen hat – Ein Absturz („Typfehler“) beim Öffnen von /mcp oder /plugin manage mit einem fehlerhaften claudeAiMcpEverConnected-Wert in ~/.claude.json wurde behoben – Absturz beim Start behoben, wenn ~/.claude.json einen fehlerhaften theme-Wert enthält – Es wurde ein Absturz behoben („nicht behebbarer Schnittstellenfehler“), wenn die Eingabeaufforderung Text mit Terminal-Farbcodes enthielt, z. B. eine aus dem Verlauf abgerufene Eingabeaufforderung oder aus dem externen Editor geladener Text – Ein Absturz beim Fortsetzen einer Sitzung, deren gespeicherter Verlauf eine als einfache Zeichenfolge gespeicherte Assistentennachricht enthält, wurde behoben – Behoben, dass Sitzungen auf langsamen oder stark ausgelasteten Rechnern manchmal mit „Claude Code wurde nach einem nicht behebbaren Schnittstellenfehler beendet“ beendet wurden, wenn der erste Spinner erschien – Es wurde ein seltener Fall behoben, bei dem der Bildschirm nach einem internen Renderfehler für den Rest der Sitzung nicht mehr aktualisiert werden konnte – Es wurde ein seltener Fall unter Windows behoben, bei dem eine Runde direkt nach der Antwort von Claude mit einem Fehler wie „Nicht genügend Speicher“ abgebrochen werden konnte, sodass die Werkzeugaufrufe dieser Antwort nie ausgeführt wurden – Behoben: Sitzungen wurden fortgesetzt, nachdem bei /clear (Neustart, --continue, --resume) ein Teil ihrer ersten Nachricht fehlte, als ein SessionStart-Hook die Ausgabe druckte, was zu einem vollständigen Fehler im Prompt-Cache führte – Problem behoben, bei dem Nachrichten von anderen Agenten (z. B. SendMessage eines Subagenten), die mitten in der Runde eintrafen, unterhalb der Zeile „Ran N Shell Commands“ und nicht dort angezeigt wurden, wo sie eintrafen – Der „kopierte“ Hinweis wurde behoben, der nicht angezeigt wurde, nachdem Text im Vollbild-/resume-Picker und anderen Bedienfeldern, die den Eingabeaufforderungsbereich abdecken, durch Ziehen ausgewählt wurde – Problem behoben, bei dem $TMPDIR in Bash-Befehlen, die außerhalb der Sandbox ausgeführt werden, während Sandboxing aktiviert ist, leer erweitert wird – Problem behoben, bei dem WebFetch und WebSearch in Cowork-Cloud-Sitzungen Claude nicht mitteilten, warum eine Anfrage abgelehnt wurde, z. B. ein aufgebrauchtes Abrufbudget oder eine Administratorrichtlinie – Problem behoben, bei dem das Telemetrie-Relay des Claude-Apps-Gateways einen in NO_PROXY aufgeführten Collector-Hostnamen oder eine Collector-Domäne ignorierte, wenn ein Proxy festgelegt wurde – Ein fehlerhafter strictKnownMarketplaces- oder blockedMarketplaces-Eintrag wurde behoben, der stillschweigend die gesamte Richtlinie für den Unternehmensmarktplatz deaktivierte – Fehler bei fehlgeschlagenen automatischen Updates behoben, die große gestaffelte Downloads in ~/.cache/claude/staging zurückließen – Behoben, dass /plugin Terminalsteuerzeichen nicht aus Meldungen auf der Registerkarte „Installiert“ entfernte, z. B. der Fehler einer fehlgeschlagenen Plugin-Aktualisierung
  • Behoben: /plugin → Installed und /skills stürzten ab, wenn ein Skill oder Legacy-Befehl wie eine integrierte Objekteigenschaft wie constructor oder toString benannt wird – Problem behoben, bei dem /plugin ohne Meldung geschlossen wurde, wenn jede Installation in einer Mehrfachauswahl fehlschlug – Problem behoben, bei dem deinstallierte Plugins erneut als „Laden fehlgeschlagen“-Zeilen in „/plugin Installed“ angezeigt wurden und „Entfernen“ eine solche Zeile nicht löschte – Problem behoben, bei dem Plugins vom offiziellen Marktplatz ohne ihren Commit in installed_plugins.json aufgezeichnet wurden und installed_plugins.json den alten Commit beibehielt, nachdem ein Plugin mit angeheftetem Commit aktualisiert wurde
  • Problem behoben, bei dem die Plugin-Neuladevorschau jede Vorschaukopie eines Plugin-Archivs bis zum Beenden entpackt hält und das zwischengespeicherte --plugin-url-Archiv überschreibt, auf das ein Neuladen zurückgreift, wenn der Download fehlschlägt – Fehler bei der Buchhaltung der Remote Control-Sitzung behoben, wenn ~/.claude.json einen fehlerhaften Platzhalterdatensatz enthält – Der Fehler wurde behoben, nachdem ein claude.ai-Login widerrufen wurde und ein abgelaufenes Anthropic-Profil dafür verantwortlich gemacht wurde. es führt jetzt mit /login – Ein Problem wurde behoben, bei dem eingegebener oder eingefügter Text bei Tastenwiederholung oder sehr schneller Eingabe gelegentlich in der Dispatch-Eingabe des claude agents verwürfelt aussah – Ein Absturz („nicht behebbarer Schnittstellenfehler“) beim Fortsetzen einer Sitzung behoben, deren gespeichertes Transkript eine Stopp-Hook-Zusammenfassung ohne eine wohlgeformte Hook-Liste enthält – Problem behoben, bei dem die Eingabetaste in einer ausgewählten Agentenfeldzeile nichts bewirkte, wenn keybindings.json die Eingabetaste im Chat-Kontext erneut bindet, beispielsweise an chat:queueSubmit – Problem behoben, bei dem das Lesen von PDF-Seiten unter Windows fehlschlug, wenn der Pfad des Arbeitsordners lang ist (etwa 120 Zeichen oder mehr) – Ein Headless-Resume (claude -p --resume, SDK, ein Neuladen des VS-Code-Erweiterungsfensters) wurde behoben, bei dem die Kosten- und Nutzungssummen der Sitzung bei Null anfingen; Headless-Sitzungen speichern jetzt ihre Gesamtwerte beim Beenden – Problem behoben, bei dem Projektfähigkeiten aus dem Haupt-Repository nicht in --worktree-Sitzungen geladen wurden, wenn .claude/skills nicht verfolgt wurde – Ein sandbox.excludedCommands-Glob wurde behoben, der einen gesamten zusammengesetzten Bash-Befehl aus der Sandbox ausnahm, wenn nur ein Teil übereinstimmte; Jetzt müssen alle Teile zusammenpassen – Es wurde ein Problem behoben, bei dem wieder aufgenommene Subagenten und Teamkollegen die MCP-Tool-Definitionen, die sie geladen hatten, neu renderten, wodurch das Prompt-Caching für diesen Agenten unterbrochen wurde
  • Ratenbegrenzte Artefaktveröffentlichungen behoben, die Claude dazu aufforderten, es nicht mehr zu versuchen; Claude wird nun mitgeteilt, dass nichts veröffentlicht wurde und wann er die gleiche Veröffentlichung erneut senden soll – Es wurde ein Problem behoben, bei dem früher in einer Konversation aufgezeichnete Anhänge nach einem Fortsetzen oder Neustart erneut gerendert wurden, wodurch längeres Nachdenken verloren ging und der Eingabeaufforderungscache fehlte – Problem behoben, bei dem bei der Konsolenanmeldung nur „Anfrage mit Statuscode 400 fehlgeschlagen“ angezeigt wurde, wenn der Server sich weigerte, einen API-Schlüssel zu erstellen; es zeigt jetzt die Nachricht des Servers an
  • Behoben, dass Nachrichten, die eingegeben wurden, während Claude noch arbeitete, manchmal vom Modell ignoriert wurden – Verbesserter Sitzungsstart für SDK und Headless (-p): Die erste Runde wartet nicht mehr auf die verzeichnisbezogene CLAUDE.md-Suche – Die Loopback-Fehlermeldungen des Claude-Apps-Gateways wurden auf den Namen CLAUDE_GATEWAY_ALLOW_LOOPBACK verbessert
  • Verbesserte Installation von /plugin: Ein neben seinem Plugin aufgeführter MCP-Server zeigt jetzt an, zu welchem Plugin er gehört
  • claude plugin install bei einem bereits installierten Plugin verbessert: Es wird jetzt angezeigt, wenn der Marktplatz eine neuere Version anbietet, und der Befehl claude plugin update wird benannt
  • Die Überlaufzeile für Startbenachrichtigungen unter dem Logo wurde verbessert: Es lautet jetzt „N weitere Benachrichtigungen ausgeblendet“ anstelle von „+N weitere · /status“.
  • Verbesserte Verarbeitung von Eingabeaufforderungen: Unsichtbare Unicode-Formatierungen und Tag-Zeichen in einer Eingabeaufforderung werden entfernt und die bereinigte Eingabeaufforderung wird vor dem Senden zur Überprüfung angezeigt – Verbesserter /ultrareview, wenn es nichts zu überprüfen gibt: Nachrichten geben an, in welchem Fall Sie sich befinden, bieten einen Befehl an, der Ihren letzten Commit überprüft, und der erste Commit eines neuen Repositorys wird vollständig überprüft
  • Verbesserte Handhabung von Artefakt-Links, sodass Claude claude.ai-Artefakt-Links mit dem Artifact-Tool statt mit WebFetch liest, wenn dieses Tool verfügbar ist – Die Berechtigungsaufforderung „Dangerous-rm“ wurde verbessert, um den markierten rm-Befehl zu benennen und einen ${VAR:?}-Schutz vorzuschlagen, damit Headless-Läufe wiederhergestellt werden können
  • Die Berechtigungsaufforderungen des Artefakt-Tools wurden verbessert: kürzere Sätze, Seiten und Artefakte, die nach Titel oder Dateinamen benannt sind, und nach dem Text aufgelistete Links
  • Fable wurde so geändert, dass es immer in /model auf dem Anthropic API erscheint; Es ist nur ausgegraut, wenn es in den Einstellungen Ihrer Organisation deaktiviert ist – Die Bash-Sandbox-Anweisungen für Bedrock, Vertex und Foundry wurden in den First-Party-Wortlaut geändert, der die Sandbox als Grenze dessen darstellt, was der Aufgabe zugewiesen wurde – /ultrareview in nicht interaktiven Sitzungen so geändert, dass es abgelehnt wird, wenn das Repository keinen Basiszweig oder gemeinsamen Verlauf hat – Die Ergebnisse des Subagenten wurden so geändert, dass sie den Hauptagenten unter einer Kopfzeile erreichen, die sie als Ausgabe des Subagenten markiert, wobei das Ergebnis eingerückt ist, sodass Text im Ergebnis eines Subagenten nicht als eigene Anweisungen der Sitzung übergeben werden kann – Die berechneten agent()-Eingabeaufforderungen von Workflow-Skripten auf Bedrock, Vertex und Foundry wurden geändert, um den Subagenten als vom Skript erstellten Text zu erreichen, sodass der Sicherheitsklassifikator sie nicht als Benutzer liest – Die automatische Haiku-Titelanforderung im Hintergrund wurde von claude -p-Läufen entfernt, die außerhalb eines SDK oder einer IDE gestartet wurden – Das veraltete TaskOutput-Tool wurde entfernt. Claude liest die Ausgabedatei einer Hintergrundaufgabe stattdessen mit „Lesen“ und die Einstellung „taskOutputMaxChars“ und „TASK_MAX_OUTPUT_LENGTH“ haben keine Auswirkung mehr – [VSCode] Dem Bedienfeldmenü wurde eine Abmeldezeile mit /logout im eingegebenen Befehlsmenü hinzugefügt
  • [VSCode] Hintergrund-Shells und andere laufende Aufgaben zur Agentenkarte hinzugefügt, jeweils mit einem Stopp und einem eingegebenen /tasks, der sie öffnet
  • [VSCode] Eine Schaltfläche „Antwort kopieren“ für Antworten und ein eingegebenes /copy hinzugefügt – [VSCode] Es wurde eine einmalige Benachrichtigung hinzugefügt, wenn inaktive Sitzungen automatisch archiviert werden, und eine Aktion „Alle dearchivieren“ für die Gruppe „Archivierte Sitzungen“. – [VSCode] Die Kosten und Token-Nutzung der Sitzung wurden dem Konto- und Nutzungsdialog und dem Sitzungsmanager hinzugefügt, wo Planbeschränkungen nicht gelten (Vertex, Bedrock, Foundry, API-Schlüssel).
  • [VSCode] Die Menüzeile „Allgemeine Konfiguration“ wurde korrigiert und zeigte den Verwendungstext von /config an, anstatt die Einstellungen zu öffnen. Außerdem wurden bei eingegebenen Befehlen wie /mcp, /hooks, /memory, /rewind und ähnlichen Befehlen Dialoge geöffnet
  • [VSCode] Problem behoben, bei dem die Stufe des Aufwandsschiebereglers in späteren Sitzungen bei einem Modell, bei dem bereits eine Stufe mit /effort gespeichert war, nicht bestehen blieb – [VSCode] Problem behoben, bei dem „Auto“ in der Modusauswahl für Konversationen fehlte, die in einem bereits verwendeten Panel geöffnet wurden, wenn die gespeicherte Modelleinstellung ein Alias mit anderer Schreibweise wie „Sonnet“ ist. – [VSCode] Behoben: /fast speicherte den Schnellmodus nicht als Standard, sodass er verloren ging, als die Erweiterung Claude Code neu startete
  • [Claude Code im Web] Der Umgebungsauswahl bei Team- und Enterprise-Plänen wurden Abschnitte „Persönlich“ und „Organisation“ hinzugefügt, und Administratoren können jetzt eine persönliche Umgebung mit der Organisation teilen
  • [Claude Code im Web] Organisationsumgebungen wurden so geändert, dass sie als schreibgeschützte Zusammenfassung über die Registerkarte „Code“ in Team- und Enterprise-Plänen geöffnet werden können, mit Bearbeitung unter Admin-Einstellungen → Cloud-Umgebungen
  • [Claude Code im Web] Problem behoben, bei dem eine Cloud-Umgebung mit benutzerdefiniertem Netzwerkzugriff und ohne Domänen gespeichert wurde und stillschweigend auf Trusted zurückgesetzt wurde; Der Dialog fragt nun nach mindestens einer Domain
  • [Claude Code im Web] Die Administrator-Claude-Code-Einstellung mit der Bezeichnung „Web“ wurde in „Cloud-Sitzungen“ geändert und die redundante schreibgeschützte Mobilzeile darunter entfernt
  • [Claude Tag] Behoben: Routinen, die in einem Slack-Kanal bei einer organisationsweiten Enterprise Grid-Installation erstellt wurden, konnten beim Ausführen andere öffentliche Kanäle in ihrem Arbeitsbereich nicht lesen
  • [Claude Tag] Die „Weitere Informationen“-Links zu Anmeldeinformationsvoreinstellungen in Claude Tag-Zugriffspaketen wurden korrigiert, um die Anmeldeinformations-Setup-Seite jedes Anbieters anstelle einer generischen API-Referenz zu öffnen
  • [Claude Tag] Die Voreinstellung der Pylon-Anmeldeinformationen in Claude Tag-Zugriffspaketen wurde geändert, sodass Administratoren sie auf den EU-Host von Pylon verweisen können
  • [Claude Tag] Google Cloud-Anmeldeinformationsformulare in Claude Tag-Zugriffspaketen korrigiert: In einer abgelehnten Schlüsseldatei wird jetzt der Grund angegeben, die Website und die Bereiche bleiben gesperrt, und bei einer abgelehnten Rotation bleibt der eingefügte Schlüssel erhalten – [Claude Tag] Das Netzwerkereignisprotokoll in den Admin-Einstellungen von Claude Tag wurde korrigiert und zeigte keinen Antwortstatus für Anfragen über Verbindungen an, die AWS-Signierung, client-Zertifikate oder eine benutzerdefinierte Zertifizierungsstelle verwenden
