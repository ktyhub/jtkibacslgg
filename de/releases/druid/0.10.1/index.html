Druide Druide-0.10.1

Druid 0.10.1 enthält Hunderte von Leistungsverbesserungen, Stabilitätsverbesserungen und Fehlerbehebungen von über 40 Mitwirkenden. Zu den wichtigsten neuen Funktionen gehören:

  • Große Leistungsverbesserungen und zusätzliche Abfragemetriken für TopN-Abfragen – Die Möglichkeit, Begrenzungsklauseln für GroupBy-Abfragen nach unten zu verschieben
  • Genauere Behandlung von Abfrage-Timeouts
  • Hadoop-Indizierungsunterstützung für das Amazon S3A-Dateisystem
  • Unterstützung für die Aufnahme von Protobuf-Daten – Ein neuer Firehose, der Eingaben über HTTP lesen kann – Verbesserte Speicherplatzverwaltung bei der Indizierung aus Cloud-Stores
  • Verschiedene Verbesserungen bei der Verwaltung von Koordinator-Suchen
  • Ein neuer Kafka-Metrik-Emitter
  • Ein neuer Dimensionsvergleichsfilter
  • Verschiedene Verbesserungen an Druid SQL Wenn Sie ein Upgrade von einer früheren Version von Druid durchführen, finden Sie unten „Aktualisierung von 0.10.0 und früher“ Hinweise zum Upgrade, einschließlich einiger abwärtsinkompatibler Änderungen. Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.10.1 Die Dokumentation für diese Version finden Sie unter: http://druid.io/docs/0.10.1/

Highlights

TopN-Leistungsverbesserungen

Die Verarbeitung von TopN-Abfragen mit 1–2 Aggregatoren auf historischen Knoten ist jetzt 2–4 Mal schneller. Dies wird durch eine neue Laufzeitinspektionslogik erreicht, die monomorphe Implementierungen von Abfrageverarbeitungsklassen generiert und so den Polymorphismus im TopN-Abfrageausführungspfad reduziert. Hinzugefügt in einer Reihe von PRs, die hier von @leventov beschrieben werden: https://github.com/druid-io/druid/issues/3798.

Limit-Klausel-Pushdown für GroupBy

Druid kann jetzt Limit-Klauseln in GroupBy-Abfragen optimieren, indem es die Limit-Anwendung auf historische/Echtzeit-Knoten verteilt und das Limit auf Teilergebnismengen anwendet, bevor diese zur Zusammenführung an den Broker gesendet werden. Dadurch wird der Netzwerkverkehr innerhalb des Clusters reduziert und die Zusammenführungsarbeitslast auf Broker-Knoten verringert. Weitere Informationen finden Sie unter http://druid.io/docs/0.10.1/querying/groupbyquery.html#query-context. Hinzugefügt in https://github.com/druid-io/druid/pull/3873 von @jon-wei.

Hadoop-Indizierungsunterstützung für Amazon S3A

Das S3A-Dateisystem von Amazon wird jetzt für Deep Storage und als Eingabequelle für Batch-Aufnahmeaufgaben unterstützt. Die Dokumentation finden Sie unter <>. Hinzugefügt in https://github.com/druid-io/druid/pull/4116 von @b-slim.

Protobuf 3.0-Unterstützung und andere Verbesserungen

Unterstützung für die Aufnahme von Protobuf 3.0-Daten wurde hinzugefügt, zusammen mit anderen Verbesserungen wie dem Lesen von Protobuf-Deskriptoren von einer URL. Protobuf-unterstützender Code wurde ebenfalls in eine eigene Kernerweiterung verschoben. Dokumentation finden Sie unter http://druid.io/docs/0.10.1/development/extensions-core/protobuf.html. Hinzugefügt in https://github.com/druid-io/druid/pull/4039 von @knoguchi.

HTTP-Firehose

Ein neuer Firehose für die Echtzeitaufnahme, der Daten aus einer Liste von URLs über HTTP liest, wurde hinzugefügt. Die Dokumentation finden Sie unter http://druid.io/docs/latest/ingestion/firehose.html#httpfirehose. Hinzugefügt in https://github.com/druid-io/druid/pull/4297 von @jihoonson.

Verbesserte Speicherplatzverwaltung für die Echtzeitindizierung aus Cloud-Stores

Die Firehose-Implementierungen für Microsoft Azure, Rackspace Cloud Files, Google Cloud Storage und Amazon S3 unterstützen jetzt das Caching und Prefetching von Daten. Diese Feuerwehrschläuche können jetzt Teile der Eingabedaten bearbeiten und bei Bedarf neue Daten abrufen, anstatt die Eingaben des Feuerwehrschlauchs vollständig auf die Festplatte lesen zu müssen. Die Dokumentation finden Sie unter den folgenden Links: http://druid.io/docs/0.10.1/development/extensions-contrib/azure.html http://druid.io/docs/0.10.1/development/extensions-contrib/cloudfiles.html http://druid.io/docs/0.10.1/development/extensions-contrib/google.html http://druid.io/docs/0.10.1/development/extensions-core/s3.html Hinzugefügt in https://github.com/druid-io/druid/pull/4193 von @jihoonson.

Verbesserungen bei der Verwaltung von Koordinator-Suchen

An der Statusverwaltungs-/Synchronisierungslogik für Suchvorgänge zur Abfragezeit wurden mehrere Verbesserungen vorgenommen, einschließlich der Versionierung von Suchspezifikationen. Die Dokumentation finden Sie unter http://druid.io/docs/0.10.1/querying/lookups.html. Hinzugefügt in https://github.com/druid-io/druid/pull/3855 von @himanshug.

Kafka-Metrik-Emitter

Es wurde ein neuer Metrik-Emitter hinzugefügt, der Metrikdaten im JSON-Format an Kafka sendet. Siehe http://druid.io/docs/0.10.1/development/extensions-contrib/kafka-emitter.html Hinzugefügt in https://github.com/druid-io/druid/pull/3860 von @dkhwangbo.

Spaltenvergleichsfilter

Ein neuer Spaltenvergleichsfilter wurde hinzugefügt. Mit diesem Filter kann der Benutzer Werte spaltenübergreifend innerhalb einer Zeile vergleichen, wie eine „WHERE ColumnA = ColumnB“-Klausel in SQL. Dokumentation finden Sie unter http://druid.io/docs/0.10.1/querying/filters.html#column-comparison-filter. Hinzugefügt in https://github.com/druid-io/druid/pull/3928 von @erikdubbelboer.

Druid SQL-Verbesserungen

Druid 0.10.1 verfügt über eine Reihe von Verbesserungen an Druid SQL, wie z. B. Unterstützung für Suchvorgänge (PRs von @gianm): https://github.com/druid-io/druid/pull/4368 – Fehlerverzeihenderer Avatica-Server https://github.com/druid-io/druid/pull/4109 – Unterstützung für eine andere Form von gefiltertem Aggregator https://github.com/druid-io/druid/pull/4085 – Regel zum Reduzieren von Sortierketten https://github.com/druid-io/druid/pull/4055 – SQL REGEXP_EXTRACT-Funktion hinzufügen https://github.com/druid-io/druid/pull/3991 – Zeilenextraktionen erweiterbar machen und eine für Suchvorgänge hinzufügen https://github.com/druid-io/druid/pull/4028 – Unterstützung für die Umstellung auf DECIMAL https://github.com/druid-io/druid/pull/3999 – Möglichkeit, Abfragen mit exakter eindeutiger Anzahl zu generieren

Weitere Leistungsverbesserungen

Druid 0.10.1 verfügt über eine Reihe weiterer Leistungsverbesserungen, darunter: https://github.com/druid-io/druid/pull/4364 – Streams dekomprimieren, ohne sie zuerst auf tmp herunterladen zu müssen, von @niketh https://github.com/druid-io/druid/pull/4315 – Verbesserung der Serverauswahl, von @dgolitsyn https://github.com/druid-io/druid/pull/4110 – „Granularität“ aus IngestSegmentFirehose entfernen, von @gianm https://github.com/druid-io/druid/pull/4038 – DateTime As Long serialisieren, um die Leistung von json zu verbessern, von @kaijianding

Und noch viel mehr!

Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.10.1

Aktualisierung von 0.10.0 und früher

Nachfolgend finden Sie die Änderungen zwischen 0.10.0 und 0.10.1, die Sie vor dem Upgrade beachten sollten. Wenn Sie von einer früheren Version als 0.10.0 aktualisieren, lesen Sie bitte die release notes der entsprechenden Zwischenversionen für zusätzliche Hinweise.

Einstellung der Unterstützung für Hadoop-Versionen < 2.6.0

Um Unterstützung für das S3A-Dateisystem von Amazon hinzuzufügen, basiert Druid jetzt auf Hadoop 2.7.3-Bibliotheken und wir verzichten auf die Unterstützung für Hadoop-Versionen, die älter als 2.6.0 sind. Für Benutzer, die eine ältere Hadoop-Version als 2.6.0 verwenden, ist es mithilfe einer Problemumgehung möglich, Druid 0.10.1 weiterhin mit der älteren Hadoop-Version auszuführen. Der Benutzer müsste hadoop.compile.version in der Haupt-Druid-pom.xml herunterstufen, die hadoop-aws-Abhängigkeit von pom.xml in der druid-hdfs-storage-Kernerweiterung entfernen und dann Druid neu erstellen. Benutzern wird dringend empfohlen, ihre Hadoop-Cluster ab dieser Version auf eine 2.6.0+-Version zu aktualisieren, da die Unterstützung für Hadoop <2.6.0 in zukünftigen Versionen möglicherweise vollständig eingestellt wird. Wenn Benutzer Hadoop 2.7.3 als Standard für Aufnahmeaufgaben verwenden möchten, sollten Benutzer alle vorhandenen druid.indexer.task.defaultHadoopCoordinates-Konfigurationen noch einmal überprüfen.

Kafka-Broker-Änderungen

Aufgrund von Änderungen seit https://github.com/druid-io/druid/pull/4115, ist der Kafka-Indexierungsdienst nicht mehr mit Kafka-Brokern der Version 0.9.x kompatibel. Benutzer müssen ihre Kafka-Broker auf eine 0.10.x-Version aktualisieren.

Änderungen im Koordinator-Suchmanagement

https://github.com/druid-io/druid/pull/3855 führt verschiedene Verbesserungen am Weitergabeverhalten der Koordinatorsuche ein. Weitere Informationen finden Sie unter http://druid.io/docs/0.10.1/querying/lookups.html. Beachten Sie die Änderungen am Koordinator HTTP API bezüglich der Lookup-Verwaltung. Wenn Lookups in einer früheren Bereitstellung verwendet werden, sollten im Rahmen des Upgrades auf 0.10.1 alle Koordinatoren gleichzeitig gestoppt, aktualisiert und dann mit der Version 0.10.1 gestartet werden, anstatt sie einzeln zu aktualisieren. Es sollte nie vorkommen, dass ein Koordinator 0.10.0 ausführt, während ein anderer Koordinator gleichzeitig 0.10.1 ausführt. Während des Cluster-Upgrades melden Suchabfrageknoten einen Fehler, der mit got notice to load lookup [LookupExtractorFactoryContainer{version='null' beginnt. Dabei handelt es sich eigentlich nicht um einen Fehler, sondern um einen Nebeneffekt des Updates. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/issues/4603.

Off-Heap-Suchcache zur Abfragezeit

Bitte beachten Sie, dass der Off-Heap-Abfragezeit-Suchcache derzeit aufgrund eines Problems mit übermäßiger Speichernutzung defekt ist und nicht verwendet werden darf: https://github.com/druid-io/druid/issues/3663

Standard-Worker-Auswahlstrategie

Bitte beachten Sie, dass sich die standardmäßige Worker-Auswahlstrategie von fillCapacity in equalDistribution geändert hat.

Laufende Updates

Für fortlaufende Updates sollte der von http://druid.io/docs/0.10.1/operations/rolling-updates.html beschriebene Standard-Druid-Update-Prozess befolgt werden.
