Druide Druide-0.12.0

Druid 0.12.0 enthält über hundert Leistungsverbesserungen, Stabilitätsverbesserungen und Fehlerbehebungen von fast 40 Mitwirkenden. Diese Version fügt dem Kafka-Indexierungsdienst wesentliche Verbesserungen hinzu. Weitere wichtige neue Funktionen sind:

  • Priorisierte Aufgabensperre
  • Verbesserte automatische Segmentverwaltung
  • Testen Sie Statistik-Post-Aggregatoren
  • Numerischer Quantil-Skizzenaggregator
  • Grundlegende Authentifizierungserweiterung
  • Verbesserungen in der Warteschlange für Abfrageanfragen
  • Batch-Analyseunterstützung
  • Verschiedene Leistungsverbesserungen
  • Verschiedene Verbesserungen an Druid SQL Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0 Die Dokumentation für diese Version finden Sie unter: http://druid.io/docs/0.12.0/

Highlights

Kafka-Indizierung inkrementeller Übergaben und entkoppelter Partitionierung

Der Kafka-Indizierungsdienst unterstützt jetzt inkrementelle Übergaben und entkoppelt die Anzahl der von einer Kafka-Indizierungsaufgabe erstellten Segmente von der Anzahl der Kafka-Partitionen. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/pull/4815#issuecomment-346155552. Hinzugefügt von @pjain1 in #4815.

Priorisierte Aufgabensperre

Druid unterstützt jetzt Prioritäten für die Indizierung von Aufgabensperren. Wenn eine Indizierungsaufgabe eine Sperre für eine Datenquelle + ein Intervall erwerben muss, können Aufgaben mit höherer Priorität jetzt Aufgaben mit niedrigerer Priorität vorrangig ausführen. Weitere Informationen finden Sie unter http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority. Hinzugefügt von @jihoonson in https://github.com/druid-io/druid/pull/4550.

Verbesserte automatische Segmentverwaltung

Automatische Bereinigung ausstehender Segmente

Indizierungsaufgaben erstellen Einträge in der Tabelle „pendingSegments“ im Metadatenspeicher; Vor 0.12.0 wurden diese temporären Einträge nicht automatisch bereinigt, was im Laufe der Zeit zu einer möglichen Verschlechterung der Clusterleistung führen konnte. Druid 0.12.0 ermöglicht es dem Koordinator, nicht verwendete Einträge in der Tabelle der ausstehenden Segmente automatisch zu bereinigen. Diese Funktion wird durch die Einstellung druid.coordinator.kill.pendingSegments.on=true in den Koordinatoreigenschaften aktiviert. Hinzugefügt von @jihoonson in #5149.

Komprimierungsaufgabe

Das Komprimieren von Segmenten (Zusammenführen eines Satzes von Segmenten innerhalb eines bestimmten Intervalls, um einen Satz mit größeren, aber weniger Segmenten zu erstellen) ist ein häufiger Anwendungsfall für die Batch-Aufnahme bei Druid. Druid 0.12.0 unterstützt jetzt eine Komprimierungsaufgabe, die alle Segmente innerhalb eines bestimmten Intervalls zu einem einzigen Segment zusammenführt. Weitere Einzelheiten finden Sie unter http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-task. Hinzugefügt von @jihoonson in #4985.

Teststatistiken nach Aggregatoren

Der druid-stats-Erweiterung wurden neue Post-Aggregatoren für Z-Score- und P-Wert-Teststatistiken hinzugefügt. Weitere Einzelheiten finden Sie unter http://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.html. Hinzugefügt von @chunghochen in #4532.

Numerischer Quantil-Skizzenaggregator

Der druid-datasketches-Erweiterung wurde ein Skizzenaggregator für numerische Quantile hinzugefügt. Hinzugefügt von @AlexanderSaydakov in #5002.

Grundlegende Authentifizierungserweiterung

Druid 0.12.0 enthält eine neue Authentifizierungs-/Autorisierungserweiterung, die eine einfache HTTP-Authentifizierung und eine einfache rollenbasierte Zugriffskontrolle bietet. Weitere Informationen finden Sie unter http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html. Hinzugefügt von @jon-wei in #5099.

Verbesserungen in der Warteschlange für Abfrageanfragen

Derzeit können clients einen Broker unbeabsichtigt überfordern, indem sie zu viele Anfragen senden, die in einer unbegrenzten Jetty-Worker-Pool-Warteschlange eingereiht werden. Clients schließen die Verbindung normalerweise nach einem bestimmten client-seitigen Timeout, aber der Broker verarbeitet diese Anfragen weiterhin, was den Anschein erweckt, als würde er nicht reagieren. In der Zwischenzeit würde clients es erneut versuchen und weiterhin Anfragen an einen bereits überlasteten Broker hinzufügen. Mit den neu eingeführten Eigenschaften druid.server.http.queueSize und druid.server.http.enableRequestLimit in der Broker-Konfiguration und der historischen Konfiguration können Benutzer die Anforderungsablehnung konfigurieren, um zu verhindern, dass clients Broker und historische Datenbanken mit Abfragen überfordern. Hinzugefügt von @himanshug in #4540.

Batch-Analyseunterstützung

Für Entwickler benutzerdefinierter Erweiterungen zur Analyse der Aufnahme ist es nun möglich, dass InputRowParser mehrere InputRows aus einer einzelnen Eingabezeile zurückgeben. Dies kann Aufnahmepipelines vereinfachen, indem der Bedarf an Eingabetransformationen außerhalb von Druid reduziert wird. Hinzugefügt von @pjain1 in #5081.

Leistungsverbesserungen

SegmentWriteOutMedium

Beim Erstellen neuer Segmente speichert Druid einige vorverarbeitete Daten in temporären Puffern. Vor 0.12.0 wurden diese Puffer immer in temporären Dateien auf der Festplatte gespeichert. In 0.12.0 ermöglicht PR #4762 von @leventov die Speicherung dieser temporären Puffer im Off-Heap-Speicher, wodurch die Anzahl der Festplatten-E/A-Vorgänge während der Aufnahme reduziert wird. Um die Verwendung von Off-Heap-Speicher für diese Puffer zu ermöglichen, muss die Eigenschaft druid.peon.defaultSegmentWriteOutMediumFactory entsprechend konfiguriert werden. Wenn Sie Off-Heap-Speicher für die temporären Puffer verwenden, stellen Sie bitte sicher, dass -XX:MaxDirectMemorySize erhöht wird, um der höheren direkten Speichernutzung Rechnung zu tragen. Einzelheiten zur Konfiguration finden Sie unter http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory.

Paralleles Zusammenführen von GroupBy-Zwischenergebnissen

PR #4704 von @jihoonson ermöglicht es dem Benutzer, eine Reihe von Verarbeitungsthreads zu konfigurieren, die für die parallele Zusammenführung von GroupBy-Zwischenergebnissen verwendet werden, die auf die Festplatte übertragen wurden. Vor 0.12.0 fand dieser Zusammenführungsschritt immer innerhalb eines einzelnen Threads statt. Einzelheiten zur Konfiguration finden Sie unter http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine.

Weitere Leistungsverbesserungen

  • DataSegment-Speicheroptimierungen: #5094 von @leventov
  • Entfernen Sie IndexedInts.iterator(): #4811 von @leventov – ExpressionSelectors: Optimierte Selektoren hinzufügen: #5048 von @gianm

SQL-Verbesserungen

Verschiedene Verbesserungen und Funktionen wurden von @gianm in den folgenden PRs zu Druid SQL hinzugefügt:

  • Übersetzung von Time-Floor-Ausdrücken verbessern: #5107
  • TIMESTAMPADD hinzufügen: #5079 – Regel hinzufügen, um nicht verwendete Aggregationen zu bereinigen: #5049 – Unterstützt die gefilterte Anzahl im CASE-Stil: #5047
  • „Array“-Ergebnisformat und Dokumentergebnisformate hinzufügen: #5032
    – Behebung von „HavingSpec“ bei komplexen Aggregatoren: #5024 – Verbessertes Verhalten beim impliziten Umwandeln von Zeichenfolgen in Datums-/Uhrzeitliterale: #5023 – Router-Verbindungsbalancer für Avatica-Abfragen hinzufügen: #4983
  • Falsche Filtervereinfachung behoben: #4945 – Router-Verarbeitung von SQL-Abfragen behoben: #4851

Aktualisierung von 0.11.0 und früher

Nachfolgend finden Sie die Änderungen zwischen 0.11.0 und 0.12.0, die Sie vor dem Upgrade beachten sollten. Wenn Sie von einer früheren Version als 0.11.0 aktualisieren, lesen Sie bitte die release notes der entsprechenden Zwischenversionen für zusätzliche Hinweise.

Rollback-Einschränkungen

Bitte beachten Sie, dass nach dem Upgrade auf 0.12.0 aufgrund der in https://github.com/druid-io/druid/pull/4762. vorgenommenen Änderungen kein Downgrade auf eine ältere Version als 0.11.0 mehr möglich ist. Ein Rollback auf die Version 0.11.0 ist weiterhin möglich.

Migration der com.metamx.java-util-Bibliothek

Die Java-Util-Bibliothek von Metamarkets wurde in Druid integriert. Infolgedessen haben sich die folgenden Paketreferenzen geändert: com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics Dies wirkt sich auf die druid.monitoring.monitors-Konfiguration aus. Verweise auf Monitorklassen unter dem alten com.metamx.metrics.*-Paket müssen aktualisiert werden, um stattdessen auf io.druid.java.metrics.* zu verweisen, z. B. io.druid.java.util.metrics.JvmMonitor. Wenn Klassen unter den oben gezeigten com.metamx-Paketen in anderen Konfigurationen wie log4j2.xml referenziert werden, müssen diese Referenzen ebenfalls aktualisiert werden. Erweiterungsentwickler müssen ihren Code aktualisieren, um auch die neuen Druid-Pakete verwenden zu können.

Koffein-Cache-Erweiterung

Die Caffeine-Cache-Erweiterung wurde aus einer Erweiterung in den Kern von Druid verschoben. Darüber hinaus ist der Caffeine-Cache jetzt die Standard-Cache-Implementierung. Bitte entfernen Sie druid-caffeine-cache, falls vorhanden, aus der Erweiterungsliste, wenn Sie auf 0.12.0 aktualisieren. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/pull/4810.

Änderungen am Kafka-Indexdienst

EarlyMessageRejectPeriod

Die Semantik der earlyMessageRejectPeriod-Konfiguration hat sich geändert. Bei der Bestimmung der Grenzen des Nachrichtenfensters wird nun earlyMessageRejectPeriod zu (task start time + task duration) und nicht nur zu (task start time) hinzugefügt. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/pull/4990.

Fortlaufendes Upgrade

In 0.12.0 gibt es Protokolländerungen zwischen dem Kafka-Supervisor und der Kafka-Indexierungsaufgabe sowie einige Änderungen an den auf der Festplatte gespeicherten Metadatenformaten. Um ein fortlaufendes Upgrade zu unterstützen, müssen daher alle mittleren Manager zuerst vor dem Overlord aktualisiert werden. Beachten Sie, dass sich diese Reihenfolge von der Standardreihenfolge für Upgrades unterscheidet. Beachten Sie außerdem, dass diese Reihenfolge nur bei Verwendung des Kafka-Indexierungsdienstes erforderlich ist. Wenn Sie den Kafka Indexing Service nicht verwenden oder Ausfallzeiten für Kafka Supervisor bewältigen können, können Sie in beliebiger Reihenfolge ein Upgrade durchführen. Bis zu dem Zeitpunkt, an dem Overlord aktualisiert wird, verhalten sich alle Kafka-Indexierungsaufgaben auf die gleiche Weise (auch wenn sie aktualisiert werden) wie zuvor, was bedeutet, dass es keine Entkopplung und inkrementelle Übergaben gibt. Sobald Overlord aktualisiert wird, unterstützen die neuen Aufgaben, die vom aktualisierten Overlord gestartet werden, die neuen Funktionen. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/pull/4815.

Rollback

Sobald sowohl der Overlord als auch der mittlere Manager zurückgesetzt wurden, sollte eine neue Reihe von Aufgaben gestartet werden, die ordnungsgemäß funktionieren. Allerdings kann der aktuelle Aufgabensatz während eines Rollbacks fehlschlagen. Weitere Informationen finden Sie unter #4815.

Schnittstellenänderungen für Erweiterungsentwickler

Der ColumnSelectorFactory API hat sich geändert. Autoren von Aggregator-Erweiterungen und alle anderen, die ColumnSelectorFactory verwenden, müssen ihren Code entsprechend aktualisieren. Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/4886. Die Methode Aggregator.reset() wurde entfernt, da sie veraltet und nicht verwendet wurde. Weitere Informationen finden Sie unter https://github.com/druid-io/druid/pull/5177. Die Schnittstelle DataSegmentPusher hat sich geändert und die Methode push() verfügt nun über einen zusätzlichen Parameter replaceExisting. Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/5187. Die Schnittstelle Escalator hat sich geändert: Die Methode createEscalatedJettyClient wurde entfernt. Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/5322.
