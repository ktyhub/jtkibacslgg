código-claude v2.1.274

¿Qué ha cambiado?

  • Se agregó una advertencia visible cuando el uso de la memoria es crítico, con pasos para liberar memoria o reiniciar de forma segura
  • Se agregó CLAUDE_CODE_MCP_STARTUP_WAIT_MS para limitar cuánto tiempo espera el primer turno no interactivo para conectarse a los servidores MCP (0 = no esperar)
  • Se agregó el atributo effort al intervalo de seguimiento claude_code.llm_request OpenTelemetry, que coincide con el evento api_request.
  • Se agregó el evento claude_code.managed_settings_resolved OTel: fuentes de configuración administrada y estado del asistente de políticas; configuraciones redactadas y resúmenes con OTEL_LOG_MANAGED_SETTINGS=1
  • Se agregó store.connect_timeout_seconds a la configuración de la puerta de enlace de aplicaciones de Claude para alargar el tiempo de espera de conexión de Postgres (5 segundos predeterminado) y se mejoró el error de arranque cuando no se puede acceder a la base de datos para que apunte a store.postgres_url y el tiempo de espera configurado.
  • Se agregó enduser.sub, el asunto del IdP, a la telemetría que Claude Desktop y Cowork envían a través de una puerta de enlace de aplicaciones de Claude.
  • Se agregó una advertencia de puerta de enlace de aplicaciones de Claude cuando una réplica tiene más solicitudes abiertas que las 256 que envía a la vez, y una línea de registro de inicio que muestra ese límite.
  • Se agregó click-to-expand para mensajes colapsados de compañeros de equipo y agentes en modo de pantalla completa.
  • Se corrigió que las sesiones se atascaran al reintentar interminablemente errores 400 de "tool_use_id" inesperado: las transcripciones corruptas ahora se reparan automáticamente cuando sea posible y, de lo contrario, un error claro (con una sugerencia /rewind) finaliza el ciclo.
  • Se corrigieron los servidores MCP configurados como http que solo hablan HTTP+SSE heredado y no se conectaban cuando respondían la primera solicitud con un error 422 u otro 4xx.
  • Se corrigió el tiempo de espera de las llamadas de la herramienta HTTP MCP Streamable después de aproximadamente 5 minutos, incluso cuando se configuró un timeout por servidor más largo.
  • Se corrigieron las indicaciones y recursos de MCP que no se actualizaban cuando un servidor envía notificaciones de cambios de lista sin declarar listChanged.
  • Se corrigieron las llamadas a la herramienta MCP rechazadas con 403 insuficiente_scope reportado como un inicio de sesión caducado: el error ahora nombra los permisos faltantes y apunta a la reautenticación /mcp
  • Se corrigieron sesiones impulsadas por ganchos (como un /goal activo) que terminaban con "El mensaje es demasiado largo" en lugar de compactarse cuando el contexto se desbordaba nuevamente después de una compactación reactiva.
  • Se corrigió la pérdida de un /goal activo al reanudar (--continue / --resume) una sesión que había compactado
  • Se corrigió que claude agents perdiera --model, --effort, --permission-mode, --allow-dangerously-skip-permissions y --agent después de un reinicio de actualización automática.
  • Se corrigió una desaceleración por turno cuando un servidor de idiomas publica diagnósticos de todo el proyecto para miles de archivos.
  • Se corrigieron los subagentes con model: "opus" en Bedrock, Vertex o Foundry que dejaban el modelo de la sesión cuando su identificación no tiene una familia de modelos reconocible (a menos que esté configurado ANTHROPIC_DEFAULT_OPUS_MODEL).
  • Se corrigieron sesiones de corredor autohospedadas que fallaban en cada turno con un 401 después de algunas actualizaciones de token fallidas, hasta la siguiente actualización programada; el corredor ahora sigue reintentando y recupera un nuevo token después de un 401
  • Se corrigieron enlaces clickable a rutas de archivos locales que no hacían nada en VS Code y otros terminales que requieren un URI file://
  • Se corrigió la transcripción que renumeraba las listas ordenadas en sus propios mensajes (escribiendo "3. 2. 1." se muestra "3. 4. 5."); Los números y los marcadores "N)" ahora se muestran tal como se escribieron.
  • Se corrigieron las notas de vista previa de AskUserQuestion que se adjuntaban a una opción elegida previamente en lugar de la resaltada.
  • Se corrigió el modo de vista previa de AskUserQuestion que eliminaba la opción resaltada al enviar una nota con Enter.
  • Se corrigió que un agente en segundo plano reanudado mantuviera la mitad de un lote de herramientas interrumpido cuando una de sus llamadas fue aprobada con un mensaje.
  • Se corrigió un claude -p --resume local iniciado con CLAUDE_CODE_RESUME_INTERRUPTED_TURN que no informaba tareas en segundo plano y que el proceso anterior dejó sin terminar.
  • Se corrigió el primer turno de una sesión en la nube que a veces comenzaba sin las herramientas de un servidor MCP alojado en SDK que aún se estaba conectando.
  • Se corrigieron las notificaciones del agente en segundo plano que afirmaban que el agente no tenía trabajo en segundo plano activo cuando todavía estaba esperando su propia tarea en segundo plano y se reanudaría.
  • Se corrigieron sugerencias de error en las sesiones de Claude Desktop para sugerir comandos de barra diagonal como /usage-credits en lugar de indicadores CLI que no se pueden usar allí.
  • Se corrigió que /schedule guardara el mensaje de una rutina sin su función de mensaje cuando Claude escribe la rutina en la forma que devuelve la lista de rutinas.
  • Se corrigió que /status no mostrara la falla de apiKeyHelper que su propio mensaje de error le indicaba que verificara.
  • Se corrigió /fast on en sesiones no interactivas que informaban y luego se apagaban según la política de modo rápido administrado de una organización; ahora dice que la organización lo ha desactivado
  • Se corrigió la herramienta Artifact que le pedía que aprobara una actualización de un artefacto que luego rechazaba porque la sesión no había leído la última versión.
  • Se corrigieron las sesiones en la nube de Cowork y claude.ai con acceso a la red al tratar las lecturas del artefacto de un compañero de equipo como si el acceso a la red estuviera desactivado.
  • Se corrigió un complemento o directorio de mercado sin un repositorio git propio que tomaba su versión de un repositorio git adjunto, como un ~/.claude administrado por git.
  • Se corrigió --strict-mcp-config con un --mcp-config vacío manteniendo el primer turno no interactivo hasta MCP_TIMEOUT en servidores MCP incidentales.
  • Se corrigieron los ganchos de aviso de parada que reenviaban su aviso completo en cada bloque de una conversación; Los bloques repetidos ahora nombran la condición con una etiqueta de 500 caracteres.
  • Se corrigieron ventanas de editor extra vacías que se abrían al inicio en Linux bajo Wayland cuando se ejecuta dentro del terminal Cursor o VS Code.
  • Se corrigió un rechazo de promesa no controlado en la puerta de enlace de aplicaciones de Claude cuando Postgres interrumpe una conexión durante una verificación de gastos.
  • Se corrigió la puerta de enlace de aplicaciones de Claude que cortaba todas las transmisiones abiertas en SIGTERM: ahora permite que las solicitudes en vuelo finalicen hasta 25 segundos antes de salir (CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS)
  • Se corrigió que installed_plugins.json se reescribiera en casi todos los inicios cuando la política de complementos proviene de configuraciones administradas remotamente, lo que hacía que Claude Desktop recargara los complementos de cada sesión abierta.
  • Se corrigieron las sesiones headless y SDK que hacían una llamada de modelo separada para cada tarea en segundo plano que finalizaba; las finalizaciones que ya están en cola ahora se responden con una llamada
  • Se corrigió que la herramienta Bash reabasteciera el perfil de shell (una parada de varios segundos en el siguiente comando) después de cada recarga del complemento; ahora lo hace solo cuando los directorios bin/ de los complementos cambiaron
  • Se corrigieron los complementos con un $schema de nivel superior en hooks/hooks.json que mostraban un aviso de "clave desconocida".
  • Se corrigieron errores de conexión de MCP y la descripción de la herramienta de inicio de sesión de MCP que muestra secretos resueltos desde los marcadores de posición ${VAR} en las configuraciones de MCP.
  • Se corrigieron las comprobaciones de permisos de Bash para comandos que se repiten o asignan ciertas variables de shell especiales; estos comandos ahora piden permiso
  • Se corrigieron sesiones aisladas del árbol de trabajo que aceptaban comandos Bash con ciertas expansiones de shell anidadas; estos ahora son rechazados
  • Se corrigió la vista previa del mensaje de permiso de edición que a veces mostraba una ubicación diferente a la de la edición aprobada en archivos con caracteres de varios bytes.
  • Se corrigieron los comandos en segundo plano que se detenían después de 30 minutos de inactividad en máquinas con una leve presión de memoria; ahora se detienen solo cuando la memoria es críticamente baja y el registro de depuración dice por qué
  • Se corrigió un mensaje que un subagente envía a la sesión principal y que desaparecía de la transcripción de Claude Desktop después de un reinicio.
  • Se corrigió un complemento cargado desde un .zip que se servía desde una extracción obsoleta después de varias recargas superpuestas.
  • Se corrigió que el resumen de progreso de un subagente fuera reemplazado por una respuesta desbocada de varios párrafos.
  • Inicio mejorado en sesiones --input-format stream-json: el primer turno ya no espera hasta 2 segundos para los servidores MCP aún conectados cuyas herramientas de búsqueda difieren; llegan en un turno posterior
  • Notificaciones mejoradas de la herramienta Monitor: la salida final de un script y su salida ahora llegan como una notificación en lugar de dos, lo que guarda un giro del modelo.
  • Errores de la herramienta Artifact mejorados: cuando no has iniciado sesión en claude.ai, el terminal ahora lo indica en el primer intento y se le indica a Claude que deje de volver a intentar una llamada rechazada antes.
  • Publicación de artefactos mejorada: una publicación creada en una versión anterior se detiene antes de enviarse y se fusiona la página más nueva.
  • Comprobaciones de seguridad mejoradas antes de eliminar un árbol de trabajo de agente que contiene comprobaciones de submódulos
  • Salida OTEL_LOG_RAW_API_BODIES=file:<dir> mejorada: nuevos atributos de evento index.jsonl y request_body_id / message.id vinculan cada respuesta a su archivo de solicitud y mensaje de transcripción
  • Arranque de puerta de enlace de aplicaciones Claude mejorado: ahora intenta la primera conexión Postgres hasta tres veces antes de salir, por lo que una base de datos a la que se puede acceder con unos segundos de retraso ya no falla en el arranque.
  • Se mejoró la verificación del límite de gasto de la puerta de enlace de aplicaciones de Claude bajo carga: ahora toma un viaje de ida y vuelta a la base de datos en lugar de cuatro, por lo que se agotan menos comprobaciones en una puerta de enlace ocupada.
  • Errores de límite de tasa de inicio de sesión de la puerta de enlace de aplicaciones Claude mejorados: /login ahora explica el rechazo y el registro de la puerta de enlace dice qué límite se alcanzó y qué configuración cambiar
  • Se cambiaron las instalaciones de Bedrock, Vertex, Foundry y con telemetría deshabilitada para usar la negociación v2 MCP client y MCP 2026-07-28 con servidores HTTP directos de forma predeterminada, como ya lo hacen otras instalaciones (optar por no participar: MCP_SDK_GENERATION=v1 o MCP_PROTOCOL_NEGOTIATION=legacy).
  • Se modificó /code-review para usar mensajes de revisión en línea más sencillos para cada modelo que no tenga configuraciones propias, en lugar de generar muchos subagentes de revisión.
  • Se modificaron las entradas de MCP "type": "sdk" en .mcp.json, configuraciones, complementos y archivos de agente que se omitirán con una advertencia: solo una aplicación host SDK puede registrar servidores en proceso
  • Se modificó la visualización de artefactos en sesiones locales: una nueva versión publicada en otro lugar ya no inicia un turno; Claude se entera de esto a través de un resultado posterior de la herramienta Artefacto.
  • Se cambiaron los clones de complementos y mercados para dejar los archivos Git LFS como punteros en lugar de descargarlos; git lfs pull en la caja los recupera
  • Se cambiaron los ejecutores autohospedados para omitir un repositorio de solo lectura que el host git rechaza en la verificación de acceso en lugar de fallar el inicio de la sesión.
  • Se cambió la línea /status GitHub para que diga "Sesiones en la nube" y /web-setup, /ultrareview y mensajes de teletransporte para que digan "sesión en la nube" en lugar de "Claude Code en la web".
  • [VSCode] Se agregó la continuación del paso en el que se interrumpió la recarga de la ventana, etiquetado en el chat, con un código Claude: Continuar después de la recarga para desactivarlo.
  • [VSCode] Se agregaron entradas de Memoria e Instrucciones al menú Personalizar: Memoria muestra los cambios de memoria automática, las memorias guardadas y las carpetas de memoria, e Instrucciones edita los archivos CLAUDE.md
  • [VSCode] Se agregó una configuración claudeCode.lockEditorGroups para evitar que Claude bloquee los grupos de editores en los que abre.
  • [VSCode] Se corrigió una pregunta secundaria de /btw formulada en los primeros segundos de una nueva conversación que ocasionalmente mostraba el historial de preguntas secundarias de otra sesión.
  • [VSCode] Se corrigió una breve congelación cuando la extensión busca por primera vez su archivo global gitignore
  • [VSCode] Se corrigió un mensaje enviado mientras Claude estaba ejecutando una herramienta que desaparecía de la conversación después de recargar la ventana.
  • [VSCode] Se corrigió que las filas de diálogo de servidores MCP y de activación de complementos de administración fueran inalcanzables desde el teclado.
  • [VSCode] Se corrigieron los inicios y cierres de sesión realizados en una terminal que no se mostraban hasta una recarga después de que CLAUDE_CONFIG_DIR cambiara en la configuración de Variables de entorno.
  • [VSCode] Se corrigió que las diferencias de edición en el chat se cortaran en la parte inferior en algunos anchos de panel y para líneas largas y ajustadas; los cuadros de diferencias ahora se ajustan a las filas mostradas
  • [VSCode] Se corrigió la superposición de escrituras de configuraciones desde la extensión, lo que dejaba ~/.claude/settings.json sin analizar o eliminaba una configuración.
  • [VSCode] Se corrigió Abrir en una nueva pestaña (Ctrl/Cmd+Shift+Esc) que a veces dejaba el cuadro de mensaje de la nueva pestaña desenfocado, por lo que escribir no llegaba a ninguna parte hasta que clilo bloqueaba.
  • [VSCode] Se corrigió la reapertura de una pestaña de Claude cerrada que dividía el diseño del editor cuando su grupo bloqueado todavía contiene otra pestaña de Claude y un archivo.
  • [VSCode] Se corrigió una nueva sesión que abría otro grupo de editor bloqueado cada vez que una pestaña de archivo compartía el grupo con su pestaña Claude.
  • [VSCode] Se corrigieron los nombres de las sesiones que se desplazaban hacia los lados en el selector de sesiones al escribir una consulta de búsqueda.
  • [VSCode] Se corrigió la tarjeta de revisión del plan que cortaba el botón Enviar comentarios y el campo de motivo cuando un plan tiene varios comentarios; la lista de comentarios ahora se desplaza
  • [VSCode] Se corrigió que el código en línea y los bloques de código en las respuestas del chat fueran ilegibles en los temas de Alto contraste.
  • [VSCode] Navegación mejorada del lector de pantalla de la conversación: cada mensaje se anuncia como "Tú" o "Claude", con el nombre de la herramienta para los pasos de la misma.
  • [VSCode] Se cambió el archivo gitignore global predeterminado a $XDG_CONFIG_HOME/git/ignore cuando XDG_CONFIG_HOME es una ruta absoluta
  • [Claude Code en la web] Se agregó un selector de ramas "Comparar con" a la vista de diferencias de una sesión en la nube, para que pueda comparar sus cambios con cualquier rama en lugar de solo con la rama base.
  • [Código Claude en la web] Se corrigió que las operaciones de git en sesiones en la nube fallaran con "servicio no disponible" cuando la renovación del token de GitHub falla brevemente
  • [Claude Code en la web] Se corrigió la edición de una rutina que ocasionalmente hacía que se activara dos veces o volvía a habilitar una rutina que acababa de pausarse.
  • [Código Claude en la web] Se corrigieron las confirmaciones en sesiones en la nube que ocasionalmente fallaban con un error de firma durante unos minutos después de que se actualizaran las credenciales de la sesión.
  • [Código Claude en la web] Se corrigió el brindis después de guardar una rutina cuyo disparador GitHub no se podía vincular para mostrar el motivo, como un límite de disparador por repositorio, en lugar de solo "editar para reintentar".
  • [Claude Code en la web] Se corrigió que las sesiones a veces regresaran a no leídas justo después de marcarlas como leídas.
  • [Código Claude en la web] Se cambiaron las rutinas para omitir una ejecución y volver a intentarlo durante hasta 72 horas cuando falta la conexión GitHub del propietario, en lugar de desactivar la rutina en la primera verificación fallida.
  • [Claude Code en la web] Se modificó el aviso de espera de una rutina: cuando su suscripción está en pausa, ahora le indica que vuelva a activar la rutina en lugar de prometerle una reanudación automática.
  • [Claude Tag] Se agregó una configuración de Invitados a los formularios Agregar canal y Agregar espacio de trabajo en la configuración de administración de Claude Tag, para que los propietarios puedan elegir Heredar, Permitir, Solo canal o Restringir desde el principio.
  • [Etiqueta de Claude] Se corrigió que Claude no respondiera cuando otra aplicación o bot de Slack lo @menciona; la etiqueta ahora recibe una respuesta y despierta a Claude en un canal que había dejado de seguir después de días de inactividad.
  • [Etiqueta de Claude] Se corrigió que a Claude le faltara el mensaje de otra aplicación que etiquetaba a @Claude justo después de que se creara un nuevo canal de Slack; ahora se entrega una vez que Claude se ha unido
  • [Etiqueta de Claude] Se corrigió que Claude doblara un seguimiento enviado minutos después de su último mensaje de Slack como una edición silenciosa; Las actualizaciones tardías, como los bloqueadores, ahora se publican como una nueva respuesta que notifica.
  • [Etiqueta de Claude] Se corrigió que la búsqueda de Slack de Claude fallara con un error cada vez que buscaba dentro de un solo canal; ahora devuelve los mensajes coincidentes de ese canal
  • [Claude Tag] Se corrigió una parada del filtro de seguridad que restablecía silenciosamente el contexto de un hilo de Slack cuando no había nadie esperando; Claude ahora siempre lo dice y ya no cancela el trabajo en segundo plano que aún se está ejecutando.
  • [Etiqueta de Claude] Se corrigieron las direcciones de correo electrónico en las respuestas de Slack de Claude con un prefijo mailto: visible; ahora se muestran como la dirección simple, clickable
  • [Claude Tag] Se corrigió que Claude se negara a ver un canal Enterprise Grid compartido con toda la organización cuando se le preguntaba desde otro espacio de trabajo en el grid.
  • [Claude Tag] Se corrigió el selector de entorno en la configuración de administración de Claude Tag que muestra una ID de entorno sin formato en lugar del nombre del entorno para entornos archivados o creados por aplicaciones.
  • [Etiqueta de Claude] Se mejoró la lista de verificación de progreso en vivo de Claude en Slack: con un límite de 2000 caracteres, se vuelve a publicar como máximo cada 15 minutos en hilos ocupados, con enlaces más antiguos a la "Lista de tareas más recientes" actualizados
  • [Etiqueta de Claude] Se eliminó la nota repetida de atribución de invitados que Claude agregaba a un lienzo de Slack cada vez que editaba uno en un canal usando la configuración de invitado "Solo canal".
  • [Revisión de código] Se corrigieron las nuevas revisiones que ocasionalmente dejaban abierto el hilo de un hallazgo fijo cuando la nueva revisión también presentaba una nota de menor gravedad debajo de él.
  • [Revisión de código] Se corrigieron revisiones raras que terminaban con "La revisión de código encontró un error" cuando GitHub o un servicio interno fallaba transitoriamente en el inicio; ahora esperan y vuelven a intentar
  • [Revisión de código] Se mejoró la forma en que las palabras de revisión de código publican cada hallazgo: oraciones cortas y sencillas que dicen quién se ve afectado, dónde falla el código y la solución inicial.
  • [Revisión de código] Se mejoró la tarjeta de verificación y el comentario de relaciones públicas cuando se omite una revisión debido a un límite de la organización: cada causa ahora vincula la página de administración que la soluciona.
