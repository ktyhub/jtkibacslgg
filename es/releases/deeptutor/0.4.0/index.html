#DeepTutor v0.4.0

🚀 DeepTutor v0.4.0 Release Note

Fecha de lanzamiento: 2026.01.09 ¡Estamos emocionados de anunciar DeepTutor v0.4.0! Esta versión trae Nueva página de inicio, Soporte de proveedor ampliado para LLM y proveedor de incrustaciones, Desacoplamiento del módulo RAG, Mejora web y un montón de mejoras menores.

🚧 Posibles problemas: La implementación de Docker y la configuración local de LLM/Incrustaciones (Ollama, LM Studio) aún pueden tener problemas de compatibilidad. Estamos trabajando activamente en mejoras. ¡Los problemas y las relaciones públicas son bienvenidos! → Abrir un problema | Guía contribuyente

⚠️ Cambios importantes: configuración del entorno

Se han actualizado los nombres de las variables de entorno. Actualice su archivo .env según .env.example. | Variable antigua | Nueva variable | Notas | |:---|:---|:---| | OPENAI_API_KEY | LLM_API_KEY | Ahora independiente del proveedor | | OPENAI_API_BASE | LLM_HOST | Renombrado para mayor claridad | | OPENAI_MODEL | LLM_MODEL | Renombrado para mayor claridad | | EMBEDDING_DIM | EMBEDDING_DIMENSION | Denominación de palabras completas | | (codificado) | BACKEND_PORT | Ahora configurable en .env (predeterminado: 8001) | | (codificado) | FRONTEND_PORT | Ahora configurable en .env (predeterminado: 3782) | Nuevas variables requeridas:

  • LLM_BINDING — Tipo de proveedor: openai, ollama, azure_openai, anthropic, etc.
  • EMBEDDING_BINDING — Tipo de proveedor: openai, ollama, jina, cohere, etc. Nuevas variables opcionales:
  • SEARCH_PROVIDER — Proveedor de búsqueda web: perplexity (predeterminado) o baidu
  • BAIDU_API_KEY — Para búsqueda de IA en Baidu (百度AI搜索)
  • NEXT_PUBLIC_API_BASE: URL de interfaz API para acceso remoto/LAN (por ejemplo, http://192.168.1.100:8001)

💡 Acceso remoto: Si accede a DeepTutor desde otro dispositivo en su red, configure NEXT_PUBLIC_API_BASE en la IP de su servidor. Si no se establece, el valor predeterminado es http://localhost:8001 (solo máquina local). 📌 Acción requerida: Copie .env.example a .env y actualice su configuración antes de actualizar.

✨ Destacados

🔌 LLM de múltiples proveedores y soporte de integración

Ampliado de un ecosistema de proveedores únicamente local a uno completo: | Proveedores de LLM | Proveedores de integración | |:---|:---| | OpenAI, Antrópico, Azure OpenAI | OpenAI, Azure OpenAI, Jina AI | | Ollama, Nube Ollama, Estudio LM | Cohere, Ollama, LM Estudio | | Groq, OpenRouter, DeepSeek, Géminis | HuggingFace (compatible con OpenAI) | La nueva arquitectura basada en adaptadores en src/services/embedding/adapters/ permite agregar fácilmente nuevos proveedores.

🧩 Desacoplamiento del módulo RAG

La nueva clase RAGService proporciona una interfaz unificada independiente del proveedor:

from src.services.rag import RAGService

service = RAGService()  # Uses RAG_PROVIDER env var (default: raganything)
await service.initialize("my_kb", ["doc.pdf"])
result = await service.search("query", "my_kb")

📌 Actualmente es compatible con RAG-Anything (MinerU + LightRAG). ¡Más backends próximamente!

🌙 Modo oscuro y revisión de la interfaz de usuario

  • Alternancia de tema con detección de preferencias del sistema y persistencia de almacenamiento local
  • Barra lateral plegable con modo compacto de solo íconos
  • Reconstrucción de la página de configuración: gestión de variables de entorno con organización basada en categorías
  • Estilo de modo oscuro consistente en todas las páginas

⚙️ Configuración centralizada

Nuevo settings.py que utiliza pydantic-settings para una configuración unificada: | Categoría | Variables de entorno | |:---|:---| | Máster en Derecho | LLM_BINDING, LLM_MODEL, LLM_HOST, LLM_API_KEY | | Incrustación | EMBEDDING_BINDING, EMBEDDING_MODEL, EMBEDDING_HOST, EMBEDDING_API_KEY, EMBEDDING_DIMENSION | | TRAPO | RAG_PROVIDER | | ETT | TTS_MODEL, TTS_URL, TTS_API_KEY, TTS_VOICE | | Buscar | PERPLEXITY_API_KEY | Actualizaciones en tiempo de ejecución a través de /api/settings/env con persistencia automática de .env.

📦 ¿Qué ha cambiado?

Infraestructura central

  • Se agregó settings.py con pydantic-settings para administración de configuración centralizada.
  • Se agregó src/core/llm_factory.py con función llm_complete() unificada
  • Se agregó el enrutador /api/embedding-providers para integrar la configuración CRUD.
  • Se agregaron puntos finales /api/settings/env para la gestión del entorno de ejecución.

Reestructuración del módulo de servicios (src/services/)

services/
├── embedding/          # 🆕 Adapter-based embedding providers
│   ├── adapters/       # Provider implementations
│   │   ├── base.py, openai_compatible.py, jina.py, cohere.py, ollama.py
│   ├── client.py       # Unified embedding client
│   ├── provider.py     # Provider manager (singleton)
│   └── provider_config.py  # Multi-provider config persistence
├── llm/                # LLM configuration & client
├── rag/                # 🆕 Decoupled RAG system
│   ├── service.py      # Unified RAGService entry point
│   ├── factory.py      # Pipeline factory
│   ├── pipelines/      # Backend implementations
│   │   └── raganything.py, lightrag.py, llamaindex.py, academic.py
│   └── components/     # Modular RAG components
│       ├── chunkers/   # Text chunking strategies
│       ├── parsers/    # Document parsers (PDF, Markdown, Text)
│       ├── embedders/  # Embedding wrappers
│       ├── indexers/   # Vector & Graph indexers
│       └── retrievers/ # Dense & Hybrid retrieval
├── prompt/             # PromptManager singleton
├── tts/                # TTS configuration
└── setup/              # Initialization utilities

Actualizaciones de interfaz

  • 🆕 Se agregó Página de inicio (web/app/page.tsx) con descripción general de funciones
  • 🆕 Página de historial reconstruida (web/app/history/page.tsx) con vistas de actividad mejoradas
  • Se agregó web/lib/theme.ts con utilidades de temas (initializeTheme(), setTheme())
  • Se agregó web/hooks/useTheme.ts para el gancho del tema React.
  • Se agregó web/components/ThemeScript.tsx para la hidratación del tema SSR.
  • Se agregó web/components/ChatSessionDetail.tsx para la página de historial.
  • Sidebar.tsx refactorizado con modo plegable
  • settings/page.tsx reconstruido con gestión de variables de entorno.

Mejoras en IdeaGen

Flujo de trabajo mejorado de 4 etapas: Filtro suelto → Explorar ideas → Filtro estricto → Generar declaración

🐳Docker

Implementación optimizada de un solo contenedor:

docker compose up -d
# Exposes: backend (8001), frontend (3782)
# Volumes: ./config (ro), ./data/user, ./data/knowledge_bases

Implementación en la nube compatible a través de NEXT_PUBLIC_API_BASE_EXTERNAL.

⬆️ Actualizar

git pull origin main
docker compose build && docker compose up -d

  • Cambiar nombre EMBEDDING_DIM → EMBEDDING_DIMENSION
