druida druida-0.12.1

Druid 0.12.1 contiene mejoras de estabilidad y correcciones de errores de 10 contribuyentes. Las principales mejoras incluyen:

  • Grandes mejoras de rendimiento para el estado de carga del coordinador API
  • Más limitación de memoria para HttpPostEmitter
  • Solucionar varios problemas de autenticación Kerberos
  • Se corrigió SQLMetadataSegmentManager para permitir inicios y paradas sucesivos.
  • Se corrigió el manejo de intervalos predeterminado en SegmentMetadataQuery
  • Admite solicitud de OPCIONES HTTP
  • Se corrigió un error de diferentes segmentos del mismo ID de segmento en la indexación de Kafka. La lista completa de cambios está aquí: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1 La documentación para esta versión está en: http://druid.io/docs/0.12.1

Destacados

Grandes mejoras de rendimiento para el estado de carga del coordinador API

El loadstatus API de Coordinadores devuelve el porcentaje de segmentos realmente cargados en el clúster frente a los segmentos que deberían cargarse en el clúster. Se ha mejorado mucho el rendimiento de este API. Agregado por @ jon-wei en # 5632.

Más limitación de memoria para HttpPostEmitter

Druid ahora puede limitar la cantidad de memoria utilizada por HttpPostEmitter al 10% del montón JVM disponible, evitando así errores OutOfMemory de eventos almacenados en el búfer. Agregado por @ jon-wei en # 5300.

Solucionar varios problemas de autenticación Kerberos

Hubo algunos errores en la autenticación Kerberos, como fallas de autenticación sin cookies o autenticación rota cuando se usa el enrutador. Consulte https://github.com/druid-io/druid/pull/5596, https://github.com/druid-io/druid/pull/5706, y https://github.com/druid-io/druid/pull/5766 para obtener más detalles. Agregado por @nishantmonu51 en #5596. Agregado por @b-slim en #5706. Agregado por @ jon-wei en # 5766.

Reparar SQLMetadataSegmentManager para permitir inicios y paradas sucesivos

Los coordinadores podrían quedarse estancados si pierden liderazgo al comenzar. Este error se ha solucionado ahora. Agregado por @jihoonson en #5554.

Corregir el manejo de intervalos predeterminado en SegmentMetadataQuery

Se supone que SegmentMetadataQuery usa el intervalo de druid.query.segmentMetadata.defaultHistory si no se especifica el intervalo, pero en su lugar consulta todos los segmentos, lo que genera un impacto inesperado en el rendimiento. SegmentMetadataQuery ahora vuelve a respetar la opción defaultHistory. Agregado por @gianm en #5489.

Admite solicitud de OPCIONES HTTP

Druid ahora admite la solicitud de OPCIONES HTTP arreglando su manejo de autenticación. Agregado por @ jon-wei en # 5615.

Corregir un error de diferentes segmentos de la misma identificación de segmento en la indexación de Kafka

El servicio de indexación de Kafka permitió reintentar tareas para sobrescribir los segmentos en el almacenamiento profundo escritos por las tareas fallidas anteriores. Sin embargo, esto provocó otro error: el mismo ID de segmento podía tener datos diferentes en el historial y en el almacenamiento profundo. Este error se ha solucionado ahora mediante el uso de rutas de segmento únicas para cada tarea de índice de Kafka. Agregado por @dclim en #5692.
