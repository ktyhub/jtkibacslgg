druida druida-0.14.0-incubating

Apache Druid (en incubación) 0.14.0-incubating contiene más de 200 funciones nuevas, mejoras de rendimiento/estabilidad/documentación y correcciones de errores de 54 contribuyentes. Las principales nuevas características y mejoras incluyen:

  • Nueva consola web
  • Servicio de indexación de Amazon Kinesis
  • Modo de desmantelamiento para históricos.
  • Caché de segmento publicado en Broker
  • Agregador de filtros Bloom y expresión.
  • Extensión Apache Parquet actualizada
  • Opción de forzar la inserción hacia abajo para consultas GroupBy anidadas
  • Mejor manejo de reglas de entrega y eliminación de segmentos
  • Elimina automáticamente los trabajos de MapReduce cuando se eliminan las tareas de ingestión de Apache Hadoop.
  • Soporte de etiquetas DogStatsD para emisor de estadísticas
  • Nuevo API para recuperar todas las especificaciones de búsqueda
  • Nuevas opciones de compactación
  • Almacenamiento en caché más eficienteEstrategia de equilibrio de segmentos de costos La lista completa de cambios está aquí: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 La documentación para esta versión está en: http://druid.io/docs/0.14.0-incubating/

Destacados

Nueva consola web

Druid tiene una nueva consola web que proporciona funciones que anteriormente estaban divididas entre las consolas del coordinador y del señor supremo. La nueva consola permite al usuario administrar fuentes de datos, segmentos, tareas, procesos de datos (históricos y administradores intermedios) y la configuración dinámica del coordinador. El usuario también puede ejecutar consultas SQL y Druid nativas dentro de la consola. Para más detalles, consulte http://druid.io/docs/0.14.0-incubating/operations/management-uis.html Agregado por @vogievetsky en #6923.

Servicio de indexación de Kinesis

Druid ahora admite la ingesta de transmisiones de Kinesis, proporcionada por la nueva extensión principal druid-kinesis-indexing-service. Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html para obtener más detalles. Agregado por @ jsun98 en # 6431.

Modo de desmantelamiento para históricos

Los procesos históricos ahora se pueden poner en modo de "desmantelamiento", donde el coordinador ya no considerará el proceso histórico como un objetivo para la replicación del segmento. El coordinador también trasladará segmentos del desmantelamiento histórico. Esto se controla mediante la configuración dinámica del Coordinador. Para más detalles, consulte http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration. Agregado por @egor-ryashin en #6349.

Caché de segmento publicado en Broker

Druid Broker ahora tiene la capacidad de mantener un caché de segmentos publicados mediante el sondeo del Coordinador, lo que puede mejorar significativamente el tiempo de respuesta para consultas de metadatos en la tabla del sistema sys.segments. Consulte http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata para obtener más detalles. Añadido por @surekhasaharan en #6901

Expresión y agregador de filtros Bloom

Se ha agregado a la extensión druid-bloom-filter un nuevo agregador para construir filtros Bloom en el momento de la consulta y soporte para realizar comprobaciones de filtros Bloom dentro de expresiones Druid. Por favor ver http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html Agregado por @ clintropolis en # 6904 y # 6397

Extensión Parquet actualizada

druid-extensions-parquet se ha movido al conjunto de extensiones principales desde las extensiones de contrib y ahora admite valores de aplanamiento e int96. Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html para obtener más detalles. Agregado por @clintropolis en #6360

Forzar la opción de empujar hacia abajo para consultas GroupBB anidadas

La ejecución de consultas externas para consultas GroupBy anidadas ahora se puede enviar a procesos históricos; Anteriormente, las consultas externas siempre se ejecutaban en el Broker. Consulte https://github.com/apache/incubator-druid/pull/5471 para obtener más detalles. Agregado por @samarthjain en #5471.

Mejor manejo de reglas de retención y transferencia de segmentos

La transferencia de segmentos ahora ignorará los segmentos que las reglas de retención de una fuente de datos eliminarían, evitando fallas de ingesta causadas por el problema #5868. Las reglas de carga de períodos ahora incluirán el futuro de forma predeterminada. Se ha agregado una nueva regla de "caída del período antes". Consulte http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule para obtener más detalles. Agregado por @QiuMM en #6676, #6414 y #6415.

Eliminar automáticamente los trabajos de MapReduce cuando se eliminan las tareas de ingesta de Hadoop

Druid ahora finalizará automáticamente los trabajos de MapReduce creados por las tareas de ingesta por lotes de Hadoop cuando se finalice la tarea de ingesta. Agregado por @ ankit0811 en # 6828.

Soporte de etiquetas DogStatsD para statsd-emitter

La extensión statsd-emitter ahora admite etiquetas estilo DogStatsD. Por favor ver http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html Agregado por @deiwin en el n.° 6605, con soporte para etiquetas constantes agregadas por @glasser en el n.° 6791.

Nuevo API para recuperar todas las especificaciones de búsqueda

Se agregó un nuevo API para recuperar todas las especificaciones de búsqueda para todos los niveles. Consulte http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups para obtener más detalles. Agregado por @jihoonson en #7025.

Nuevas opciones de compactación

La compactación automática ahora admite la opción maxRowsPerSegment. Consulte http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments para obtener más detalles. La tarea de compactación ahora admite una nueva opción segmentGranularity, que deja obsoleta la opción anterior keepSegmentGranularity para controlar la granularidad de los segmentos compactados. Consulte la tabla segmentGranularity en http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html para obtener más información sobre estas propiedades. Agregado por @jihoonson en los números 6758 y 6780.

Almacenamiento en caché más eficienteEstrategia de equilibrio de segmentos de costos

La estrategia de equilibrio del segmento Coordinador cachingCost ahora solo considerará procesos históricos para las decisiones de equilibrio. Anteriormente, la estrategia también consideraría innecesariamente las tareas de los trabajadores activos, que no son objetivos para la replicación del segmento. Agregado por @QiuMM en #6879.

Nuevas métricas:

  • Nueva métrica de tasa de asignación jvm/heapAlloc/bytes, agregada por @egor-ryashin en el n.° 6710.
  • Nueva métrica de recuento de consultas query/count, agregada por @QiuMM en el n.º 6473.
  • Métricas de consulta SQL sqlQuery/bytes y sqlQuery/time, agregadas por @gaodayue en el n.° 6302.
  • Métricas de retraso de ingesta Apache Kafka ingest/kafka/maxLag y ingest/kafka/avgLag, agregadas por @QiuMM en el n.º 6587
  • Métricas de recuento de tareas task/success/count, task/failed/count, task/running/count, task/pending/count, task/waiting/count, agregadas por @QiuMM en #6657

Nuevas interfaces para desarrolladores de extensiones

Evento de registro de solicitud

Ahora es posible controlar los campos en RequestLogEvent, emitidos por EmittingRequestLogger. Consulte el n.° 6477 para obtener más detalles. Agregado por @leventov.

Comprobaciones de certificados TLS personalizados

Se ha agregado un punto de extensión para verificaciones de certificados TLS personalizados. Consulte http://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checks para obtener más detalles. Agregado por @ jon-wei en # 6432.

Kafka Indexing Service ya no es experimental

La extensión Kafka Indexing Service ha dejado de estar en estado experimental.

Mejoras de SQL

Mejoras en dsql

La línea de comando dsql client ahora admite el historial de CLI, el autocompletado básico y la especificación de tiempos de espera de consulta en el contexto de la consulta. Agregado en el n.° 6929 por @gianm.

Agregar identificación de SQL, registros de solicitudes y métricas

Las consultas SQL ahora tienen un ID y las consultas nativas ejecutadas como parte de una consulta SQL tendrán el ID de consulta SQL asociado en los registros de solicitudes de la consulta nativa. Las consultas SQL ahora se registrarán en los registros de solicitudes. Ahora se emiten dos nuevas métricas, sqlQuery/time y sqlQuery/bytes, para consultas SQL. Consulte http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging y http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics para obtener más detalles. Añadido por @gaodayue en #6302

Más compatibilidad con el agregador SQL

Los siguientes agregadores ahora son compatibles con SQL:

  • Bosquejo de DataSketches HLL
  • Boceto Theta de DataSketches
  • Bosquejo de cuantiles de DataSketches
  • Histograma de contenedores fijo
  • Agregador de filtros Bloom Agregado por @jon-wei en #6951 y @clintropolis en #6502

Otras mejoras de SQL

  • SQL: agregue soporte para consultas con proyecto después de semiunión. #6756
  • SQL: Soporte para seleccionar dimensiones de múltiples valores. #6462
  • SQL: admite AVG en tablas del sistema. #601
  • SQL: Agregar función "POSICIÓN". #6596
  • SQL: establezca el nombre del catálogo INFORMACIÓN_SCHEMA en "druida". #6595
  • SQL: Se corrigió el orden de clasificación, sortProject en DruidSemiJoin. #6769 Agregado por @gianm.

Actualización desde 0.13.0-incubating y anteriores

Tiempo de inactividad de la ingestión de Kafka al actualizar

Debido al problema descrito en el número 6958, las tareas de indexación de Kafka existentes pueden finalizarse innecesariamente durante una actualización continua de Overlord. Overlord reiniciará las tareas finalizadas y funcionarán correctamente después del reinicio inicial.

Cambios en la extensión del parquet

La extensión druid-parquet-extensions se ha movido de contrib a core. Al implementar 0.14.0-incubating, asegúrese de que su directorio extensions-contrib no tenga versiones anteriores de la extensión Parquet. Además, ahora hay dos estilos de analizadores Parquet en la extensión:

  • parquet-avro: convierte Parquet a Avro y luego analiza la representación de Avro. Este era el analizador existente antes de 0.14.0-incubating.
  • parquet: Un nuevo analizador que analiza el formato Parquet directamente. Sólo este nuevo analizador admite valores int96. Antes de 0.14.0-incubating, al especificar un analizador de tipo parquet la tarea era utilizar el analizador de conversión Avro. En 0.14.0-incubating, para continuar usando el analizador de conversión Avro, deberá actualizar sus especificaciones de ingesta para usar parquet-avro en su lugar. El campo inputFormat en inputSpec para tareas que utilizan la entrada Parquet también debe coincidir con la elección del analizador:
  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html para obtener más detalles.

Ejecutando Druid con Hadoop que no es 2.8.3

Si planea utilizar Druid 0.14.0-incubating con versiones de Hadoop distintas a 2.8.3, es posible que deba hacer lo siguiente:

  • Establezca las coordenadas de dependencia de Hadoop para su versión de destino como se describe en http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html en Tip #3: Use specific versions of Hadoop libraries.
  • Reconstruya Druid con su versión objetivo de Hadoop cambiando hadoop.compile.version en el Druid principal pom.xml y luego siguiendo las instrucciones de compilación estándar.

Otros cambios de comportamiento

Limpieza de tareas antiguas

Las entradas de tareas antiguas en el almacenamiento de metadatos ahora se limpiarán automáticamente junto con sus registros de tareas. Consulte http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging y #6592 para obtener más detalles.

Tamaño del búfer de procesamiento automático

La propiedad druid.processing.buffer.sizeBytes tiene un nuevo comportamiento predeterminado si no está configurada. Druid ahora elegirá automáticamente un valor para el tamaño del búfer de procesamiento usando la siguiente fórmula:

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

donde:

  • totalDirectMemory: el límite de memoria directa para el JVM especificado por -XX:MaxDirectMemorySize
  • numMergeBuffers: el valor de druid.processing.numMergeBuffers.
  • numProcessingThreads: el valor de druid.processing.numThreads. Como máximo, Druid utilizará 1 GB para el tamaño del búfer de procesamiento elegido automáticamente. El tamaño del búfer de procesamiento aún se puede especificar manualmente. Consulte el n.º 6588 para obtener más detalles.

Las reglas de retención ahora incluyen el futuro de forma predeterminada

Tenga en cuenta que las nuevas reglas de retención ahora incluirán el futuro de forma predeterminada. Consulte el n.° 6414 para obtener más detalles.

Cambios de propiedad

Anuncio de segmento

La propiedad druid.announcer.type utilizada para elegir entre Zookeeper o la administración/descubrimiento de segmentos basados en HTTP se ha movido a druid.serverview.type. Si estaba usando http antes de 0.14.0-incubating, deberá actualizar sus configuraciones para usar el nuevo druid.serverview.type. Consulte lo siguiente para obtener más detalles:

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

corrige la propiedad que falta en JsonTypeInfo de SegmentWriteOutMediumFactory

Se ha corregido la propiedad druid.peon.defaultSegmentWriteOutMediumFactory.@type. La propiedad ahora es druid.peon.defaultSegmentWriteOutMediumFactory.type sin "@". Consulte el n.° 6656 para obtener más detalles.

Depreciaciones

Agregador de histograma aproximado

El agregador AproximateHistogram ha quedado obsoleto; es un algoritmo dependiente de la distribución sin límites de error formales y tiene importantes problemas de precisión. En su lugar, se debe utilizar el agregador DataSketches quantiles para casos de uso de cuantiles e histogramas. Consulte Agregadores de histogramas y cuantiles

Agregador Cardinality/HyperUnique

Los agregadores Cardinality e HyperUnique han quedado obsoletos en favor del agregador DataSketches HLL y el agregador Theta Sketch. Estos agregadores tienen mejores características de precisión y rendimiento. Consulte Contar agregadores distintos para obtener más detalles.

Período de fragmento de consulta

La configuración del contexto de consulta chunkPeriod ahora está obsoleta, junto con la métrica query/intervalChunk/time asociada. Consulte el n.º 6591 para obtener más detalles.

keepSegmentGranularity para compactación

La opción keepSegmentGranularity para tareas de compactación ha quedado obsoleta. Consulte el n.º 6758 y la tabla segmentGranularity en http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html para obtener más información sobre estas propiedades.

Cambios en la interfaz para desarrolladores de extensiones

clase SegmentId

Druid ahora usa una clase SegmentId en lugar de cadenas simples para representar los ID de los segmentos. Consulte el n.º 6370 para obtener más detalles. Agregado por @leventov.

druid-api, druid-common, java-util movidos a druid-core

Los módulos druid-api, druid-common, java-util se han trasladado a druid-core. Actualice sus dependencias en consecuencia si su proyecto dependía de estas bibliotecas. Consulte el n.° 6443 para obtener más detalles.
