druida druida-0.17.0

Apache Druid 0.17.0 contiene más de 250 funciones nuevas, mejoras de rendimiento, correcciones de errores y mejoras importantes en la documentación de 52 colaboradores. Consulte la lista completa de cambios y todo lo etiquetado en el hito.

Destacados

Mejoras en la ingesta por lotes

Druid 0.17.0 incluye una actualización importante del sistema nativo de ingesta por lotes. Esta actualización agrega el marco interno para admitir formatos binarios que no son de texto, con soporte inicial para ORC y Parquet. Además, las tareas por lotes nativas ahora pueden leer datos de HDFS. Esta revisión cambia la forma en que se especifican la fuente de ingesta y el formato de datos en la tarea de ingesta. Para utilizar las nuevas funciones, consulte la documentación sobre InputSources y InputFormats. Consulte la siguiente documentación para obtener más detalles: https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

Partición de rango de dimensión única para la ingesta de lotes nativos paralelos

La tarea de índice paralelo ahora admite la especificación de particiones de tipo single_dim, que permite la partición basada en rangos en una sola dimensión. Consulte https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html para obtener más detalles.

Cambios de compactación

Sugerencias de división de tareas de índice paralelo

La tarea de indexación paralela ahora tiene una nueva configuración, splitHintSpec, en tuningConfig para permitir a los operadores proporcionar sugerencias para controlar la cantidad de datos que lee cada subtarea de la primera fase. Actualmente existe un tipo de especificación de sugerencia dividida, SegmentsSplitHintSpec, que se utiliza para volver a ingerir segmentos de Druida.

Autocompactación paralela

La compactación automática ahora puede utilizar la tarea de indexación paralela, lo que permite un mayor rendimiento de compactación. Para controlar el nivel de paralelismo, la autocompactación tuningConfig tiene nuevos parámetros, maxNumConcurrentSubTasks y splitHintSpec. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration para obtener más detalles. https://github.com/apache/incubator-druid/pull/8570

Autocompactación con estado

La compactación automática ahora utiliza la especificación de partición para rastrear los cambios realizados por tareas de compactación anteriores, lo que permite al coordinador reducir las operaciones de compactación redundantes. Consulte https://github.com/apache/druid/issues/8489 para obtener más detalles. Si tiene habilitada la compactación automática, consulte la información en "Cambios de compactación automática con estado" en la sección "Actualización a Druid 0.17.0" antes de realizar la actualización.

Consulta paralela fusionándose en corredores

El corredor Druid ahora puede fusionar de manera oportunista los resultados de las consultas en paralelo utilizando múltiples subprocesos. Consulte druid.processing.merge.useParallelMergePool en la sección Agente de la [referencia de configuración] (https://druid.apache.org/docs/0.17.0/configuration/index.html) para obtener detalles sobre cómo configurar esta nueva característica. La combinación paralela está habilitada de forma predeterminada (controlada por la propiedad druid.processing.merge.useParallelMergePool) y la mayoría de los usuarios no deberían tener que cambiar ninguna de las propiedades de configuración avanzada descritas en la referencia de configuración. Además, el paralelismo de fusión se puede controlar por consulta utilizando el contexto de consulta. Puede encontrar información sobre los nuevos parámetros de contexto de consulta en https://druid.apache.org/docs/0.17.0/querying/query-context.html. https://github.com/apache/incubator-druid/pull/8578

Manejo de nulos compatible con SQL

En 0.17.0, hemos agregado documentación oficial para el modo de manejo de nulos compatible con SQL de Druid. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling y https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling para obtener más detalles. Se han solucionado varios errores que existían en este modo no documentado anteriormente, particularmente en torno al manejo de nulos en columnas numéricas. Recomendamos que los usuarios comiencen a considerar la transición de sus clústeres a este nuevo modo después de actualizar a 0.17.0. La lista completa de errores de manejo de nulos corregidos en 0.17.0 se puede encontrar en https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+

extensión LDAP

Druid ahora admite la autenticación LDAP. La autorización mediante grupos LDAP también se admite mediante la asignación de grupos LDAP a roles de Druida.

  • La autenticación LDAP se maneja especificando un validador de credenciales de tipo LDAP.
  • La autorización usando LDAP se maneja especificando un proveedor de roles de tipo LDAP y definiendo asignaciones de roles de grupo LDAP->Druid dentro de Druid. La integración LDAP requiere la extensión principal druid-basic-security. Consulte https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html para obtener más detalles. Como esta es la primera versión con soporte LDAP y existe una gran variedad de ecosistemas LDAP, es posible que algunos casos de uso y características de LDAP aún no sean compatibles. Presente un problema si necesita mejoras en esta nueva funcionalidad. https://github.com/apache/incubator-druid/pull/6972

Emisor del asistente desplegable

Se agregó un nuevo emisor de métricas de Dropwizard como extensión de contribución. Los tipos de métricas de Dropwizard actualmente admitidos son contador, indicador, medidor, temporizador e histograma. Estas métricas se pueden emitir mediante una consola o un reportero JMX. Consulte https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html para obtener más detalles. https://github.com/apache/incubator-druid/pull/7363

Recurso de autodescubrimiento

Se agregó un nuevo par de puntos finales a todos los servicios Druid que devuelven información sobre si el servicio Druid ha recibido una confirmación de que el servicio se ha agregado al clúster, desde el mecanismo central de descubrimiento de servicios (actualmente ZooKeeper). Estos puntos finales pueden ser útiles como comprobaciones de estado/preparación. Los nuevos puntos finales son:

  • /status/selfDiscovered/status
  • /status/selfDiscovered Consulte el Druida referencia API para obtener más detalles. https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Tabla del sistema de supervisores

Los supervisores de tareas (por ejemplo, los supervisores de Kafka o Kinesis) ahora se registran en las tablas del sistema en una nueva tabla sys.supervisors. Consulte https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table para obtener más detalles. https://github.com/apache/incubator-druid/pull/8547

Inicio histórico rápido con carga diferida

Se agregó una nueva propiedad de configuración booleana para históricos, druid.segmentCache.lazyLoadOnStart. Esta nueva propiedad permite que los históricos difieran la carga de un segmento hasta la primera vez que se consulta ese segmento, lo que puede reducir significativamente los tiempos de inicio históricos para clústeres con una gran cantidad de segmentos. Consulte la referencia de configuración para obtener más detalles. https://github.com/apache/incubator-druid/pull/6988

Cambio de distribución de caché de segmento histórico

Se ha agregado una nueva propiedad histórica, druid.segmentCache.locationSelectorStrategy. Si hay varias ubicaciones de almacenamiento de segmentos especificadas en druid.segmentCache.locations, la nueva propiedad locationSelectorStrategy permite al usuario especificar qué estrategia se utiliza para llenar las ubicaciones. Las opciones admitidas actualmente son roundRobin y leastBytesUsed. Consulte la referencia de configuración para obtener más detalles. https://github.com/apache/incubator-druid/pull/8038

Nuevos puntos finales de preparación

Se ha agregado un nuevo punto final de Broker: /druid/broker/v1/readiness. Se ha agregado un nuevo punto final histórico: /druid/historical/v1/readiness. Estos puntos finales son similares a los puntos finales /druid/broker/v1/loadstatus y /druid/historical/v1/loadstatus existentes. Se diferencian en que no requieren comprobaciones de autenticación/autorización y, en lugar de un cuerpo JSON, solo devuelven un código de respuesta HTTP 200 exitoso o 503. https://github.com/apache/incubator-druid/pull/8841

Asignación de tareas de soporte según categorías de MiddleManager

Ahora es posible definir una propiedad de nombre de "categoría" para cada MiddleManager. Se agregaron nuevas estrategias de selección de trabajadores que tienen en cuenta las categorías, lo que permite al usuario controlar cómo se asignan las tareas a los Middle Managers en función de las categorías configuradas. Consulte la documentación de druid.worker.category en la [referencia de configuración] (https://druid.apache.org/docs/0.17.0/configuration/index.html) y los siguientes enlaces para obtener más detalles: https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

Actualizaciones de vulnerabilidades de seguridad

Se ha actualizado una gran cantidad de dependencias a versiones más nuevas para abordar las vulnerabilidades de seguridad. Consulte los RP a continuación para obtener más detalles:

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

Actualización a Druida 0.17.0

La consulta nativa seleccionada ha sido reemplazada

El tipo de consulta nativa Seleccionar obsoleto se eliminó en 0.17.0. Si tiene consultas nativas que usan Seleccionar, debe modificarlas para usar Escanear en su lugar. Consulte la documentación de consulta de escaneo (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) para obtener detalles sobre la sintaxis y el formato de salida. Para consultas Druid SQL que utilizan Select, no se necesitan cambios; El planificador SQL ya utiliza el tipo de consulta Escanear en secreto para consultas Seleccionar. https://github.com/apache/incubator-druid/pull/8739

Se han eliminado las consolas antiguas.

Las consolas heredadas del coordinador y del señor supremo se eliminaron y se reemplazaron con la nueva consola web en el coordinador y el señor supremo. https://github.com/apache/incubator-druid/pull/8838

Actualización de Calcite 1.21, manejo nulo de Druid SQL

Druid 0.17.0 actualiza Calcite a la versión 1.21. Esta versión más nueva de Calcite puede realizar optimizaciones adicionales que asumen un comportamiento de manejo de nulos compatible con SQL al planificar consultas. Si utiliza Druid SQL y confía en el comportamiento de manejo de nulos, lea la información en https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling y asegúrese de que su clúster Druid se esté ejecutando en el modo de manejo de nulos compatible con SQL antes de actualizar. https://github.com/apache/incubator-druid/pull/8566

Ajustes de registro

Druid 0.17.0 ha ordenado su ciclo de vida, consultas y registros de ingesta. Consulte https://github.com/apache/incubator-druid/pull/8889 para obtener una lista detallada de cambios. Si confió en mensajes de registro específicos para integraciones externas, revise los nuevos cambios de registro antes de actualizar. El conjunto completo de mensajes de registro aún se puede ver cuando el registro está configurado en el nivel DEBUG. Los archivos de configuración de plantilla log4j2 que muestran cómo habilitar el registro DEBUG por paquete se proporcionan en la carpeta de configuración _common en los clústeres de ejemplo en conf/druid.

Cambios de autocompactación con estado

La lógica de programación de autocompactación en 0.17.0 rastrea información de partición de segmentos adicional en el almacén de metadatos de Druid que no está presente en versiones anteriores. Esta información se utiliza para determinar si un conjunto de segmentos ya se ha compactado según las configuraciones de compactación automática actuales del clúster. Cuando estos nuevos metadatos no están presentes, siempre se programará un conjunto de segmentos para una compactación inicial y estos nuevos metadatos se crearán después de compactarlos, lo que permitirá que el programador los omita más adelante si la configuración de compactación automática no se modifica. Dado que estos metadatos de partición de segmentos adicionales no están presentes antes de 0.17.0, la lógica de programación de compactación automática volverá a compactar todos los segmentos dentro de una fuente de datos una vez después de la actualización a 0.17.0. Esta nueva compactación en todo el conjunto de segmentos para cada fuente de datos que tiene habilitada la compactación automática significa que:

  • Habrá un período de transición después de la actualización en el que se pondrán en cola más tareas de compactación total que en condiciones normales.
  • El uso del almacenamiento profundo aumentará a medida que se vuelva a compactar todo el conjunto de segmentos (el antiguo conjunto de segmentos aún se conserva en el almacenamiento profundo a menos que se elimine explícitamente). Se recomienda a los usuarios que estén atentos al aumento temporal de las tareas de compactación programadas y el impacto en el uso del almacenamiento profundo. La documentación sobre cómo eliminar segmentos antiguos se encuentra en https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data.

Propiedad targetCompactionSizeBytes eliminada

La propiedad targetCompactionSizeBytes se eliminó de la tarea de compactación y de la configuración de autocompactación. Para la compactación automática, maxRowsPerSegment ahora es una configuración obligatoria. Para tareas de compactación no automática, se puede utilizar cualquier partitionsSpec. https://github.com/apache/incubator-druid/pull/8573

Ajuste de tarea de compactaciónConfig

Debido a los cambios de compactación automática paralela introducidos por #8570, cualquier especificación de tarea de compactación enviada manualmente debe actualizarse para usar un tipo index_parallel para la sección tuningConfig en lugar de index. Estos cambios de especificaciones deben aplicarse después de que el clúster se actualice a 0.17.0. Las configuraciones de autocompactación existentes pueden permanecer sin cambios después de la actualización; la compactación automática creará tareas de compactación no paralelas hasta que las configuraciones de compactación automática se actualicen para utilizar el paralelismo después de la actualización. Para controlar el nivel de paralelismo, la autocompactación tuningConfig dispone de nuevos parámetros, maxNumConcurrentSubTasks y splitHintSpec. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration para obtener más detalles.

Tarea de compactación ioConfig

La tarea de compactación ahora requiere un ioConfig en la especificación de la tarea. Consulte https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig para obtener más detalles. No es necesario agregar ioConfig a las configuraciones de compactación automática existentes; el coordinador después de la actualización creará automáticamente especificaciones de tarea con las secciones ioConfig. https://github.com/apache/incubator-druid/pull/8571

Campos de especificación de partición renombrados

Los campos targetPartitionSize y maxSegmentSize en las especificaciones de partición han quedado obsoletos. Se les cambió el nombre a targetNumRowsPerSegment y maxRowsPerSegment respectivamente. https://github.com/apache/incubator-druid/pull/8507

Las métricas de caché están desactivadas de forma predeterminada

Las métricas de caché ahora están deshabilitadas de forma predeterminada. Para habilitar las métricas de caché, agregue "org.apache.druid.client.cache.CacheMonitor" a la propiedad druid.monitoring.monitors. https://github.com/apache/incubator-druid/pull/8561

El supervisor API ha cambiado para ser coherente con la tarea API

Las especificaciones de la tarea del supervisor ahora deberían incluir las secciones dataSchema, tuningConfig y ioConfig como subcampos de un campo spec. Consulte https://github.com/apache/incubator-druid/pull/8810 para ver ejemplos. El formato antiguo todavía se acepta en 0.17.0.

Cambio de semántica de segmentos API

El punto final /datasources/{dataSourceName}/segments en el Coordinador ahora devuelve todos los segmentos utilizados (incluidos los eclipsados) en los intervalos especificados, en lugar de solo los visibles. https://github.com/apache/incubator-druid/pull/8564

Proveedor de contraseñas para la autenticación básica de HttpEmitterConfig

La propiedad druid.emitter.http.basicAuthentication ahora acepta un proveedor de contraseñas. Recomendamos actualizar sus configuraciones para usar un proveedor de contraseñas si usa el emisor HTTP. https://github.com/apache/incubator-druid/pull/8618

Cambio de transformación de expresión multivalor

La reutilización de columnas de valores múltiples en expresiones ya no dará lugar a explosiones cartesianas innecesarias. Consulte los siguientes enlaces para obtener más detalles. https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Ingestión de Kafka/Kinesis durante las actualizaciones continuas

Durante una actualización continua, si hay tareas ejecutando 0.17.0 y Overlords ejecutando versiones anteriores, y una tarea progresó leyendo datos de su flujo pero rechazó todos los registros que vio (por ejemplo, todos no se podían analizar), verá NullPointerExceptions en Overlords que ejecutan versiones anteriores cuando la tarea actualice el Overlord con sus compensaciones de flujo actuales. Anteriormente, había un error en esta área (https://github.com/apache/incubator-druid/issues/8765) por el cual dichas tareas no comunicaban sus compensaciones actuales al señor supremo. El protocolo de publicación de tareas/señores supremos se ha actualizado para solucionar este problema, pero los señores supremos más antiguos no reconocen este cambio de protocolo. Esta condición debería ser bastante rara.

Cambio de versión predeterminada de Hadoop

Druid 0.17.0 ahora incluye bibliotecas Hadoop 2.8.5 en lugar de 2.8.3. Si estaba haciendo referencia a las bibliotecas 2.8.3 incluidas en su configuración a través de la propiedad druid.indexer.task.defaultHadoopCoordinates o la propiedad hadoopDependencyCoordinates en sus especificaciones de ingesta de Hadoop, deberá actualizar estas referencias para que apunten a las bibliotecas 2.8.5 incluidas.

Método ParseSpec.verify eliminado

Si mantenía una extensión personalizada que proporciona una implementación para la interfaz ParseSpec, el método verify se eliminó y la anotación @Override en el método deberá eliminarse en cualquier implementación personalizada. https://github.com/apache/druid/pull/8744

Problemas conocidos

Filtrado de columnas largas en modo de manejo de nulos compatible con SQL

Actualmente somos conscientes de un error al aplicar ciertos tipos de filtros en valores nulos de columnas largas cuando el manejo de nulos compatible con SQL está habilitado (https://github.com/apache/druid/issues/9255). Presente un problema si encuentra otros problemas de manejo de nulos.

Vista previa de especificaciones de ingesta en la consola web

Las especificaciones de vista previa que se muestran para las tareas de ingesta por lotes nativas creadas en el cargador de datos de la consola web no tienen el formato correcto y fallarán si las copia y envía manualmente. Sin embargo, al enviar estas especificaciones a través del Cargador de datos se envía una especificación con el formato correcto. https://github.com/apache/druid/issues/9144

Otros problemas conocidos

Para obtener una lista completa de problemas abiertos, consulte https://github.com/apache/druid/labels/Bug
