druida druida-0.20.0

Apache Druid 0.20.0 contiene alrededor de 160 funciones nuevas, correcciones de errores, mejoras de rendimiento, mejoras de documentación y cobertura de pruebas adicionales de 36 contribuyentes. Consulte la lista completa de cambios y todo lo etiquetado en el hito para obtener más detalles.

<a name="20-new-features" href="#20-new-features">#</a> Nuevas funciones

<a name="20-ingestion" href="#20-ingestion">#</a> Ingestión

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> Combinando InputSource

Se agregó una nueva combinación de InputSource, que permite al usuario combinar múltiples fuentes de entrada durante la ingesta. Consulte https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source para obtener más detalles. https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Determina automáticamente numShards para la partición hash de ingesta paralela

Cuando se utiliza la partición hash en la ingesta de lotes en paralelo, ya no es necesario especificar numShards en la especificación de partición. Druid ahora puede determinar automáticamente una cantidad de fragmentos escaneando los datos en una nueva fase de ingesta que determina las cardinalidades de la clave de partición. https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Límites de recuento de archivos de subtarea para la ingesta por lotes en paralelo

El splitHintSpec basado en tamaño ahora admite un nuevo parámetro maxNumFiles, que limita la cantidad de archivos que se pueden asignar a subtareas individuales en la ingesta por lotes en paralelo. El splitHintSpec basado en segmentos utilizado para reingerir datos de segmentos Druid existentes también tiene un nuevo parámetro maxNumSegments que funciona de manera similar. Consulte https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec para obtener más detalles. https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Métricas de uso de espacios de tareas

Se han agregado nuevas métricas de uso de espacios para tareas. Consulte las entradas de las métricas taskSlot en https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service para obtener más detalles. https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Compactación

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Compatibilidad con todos los esquemas de partición para autocompactación

Ahora se puede definir una especificación de partición para la compactación automática, lo que permite a los usuarios volver a particionar sus datos en el momento de la compactación. Consulte la documentación de la nueva propiedad partitionsSpec en la compactación tuningConfig para obtener más detalles: https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> Estado de compactación automática API

Se agregó un nuevo coordinador API que muestra el estado de autocompactación de una fuente de datos. El nuevo API muestra si la compactación automática está habilitada para una fuente de datos y un resumen de hasta dónde ha progresado la compactación. La consola web también se actualizó para mostrar esta información: https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png Consulte https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status para obtener detalles sobre el nuevo API y https://druid.apache.org/docs/latest/operations/metrics.html#coordination para obtener información sobre nuevas métricas de compactación relacionadas. https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Consultando

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Poda de segmento de consulta con partición hash

Druid ahora admite la poda de segmentos en el momento de la consulta (excluyendo ciertos segmentos como candidatos de lectura para una consulta) para segmentos particionados mediante hash. Esta optimización se aplica cuando todos los partitionDimensions especificados en la especificación de partición hash durante el tiempo de ingesta están presentes en el conjunto de filtros de una consulta, y los filtros en la consulta filtran en valores discretos de partitionDimensions (por ejemplo, filtros selectores). La poda de segmentos con partición hash no se admite con filtros no discretos, como los filtros vinculados. Para los usuarios existentes con segmentos existentes, deberán volver a ingerir esos segmentos para aprovechar esta nueva característica, ya que la poda de segmentos requiere que se almacene un partitionFunction junto con los segmentos, lo cual no existe en los segmentos creados por versiones anteriores de Druid. No es necesario especificar partitionFunction explícitamente, ya que la función predeterminada es la misma función de partición que se usó en versiones anteriores de Druid. Tenga en cuenta que los segmentos creados con un valor partitionDimensions predeterminado (partición por todas las dimensiones + la columna de tiempo) no se pueden podar de esta manera; los segmentos deben crearse con un partitionDimensions explícito. https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vectorización

Para habilitar las funciones de vectorización, establezca la propiedad druid.query.default.context.vectorizeVirtualColumns en true o establezca la propiedad vectorize en el contexto de consulta. Consulte https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters para obtener más información.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Soporte de vectorización para columnas virtuales de expresión

Las columnas virtuales de expresión ahora tienen soporte de vectorización (dependiendo de las expresiones que se utilicen), lo que resulta en una mejora del rendimiento de 3 a 5 veces en algunos casos. Consulte https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support para obtener detalles sobre las expresiones específicas que admiten la vectorización. https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> Más soporte de vectorización para agregadores

Se ha agregado soporte de vectorización para varios tipos de agregación: agregadores mínimos/máximos numéricos, agregadores de varianza, agregadores CUALQUIER y agregadores de la extensión druid-histogram. https://github.com/apache/druid/pull/10260 - numérico mínimo/máximo https://github.com/apache/druid/pull/10304 - histograma https://github.com/apache/druid/pull/10338 - CUALQUIER https://github.com/apache/druid/pull/10390 - variación Hemos observado una mejora de rendimiento de aproximadamente 1,3 a 1,8 veces en algunos casos con la vectorización habilitada para el agregador mínimo, máximo y CUALQUIER, y aproximadamente de 1,04 a 1,07 veces con el agregador de histograma.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> parámetro offset para consultas GroupBy y Scan

Ahora es posible establecer un parámetro offset para consultas GroupBy y Scan, que le indica a Druid que omita una cantidad de filas al devolver resultados. Consulte https://druid.apache.org/docs/0.20.0/querying/limitspec.html y https://druid.apache.org/docs/0.20.0/querying/scan-query.html para obtener más detalles. https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> Cláusula OFFSET para consultas SQL

Las consultas Druid SQL ahora admiten una cláusula OFFSET. Consulte https://druid.apache.org/docs/0.20.0/querying/sql.html#offset para obtener más detalles. https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Operadores de búsqueda de subcadenas

Druid ha agregado nuevos operadores de búsqueda de subcadenas en su lenguaje de expresión y para consultas SQL. Consulte la documentación para las funciones de cadena CONTAINS_STRING y ICONTAINS_STRING para Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) y la documentación para contains_string y icontains_string para el lenguaje de expresión Druid (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions). Hemos observado una mejora de rendimiento de aproximadamente 2,5 veces en algunos casos al utilizar estas funciones en lugar de STRPOS. https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> Operador UNION ALL para consultas SQL

Las consultas Druid SQL ahora admiten el operador UNION ALL, que fusiona los resultados de varias consultas. Consulte https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all para obtener detalles sobre qué formas de consulta admite este operador. https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Configuración de contexto de consulta predeterminada para todo el clúster

Ahora es posible establecer propiedades de contexto de consulta predeterminadas en todo el clúster agregando una configuración del formato druid.query.override.default.context.*, con * reemplazado por el nombre de la propiedad. https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Otras características

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> UI de reglas de retención mejorada

Se ha mejorado la interfaz de usuario de las reglas de retención en la consola web. Ahora proporciona sugerencias y validación básica en el menú desplegable del período, muestra las reglas predeterminadas del clúster y hace que la edición de las reglas predeterminadas sea más accesible. https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Mejoras en la extensión de caché Redis

La extensión de caché Redis ahora admite el clúster Redis, seleccionando qué base de datos se utiliza, conectándose a servidores protegidos por contraseña y configuraciones de estilo de punto para las propiedades expiration y timeout. https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Deshabilitar la versión del servidor de envío en los encabezados de respuesta

Ahora es posible desactivar el envío de información de la versión del servidor en los encabezados de respuesta de Druid. Esto está controlado por una nueva propiedad druid.server.http.sendServerVersion, cuyo valor predeterminado es true. https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Especificar propiedades de configuración basadas en bytes con unidades

Druid ahora admite unidades para especificar propiedades de configuración basadas en bytes, por ejemplo:

druid.server.maxSize=300g

equivalente a

druid.server.maxSize=300000000000

Consulte https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html para obtener más detalles. https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Corrección de errores

<a name="20-query-correctness" href="#20-query-correctness">#</a> Soluciona el problema de corrección de la consulta cuando el historial no tiene una línea de tiempo de segmento

Druid 0.20.0 soluciona un problema de corrección de la consulta cuando un corredor emite una consulta esperando que un histórico tenga ciertos segmentos para una fuente de datos, pero el histórico cuando se consulta en realidad no tiene ningún segmento para esa fuente de datos (por ejemplo, todos se descargaron antes de que el histórico procesara la consulta). Antes de 0.20.0, la consulta regresaba exitosamente pero sin los resultados de los segmentos que faltaban de la manera descrita anteriormente. En 0.20.0, las consultas ahora fallarán en tales situaciones. https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Soluciona el problema que impide que se complete la caché a nivel de resultados

Druid 0.20.0 soluciona un problema introducido en 0.19.0 (https://github.com/apache/druid/issues/10337) que puede evitar que se completen los cachés de consultas cuando el almacenamiento en caché a nivel de resultados está habilitado. https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Corrección para el orden del agregador de variaciones

Anteriormente, el agregador de varianzas usaba un comparador incorrecto que comparaba usando la variable interna count de un agregador en lugar de la varianza. https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Corrige el almacenamiento en caché incorrecto para consultas groupBy con especificaciones de límite

Druid 0.20.0 soluciona un problema con las consultas groupBy y el almacenamiento en caché, donde la especificación de límite de la consulta no se consideraba en la clave de caché, lo que generaba resultados potencialmente incorrectos si se emitían consultas idénticas excepto por la especificación de límite. https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Corrección para stringFirst y stringLast con el resumen habilitado

https://github.com/apache/druid/issues/7243 se resolvió, los agregadores stringFirst y stringLast ya no causan una excepción cuando se usan durante la ingesta con el resumen habilitado. https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Actualización a Druid 0.20.0

Tenga en cuenta las siguientes consideraciones al actualizar de 0.19.0 a 0.20.0. Si está actualizando desde una versión anterior a 0.19.0, consulte los release note de las versiones intermedias relevantes.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Predeterminado maxSize

druid.server.maxSize ahora tendrá de forma predeterminada la suma de los valores de maxSize definidos en druid.segmentCache.locations. El usuario aún puede proporcionar un valor personalizado para druid.server.maxSize que tendrá prioridad sobre el valor predeterminado. https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Compactar y eliminar cambios de ID de tarea

Las tareas de compactación y eliminación emitidas por el coordinador ahora tendrán sus ID de tarea con el prefijo coordinator-issued, mientras que las tareas de eliminación emitidas por el usuario tendrán el prefijo api-issued. https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> Nuevos límites de tamaño para las especificaciones de sugerencias divididas de ingesta paralela

El splitHintSpec basado en tamaño y segmento para la ingesta de lotes paralelos ahora aplica un límite predeterminado de archivos/segmentos de 1000 por subtarea, controlado por maxNumFiles y maxNumSegments respectivamente. https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> Nuevos métodos PostAggregator y AggregatorFactory

Los usuarios que hayan desarrollado una extensión con implementaciones personalizadas de PostAggregator o AggregatorFactory deberán actualizar sus extensiones, ya que estas dos interfaces tienen nuevos métodos definidos en 0.20.0. PostAggregator ahora tiene un nuevo método:

  ValueType getType();

Para admitir información de tipo en PostAggregator, AggregatorFactory también tiene 2 métodos nuevos:

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Consulte https://github.com/apache/druid/pull/9638 para obtener más detalles sobre los cambios en la interfaz.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> Nuevos métodos relacionados con Expr

Los usuarios que hayan desarrollado una extensión con implementaciones personalizadas de Expr deberán actualizar sus extensiones, ya que Expr y las interfaces relacionadas han cambiado en 0.20.0. Consulte el PR a continuación para obtener más detalles: https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> Métrica query/cpu/time más precisa

En 0.20.0, se ha mejorado la precisión de la métrica query/cpu/time. Anteriormente, no contabilizaba ciertas partes del trabajo durante el procesamiento de consultas, que se describen con más detalle en el siguiente PR: https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> Nuevas columnas de métricas del servicio de registro de auditoría

Si utiliza el registro de auditoría, tenga en cuenta que se han agregado nuevas columnas a la métrica del servicio de registro de auditoría (comment, remote_address y created_date). También se ha agregado una columna payload opcional, que se puede habilitar configurando druid.audit.manager.includePayloadAsDimensionInMetric en true. https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext en registros de solicitudes

Si está utilizando el registro de solicitudes de consulta, los eventos del registro de solicitudes ahora incluirán el sqlQueryContext para consultas SQL. https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> Estado adicional por segmento en el almacén de metadatos

Los segmentos con particiones hash creados por Druid 0.20.0 ahora tendrán datos partitionFunction adicionales en el almacén de metadatos. Además, las tareas de compactación ahora almacenarán información adicional por segmento en el almacén de metadatos, que se utiliza para rastrear el historial de compactación. https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Problemas conocidos

<a name="20-location-strat" href="#20-location-strat">#</a> Fallo de inyección druid.segmentCache.locationSelectorStrategy

Especificar un valor para druid.segmentCache.locationSelectorStrategy evita que los servicios se inicien debido a un error de inyección. Consulte https://github.com/apache/druid/issues/10348 para obtener más detalles.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Fuga de recursos en el muestreador de datos de la consola web

Cuando se agota el tiempo de espera mientras se muestrean datos en la consola web, los recursos internos creados para leer desde la fuente de entrada no se cierran correctamente. Consulte https://github.com/apache/druid/pull/10467 para obtener más información.
