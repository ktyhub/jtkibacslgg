claude-code v2.1.222

code-claude v2.1.222

Qu'est-ce qui a changé

  • Correction des sessions isolées par arbre de travail et de leurs sous-agents pouvant exécuter des commandes git destructrices sur la caisse principale ; l'isolation s'applique désormais aux modifications de fichiers et à Bash dans chaque type de session
  • Correction des hooks d'autorisation automatique de PreToolUse contournant les restrictions d'outils dans les tâches d'agent en arrière-plan (résumés, compactage, renommage)
  • Correction de /usage-credits sur Team et Enterprise affichant "vous avez déjà envoyé une demande de crédit d'utilisation" pour les membres dont la demande précédente a été rejetée, les empêchant d'en envoyer une nouvelle.
  • Correction du blocage de la vérification de connectivité au démarrage, puis de son échec derrière un proxy HTTPS ; il utilise désormais le même transport compatible proxy que les requêtes API et expire avec un message clair
  • Correction des erreurs « Connexion fermée à mi-réponse » signalées sur les réponses qui étaient effectivement terminées
  • Correction de la surattribution de l'utilisation de /usage aux serveurs MCP : le partage d'un serveur reflète désormais uniquement les requêtes qui ont réellement consommé les résultats de son outil, au lieu de chaque tour après tout appel à celui-ci.
  • Correction des sessions ne se liant pas aux demandes d'extraction créées après le push de la branche, y compris via le GitHub REST API
  • Correction des alias de sous-agents et de familles de coéquipiers de style model: opus restreints à l'organisation, passant au modèle parent au lieu de passer au modèle le plus récent autorisé par l'organisation dans la famille.
  • Correction du délai d'inactivité du flux se déclenchant sur les passerelles ANTHROPIC_BASE_URL personnalisées malgré l'arrivée des pings de maintien du serveur sur le réseau.
  • Correction des connecteurs claude.ai étant faussement marqués comme nécessitant une autorisation lorsque le jeton de session n'est pas valide — ils affichent désormais un indice /login à la place
  • Correction des erreurs d'outils ne s'affichant pas pour les outils qui ne sont plus disponibles localement, par exemple après la suppression d'un serveur MCP
  • Correction de SendMessage rejetant un long résumé — il est désormais tronqué à la place, donc les envois n'échouent plus avec une limite de caractères
  • Correction de l'étiquette d'effort du spinner dans la vue de transcription d'un sous-agent affichant le niveau d'effort de la session au lieu du paramètre effort: du sous-agent.
  • Correction de plantages rares lorsqu'un observateur de fichiers rencontrait une erreur du système de fichiers ou lors du démontage de l'observateur de fichiers
  • Correction des lecteurs d'écran relisant toute la ligne de saisie à chaque retour arrière en mode --ax-screen-reader - les suppressions de fin de ligne font désormais écho uniquement aux caractères supprimés
  • Correction des clés de sélection de modèle d'hôte n'ayant pas la priorité sur un managed-settings.json obsolète sur le disque lorsque CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST est défini
  • Sécurité améliorée du mode automatique : les messages envoyés à d'autres sessions d'agent via SendMessage sont désormais évalués par le classificateur d'autorisations avant leur envoi.
  • Amélioration du refus lorsque Claude tente d'invoquer une compétence avec disable-model-invocation : Claude est désormais invité à vous demander d'exécuter la compétence au lieu de répliquer son workflow
  • Amélioration de la vue /diff, des différences de l'espace de travail de contrôle à distance et des différences d'édition de fichiers dans Claude Code sur les sessions Web pour utiliser le contenu brut du blob git, en ignorant les pilotes de comparaison configurés dans l'espace de travail et textconv.
  • Modification du démarrage automatique de la télécommande afin que les paramètres du dépôt local (.claude/settings.json ou .claude/settings.local.json) ne puissent plus l'activer (ils peuvent toujours l'éteindre) ; activez-le à la portée de l'utilisateur via /config
  • Suppression de la fonctionnalité ultraplan
