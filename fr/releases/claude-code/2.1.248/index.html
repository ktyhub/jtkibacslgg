claude-code v2.1.248

Correctif Publié27 août 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.248

Qu'est-ce qui a changé

  • Ajout de --restricted (ou CLAUDE_CODE_RESTRICTED=1) : supprime les outils intégrés qui exécutent des commandes ou du code et WebFetch (sauf si nommé dans --tools), conserve les outils de fichiers dans le répertoire de travail, refuse bypassPermissions et ignore les fichiers de paramètres utilisateur, projet et locaux.
  • Ajout de experimental.cacheTtl ("5m" ou "1h") au front-matter de l'agent : un TTL de cache d'invite par agent utilisé lorsqu'aucun paramètre TTL de sous-agent n'est configuré
  • Ajout de claude self-hosted-runner --client-label <label> (ou SELF_HOSTED_RUNNER_CLIENT_LABEL) pour remplacer l'étiquette avec laquelle le coureur s'enregistre (par défaut : nom d'hôte)
  • Ajout de diagnostics des paramètres gérés par le serveur : un avertissement de démarrage lorsque le chargement des paramètres échoue, et une ligne /doctor et /status expliquant un échec de chargement ou pourquoi ils n'ont pas été récupérés (Bedrock/Vertex/fournisseur tiers, ANTHROPIC_BASE_URL personnalisé)
  • Ajout d'un avertissement dans /web-setup lorsque le jeton GitHub CLI n'a pas la portée workflow, car les push vers de très grands référentiels peuvent être rejetés sans celui-ci.
  • Ajout de /usage-credits pour les organisations Enterprise facturées via AWS Marketplace, les essais en libre-service Enterprise et Enterprise, afin que les membres puissent demander une limite d'utilisation plus élevée à leur administrateur.
  • Ajout de la messagerie inter-sessions (SendMessage / ListAgents) entre les sessions sur la même machine sur Bedrock, Vertex et Foundry, et lorsque la télémétrie est désactivée
  • Correction d'un échec de cache d'invite (et de perte de contexte de réflexion étendue) environ une fois par heure lors de longues sessions, provoqué par le nouveau rendu des définitions d'outils après une actualisation du jeton OAuth.
  • Correction de la définition de l'outil ScheduleWakeup changeant entre une session et son --resume lorsque le compte était entré en dépassement d'utilisation, provoquant un échec complet du cache d'invite au premier tour de la session reprise.
  • Correction des sessions Claude Desktop et Cowork disparaissant après 30 jours : le nettoyage des transcriptions conserve désormais les sessions écrites sur le bureau pendant qu'elles sont dans l'application (sauf si la politique de l'organisation gère la rétention) ; le nouveau réglage desktopSessionCleanupPeriodDays plafonne l'exemption
  • Correction de l'envoi à l'écran de connexion lorsqu'un autre processus Claude Code détenait le verrou d'actualisation du jeton alors que le jeton de session avait expiré ; la requête échoue désormais avec une erreur réessayable à la place
  • Windows : Correction de la liste claude agents ne répondant pas au clavier après s'être détachée d'une session, ou lors d'un lancement dans un onglet de terminal laissé en mode win32-input
  • Correction de l'échec de la connexion recommandée à la console dans /login avec une erreur OAuth avant d'afficher une URL de connexion sur les machines sur lesquelles elle ne peut pas être utilisée (par exemple lorsque ANTHROPIC_API_KEY ou une clé d'assistance API est définie) ; il revient désormais à la connexion par clé API
  • Correction des noms de modèles dans /model et des avis de changement de mode rapide à afficher sous forme de code, de sorte que les suffixes comme [1m] s'affichent littéralement au lieu de sous forme de lien
  • Correction de claude agents sautant l'invite trust de l'espace de travail lorsque la variable d'environnement CI est définie
  • Correction du plantage de claude agents au lancement lorsque le cache d'état PR contenait une entrée mal formée
  • Correction de la vue de l'agent ressuscitant une session en arrière-plan vieille d'une semaine après l'arrêt de la machine : une telle session s'affiche désormais comme arrêtée à sa fin réelle, et son ouverture demande avant de reprendre sa conversation enregistrée
  • Correction de la vue de l'agent ouvrant parfois une conversation plus ancienne et supprimant l'invite saisie lors du démarrage d'une nouvelle session
  • Correction de claude agents : l'ouverture d'une session arrêtée que vous avez déjà reprise dans un autre terminal ne démarre plus un deuxième processus sur cette conversation ; la ligne indique maintenant qu'elle est ouverte dans un terminal
  • Correction de claude agents et claude rm refusant de supprimer une session ("a des commits qui ne sont poussés nulle part") lorsque sa branche d'arbre de travail était déjà fusionnée dans votre branche par défaut extraite (par exemple main local) mais pas encore poussée
  • Correction des sessions en arrière-plan attendant silencieusement lorsqu'un hook PermissionRequest ou PreToolUse imprime une réponse invalide : la ligne claude agents nomme désormais le hook et l'erreur de schéma
  • Correction de hooks traitant silencieusement un objet stdout {…} qui n'est pas valide JSON comme texte brut ; c'est maintenant signalé comme une erreur de hook avec le message d'analyse
  • Correction de /mcp répertoriant une entrée de projet .mcp.json qui déclare le type de connecteur claude.ai sous l'en-tête trusted "claude.ai" ; il apparaît désormais sous sa véritable portée
  • Correction des serveurs MCP dont headersHelper fournit l'en-tête Authorization tombant dans la découverte OAuth sur un 401 au lieu de réexécuter l'assistant et de réessayer l'appel comme documenté
  • Correction de /login sur une passerelle d'applications Claude bloquée lorsque la boîte de dialogue d'approbation de sécurité des paramètres gérés était requise
  • Correction de la découverte du modèle de passerelle (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) ne s'exécutant jamais lorsque apiKeyHelper est le seul identifiant
  • Correction de claude logs laissant le suivi de la souris, le collage entre crochets et l'écran alternatif allumé dans le terminal à partir duquel il était exécuté
  • Correction de la liste des règles d'autorisation de dépôt de la boîte de dialogue trust affichant un caractère tronqué lorsqu'une longue règle était coupée au milieu d'un emoji
  • Correction de l'indicateur de mode d'autorisation restant caché derrière l'indice "Appuyez à nouveau sur Ctrl-C pour quitter" lorsque vous appuyez sur Maj+Tab juste après ctrl+c.
  • Correction de /ultrareview et des sessions cloud amorcées localement téléchargeant des modifications non validées vers des fichiers de style prod.env et *.tfvars, ou vers des copies d'échange, temporaires et de sauvegarde des fichiers d'informations d'identification (par exemple key.pem.tmp, id_rsa.swo) ; ils restent maintenant sur votre machine
  • Correction des sessions de contrôle à distance n'affichant parfois jamais d'invite d'autorisation ou les derniers messages sur l'appareil connecté après la reconnexion silencieuse du CLI
  • Correction des sessions cloud qui échouaient parfois au démarrage lorsque les informations d'identification de session du conteneur n'étaient pas encore lisibles
  • Correction de claude remote-control rejetant ses propres indicateurs (par exemple --spawn, --name) lorsqu'un indicateur global ou une option injectée dans le wrapper précède la sous-commande
  • Correction des avertissements de démarrage (par exemple "N serveurs MCP nécessitent une authentification") affichant une colonne à droite du reste de la transcription
  • Correction d'une session d'arbre de travail en arrière-plan perdant son extraction : la session en arrière-plan détient désormais le verrou de l'arbre de travail pendant son exécution, donc le nettoyage et git worktree remove le laissent tranquille
  • Correction des mentions @ d'autres sessions ne correspondant pas aux noms saisis avec des caractères non latins (par exemple le coréen saisi via un IME)
  • Correction d'une valeur crossSessionInbound invalide ignorée silencieusement : elle avertit et conserve désormais les messages inter-sessions (paramètres utilisateur) ou les refuse (paramètres gérés) jusqu'à ce qu'ils soient corrigés.
  • Correction des messages de limite de débit, d'utilisation et de mode rapide vous indiquant d'exécuter /usage-credits lorsque cette commande n'est pas disponible pour votre organisation (par exemple masquée avec DISABLE_EXTRA_USAGE_COMMAND)
  • [VSCode] Correction d'un onglet de discussion bloqué sur "Aucune conversation trouvée" alors que sa session n'était jamais enregistrée ; il démarre maintenant une nouvelle conversation
  • Amélioration de l'empreinte d'invite de l'outil Workflow : sa description est désormais d'environ 1 000 jetons au lieu de 5,7 000, avec la référence d'écriture de script déplacée dans une compétence groupée workflow-authoring.
  • Amélioration du badge PR du pied de page d'invite pour vérifier GitHub moins souvent tandis que la demande d'extraction est inchangée ; un push ou une commande gh pr le rafraîchit quand même tout de suite
  • Paramètres gérés améliorés : le délai d'attente côté client, le mode de démarrage MCP et les variables d'environnement stream-watchdog ne déclenchent plus l'invite d'approbation des paramètres.
  • Amélioration de /ultrareview <PR#> pour vérifier avant le lancement que le compte GitHub connecté à votre compte Claude peut accéder au référentiel, et pour expliquer comment le réparer, au lieu d'échouer après le démarrage de la session cloud
  • Messagerie inter-session améliorée : revient à un répertoire /tmp privé par utilisateur lorsque celui par défaut ne peut pas être utilisé, et la notification et le nom /status du répertoire à corriger
  • Modification de shift+enter dans l'entrée de répartition de la vue agent pour insérer une nouvelle ligne (correspondant à l'invite) ; ctrl+enter distribue et attache maintenant
  • /loop modifié : le mode dynamique à votre rythme et le mode autonome par défaut sans invite sont désormais toujours disponibles, y compris sur Bedrock/Vertex/Foundry
  • Modification des échecs d'exportation de télémétrie anthropique pour qu'ils soient enregistrés au niveau du débogage en tant que [Anthropic telemetry] au lieu de [3P telemetry] OTEL diag error, afin qu'ils ne soient pas confondus avec l'échec de votre collecteur OTel.
  • Modification de la messagerie intersessions dans les espaces de noms d'utilisateurs Linux : le trust équivalent à la racine pour les propriétaires non mappés est limité aux répertoires système canoniques
  • Modification de SendMessage d'un sous-agent à une autre session : le résultat indique désormais que toute réponse est transmise à la conversation de la session parent, et non au sous-agent.
