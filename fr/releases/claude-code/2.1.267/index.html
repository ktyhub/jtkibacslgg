claude-code v2.1.267

Correctif Publié9 sept. 2026 Sourceanthropics/claude-code Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

code-claude v2.1.267

Qu'est-ce qui a changé

  • Ajout du paramètre maxEffortLevel (niveau supérieur ou par modèle sous modelSettings) : plafonne le niveau d'effort sur chaque fournisseur, y compris Bedrock, Vertex et Foundry ; les utilisateurs peuvent toujours choisir un niveau inférieur
  • Ajout de --system-prompt-snapshot off pour rendre l'invite du système à jour à chaque demande au lieu de réutiliser l'invite enregistrée de la conversation (pour itérer sur le texte de l'invite)
  • Correction des tâches planifiées Cowork dans le cloud qui échouaient au démarrage pour les organisations dont les paramètres gérés nécessitent un sandboxing
  • Correction de /context et d'autres sorties de commandes locales rendant vides sur les clients mobiles
  • Correction de shift+enter et option+backspace ne fonctionnant pas après la reconnexion à une session tmux ou ssh dans une vue d'agent
  • Correction de l'en-tête sombre de la dernière invite n'apparaissant pas en haut de la conversation lors du défilement vers le haut en mode plein écran
  • Correction des appels Workflow agent() avec des schémas de sortie volumineux refusés en mode automatique au lieu d'être vérifiés par le classificateur de sécurité
  • Correction d'un cas où un chemin d'entrée de marché contenant une barre oblique inverse pouvait contourner la vérification de confinement pour les marchés récupérés sur macOS et Linux
  • Correction des informations d'identification AWS ou Google Cloud expirées sous une application hôte telle que Claude Desktop réessayant dix fois avec un "échec de la demande" générique avant l'apparition de l'erreur de ré-authentification
  • Correction de la reprise d'une session après l'exécution de /compact ou d'une autre commande slash via -p --resume : un faux "Continuer là où vous vous étiez arrêté." le tour n'est plus inséré
  • Correction de la reprise d'une session volumineuse (transcription supérieure à 5 Mo) : les appels d'outils parallèles et leur sortie hook ne sont plus supprimés de la conversation rechargée
  • Correction de allowedHttpHookUrls, httpHookAllowedEnvVars et allowedChannelPlugins gérés pour ne rien admettre, pas tout, lorsqu'ils sont illisibles
  • Correction de /login sur les machines dont les paramètres gérés nécessitent une connexion à la passerelle des applications Claude : Esc ferme désormais la boîte de dialogue au lieu de ne rien faire
  • Correction des publications d'artefacts interrompues par une connexion interrompue en cours de téléchargement : ils réessayent désormais une fois lorsque Claude Code peut indiquer que le téléchargement n'est jamais terminé, au lieu de signaler un résultat inconnu.
  • Correction du sujet effort: sur les commandes personnalisées, les compétences et les sous-agents ignorés sur les modèles dont l'effort par défaut est toujours épinglé (Opus 4.7, Opus 4.8, Fable 5).
  • Correction de l'échec de la publication d'artefacts avec une erreur inutile lorsque le fichier d'échange n'est pas valide UTF-8 ou contient un caractère de remplacement (U+FFFD) ; l'erreur nomme maintenant la ligne et la colonne à corriger
  • Correction du menu du répertoire claude agents @ ne répertoriant pas les référentiels créés après le démarrage de la session
  • Correction des clients de contrôle à distance qui rejoignent une session Claude Desktop ou VS Code affichant un mode d'autorisation obsolète jusqu'à ce qu'il soit à nouveau modifié
  • Correction de claude remote-control quittant et supprimant chaque session attachée lorsque ses informations d'identification de serveur expirent (environ 30 jours après le démarrage) ; l'hôte se réinscrit maintenant et continue
  • Correction de l'avertissement de limite d'utilisation clignotant pendant une session lorsque les demandes de différents modèles ou modes signalent différentes fenêtres de limite
  • Correction d'un raisonnement antérieur abandonné lorsqu'un serveur MCP renvoie, ou qu'un outil intégré restitue, un outil que le modèle a déjà chargé
  • Correction d'un outil qui disparaît au milieu d'une conversation, à partir d'un serveur MCP déconnecté ou d'une mise à niveau, réécrivant la liste des outils et éliminant les réflexions antérieures
  • Correction d'un travailleur en arrière-plan provenant d'une conversation ajoutant EnterWorktree au bloc d'outils de la conversation en cours de session, ce qui empêchait la réutilisation du cache d'invite.
  • Correction des outils MCP et plugins en cours de session ajoutés à la liste d'outils dans les sessions sans ToolSearch, ce qui empêchait la réutilisation du cache d'invite ; les modèles pris en charge les reçoivent désormais sous forme de définitions différées
  • Correction du changement de modèle avec /model renvoyant chaque définition d'outil (un échec de cache d'invite) ; Le texte d'attribution de validation et de relations publiques arrive désormais sous forme de note de conversation qui met à jour les modifications du modèle.
  • Correction des sessions reprises réécrivant l'ensemble d'outils en ligne lorsqu'un connecteur MCP se reconnecte à un moment différent qu'avant
  • Correction des sessions reprises restituant les descriptions des outils au lieu de rejouer celles enregistrées lors de l'exécution d'un outil au premier tour.
  • Correction des erreurs de cache d'invite et suppression de la réflexion étendue lorsque les outils d'un connecteur claude.ai changent entre une session et sa reprise
  • Correction des reprises de sessions réécrivant les annonces précédentes de l'outil MCP (et abandonnant la réflexion approfondie) avant que leurs connecteurs ne se reconnectent
  • Correction d'une rupture de cache d'invite lors de la reprise interactive d'une conversation en mode impression (-p) : le préfixe d'invite système ne change plus
  • Amélioration du panneau /diff : il ne clignote plus "0 fichiers modifiés" et une flèche avant de s'installer, et son état vide est centré dans le panneau
  • Amélioration du guide de description de l'outil Bash afin que Claude décrive ce qu'une commande fait avec des mots simples au lieu de faire écho à la commande
  • Amélioration du guidage du bac à sable afin que Claude suggère /copy lorsque les commandes clipboard telles que pbcopy échouent à l'intérieur du bac à sable
  • Amélioration du temps de premier rendu --resume pour les sessions avec de nombreux appels d'outils Bash
  • Amélioration de la réactivité de la saisie rapide : les frappes au clavier n'attendent plus occasionnellement une image derrière le spinner ou les repeints en streaming
  • Amélioration de la stabilité du cache d'invite : les sous-agents et les sessions démarrées avec --system-prompt ou --append-system-prompt enregistrent désormais les définitions d'invite système et d'outil une seule fois au lieu de les restituer
  • Amélioration des erreurs de publication de l'outil Artefact : lorsqu'une publication est refusée, le message indique désormais pourquoi et quoi faire à ce sujet.
  • Exécuteur auto-hébergé : modification de --use-anthropic-git-proxy pour qu'il soit signalé au serveur lors de l'enregistrement et pour imprimer un avertissement pour chaque session qui se clone toujours via l'ancien proxy git
  • Passerelle : modification de forward_user_identity en amont pour renvoyer un 429 tel quel à un développeur dont l'e-mail a été transféré, au lieu de basculer vers le suivant en amont, de sorte que les limites par utilisateur du proxy soient maintenues
  • [VSCode] Correction de l'hôte d'extension bloqué à 100 % du processeur lors du bifurcation, de la modification d'un message précédent ou du rembobinage dans une conversation dont la transcription enregistrée contient un lien parent cyclic
  • [VSCode] Correction du collage d'une capture d'écran sur WSL2/WSLg en insérant des octets d'image brute dans l'entrée du chat ; l'image est désormais attachée lorsque le clipboard la fournit, sinon le collage est ignoré
  • [VSCode] Correction des blocs de discussion de discussion toujours rendus avec un thème d'éditeur sombre ; ils suivent désormais le thème de couleurs actif VS Code, y compris un contraste élevé
  • [VSCode] Correction du rendu du texte mixte de droite à gauche et en anglais dans le mauvais ordre lors de la saisie du message
  • [VSCode] Correction de l'acceptation d'une modification dans la vue différentielle sur un fichier avec des fins de ligne Windows (CRLF) échouant avec "Chaîne introuvable dans le fichier"
  • [VSCode] Correction des @-mentions supprimant des fichiers dont les chemins contiennent des espaces
  • [VSCode] Correction de l'échec du chargement de la vue de la liste des sessions dans les fenêtres connectées via Remote-SSH lorsque le dossier de l'espace de travail n'existe que sur l'hôte distant.
  • [VSCode] Correction des processus ripgrep incontrôlables lors de l'affichage de fichiers dans des espaces de travail volumineux ou contenant beaucoup de liens symboliques
  • [Claude Code sur le web] Correction des sessions GitHub Enterprise Server affichant votre compte GitHub comme déconnecté une fois son token expiré ; Les opérations de relations publiques et d'émission l'actualisent désormais automatiquement
  • [Claude Code sur le Web] Correction des appels gh et GitHub API échouant dans les organisations sans l'application Claude GitHub ; ils utilisent maintenant votre compte GitHub connecté et le disent quand aucun n'est connecté
  • [Claude Tag] Ajout d'un lien "Utiliser un connecteur personnalisé" vers les formulaires de connexion prédéfinis dans les paramètres d'administration de Claude Tag, afin que vous puissiez passer à une connexion personnalisée sans recommencer
  • [Claude Tag] Correction de Claude répondant "Le API a rejeté la demande comme invalide" lorsque l'organisation était à court de crédits d'utilisation ; la réponse le dit maintenant et explique comment en ajouter davantage
  • [Tag Claude] Correction des demandes de discussion pour modifier ou supprimer un message posté par Claude au niveau supérieur de la chaîne recevant une réponse avec une correction au lieu d'atteindre la session qui l'a publié
  • [Claude Tag] Correction de Connect sur les demandes d'accès à l'outil sous Paramètres d'administration > Les demandes d'examen échouaient avec "Échec de l'autorisation" ou affichant le paquet d'accès demandé comme supprimé
