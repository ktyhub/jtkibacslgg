DeepTutor v0.4.0

🚀 DeepTutor v0.4.0 Release Note

Date de sortie : 2026.01.09 Nous sommes ravis d'annoncer DeepTutor v0.4.0 ! Cette version apporte une Nouvelle page d'accueil, une Prise en charge étendue du fournisseur LLM et Embeddings, un Découplage du module RAG, une Amélioration Web et un tas d'améliorations mineures.

🚧 Problèmes possibles : Le déploiement de Docker et la configuration locale de LLM/Embeddings (Ollama, LM Studio) peuvent encore avoir des problèmes de compatibilité. Nous travaillons activement sur des améliorations. Les numéros et les relations publiques sont les bienvenus ! → Ouvrir un numéro | Guide de contribution

⚠️ Dernières modifications : configuration de l'environnement

Les noms des variables d'environnement ont été mis à jour. Veuillez mettre à jour votre fichier .env basé sur .env.example. | Ancienne variable | Nouvelle variable | Remarques | |:---|:---|:---| | OPENAI_API_KEY | LLM_API_KEY | Désormais indépendant du fournisseur | | OPENAI_API_BASE | LLM_HOST | Renommé pour plus de clarté | | OPENAI_MODEL | LLM_MODEL | Renommé pour plus de clarté | | EMBEDDING_DIM | EMBEDDING_DIMENSION | Dénomination de mots complets | | (codé en dur) | BACKEND_PORT | Désormais configurable dans .env (par défaut : 8001) | | (codé en dur) | FRONTEND_PORT | Maintenant configurable dans .env (par défaut : 3782) | Nouvelles variables obligatoires :

  • LLM_BINDING — Type de fournisseur : openai, ollama, azure_openai, anthropic, etc.
  • EMBEDDING_BINDING — Type de fournisseur : openai, ollama, jina, cohere, etc. Nouvelles variables facultatives :
  • SEARCH_PROVIDER — Fournisseur de recherche Web : perplexity (par défaut) ou baidu
  • BAIDU_API_KEY — Pour la recherche Baidu AI (百度AI搜索)
  • NEXT_PUBLIC_API_BASE — URL frontale API pour accès à distance/LAN (par exemple, http://192.168.1.100:8001)

💡 Accès à distance : Si vous accédez à DeepTutor depuis un autre appareil de votre réseau, définissez NEXT_PUBLIC_API_BASE sur l'adresse IP de votre serveur. S'il n'est pas défini, la valeur par défaut est http://localhost:8001 (machine locale uniquement). 📌 Action requise : Copiez .env.example vers .env et mettez à jour votre configuration avant la mise à niveau.

✨ Points forts

🔌 LLM multi-fournisseurs et support d'intégration

Extension d'un écosystème de fournisseurs local uniquement à un écosystème de fournisseurs complet : | Fournisseurs LLM | Fournisseurs d'intégration | |:---|:---| | OpenAI, Anthropique, Azure OpenAI | OpenAI, Azure OpenAI, Jina AI | | Ollama, Ollama Cloud, LM Studio | Cohere, Ollama, LM Studio | | Groq, OpenRouter, DeepSeek, Gémeaux | HuggingFace (compatible OpenAI) | La nouvelle architecture basée sur un adaptateur dans src/services/embedding/adapters/ permet d'ajouter facilement de nouveaux fournisseurs.

🧩 Découplage du module RAG

La nouvelle classe RAGService fournit une interface unifiée et indépendante du fournisseur :

from src.services.rag import RAGService

service = RAGService()  # Uses RAG_PROVIDER env var (default: raganything)
await service.initialize("my_kb", ["doc.pdf"])
result = await service.search("query", "my_kb")

📌 Prend actuellement en charge RAG-Anything (MinerU + LightRAG). Plus de backends à venir !

🌙 Refonte du mode sombre et de l'interface utilisateur

  • Changement de thème avec détection des préférences système et persistance du stockage local
  • Barre latérale pliable avec mode compact avec icônes uniquement
  • Reconstruction de la page Paramètres : Gestion des variables d'environnement avec organisation par catégories
  • Style de mode sombre cohérent sur toutes les pages

⚙️ Configuration centralisée

Nouveau settings.py utilisant pydantic-settings pour une configuration unifiée : | Catégorie | Variables d'environnement | |:---|:---| | LLM | LLM_BINDING, LLM_MODEL, LLM_HOST, LLM_API_KEY | | Intégration | EMBEDDING_BINDING, EMBEDDING_MODEL, EMBEDDING_HOST, EMBEDDING_API_KEY, EMBEDDING_DIMENSION | | CHIFFON | RAG_PROVIDER | | TTS | TTS_MODEL, TTS_URL, TTS_API_KEY, TTS_VOICE | | Rechercher | PERPLEXITY_API_KEY | Mises à jour du runtime via /api/settings/env avec persistance automatique .env.

📦Ce qui a changé

Infrastructure de base

  • Ajout de settings.py avec pydantic-settings pour une gestion centralisée de la configuration
  • Ajout de src/core/llm_factory.py avec fonction unifiée llm_complete()
  • Ajout du routeur /api/embedding-providers pour l'intégration de la configuration CRUD
  • Ajout des points de terminaison /api/settings/env pour la gestion de l'environnement d'exécution

Restructuration du module de services (src/services/)

services/
├── embedding/          # 🆕 Adapter-based embedding providers
│   ├── adapters/       # Provider implementations
│   │   ├── base.py, openai_compatible.py, jina.py, cohere.py, ollama.py
│   ├── client.py       # Unified embedding client
│   ├── provider.py     # Provider manager (singleton)
│   └── provider_config.py  # Multi-provider config persistence
├── llm/                # LLM configuration & client
├── rag/                # 🆕 Decoupled RAG system
│   ├── service.py      # Unified RAGService entry point
│   ├── factory.py      # Pipeline factory
│   ├── pipelines/      # Backend implementations
│   │   └── raganything.py, lightrag.py, llamaindex.py, academic.py
│   └── components/     # Modular RAG components
│       ├── chunkers/   # Text chunking strategies
│       ├── parsers/    # Document parsers (PDF, Markdown, Text)
│       ├── embedders/  # Embedding wrappers
│       ├── indexers/   # Vector & Graph indexers
│       └── retrievers/ # Dense & Hybrid retrieval
├── prompt/             # PromptManager singleton
├── tts/                # TTS configuration
└── setup/              # Initialization utilities

Mises à jour du front-end

  • 🆕 Ajout de la Page d'accueil (web/app/page.tsx) avec aperçu des fonctionnalités
  • 🆕 Page Historique reconstruite (web/app/history/page.tsx) avec des vues d'activité améliorées
  • Ajout de web/lib/theme.ts avec des utilitaires de thème (initializeTheme(), setTheme())
  • Ajout de web/hooks/useTheme.ts pour le hook de thème React
  • Ajout de web/components/ThemeScript.tsx pour l'hydratation du thème SSR
  • Ajout de web/components/ChatSessionDetail.tsx pour la page d'historique
  • Sidebar.tsx refactorisé avec mode pliable
  • settings/page.tsx reconstruit avec gestion des variables d'environnement

Améliorations d'IdeaGen

Flux de travail amélioré en 4 étapes : Filtre lâche → Explorer des idées → Filtre strict → Générer une instruction

🐳Docker

Déploiement rationalisé sur un seul conteneur :

docker compose up -d
# Exposes: backend (8001), frontend (3782)
# Volumes: ./config (ro), ./data/user, ./data/knowledge_bases

Déploiement cloud pris en charge via NEXT_PUBLIC_API_BASE_EXTERNAL.

⬆️ Mise à niveau

git pull origin main
docker compose build && docker compose up -d

Remarques sur la migration :

  • Renommer EMBEDDING_DIM → EMBEDDING_DIMENSION
  • Le fournisseur RAG par défaut a été remplacé par raganything
