druid 0.12.0

Mineure Publié9 mars 2018 Sourceapache/druid Anglais original

Cette page est traduite automatiquement. Le texte anglais original fait foi.

druide druide-0.12.0

Druid 0.12.0 contient plus d'une centaine d'améliorations de performances, de stabilité et de corrections de bugs provenant de près de 40 contributeurs. Cette version ajoute des améliorations majeures au service d'indexation Kafka. Parmi les autres nouveautés majeures figurent :

  • Verrouillage des tâches prioritaires
  • Amélioration de la gestion automatique des segments
  • Tester les statistiques post-agrégateurs
  • Agrégateur de croquis de quantiles numériques
  • Extension d'authentification de base
  • Améliorations de la file d'attente des requêtes de requête
  • Prise en charge des lots d'analyse
  • Diverses améliorations des performances
  • Diverses améliorations de Druid SQL La liste complète des changements est ici : https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0 La documentation de cette version se trouve à l'adresse suivante : http://druid.io/docs/0.12.0/

Faits saillants

Kafka indexe les transferts incrémentiels et le partitionnement découplé

Le service d'indexation Kafka prend désormais en charge les transferts incrémentiels, ainsi que le découplage du nombre de segments créés par une tâche d'indexation Kafka du nombre de partitions Kafka. Veuillez consulter https://github.com/druid-io/druid/pull/4815#issuecomment-346155552 pour plus d'informations. Ajouté par @pjain1 dans #4815.

Verrouillage des tâches prioritaires

Druid prend désormais en charge les priorités pour les verrous de tâches d'indexation. Lorsqu'une tâche d'indexation doit acquérir un verrou sur une source de données + un intervalle, les tâches de priorité plus élevée peuvent désormais préempter les tâches de priorité inférieure. Veuillez consulter http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority pour plus d'informations. Ajouté par @jihoonson dans https://github.com/druid-io/druid/pull/4550.

Amélioration de la gestion automatique des segments

Nettoyage automatique des segments en attente

Les tâches d'indexation créent des entrées dans la table « endingSegments » du magasin de métadonnées ; avant 0.12.0, ces entrées temporaires n'étaient pas automatiquement nettoyées, ce qui entraînait une éventuelle dégradation des performances du cluster au fil du temps. Druid 0.12.0 permet au coordinateur de nettoyer automatiquement les entrées inutilisées dans le tableau des segments en attente. Cette fonctionnalité est activée en définissant druid.coordinator.kill.pendingSegments.on=true dans les propriétés du coordinateur. Ajouté par @jihoonson dans #5149.

Tâche de compactage

Le compactage de segments (fusionner un ensemble de segments dans un intervalle donné pour créer un ensemble avec des segments plus grands mais moins nombreux) est un cas d'utilisation courant de l'ingestion par lots de Druid. Druid 0.12.0 prend désormais en charge une tâche de compactage qui fusionne tous les segments dans un intervalle donné en un seul segment. Veuillez consulter http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-task pour plus de détails. Ajouté par @jihoonson dans #4985.

Testez les statistiques post-agrégateurs

De nouveaux post-agrégateurs de statistiques de test de score z et de valeur p ont été ajoutés à l'extension druid-stats. Veuillez consulter http://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.html pour plus de détails. Ajouté par @chunghochen dans #4532.

Agrégateur de croquis de quantiles numériques

Un agrégateur d'esquisses de quantiles numériques a été ajouté à l'extension druid-datasketches. Ajouté par @AlexanderSaydakov dans #5002.

Extension d'authentification de base

Druid 0.12.0 inclut une nouvelle extension d'authentification/autorisation qui fournit une authentification HTTP de base et un contrôle d'accès simple basé sur les rôles. Veuillez consulter http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html pour plus d'informations. Ajouté par @jon-wei dans #5099.

Améliorations de la file d'attente des requêtes de requête

Actuellement, clients peut submerger un courtier par inadvertance en envoyant trop de requêtes qui sont mises en file d'attente dans une file d'attente illimitée du pool de tâches Jetty. Clients ferme généralement la connexion après un certain délai d'attente côté client, ​​mais le courtier continuera à traiter ces demandes, donnant l'impression de ne pas répondre. Pendant ce temps, clients continuerait de réessayer, continuant d'ajouter des requêtes à un courtier déjà surchargé. Les propriétés nouvellement introduites druid.server.http.queueSize et druid.server.http.enableRequestLimit dans configuration du courtier et configuration historique permettent aux utilisateurs de configurer le rejet des demandes pour empêcher les clients de submerger les courtiers et les historiques de requêtes. Ajouté par @himanshug dans #4540.

Prise en charge de l'analyse par lots

Pour les développeurs d’extensions d’analyse d’ingestion personnalisées, il est désormais possible pour les InputRowParsers de renvoyer plusieurs InputRows à partir d’une seule ligne d’entrée. Cela peut simplifier les pipelines d’ingestion en réduisant le besoin de transformations d’entrée en dehors de Druid. Ajouté par @pjain1 dans #5081.

Améliorations des performances

SegmentWriteOutMedium

Lors de la création de nouveaux segments, Druid stocke certaines données prétraitées dans des tampons temporaires. Avant 0.12.0, ces tampons étaient toujours conservés dans des fichiers temporaires sur le disque. Dans 0.12.0, le PR #4762 de @leventov permet à ces tampons temporaires d'être stockés dans la mémoire hors tas, réduisant ainsi le nombre d'opérations d'E/S disque lors de l'ingestion. Pour activer l'utilisation de la mémoire hors tas pour ces tampons, la propriété druid.peon.defaultSegmentWriteOutMediumFactory doit être configurée en conséquence. Si vous utilisez de la mémoire hors tas pour les tampons temporaires, assurez-vous que -XX:MaxDirectMemorySize est augmenté pour prendre en charge l'utilisation plus élevée de la mémoire directe. Veuillez consulter http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory pour les détails de configuration.

Fusion parallèle des résultats GroupBy intermédiaires

PR #4704 de @jihoonson permet à l'utilisateur de configurer un certain nombre de threads de traitement à utiliser pour la fusion parallèle des résultats GroupBy intermédiaires qui ont été déversés sur le disque. Avant 0.12.0, cette étape de fusion avait toujours lieu au sein d'un seul thread. Veuillez consulter http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine pour les détails de configuration.

Autres améliorations de performances

  • Optimisations de la mémoire DataSegment : #5094 par @leventov
  • Supprimer IndexedInts.iterator() : #4811 par @leventov
  • ExpressionSelectors : Ajouter des sélecteurs optimisés : #5048 par @gianm

Diverses améliorations et fonctionnalités ont été ajoutées à Druid SQL, par @gianm dans les PR suivants :

  • Améliorer la traduction des expressions de plancher temporel : #5107
  • Ajouter TIMESTAMPADD : #5079
  • Ajouter une règle pour élaguer les agrégations inutilisées : #5049
  • Prise en charge du nombre filtré de style CASE distinct : #5047
  • Ajouter le format de résultat "tableau" et les formats de résultat du document : #5032
  • Correction de gettingSpec sur les agrégateurs complexes : #5024
  • Comportement amélioré lors de la conversion implicite de chaînes en littéraux date/heure : #5023
  • Ajouter des équilibreurs de connexion de routeur pour les requêtes Avatica : #4983
  • Correction d'une simplification incorrecte du filtre : #4945
  • Correction de la gestion par le routeur des requêtes SQL : #4851

Mise à jour depuis 0.11.0 et versions antérieures

Veuillez consulter ci-dessous les modifications entre 0.11.0 et 0.12.0 dont vous devez être conscient avant la mise à niveau. Si vous effectuez une mise à jour à partir d'une version antérieure à 0.11.0, veuillez consulter les release note des versions intermédiaires concernées pour des notes supplémentaires.

Restrictions de restauration

Veuillez noter qu'après la mise à niveau vers 0.12.0, il n'est plus possible de revenir à une version antérieure à 0.11.0, en raison des modifications apportées à https://github.com/druid-io/druid/pull/4762.. Il est toujours possible de revenir à la version 0.11.0.

Migration de la bibliothèque com.metamx.java-util

La bibliothèque java-util Metamarkets a été intégrée à Druid. En conséquence, les références de packages suivantes ont changé : com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics Cela affectera la configuration du druid.monitoring.monitors. Les références aux classes de surveillance sous l'ancien package com.metamx.metrics.* devront être mises à jour pour référencer io.druid.java.metrics.* à la place, par ex. io.druid.java.util.metrics.JvmMonitor. Si les classes des packages com.metamx présentés ci-dessus sont référencées dans d'autres configurations telles que log4j2.xml, ces références devront également être mises à jour. Les développeurs d'extensions devront également mettre à jour leur code pour utiliser les nouveaux packages Druid.

Extension du cache Caféine

L'extension de cache Caffeine a été déplacée d'une extension vers le noyau Druid. De plus, le cache Caffeine est désormais l'implémentation du cache par défaut. Veuillez supprimer druid-caffeine-cache s'il est présent de la liste des extensions lors de la mise à niveau vers 0.12.0. Plus d’informations peuvent être trouvées sur https://github.com/druid-io/druid/pull/4810.

Modifications du service d'indexation Kafka

earlyMessageRejectPeriod

La sémantique de la configuration earlyMessageRejectPeriod a changé. Le earlyMessageRejectPeriod sera désormais ajouté au (task start time + task duration) au lieu du simple (task start time) lors de la détermination des limites de la fenêtre de message. Veuillez consulter https://github.com/druid-io/druid/pull/4990 pour plus d'informations.

Mise à niveau continue

Dans 0.12.0, il existe des changements de protocole entre le superviseur Kafka et la tâche d'indexation Kafka, ainsi que certaines modifications apportées aux formats de métadonnées conservées sur le disque. Par conséquent, pour prendre en charge la mise à niveau continue, tous les cadres intermédiaires devront être mis à niveau en premier avant l'Overlord. Notez que cet ordre est différent de l'ordre standard de mise à niveau. Notez également que cet ordre n'est nécessaire que lors de l'utilisation du service d'indexation Kafka. Si l'on n'utilise pas le service d'indexation Kafka ou si l'on peut gérer les temps d'arrêt de Kafka Supervisor, on peut effectuer la mise à niveau dans n'importe quel ordre. Jusqu'à la mise à niveau d'Overlord, toutes les tâches d'indexation Kafka se comporteront de la même manière (même si elles sont mises à niveau) que précédemment, ce qui signifie aucun découplage ni transfert incrémentiel. Une fois Overlord mis à niveau, les nouvelles tâches lancées par Overlord mis à niveau prendront en charge les nouvelles fonctionnalités. Veuillez consulter https://github.com/druid-io/druid/pull/4815 pour plus d'informations.

Revenir en arrière

Une fois que le suzerain et les cadres intermédiaires auront été annulés, un nouvel ensemble de tâches devrait être lancé, qui fonctionnera correctement. Cependant, l'ensemble de tâches actuel peut échouer lors d'une restauration. Veuillez consulter le numéro 4815 pour plus d'informations.

Modifications de l'interface pour les développeurs d'extensions

Le ColumnSelectorFactory API a changé. Les auteurs d'extensions d'agrégateur et tous ceux qui utilisent ColumnSelectorFactory devront mettre à jour leur code en conséquence. Veuillez consulter https://github.com/druid-io/druid/pull/4886 pour plus de détails. La méthode Aggregator.reset() a été supprimée car elle était obsolète et inutilisée. Veuillez consulter https://github.com/druid-io/druid/pull/5177 pour plus d'informations. L'interface DataSegmentPusher a changé et la méthode push() dispose désormais d'un paramètre replaceExisting supplémentaire. Veuillez consulter https://github.com/druid-io/druid/pull/5187 pour plus de détails. L'interface Escalator a changé : la méthode createEscalatedJettyClient a été supprimée. Veuillez consulter https://github.com/druid-io/druid/pull/5322 pour plus de détails.
