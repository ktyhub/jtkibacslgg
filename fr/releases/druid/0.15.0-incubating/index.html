druide druide-0.15.0-incubating

Apache Druid 0.15.0-incubating contient plus de 250 nouvelles fonctionnalités, des améliorations de performances/stabilité/documentation et des corrections de bugs de 39 contributeurs. Les principales nouvelles fonctionnalités et améliorations incluent :

  • Nouvelle interface utilisateur du chargeur de données
  • Prise en charge du sujet transactionnel Kafka
  • Nouvelle requête de moyenne mobile
  • Ordre de temps pour la requête Scan
  • Nouvel agrégateur de croquis Moments
  • Améliorations SQL
  • Module de recherche léger pour les routeurs
  • Extension ORC de base
  • Extension de base de GCP
  • Améliorations des documents La liste complète des changements est ici : https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.15.0 La documentation de cette version se trouve à l'adresse suivante : http://druid.apache.org/docs/0.15.0-incubating/

Faits saillants

Nouvelle interface utilisateur du chargeur de données (partie indexation par lots)

<img width="1440" alt="0 15 0-data-loader" src="https://user-images.githubusercontent.com/2322288/59154870-f41b3d80-8a30-11e9-97d4-18800d91402d.png"> Druid dispose d'une nouvelle interface utilisateur Data Loader qui est intégrée à la [Druid Console] (http://druid.apache.org/docs/latest/operations/management-uis.html#druid-console). La nouvelle interface utilisateur de Data Loader affiche des données échantillonnées pour vérifier facilement la spécification d'ingestion et génère automatiquement la spécification d'ingestion finale. Les utilisateurs sont censés émettre facilement des tâches d'indexation par lots au lieu d'écrire eux-mêmes une spécification JSON. Ajouté par @vogievetsky et @dclim dans https://github.com/apache/incubator-druid/pull/7572 et https://github.com/apache/incubator-druid/pull/7531, respectivement. ## Prise en charge des sujets transactionnels Kafka Le service d'indexation Kafka prend désormais en charge les sujets transactionnels Kafka. Veuillez noter que seuls Kafka 0.11.0 ou les versions ultérieures sont pris en charge après cette modification. Ajouté par @surekhasaharan dans https://github.com/apache/incubator-druid/pull/6496. ## Nouvelle requête de moyenne mobile Un nouveau type de requête a été introduit pour calculer la [moyenne mobile] (https://en.wikipedia.org/wiki/Moving_average). Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/development/extensions-contrib/moving-average-query.html pour plus de détails. Ajouté par @yurmix dans https://github.com/apache/incubator-druid/pull/6430. ## Ordre de temps pour la requête d'analyse Le type de requête Scan prend désormais en charge l’ordre temporel. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/querying/scan-query.html#time-ordering pour plus de détails. Ajouté par @justinborromeo dans https://github.com/apache/incubator-druid/pull/7133. ## Agrégateur de croquis de nouveaux moments L'[Moments Sketch](https://github.com/stanford-futuredata/momentsketch) est un nouveau type d'esquisse pour le calcul approximatif des quantiles. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/development/extensions-contrib/momentsketch-quantiles.html pour plus de détails. Ajouté par @edgan8 dans https://github.com/apache/incubator-druid/pull/6581. ## Améliorations SQL La communauté Druid s'est efforcée d'améliorer la prise en charge de SQL et ce n'est désormais plus expérimental. ### Nouvelles fonctions SQL - Les fonctions LPAD et RPAD ont été ajoutées par @xueyumusic dans https://github.com/apache/incubator-druid/pull/7388. - Les fonctions DEGREES et RADIANS ont été ajoutées par @xueyumusic dans https://github.com/apache/incubator-druid/pull/7336. - La fonction STRING_FORMAT a été ajoutée par @gianm dans https://github.com/apache/incubator-druid/pull/7327. - La fonction PARSE_LONG a été ajoutée par @gianm dans https://github.com/apache/incubator-druid/pull/7326. - La fonction ROUND a été ajoutée par @gianm dans https://github.com/apache/incubator-druid/pull/7224. - Les fonctions trigonométriques ont été ajoutées par @xueyumusic dans https://github.com/apache/incubator-druid/pull/7182. ### Saisie semi-automatique dans Druid Console <img width="915" alt="0 15 0-autocomplete" src="https://user-images.githubusercontent.com/2322288/59154863-e9f93f00-8a30-11e9-8232-a8e5cafd43bb.png"> Druid Console prend désormais en charge la saisie semi-automatique pour SQL. Ajouté par @shuqi7 dans https://github.com/apache/incubator-druid/pull/7244. ### Prise en charge des analyses chronométrées pour SQL Druid SQL prend en charge les requêtes d'analyse chronométrées. Ajouté par @justinborromeo dans https://github.com/apache/incubator-druid/pull/7373. ## Vue des recherches ajoutée à la console Web <img width="1439" alt="0 15 0-lookup-view" src="https://user-images.githubusercontent.com/2322288/59154856-ce8e3400-8a30-11e9-812f-ea46e0effaae.png"> Vous pouvez désormais configurer vos recherches directement depuis la console Web. Ajouté par @shuqi7 dans https://github.com/apache/incubator-druid/pull/7259. ## Diverses améliorations de la console Web #### Mode "NoSQL" : https://github.com/apache/incubator-druid/pull/7493 [@shuqi7] La console Web dispose désormais d'un mode de sauvegarde qui lui permet de fonctionner au mieux si DruidSQL est désactivé ou indisponible. #### Ajout d'une boîte de dialogue de configuration du compactage : https://github.com/apache/incubator-druid/pull/7242 [@shuqi7] Vous pouvez désormais configurer les paramètres de compactage automatique pour une source de données à partir de la vue Source de données. #### Requête de bouclage automatique avec limite : https://github.com/apache/incubator-druid/pull/7449 [@vogievetsky] <img width="390" alt="0 15 0-misc" src="https://user-images.githubusercontent.com/2322288/59154873-05644a00-8a31-11e9-88cf-81441d321b37.png"> La vue des requêtes de la console encapsulera désormais (par défaut) les requêtes DruidSQL avec un `SELECT * FROM (...) LIMIT 1000` vous permettant de saisir des requêtes comme `SELECT * FROM your_table` sans vous soucier de l'impact sur le cluster. Vous pouvez toujours envoyer des requêtes « brutes » en sélectionnant l'option dans le menu `...`. #### Requête d'explication SQL : https://github.com/apache/incubator-druid/pull/7402 [@shuqi7] Vous pouvez maintenant cliquer sur cli dans le menu `...` dans la vue requête pour obtenir une explication de la requête DruidSQL. #### Surface `is_overshadowed` en tant que colonne dans la table de segments https://github.com/apache/incubator-druid/pull/7555 , https://github.com/apache/incubator-druid/pull/7425 [@shuqi7][@surekhasaharan] La colonne `is_overshadowed` indique que ce segment est éclipsé par tous les segments publiés. Il peut être utile de voir quels segments doivent être chargés par les historiques. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/querying/sql.html pour plus de détails. #### Amélioration de l'interface utilisateur d'état pour les actions sur les tâches, les superviseurs et les sources de données : https://github.com/apache/incubator-druid/pull/7528 [shuqi7] Ce PR condense la liste d'actions dans un menu bien rangé et vous permet de voir l'état détaillé des superviseurs et des tâches. De nouvelles actions pour les sources de données concernant le chargement et la suppression de données par intervalle ont également été ajoutées. ## Module de recherche de lumière pour les routeurs Un module de recherche léger a été introduit pour les routeurs et ils n'ont désormais besoin que d'une quantité minimale de mémoire. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/operations/basic-cluster-tuning.html#router pour le réglage de base de la mémoire. Ajouté par @clintropolis dans https://github.com/apache/incubator-druid/pull/7222. ## Extension ORC de base L'extension ORC est désormais promue au rang d'extension principale. Veuillez lire la section ci-dessous « Mise à jour à partir de 0.14.0-incubating et versions antérieures » si vous utilisez l'extension ORC dans une version antérieure de Druid. Ajouté par @clintropolis dans https://github.com/apache/incubator-druid/pull/7138. ## Extension GCP principale L'extension GCP est désormais promue extension principale. Veuillez lire la section ci-dessous « Mise à jour à partir de 0.14.0-incubating et versions antérieures » si vous utilisez l'extension GCP dans une version antérieure de Druid. Ajouté par @drcrallen dans https://github.com/apache/incubator-druid/pull/6953. ## Améliorations des documents ### Exemples de configurations et de scripts de déploiement sur une seule machine Plusieurs configurations et scripts ont été ajoutés pour une configuration facile sur une seule machine. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/operations/single-server.html pour plus de détails. Ajouté par @jon-wei dans https://github.com/apache/incubator-druid/pull/7590. ### Outil de migration depuis le stockage profond local/les métadonnées Derby Un nouvel outil a été ajouté pour faciliter la migration d'une machine unique vers un environnement de cluster. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/operations/deep-storage-migration.html pour plus de détails. Ajouté par @jon-wei dans https://github.com/apache/incubator-druid/pull/7598. ### Document pour le guide de réglage de base Des documents pour le guide de réglage de base ont été ajoutés. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/operations/basic-cluster-tuning.html pour plus de détails. Ajouté par @jon-wei dans https://github.com/apache/incubator-druid/pull/7629. ## Amélioration de la sécurité La table système Druid ne nécessite désormais que les autorisations obligatoires au lieu de l'autorisation de lecture pour l'ensemble de la base de données `sys`. Veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/development/extensions-core/druid-basic-security.html pour plus de détails. Ajouté par @jon-wei dans https://github.com/apache/incubator-druid/pull/7579. ## Obsolète/supprimé ### Supprimer la prise en charge de la fusion automatique des segments La fusion automatique de segments par le coordinateur n'est plus prise en charge. Veuillez utiliser [compactage automatique](http://druid.apache.org/docs/0.15.0-incubating/design/coordinator.html#compacting-segments) à la place. Ajouté par @jihoonson dans #6883. ### Supprimer la prise en charge de l'outil `insert-segment-to-db` Dans Druid 0.14.x ou version antérieure, Druid stocke les métadonnées de segment (fichier `descriptor.json`) dans un stockage profond en plus du magasin de métadonnées. Ce comportement a changé dans 0.15.0 et il ne stocke plus le fichier de métadonnées de segment dans le stockage profond. Par conséquent, l'outil `insert-segment-to-db` n'est plus non plus pris en charge car il fonctionne sur la base des fichiers `descriptor.json` dans le stockage profond. Veuillez consulter le http://druid.apache.org/docs/0.15.0-incubating/operations/insert-segment-db.html pour plus de détails. Veuillez noter que la tâche kill échouera si vous utilisez HDFS comme stockage profond et que le fichier `descriptor.json` est manquant dans 0.14.x ou dans les versions antérieures. Ajouté par @jihoonson dans https://github.com/apache/incubator-druid/pull/6911. ### Suppression de la configuration "useFallback" pour SQL Cette option a été supprimée car elle génère des plans de requête non évolutifs et ne fonctionne pas avec certaines fonctions SQL. Ajouté par @gianm dans https://github.com/apache/incubator-druid/pull/7567. ### Suppression d'un API public dans `CompressionUtils` pour les développeurs d'extensions `public static void gunzip(File pulledFile, File outDir)` a été supprimé dans https://github.com/apache/incubator-druid/pull/6908 par @clintropolis. ## Autres changements de comportement ### Le coordinateur attend l'initialisation avant de terminer le démarrage Une nouvelle configuration (`druid.coordinator.segment.awaitInitializationOnStart`) a été ajoutée pour que le coordinateur attende l'initialisation de la vue de segment. Cette option est activée par défaut. Ajouté par @QiuMM dans https://github.com/apache/incubator-druid/pull/6847. ### Coordonnateur API changement de comportement Le coordinateur interroge périodiquement les informations de métadonnées de segment à partir du magasin de métadonnées et les met en cache en mémoire. Dans Druid 0.14.x ou version antérieure, la suppression de segments via les coordonnateurs API (`/druid/coordinator/v1/datasources/{dataSourceName}` et `/druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}`) met immédiatement à jour le cache de segments en mémoire ainsi que le magasin de métadonnées. Mais ce comportement a changé dans 0.15.0 et le cache est mis à jour par sondage plutôt que immédiatement après la suppression. Les API ci-dessous peuvent renvoyer les segments supprimés via les appels API ci-dessus jusqu'à ce que le cache soit mis à jour lors du prochain sondage. -`/druid/coordinator/v1/metadata/datasources/{dataSourceName}` -`/druid/coordinator/v1/metadata/datasources/{dataSourceName}/segments` -`/druid/coordinator/v1/metadata/datasources/{dataSourceName}/segments/{segmentId}` -`/druid/coordinator/v1/metadata/datasources` -`/druid/coordinator/v1/loadstatus` Les métriques ci-dessous peuvent également contenir des segments supprimés via les appels API ci-dessus jusqu'à ce que le cache soit mis à jour lors du prochain sondage. -`segment/unavailable/count` -`segment/underReplicated/count` Ce comportement a été modifié dans https://github.com/apache/incubator-druid/pull/7595 par @surekhasaharan. ### Recherche d'annonce API changement Le `/druid/coordinator/v1/lookups/config` API renvoie désormais une liste des niveaux actuellement actifs dans le cluster en plus de ceux connus dans la configuration dynamique. Ajouté par @clintropolis dans https://github.com/apache/incubator-druid/pull/7647. ### Perte de Zookeeper Avec une nouvelle configuration (`druid.zk.service.terminateDruidProcessOnConnectFail`), les processus Druid peuvent se terminer lors de la déconnexion du ZooKeeper. Ajouté par @michael-trelinski dans https://github.com/apache/incubator-druid/pull/6740. # Mise à jour depuis 0.14.0-incubating et versions antérieures ## Modification de la version minimale compatible de Kafka pour le service d'indexation Kafka Kafka 0.11.x ou les versions ultérieures ne sont prises en charge qu'après https://github.com/apache/incubator-druid/pull/6496.. Veuillez envisager de mettre à jour la version de Kafka si vous en utilisez une plus ancienne. ## Modifications de l'extension ORC L'extension ORC a été promue en extension `core`. Lors du déploiement de 0.15.0-incubating, veuillez vous assurer que votre répertoire `extensions` ne contient pas d'anciennes versions de l'extension `druid-orc-extensions`. De plus, même si la nouvelle extension principale peut indexer toutes les données que l'ancienne extension `contrib` pouvait, la spécification JSON pour la tâche d'ingestion est *incompatible* et devra être modifiée pour fonctionner avec la nouvelle extension `core`. Pour migrer vers 0.15.0-incubating : * Dans `inputSpec` de `ioConfig`, `inputFormat` doit être remplacé de `"org.apache.hadoop.hive.ql.io.orc.OrcNewInputFormat"` par `"org.apache.orc.mapreduce.OrcInputFormat"` * L'extension `contrib` supportait une propriété `typeString`, qui fournissait le schéma du Fichier ORC, dont il fallait essentiellement avoir les types corrects, mais notamment _pas_ les noms de colonnes, ce qui facilitait le renommage des colonnes. Dans l'extension `core`, le renommage des colonnes peut être réalisé avec [Expressions `flattenSpec`] (http://druid.apache.org/docs/0.15.0-incubating/ingestion/flatten-json.html). * L'extension `contrib` prenait en charge une propriété `mapFieldNameFormat`, qui permettait de spécifier une dimension pour aplatir les colonnes `OrcMap` avec des types primitifs. Cette fonctionnalité a également été remplacée par [Expressions `flattenSpec`](http://druid.apache.org/docs/0.15.0-incubating/ingestion/flatten-json.html). Pour plus de détails et d'exemples, veuillez consulter http://druid.apache.org/docs/0.15.0-incubating/development/extensions-core/orc.html. ## Modifications de l'extension GCP L'extension GCP a été promue en extension `core`. Lors du déploiement de 0.15.0-incubating, veuillez vous assurer que votre répertoire `extensions` ne contient pas d'anciennes versions de l'extension `druid-google-extensions`. ## Fusion automatique des segments abandonnée La configuration du coordinateur pour la fusion automatique de segments (`druid.coordinator.merge.on`) n'est plus prise en charge. Veuillez utiliser [compactage automatique](http://druid.apache.org/docs/0.15.0-incubating/design/coordinator.html#compacting-segments) à la place. ## Suppression du fichier de métadonnées `descriptor.json` dans le stockage profond Le fichier de métadonnées du segment (`descriptor.json`) n'est plus stocké dans le stockage profond. Si vous utilisez HDFS comme stockage profond et que vous devez revenir à 0.14.x ou à une version antérieure, veuillez considérer que la tâche d'élimination pourrait échouer en raison des fichiers `descriptor.json` manquants. # Crédits Merci à tous ceux qui ont contribué à cette version ! @a2l007 @asdf2014 @capistrant @clintropolis @dampcake @dclim @donbowman @drcrallen @Dylan1312 @edgan8 @es1220 @esevastyanov @FaxianZhao @fjy @gianm @glasser @hpandeycodeit @jihoonson @jon-wei @jorbay-au @justinborromeo @kamaci @KazuhitoT @leventov @lxqfy @michael-trelinski @peferron @puneetjaiswal @QiMM @richardstartin @samarthjain @scrawfor @shuqi7 @surekhasaharan @venkatramanp @vogievetsky @xueyumusic @xvrl @yurmix --- > **Source** [apache/druid](https://github.com/apache/druid) · `druid-0.15.0-incubating` · 2019-06-27 · [version amont](https://github.com/apache/druid/releases/tag/druid-0.15.0-incubating) *Verbatim reflété pour l'indexation.
