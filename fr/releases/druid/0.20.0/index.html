druid 0.20.0

druide druide-0.20.0

Apache Druid 0.20.0 contient environ 160 nouvelles fonctionnalités, corrections de bugs, améliorations des performances, améliorations de la documentation et couverture de tests supplémentaire de 36 contributeurs. Reportez-vous à la [liste complète des modifications] (https://github.com/apache/druid/compare/0.19.0...0.20.0) et à [tout ce qui est associé au jalon] (https://github.com/apache/druid/milestone/40) pour plus de détails.

<a name="20-new-features" href="#20-new-features">#</a> Nouvelles fonctionnalités

<a name="20-ingestion" href="#20-ingestion">#</a> Ingestion

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> Combinaison d'InputSource

Un nouveau InputSource de combinaison a été ajouté, permettant à l'utilisateur de combiner plusieurs sources d'entrée lors de l'ingestion. Veuillez consulter https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source pour plus de détails. https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Déterminer automatiquement les numShards pour le partitionnement de hachage d'ingestion parallèle

Lorsque le partitionnement par hachage est utilisé dans l'ingestion par lots parallèle, il n'est plus nécessaire de spécifier numShards dans la spécification de partition. Druid peut désormais déterminer automatiquement un certain nombre de fragments en analysant les données dans une nouvelle phase d'ingestion qui détermine les cardinalités de la clé de partitionnement. https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Limites du nombre de fichiers de sous-tâches pour l'ingestion de lots parallèles

Le splitHintSpec basé sur la taille prend désormais en charge un nouveau paramètre maxNumFiles, qui limite le nombre de fichiers pouvant être attribués à des sous-tâches individuelles lors d'une ingestion par lots parallèle. Le splitHintSpec basé sur les segments utilisé pour réingérer les données des segments Druid existants possède également un nouveau paramètre maxNumSegments qui fonctionne de manière similaire. Veuillez consulter https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec pour plus de détails. https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Métriques d'utilisation des emplacements de tâches

De nouvelles mesures d'utilisation des emplacements de tâches ont été ajoutées. Veuillez consulter les entrées pour les métriques taskSlot sur https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service pour plus de détails. https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Compactage

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Prise en charge de tous les schémas de partitionnement pour le compactage automatique

Une spécification de partitionnement peut désormais être définie pour le compactage automatique, permettant aux utilisateurs de répartir leurs données au moment du compactage. Veuillez consulter la documentation de la nouvelle propriété partitionsSpec dans la compaction tuningConfig pour plus de détails : https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> État du compactage automatique API

Un nouveau coordinateur API qui affiche l'état du compactage automatique d'une source de données a été ajouté. Le nouveau API indique si le compactage automatique est activé pour une source de données et un résumé de la progression du compactage. La console Web a également été mise à jour pour afficher ces informations : https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png Veuillez consulter https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status pour plus de détails sur le nouveau API et https://druid.apache.org/docs/latest/operations/metrics.html#coordination pour plus d'informations sur les nouvelles mesures de compactage associées. https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Requête

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Élagage de segment de requête avec partitionnement par hachage

Druid prend désormais en charge l'élagage des segments au moment de la requête (en excluant certains segments comme candidats à la lecture pour une requête) pour les segments partitionnés par hachage. Cette optimisation s'applique lorsque tous les partitionDimensions spécifiés dans la spécification de partition de hachage pendant le temps d'ingestion sont présents dans l'ensemble de filtres d'une requête, et les filtres de la requête filtrent sur les valeurs discrètes du partitionDimensions (par exemple, les filtres de sélection). L'élagage de segments avec partitionnement par hachage n'est pas pris en charge avec les filtres non discrets tels que les filtres liés. Pour les utilisateurs existants disposant de segments existants, vous devrez réingérer ces segments pour profiter de cette nouvelle fonctionnalité, car l'élagage des segments nécessite qu'un partitionFunction soit stocké avec les segments, ce qui n'existe pas dans les segments créés par les anciennes versions de Druid. Il n'est pas nécessaire de spécifier explicitement le partitionFunction, car la fonction par défaut est la même fonction de partition que celle utilisée dans les versions précédentes de Druid. Notez que les segments créés avec une valeur partitionDimensions par défaut (partition par toutes les dimensions + la colonne de temps) ne peuvent pas être élagués de cette manière, les segments doivent être créés avec un partitionDimensions explicite. https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vectorisation

Pour activer les fonctionnalités de vectorisation, veuillez définir la propriété druid.query.default.context.vectorizeVirtualColumns sur true ou définir la propriété vectorize dans le contexte de requête. Veuillez consulter https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters pour plus d'informations.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Prise en charge de la vectorisation pour les colonnes virtuelles d'expression

Les colonnes virtuelles d'expression prennent désormais en charge la vectorisation (en fonction des expressions utilisées), ce qui entraîne une amélioration des performances de 3 à 5 fois dans certains cas. Veuillez consulter https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support pour plus de détails sur les expressions spécifiques prenant en charge la vectorisation. https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> Plus de prise en charge de la vectorisation pour les agrégateurs

La prise en charge de la vectorisation a été ajoutée pour plusieurs types d'agrégation : agrégateurs numériques min/max, agrégateurs de variance, agrégateurs ANY et agrégateurs de l'extension druid-histogram. https://github.com/apache/druid/pull/10260 - numérique min/max https://github.com/apache/druid/pull/10304 - histogramme https://github.com/apache/druid/pull/10338 - TOUT https://github.com/apache/druid/pull/10390 - variation Nous avons observé une amélioration des performances d'environ 1,3x à 1,8x dans certains cas avec la vectorisation activée pour l'agrégateur min, max et ANY, et d'environ 1,04x à 1,07x avec l'agrégateur d'histogramme.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> Paramètre offset pour les requêtes GroupBy et Scan

Il est désormais possible de définir un paramètre offset pour les requêtes GroupBy et Scan, qui indique à Druid d'ignorer un certain nombre de lignes lors du renvoi des résultats. Veuillez consulter https://druid.apache.org/docs/0.20.0/querying/limitspec.html et https://druid.apache.org/docs/0.20.0/querying/scan-query.html pour plus de détails. https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> Clause OFFSET pour les requêtes SQL

Les requêtes Druid SQL prennent désormais en charge une clause OFFSET. Veuillez consulter https://druid.apache.org/docs/0.20.0/querying/sql.html#offset pour plus de détails. https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Opérateurs de recherche de sous-chaînes

Druid a ajouté de nouveaux opérateurs de recherche de sous-chaînes dans son langage d'expression et pour les requêtes SQL. Veuillez consulter la documentation des fonctions de chaîne CONTAINS_STRING et ICONTAINS_STRING pour Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) et la documentation de contains_string et icontains_string pour le langage d'expression Druid (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions). Nous avons observé une amélioration des performances d'environ 2,5 fois dans certains cas en utilisant ces fonctions au lieu de STRPOS. https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> Opérateur UNION ALL pour les requêtes SQL

Les requêtes Druid SQL prennent désormais en charge l'opérateur UNION ALL, qui fusionne les résultats de plusieurs requêtes. Veuillez consulter https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all pour plus de détails sur les formes de requête prises en charge par cet opérateur. https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Paramètres de contexte de requête par défaut à l'échelle du cluster

Il est désormais possible de définir des propriétés de contexte de requête par défaut à l'échelle du cluster en ajoutant une configuration du formulaire druid.query.override.default.context.*, * étant remplacé par le nom de la propriété. https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Autres fonctionnalités

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> Amélioration de l'interface utilisateur des règles de rétention

L'interface utilisateur des règles de rétention dans la console Web a été améliorée. Il fournit désormais des suggestions et une validation de base dans la liste déroulante des périodes, affiche les règles par défaut du cluster et rend la modification des règles par défaut plus accessible. https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Améliorations de l'extension de cache Redis

L'extension de cache Redis prend désormais en charge le cluster Redis, sélectionnant la base de données utilisée, la connexion aux serveurs protégés par mot de passe et les configurations de style point pour les propriétés expiration et timeout. https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Désactiver l'envoi de la version du serveur dans les en-têtes de réponse

Il est désormais possible de désactiver l'envoi des informations de version du serveur dans les en-têtes de réponse de Druid. Ceci est contrôlé par une nouvelle propriété druid.server.http.sendServerVersion, dont la valeur par défaut est true. https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Spécifier les propriétés de configuration basées sur les octets avec les unités

Druid prend désormais en charge les unités pour spécifier les propriétés de configuration basées sur les octets, par exemple :

druid.server.maxSize=300g

équivalent à

druid.server.maxSize=300000000000

Veuillez consulter https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html pour plus de détails. https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Corrections de bugs

<a name="20-query-correctness" href="#20-query-correctness">#</a> Correction d'un problème d'exactitude des requêtes lorsque l'historique n'a pas de chronologie de segment

Druid 0.20.0 corrige un problème d'exactitude de la requête lorsqu'un courtier émet une requête en s'attendant à ce qu'un historique contienne certains segments pour une source de données, mais que l'historique interrogé n'a en réalité aucun segment pour cette source de données (par exemple, ils ont tous été déchargés avant que l'historique ne traite la requête). Avant 0.20.0, la requête était renvoyée avec succès, mais sans les résultats des segments manquants, de la manière décrite précédemment. Dans 0.20.0, les requêtes échoueront désormais dans de telles situations. https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Correction d'un problème empêchant le remplissage du cache au niveau des résultats

Druid 0.20.0 corrige un problème introduit dans 0.19.0 (https://github.com/apache/druid/issues/10337) qui peut empêcher le remplissage des caches de requêtes lorsque la mise en cache au niveau des résultats est activée. https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Correction du classement de l'agrégateur de variances

L'agrégateur de variance utilisait auparavant un comparateur incorrect qui effectuait la comparaison en utilisant la variable count interne de l'agrégateur au lieu de la variance. https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Correction d'une mise en cache incorrecte pour les requêtes groupBy avec des spécifications de limite

Druid 0.20.0 corrige un problème avec les requêtes groupBy et la mise en cache, où la limitSpec de la requête n'était pas prise en compte dans la clé de cache, ce qui entraînait des résultats potentiellement incorrects si des requêtes identiques à l'exception de la limitSpec étaient émises. https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Correction pour stringFirst et stringLast avec le rollup activé

https://github.com/apache/druid/issues/7243 a été résolu, les agrégateurs stringFirst et stringLast ne provoquent plus d'exception lorsqu'ils sont utilisés lors de l'ingestion avec le cumul activé. https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Mise à niveau vers Druid 0.20.0

Veuillez prendre en compte les considérations suivantes lors de la mise à niveau du 0.19.0 vers le 0.20.0. Si vous effectuez une mise à jour à partir d'une version antérieure à 0.19.0, veuillez consulter les release note des versions intermédiaires concernées.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Par défaut maxSize

druid.server.maxSize utilisera désormais par défaut la somme des valeurs maxSize définies dans le druid.segmentCache.locations. L'utilisateur peut toujours fournir une valeur personnalisée pour druid.server.maxSize qui aura priorité sur la valeur par défaut. https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Modifications de l'ID de la tâche de compactage et d'élimination

Les tâches de compactage et d'arrêt émises par le coordinateur auront désormais leur ID de tâche préfixé par coordinator-issued, tandis que les tâches d'arrêt émises par l'utilisateur seront préfixées par api-issued. https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> Nouvelles limites de taille pour les spécifications d'indice de partage d'ingestion parallèle

Le splitHintSpec basé sur la taille et basé sur les segments pour l'ingestion de lots parallèles applique désormais une limite de fichier/segment par défaut de 1 000 par sous-tâche, contrôlée respectivement par le maxNumFiles et le maxNumSegments. https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> Nouvelles méthodes PostAggregator et AggregatorFactory

Les utilisateurs qui ont développé une extension avec des implémentations personnalisées de PostAggregator ou AggregatorFactory devront mettre à jour leurs extensions, car ces deux interfaces ont de nouvelles méthodes définies dans 0.20.0. PostAggregator dispose désormais d'une nouvelle méthode :

  ValueType getType();

Pour prendre en charge les informations de type sur PostAggregator, AggregatorFactory dispose également de 2 nouvelles méthodes :

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Veuillez consulter https://github.com/apache/druid/pull/9638 pour plus de détails sur les modifications de l'interface.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> Nouvelles méthodes liées au Expr

Les utilisateurs qui ont développé une extension avec des implémentations personnalisées de Expr devront mettre à jour leurs extensions, car Expr et les interfaces associées ont été modifiées dans 0.20.0. Veuillez consulter le PR ci-dessous pour plus de détails : https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> Métrique query/cpu/time plus précise

Dans 0.20.0, la précision de la métrique query/cpu/time a été améliorée. Auparavant, il ne prenait pas en compte certaines parties du travail lors du traitement des requêtes, décrites plus en détail dans le PR suivant : https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> Nouvelles colonnes de métriques du service de journal d'audit

Si vous utilisez la journalisation d'audit, sachez que de nouvelles colonnes ont été ajoutées à la métrique du service de journal d'audit (comment, remote_address et created_date). Une colonne facultative payload a également été ajoutée, qui peut être activée en réglant druid.audit.manager.includePayloadAsDimensionInMetric sur true. https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext dans les journaux de requêtes

Si vous utilisez la journalisation des demandes de requête, les événements du journal des demandes incluront désormais le sqlQueryContext pour les requêtes SQL. https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> État supplémentaire par segment dans le magasin de métadonnées

Les segments partitionnés par hachage créés par Druid 0.20.0 auront désormais des données partitionFunction supplémentaires dans le magasin de métadonnées. De plus, les tâches de compactage stockeront désormais des informations supplémentaires par segment dans le magasin de métadonnées, utilisées pour suivre l'historique de compactage. https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Problèmes connus

<a name="20-location-strat" href="#20-location-strat">#</a> Échec de l'injection druid.segmentCache.locationSelectorStrategy

La spécification d'une valeur pour druid.segmentCache.locationSelectorStrategy empêche le démarrage des services en raison d'une erreur d'injection. Veuillez consulter https://github.com/apache/druid/issues/10348 pour plus de détails.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Fuite de ressources dans l'échantillonneur de données de la console Web

Lorsqu'un délai d'attente se produit lors de l'échantillonnage des données dans la console Web, les ressources internes créées pour lire à partir de la source d'entrée ne sont pas correctement fermées. Veuillez consulter https://github.com/apache/druid/pull/10467 pour plus d'informations.
