claude-code v2.1.236

パッチ 公開日2026年8月19日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.236

何が変わったのか

  • ANTHROPIC_DEFAULT_MODEL 環境変数を追加しました。新しいセッションが開始されるモデルを設定しますが、/model の選択はそれをオーバーライドし、再起動後も保持されます (ANTHROPIC_MODEL とは異なります)。
  • クロスセッション SendMessage に notify_when_idle を追加: このマシン上の別のクロード コード セッションに、次回アイドル状態になったときに 1 つの通知を送信するように依頼します — オプトイン、ワンショット、ポーリングなし (macOS および Linux)
  • サンドボックス: macOS では、許可された読み取り領域内でワイルドカード読み取り拒否ルール (例: **/.env) が優先され、一致したディレクトリのコンテンツがカバーされ、拒否されたファイルの名前を変更してもバイパスできなくなりました。
  • clipboard のコピー、バックグラウンド ハウスキーピング、バックグラウンド セッション、およびセッションが切り替わったディレクトリが削除された後に壊れるローカル MCP ログを修正しました (2.1.229 以降)
  • フルスクリーン レンダラーが 1 回起動に失敗すると永続的に失敗する問題を修正しました。その後の起動ごとに終了するのではなく、クラシック レンダラーにフォールバックするようになりました。
  • /model ピッカーのレンダリングが端末よりも高くなる問題を修正しました。ウィンドウに収まる数のモデルのみが表示され、残りはスクロールでアクセスできるようになりました。
  • 不正な終了タグが概要フィールド内のメッセージ テキストに残っている場合に拒否される SendMessage 呼び出しを修正しました
  • サブプロセスの開始に失敗した場合の未処理の Promise 拒否を修正しました。たとえば、Windows 相互運用機能が無効になっている WSL 上の powershell.exe (2.1.234 のリグレッション)
  • 全画面モードで端末のサイズが変更された後、次の更新まで新しく送信されたメッセージが表示されないことがある問題を修正しました
  • 複数行のプロンプトをクリアした後にプロンプトの上に残る空白のバンドと、全画面モードで端末のサイズを変更したり元に戻したりした後にペインが再描画されない問題を修正しました。
  • 最初のキー入力を承認としてキャプチャしながら、起動時に管理設定の承認プロンプトが表示されないことがある問題を修正しました
  • tmux でジャンプするターミナル タブのタイトルを修正しました (iTerm tmux 統合): タイトルは、960 ミリ秒ごとにアニメーション化するのではなく、テキストが変更された場合にのみ書き込まれるようになりました。
  • クラウド環境リストが空または不正な形式で返されたときの不明瞭なエラーを修正しました
  • Fable 5 の初回使用クレジット プロンプトで、リモート コントロール使用時に応答がないと 60 秒後にフォールバック モデルが自動選択される問題を修正しました。
  • ~/.claude.json のキャッシュされたゲストパス報酬が不正な形式だった場合、バックグラウンド エラーが繰り返され、スピナー ヒントが表示されない問題を修正しました。
  • セッションの作業ディレクトリが削除された後、スキルが変更されるたびにエラーが発生する、SDK/VS Code セッションでのスキルのホットリロードを修正しました (2.1.229+)
  • アイドル、リタイア、または起動タイムアウト時に解放された自己ホスト型ランナー セッションが、セッション後のフックが終了する前に別のランナーで再開される場合がある問題を修正しました。
  • iTerm2 で一部のフォント サイズで Clawd マスコットの目と足が不均一にレンダリングされる問題を修正しました
  • 時折発生する暴走セッションの要約を修正しました。要約テキスト (自動および /recap) は 400 文字に制限され、単語の境界でカットされるようになりました。
  • 起動パフォーマンスの向上: セッション カウンターがバックグラウンドで書き込まれるようになりました。
  • 自動モードの改善: 自動モードがアクティブな間、Monitor 許可ルールが脇に置かれるようになりました。そのため、Monitor コマンドは Bash コマンドと同じ方法でレビューされます。
  • Bedrock、Vertex AI、および Foundry での自動モードの改善、およびテレメトリが無効な場合: 分類子は、重大度スコア分類を含む、Claude API と同じデフォルトを使用するようになりました。
  • 自動モードの改善: git ステータス チェックが、リポジトリの status.showUntrackedFiles=no 設定によって騙されてクリーンなツリーを報告することがなくなりました。
  • 最新モデルの名前のみを強調表示するように /model ピッカーを変更しました。そのため、強調表示はリストの任意のサブセットではなく、新しいリリースをマークします。
  • /goal: 長時間実行されるバックグラウンド作業の背後に目標が保留されているアイドル セッションは、ユーザーが戻るのを待たずに、30 分 (その後 1 時間、2 時間) 後に自動的にチェックインされるようになりました。
  • /usage は、チーム メンバーとエンタープライズ メンバーの使用量クレジットの使用行を表示し、使用される前に上限が 0% の行を表示するようになりました。
  • 印刷/SDK モードの SIGTERM は、終了する前に中断されたターンまたは合成ツールの拒否を記録しなくなりました。実行中のコマンドは依然として終了し、プロセスはコード 143 で終了します。
  • スラッシュ コマンドのタイプミスまたはこのセッションでは使用できないコマンドで Enter キーを押すと、最も近いあいまい一致を実行する代わりにそれが報告されるようになりました。プレフィックスとエイリアスは引き続き実行されます
  • リモート コントロールは、CLI が終了するか端末が閉じると、数秒以内にセッションをオフラインとしてマークするようになりました。
  • SendMessage は、rapid バーストがセッションの受信ボックスの許容量を超えると、メッセージがドロップされたときに送信されたことを報告するのではなく、セッションへのそれ以上のメッセージを前もって拒否するようになりました。
  • プロンプト境界上のセッション タイトル チップをフッターの右端に揃えました。
  • 右揃えのフッター項目 (目標インジケーター、セッション状態、バックグラウンド エージェントのステータス) と切り捨てられた通知が、プロンプト領域の残りの部分と一貫した右マージンを共有するようになりました。
  • [VSCode] トランスクリプトのスクリーン リーダー サポートを追加しました: 返信、許可リクエスト、エラー、ステータス変更のライブ アナウンス、およびターンごとの見出しナビゲーション
