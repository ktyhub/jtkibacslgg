claude-code v2.1.248

パッチ 公開日2026年8月27日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.248

何が変わったのか

  • --restricted (または CLAUDE_CODE_RESTRICTED=1) の追加: コマンドまたはコードを実行する組み込みツールと WebFetch (--tools で指定されていない限り) を削除し、ファイル ツールを作業ディレクトリ内に保持し、bypassPermissions を拒否し、ユーザー、プロジェクト、およびローカル設定ファイルを無視します。
  • エージェントのフロントマターに experimental.cacheTtl ("5m" または "1h") を追加しました: サブエージェント TTL 設定が構成されていない場合に使用されるエージェントごとのプロンプト キャッシュ TTL
  • ランナーが登録するラベルをオーバーライドするための claude self-hosted-runner --client-label <label> (または SELF_HOSTED_RUNNER_CLIENT_LABEL) を追加しました (デフォルト: ホスト名)
  • サーバー管理の設定診断の追加: 設定のロードに失敗した場合の起動警告、およびロードの失敗またはフェッチされなかった理由を説明する /doctor および /status 行 (Bedrock/Vertex/サードパーティ プロバイダー、カスタム ANTHROPIC_BASE_URL)
  • GitHub CLI トークンに workflow スコープがない場合、/web-setup に警告を追加しました。これがないと、非常に大きなリポジトリへのプッシュが拒否される可能性があるためです。
  • AWS Marketplace、セルフサービス Enterprise、および Enterprise トライアルを通じて請求される Enterprise 組織向けに /usage-credits を追加しました。これにより、メンバーは管理者に使用制限の引き上げをリクエストできます
  • Bedrock、Vertex、Foundry 上の同じマシン上のセッション間、およびテレメトリが無効な場合のクロスセッション メッセージング (SendMessage / ListAgents) を追加しました。
  • OAuth トークンの更新後にツール定義が再レンダリングされることが原因で、長いセッションでおよそ 1 時間に 1 回発生するプロンプト キャッシュ ミス (および拡張思考コンテキストの損失) を修正しました。
  • アカウントが使用量超過になったときに、セッションとその --resume の間で ScheduleWakeup ツール定義が変更され、再開されたセッションの最初のターンで完全なプロンプト キャッシュ ミスが発生する問題を修正しました。
  • Claude Desktop および Cowork セッションが 30 日後に消える問題を修正しました。トランスクリプトのクリーンアップにより、デスクトップで作成されたセッションがアプリ内にある間も保持されるようになりました (組織のポリシーで保存期間が管理されている場合を除く)。新しい desktopSessionCleanupPeriodDays 設定により免除の上限が設定されます
  • セッショントークンの有効期限が切れている間に別のクロードコードプロセスがトークンリフレッシュロックを保持していた場合にログイン画面に送信される問題を修正しました。リクエストは代わりに再試行可能なエラーで失敗するようになりました
  • Windows: セッションから切断した後、または win32 入力モードのままのターミナル タブで起動した場合に、claude agents リストがキーボードに応答しない問題を修正しました。
  • /login での推奨コンソール サインインが、使用できないマシン (たとえば、ANTHROPIC_API_KEY または API キー ヘルパーが設定されている場合) でサインイン URL を表示する前に OAuth エラーで失敗する問題を修正しました。 API キー サインインに戻ります。
  • /model のモデル名と高速モード スイッチ通知がコードとしてレンダリングされるように修正されたため、[1m] のようなサフィックスはリンクとしてではなく文字通り表示されます。
  • CI 環境変数が設定されている場合に、ワークスペース trust プロンプトをスキップする claude agents を修正しました。
  • PR ステータス キャッシュに不正な形式のエントリが保持されている場合に起動時にクラッシュする claude agents を修正しました
  • マシンがオフになった後、数週間前のバックグラウンド セッションを復活させるエージェント ビューを修正しました。そのようなセッションは実際の終了時に停止したものとして表示され、セッションを開くと、保存された会話を再開する前に尋ねられます。
  • 新しいセッションを開始するときに、エージェント ビューで古い会話が開かれ、入力されたプロンプトがドロップされることがある問題を修正しました
  • 修正 claude agents: 別の端末で既に再開した、停止したセッションを開いても、その会話で 2 番目のプロセスが開始されなくなりました。行はターミナルで開いていることを示しています
  • ワークツリー ブランチがすでにチェックアウトされたデフォルト ブランチ (ローカル main など) にマージされているがまだプッシュされていない場合、セッション (「どこにもプッシュされていないコミットがある」) の削除を拒否する claude agents と claude rm を修正しました。
  • PermissionRequest または PreToolUse フックが無効な回答を出力するときにサイレントに待機するバックグラウンド セッションを修正しました。claude agents 行にはフックとスキーマ エラーの名前が付けられるようになりました。
  • 有効な JSON ではない標準出力 {…} オブジェクトをプレーン テキストとしてサイレントに処理するフックを修正しました。解析メッセージのフックエラーとして報告されるようになりました。
  • trusted "claude.ai" 見出しの下で claude.ai コネクタ タイプを宣言するプロジェクト .mcp.json エントリをリストする /mcp を修正しました。実際のスコープの下に表示されるようになりました
  • 記載されているように、ヘルパーを再実行して呼び出しを再試行する代わりに、headersHelper が Authorization ヘッダーを提供する MCP サーバーが 401 での OAuth 検出に該当する問題を修正しました。
  • 管理設定のセキュリティ承認ダイアログが必要な場合にクロード アプリ ゲートウェイがハングする /login を修正しました
  • apiKeyHelper が唯一の資格情報である場合、ゲートウェイ モデル検出 (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) が実行されない問題を修正しました。
  • claude logs がマウス追跡、括弧で囲まれた貼り付けを放置し、実行元の端末で代替画面がオンになる問題を修正しました。
  • trust ダイアログのリポジトリ許可ルールのリストで、絵文字の途中で長いルールが切り取られた場合に文字化けが表示される問題を修正しました。
  • Ctrl+Cの直後にShift+Tabを押すと、許可モードインジケータが「Ctrl+Cをもう一度押して終了する」ヒントの後ろに隠れたままになる問題を修正しました。
  • /ultrareview およびローカルにシードされたクラウド セッションが、コミットされていない編集を prod.env スタイルおよび *.tfvars ファイル、または認証情報ファイル (key.pem.tmp、id_rsa.swo など) のエディター スワップ、一時、およびバックアップ コピーにアップロードする問題を修正しました。それらはマシン上に残るようになりました
  • CLI がサイレントに再接続された後、リモート コントロール セッションで接続されたデバイスに許可プロンプトや最新のメッセージが表示されないことがある問題を修正しました。
  • コンテナのセッション資格情報がまだ読み取れない場合、クラウド セッションが起動時に失敗することがある問題を修正しました
  • グローバル フラグまたはラッパー挿入オプションがサブコマンドの前にある場合に、claude remote-control が独自のフラグ (例: --spawn、--name) を拒否する問題を修正しました。
  • 残りのトランスクリプトの 1 列右をレンダリングする起動警告 (例: 「N MCP サーバーは認証が必要です」) を修正しました。
  • バックグラウンドのワークツリー セッションがチェックアウトを失う問題を修正しました。バックグラウンド セッションは、実行中にワークツリーのロックを保持するようになったため、クリーンアップと git worktree remove はそのままにしておきます。
  • 非ラテン文字で入力された名前 (IME 経由で入力された韓国語など) と一致しない他のセッションの @ メンションを修正しました。
  • サイレントに無視される無効な crossSessionInbound 値を修正しました。修正されるまで、クロスセッション メッセージ (ユーザー設定) を警告して保持するか、拒否する (管理設定) ようになりました。
  • 組織でコマンドが利用できない場合 (DISABLE_EXTRA_USAGE_COMMAND で非表示になっている場合など)、/usage-credits を実行するように指示するレート制限、使用状況、および高速モードのメッセージを修正しました。
  • [VSCode] セッションが保存されなかった場合にチャット タブが「会話が見つかりません」でスタックする問題を修正しました。代わりに新しい会話が開始されるようになりました
  • ワークフロー ツールのプロンプト フットプリントを改善しました。その説明は 5.7k ではなく約 1k トークンになり、スクリプト作成リファレンスはバンドルされた workflow-authoring スキルに移動されました。
  • プル リクエストが変更されていない間、GitHub をチェックする頻度が低くなるようにプロンプト フッターの PR バッジを改善しました。プッシュまたは gh pr コマンドでもすぐに更新されます
  • 管理対象設定の改善: client-side タイムアウト、MCP スタートアップ モード、およびストリーム ウォッチドッグ環境変数によって、設定承認プロンプトがトリガーされなくなりました。
  • クラウド セッションの開始後に失敗するのではなく、クロード アカウントに接続されている GitHub アカウントがリポジトリにアクセスできることを起動前に確認し、その修正方法を説明するように /ultrareview <PR#> を改善しました。
  • クロスセッションメッセージングの改善: デフォルトのディレクトリが使用できない場合は、ユーザーごとのプライベート /tmp ディレクトリにフォールバックし、修正するディレクトリに通知と /status の名前が付けられます。
  • エージェント ビューのディスパッチ入力で Shift+Enter を変更し、改行を挿入するようにしました (プロンプトと一致)。 Ctrl+Enter でディスパッチしてアタッチできるようになりました
  • /loop の変更: セルフペースのダイナミック モードとプロンプトなしの自律的なデフォルトが、Bedrock/Vertex/Foundry を含め常に利用可能になりました。
  • Anthropic テレメトリのエクスポートの失敗を、[3P telemetry] OTEL diag error ではなく [Anthropic telemetry] としてデバッグ レベルでログに記録するように変更しました。これにより、OTel コレクターの失敗と間違われなくなります。
  • Linux ユーザー名前空間でのクロスセッション メッセージングの変更: マップされていない所有者のルートに相当する trust は、正規のシステム ディレクトリに限定されます
  • SendMessage をサブエージェントから別のセッションに変更しました。その結果、応答はサブエージェントではなく親セッションの会話に配信されることがわかります。
