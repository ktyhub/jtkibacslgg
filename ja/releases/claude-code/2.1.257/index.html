claude-code v2.1.257

パッチ 公開日2026年9月1日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.257

何が変わったのか

  • クロード フェイブル 5.1 (claude-fable-5-1) を追加しました。デフォルトのフェイブル モデルになりました - 1M コンテキスト、$0.25/Mtok キャッシュ読み取りで Mtok あたり $10/$50
  • 「時刻形式」(timeFormat) および timeZone 設定を追加しました: 12 時間制、24 時間制、24 時間制 UTC、またはターンエンド クロックとトランスクリプト ビューのタイムスタンプの strftime パターン
  • 自動モードに Containment Escape ルールを追加しました。これにより、環境で期待済みとマークされない限り、クラウド メタデータ認証情報の取得、下り回避、およびクロステナント リーチが自動承認されなくなりました。
  • CLAUDE_CODE_SUBAGENT_MODEL (またはメイン モデル) をすべてのサブエージェントに適用するための CLAUDE_CODE_SUBAGENT_MODEL_FORCE を追加し、スポーンごとおよびエージェント定義モデルのオーバーライドを無視しました。
  • /model と一致するように、現在のセッションのみの作業量を変更するために /effort に s を追加しました。
  • 強制終了されたセッションによって残された古いサンドボックス マスク ファイルに対する /doctor 警告を追加しました
  • 作業ディレクトリ外で最初のファイルが読み取られる前に自動モードで 1 回限りのプロンプトを追加し、そのような読み取りをブロックするオプションを追加しました (permissions.blockReadsOutsideWorkingDirectories)
  • 検出された /model ピッカー エントリ (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) でのゲートウェイ提供の description のサポートを追加しました。何もないエントリでも「ゲートウェイから」と読み取られます
  • 起動後に作成された.claude/フォルダー内の設定が再起動するまで取得されない問題を修正
  • ← で開かれたエージェント ビューからディスパッチされたセッションが常に元のセッションの許可モードで開始され、ターゲット ディレクトリの defaultMode とエージェントの permissionMode をオーバーライドする問題を修正しました。
  • claude agents で無視される Ctrl+G の keybindings.json リバインドを修正しました。 Ctrl+S / Ctrl+T は新しい Agents コンテキストを介して再バインド可能になりました
  • 自己更新中に macOS npm インストールでバックグラウンド セッションを開始できない問題と、Windows で古いデーモン ロック ファイルが再利用されたプロセス ID を指している場合にバックグラウンド セッションが開始できない問題を修正しました。
  • スラッシュ コマンド パネルの背後で応答が流れているときに動作中のスピナーが停止する問題を修正しました
  • スケジュールされたウェイクアップ後にバックグラウンド セッションの state.json detail が独自のディスパッチ プロンプトを繰り返す問題を修正しました。
  • claude agents が再プロンプトしたバックグラウンド セッションが再度終了した後も完了状態に埋もれたままになる問題を修正しました。最新の仕上げにより現在注文が完了しています
  • 削除されたばかりのディレクトリから「バックグラウンド」と報告され、クラッシュしたセッション行が残る claude --bg を修正しました。理由を出力して終了します 1
  • セッション中に接続しているリモート コントロールが Bash ツール定義を再送信し、プロンプト キャッシュ ミスを引き起こす問題を修正しました。
  • Bedrock、Mantle、Vertex、および WIF で構成された資格情報をオーバーライドする二重リストされたカスタム Authorization ヘッダーと、残りの Anthropic プロファイルを ~/.config/anthropic から選択する Vertex セットアップ ウィザードを修正しました。
  • ANTHROPIC_FOUNDRY_API_KEY が設定されている場合、Claude アプリ ゲートウェイが野良ホスト Authorization またはプロファイル ヘッダーを Foundry、Vertex、Bedrock に送信し、Foundry Entra ID アップストリームが起動しない問題を修正
  • API キー モードで、Foundry サブスクリプション キーと一緒に送信される残りの Anthropic API キーまたは認証トークンを修正しました
  • プロンプトがメッセージ ロールなしで保存され、何もせずに実行される /schedule ルーチンを修正しました
  • claude agents が、バックグラウンド セッションが別のセッションからのメッセージの承認を待っていること、またはメッセージの送信者を待機していることを示さない問題を修正しました。
  • 開いているバックグラウンド セッション内で Ctrl+S を押して隠したプロンプトが、セッションがアイドル状態になったとき、またはセッションが停止されてから再度開かれたときに失われる問題を修正しました。
  • デスクトップ アプリのコード セッションを含むウォーム スタート時にサーバー管理の設定を介してプッシュされたテレメトリ (OTEL) 設定が無視される問題を修正
  • リーダーのメールボックスへの書き込みが一時的にロックされているときに、チームメイトの許可リクエストが 2 回応答される問題を修正しました
  • コマンドの自動継続応答のストリーミング中に、実行中のターンの下に表示されるファントムの重複したスラッシュ コマンド行を修正しました
  • policyHelper timeoutMs および refreshIntervalMs の値がタイマーの最大値 (2147483647) を超えると、ミリ秒ごとに失敗または再実行が発生する問題を修正しました。彼らは今締め付けられている
  • 別のサブエージェントのトランスクリプトに切り替えた後のトークンカウンターのフリーズまたはクロールを修正し、応答ストリーム中にバックグラウンドのサブエージェントとチームメイトのカウンターがライブで更新されるようにしました
  • 末尾にドットが付いているサンドボックス ネットワーク ホスト (example.com.) を修正しました。deniedDomains エントリはサンドボックス内のホストをブロックせず、そのようなホストに対して「再度尋ねないでください」というプロンプトが表示され続けました。
  • リモート コントロールの同意プロンプト (Esc、または claude remote-control での n) を同意としてカウントして閉じる問題を修正しました。これにより、次のリクエストが質問なしで接続されるようになりました。
  • /mcp の再接続を修正し、起動後に管理対象 MCP 許可/拒否リストまたは strictPluginOnlyCustomization がロードする必要がある設定ファイル MCP サーバーへの接続を有効にします。
  • strictPluginOnlyCustomization が MCP をプラグイン専用サーバーにロックするときに、リモート サーバーに保存されている OAuth 資格情報が残る claude mcp remove を修正しました。
  • クロード アプリから開始されたリモート コントロール (claude remote-control) セッションが選択されたモデルを無視し、代わりにマシンのデフォルトで実行される問題を修正しました。
  • allowManagedPermissionRulesOnly が有効な場合、最初の設定のリロード後に --disallowedTools とセッション拒否ルールが削除される問題を修正
  • --resume がバックグラウンドでの会話を 2 回リストし、--continue が停止したバックグラウンド前のコピーを再度開く問題を修正しました。 --continue は終了したバックグラウンド セッションも開くようになりました
  • 全画面モードで click ! シェル コマンド出力を展開できない問題を修正しました
  • 古いクロード コード バイナリを実行したままになっているバックグラウンド セッションが、廃止されるのではなく、自動更新中に積み重なってしまう問題を修正しました。
  • claude agents --json が端末を raw モードに一時的に切り替え、終了時に別のプログラムの端末設定を元に戻す問題を修正しました
  • プロアクティブ出力スタイルのセッションが開始されたバックグラウンド コマンドまたはモニターがまだ実行されている間、アイドリングではなくフィラー メッセージと繰り返しのログ読み取りでビジー ループになる問題を修正しました。
  • コンピュータのスリープ、接続の切断、またはサーバー エラーによって応答が途中で切断された場合にサブエージェントが停止する問題を修正しました。不完全な応答で終了するのではなく、自動的に続行されるようになりました。
  • claude agents セッション内の /btw パネルで ← が何もしない問題を修正しました。エージェント リストに戻り (応答中であっても)、セッションを再度開くとパネルが戻るようになりました。
  • バックグラウンド要求 (コンパクション、/recap、プロンプト提案) でプロンプト キャッシュが欠落し、毎回完全な会話がキャッシュされずに再送信されるアドバイザー モデル セットのセッションを修正しました。
  • モデルが武装したモニターがまだ実行されている間に、最終結果の約 5 秒後に claude -p が終了する問題を修正しました。時計が起動するかタイムアウトになるのを待ちます
  • 一致するコマンドが複合コマンドまたはサブシェル内で実行された場合に自動モードでスキップされる permissions.ask ルールを修正し、確認プロンプトなしで実行できるようにしました
  • 宣言されたコマンド、エージェント、スキル、フック、またはシンボリックリンクであるその他のコンポーネント パスを介して、プラグインが独自のディレクトリの外にあるファイルを読み取ることができる問題を修正しました。そのようなパスはエラーで拒否されるようになりました
  • 現在の作業ディレクトリ内のディレクトリを拒否する /add-dir を修正しました。 --add-dir が起動時に行うのと同様に、そのディレクトリのスキル、コマンド、エージェントが読み込まれるようになりました。
  • トランスクリプトビューから停止したサブエージェントを再開するときにメインエージェントに通知されない問題を修正
  • ANSI カラーのテキスト (CI ログなど) を /feedback のようなダイアログに貼り付けるときのクラッシュを修正しました
  • プロジェクトの .mcp.json が FIFO またはデバイス ファイルのシンボリック リンクである場合に、claude mcp add/remove がハングしたりメモリを使い果たしたりする問題を修正しました。すぐに失敗し、実用的なメッセージが表示されるようになりました
  • 非 JSONL データが claude -p --input-format stream-json にパイプされるときの無制限のメモリ増加を修正しました。明らかなエラーが発生してすぐに失敗するようになりました
  • サブエージェントまたは他のツールの実行中にターンをバックグラウンドで実行する (← または Ctrl+B) 問題を修正し、バックグラウンド セッションでそのツールが再実行されずに拒否されたものとして扱われる場合がありました。
  • < file リダイレクトや tac や egrep などのリーダー コマンドに適用されない Bash Read()/Edit() 拒否ルールを修正しました。引数またはリダイレクト ターゲットの拒否ルールがコマンドを拒否するようになりました。
  • トランスクリプトが 5 MB を超えたサブエージェントの再開またはメッセージング (たとえば、多くの画像を読み取った後) が「トランスクリプトが見つかりません」で失敗する問題を修正しました。
  • 「複雑すぎてワークツリー内に留まっていることを確認できない」ため、Git に触れることのない Bash ループ、$VAR 読み取り、"$(…)" およびヒアドキュメントを拒否するワークツリー分離セッションを修正しました。
  • 会話を空に巻き戻した後にプロンプトキャッシュの警告が表示される /model と /effort を修正しました
  • 画像がリクエストごとのサイズの上限を超えた場合、スクリーンショットを大量に使用する長いセッションで毎ターンのプロンプトキャッシュミスを修正しました
  • 編集権限プロンプトの差分表示で絵文字とマルチコードポイント文字が間違った幅で表示される問題を修正しました。
  • WebSocket MCP サーバー接続エラーが、根本的なエラーではなく「[object ErrorEvent]」としてログに記録される問題を修正しました。
  • 別のクロード コード プロセスが npm アップデートをダウンロードしているときに、「バックグラウンド サービスを開始できませんでした」というメッセージが表示されてバックグラウンド セッションを開くことができない問題を修正しました。スタートは今それを待っています
  • タスク停止またはクロード コードの終了後もシェルから切り離されるバックグラウンド コマンド (たとえば、timeout または setsid の下) を修正しました。
  • タスクパネルまたは接続されたclientからバックグラウンドコマンドを停止したときにクロードに通知されない問題を修正
  • モニターを実行したままバックグラウンド サブエージェントを停止する問題を修正
  • cd をサブディレクトリに移動した後、リンクされたワークツリー内のサンドボックス化された git コマンドがリポジトリの共通 .git ディレクトリへの書き込みアクセスを失う問題を修正しました。
  • Opus 4.7 以降の長い隠れ思考フェーズ中に Bedrock および Bedrock Mantle リクエストが沈黙し、アイドル タイムアウトにより接続が切断される問題を修正しました。ストリームは進行状況イベントを伝送するようになりました
  • クロード アプリ ゲートウェイの有効期限が切れた後、またはセッションが取り消された後のクロード コードの起動を修正しました。ネットワーク エラーを報告する代わりに、セッションが終了したと表示され、/login が提供されるようになりました。
  • セッションのネットワーク プロキシが起動時に開始できなかった場合、クラウド セッションで残りのセッションの git/GitHub 資格情報が失われる問題を修正しました。バックグラウンドで再試行され、回復するようになりました
  • バックグラウンド デーモンの起動が中断された後、システムの一時ディレクトリに残った cc-daemon-* フォルダーを修正しました。 cleanupPeriodDays 保持スイープによりそれらが削除されるようになりました
  • zsh が bash とは異なる方法で解析する特定の [[ ]] 条件を自動承認する Bash 権限チェックを修正しました。これらのコマンドは承認を求めるようになりました
  • 設定で詳細なトレースや生の API 本体のログがオフになっている場合、またはトレースのエクスポートがオンになっている場合に、テレメトリの文言ではなく一般的な警告が表示される管理設定の承認プロンプトを修正しました。
  • シャットダウン要求を承認した後、tmux/iTerm2 ペインのエージェント チームのチームメイトが開いたままになることがある問題を修正
  • キーレス コンソール サインイン (「コンソール アカウントでサインイン」) が組織のサーバー管理設定を適用しない問題と、/status にそのサインインの組織が表示されない問題を修正しました。
  • レンダリング パフォーマンスの向上: 長い会話でのターンごとの再レンダリング作業が減り、返信が増えてもストリーミングが遅くなることはなくなり、バックグラウンド エージェントの更新によって画面全体が再レンダリングされることはなくなりました。
  • キーストロークごとのレンダリング作業を削減することにより、プロンプト入力の応答性が向上しました。
  • ポリシー ヘルパー診断の改善 — 更新の失敗が /status で表示されるようになり、管理設定ダイアログを cli で実行すると、クロード コードが終了した理由が表示され、ヘルパー タイムアウトはタイムアウトとして報告されます。
  • ターゲットをサポートされていないとして報告するのではなく、glab mr note 経由で GitLab マージ リクエストの結果を投稿するように /code-review --comment を改善しました。
  • 通知の改善: 別のダイアログの下にキューに入れられた MCP の引き出しまたは許可の要求は、表示される要求と同じ遅延でアイドル状態のデスクトップ通知を送信するようになりました。
  • 詳細/トランスクリプト出力の改善: 一緒に到着する非同期フック完了通知が、フックごとに 1 行ではなく 1 行で表示されるようになりました。
  • git プッシュ ネゴシエーションも有効にするように claude self-hosted-runner --configure-git を改善しました。そのため、古いクローンからの新しいブランチの最初のプッシュでは、ツリー全体ではなく新しいコミットのみがアップロードされます。
  • 応答がゲートウェイ キープアライブによってオープンに保持されている間、SDK ホストへの活性レポートが改善されました。これにより、発生した CLAUDE_STREAM_IDLE_TIMEOUT_MS での長時間の待機がハング セッションと誤認されなくなります。
  • MCP 接続と OAuth デバッグ/エラー ログが改善され、サーバーの URL またはリクエスト ヘッダーに含まれる認証情報が編集されるようになりました。
  • 元の会話のプロンプト キャッシュを新しいバックグラウンド セッションに保持するように /fork を改善しました。そのワークツリー ブリーフィングは、システム プロンプトの変更ではなくメッセージとして届くようになりました。
  • 残りの GitHub/Slack ショートコード エイリアス (:satisfied:、:telephone:、:collision: など) を受け入れるように絵文字オートコンプリートを改善しました。
  • 新しいモデルのデフォルト エフォート ホールドを永続的にではなく、そのセッションに対してのみ解除するように --effort を変更しました。リモート コントロール セッション用に claude.ai で選択された作業が保留中に適用されるようになりました
  • キャッシュされたサーバー管理設定によって起動時にシャドウされた MDM の policyHelper または managed-settings.json を、次回の起動時ではなく、フェッチによって削除されたことが報告されるとすぐに実行 (または終了) するように変更しました。
  • ソースの値を結合するのではなく、sandbox.credentials.awsPairs と sandbox.ripgrep を設定する最上位の管理ソースから全体を取得するように managedSourcesBehavior: "merge" を変更しました。
  • ゲートウェイ モデル検出 (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1) は、ゲートウェイを照会するだけなので、CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC が設定されている場合でも実行されるように変更されました。
  • 何も実行されていないときにコピーをサイレントに開始するのではなく、独自の ID でセッションを継続するように claude --resume <session-id> --bg を変更しました。コピーが発表されました
  • /btw 履歴の閲覧を ←/→ から Shift+←/Shift+→ (または [/]) に変更し、最近の補足質問をステップスルーしてライブ回答に戻ります。
  • .claude/settings.json または .claude/settings.local.json の defaultMode: "bypassPermissions" を、"auto" のように無視されるように変更しました。ユーザー設定または管理対象設定で設定するか、--permission-mode を渡します
  • まだ Fable 5.1 用に構成されていないゲートウェイが拒否するため、Claude アプリ ゲートウェイ セッションの fable と best を変更して、現時点では Fable 5 に解決し続けるようにしました。 /modelでFable 5.1を選択して使用します
  • --add-dir、/add-dir、additionalDirectories を変更し、ネットワーク パス (UNC 共有、/net/<host> 自動マウント) にアクセスする前にメッセージを表示して拒否するようにしました。 Windows では、マップされたドライブ文字を使用します
  • 管理対象設定のフェッチがすでに行っているように、ゲートウェイのピン留めされた TLS 証明書を検証するために、クロード アプリ ゲートウェイのサインインおよびトークン更新リクエストを変更しました。
  • Cowork と claude.ai のクラウド セッションを変更しました。自分のものではないアーティファクトを読み取ると、自動モードであっても常に最初に尋ねられるようになりました。
  • Bash および PowerShell の権限プロンプトでの Ctrl+E コマンドの説明を削除しました。
  • [VSCode] セッション リスト パネルに折りたたみ可能な ACCOUNT & USAGE および SESSION MANAGER セクション ヘッダーを追加し、アカウントの電子メール、使用量メーター、および使用量ダイアログを開く詳細の表示リンクを追加しました。
  • [VSCode] 現在のモデルを表示し、工数行と「その他のモデル」ページを備えたモデル ピッカーを開く入力フッターにモデル ピルを追加しました。
  • [VSCode] セッション リストの [グループ化されていない] セクションに折りたたみトグルを追加しました。
  • [VSCode] カスタム スタイルを含む出力スタイルの選択をコマンド メニューに追加しました
  • [VSCode] サードパーティ プロバイダーのデプロイメント (Bedrock、Vertex など) で依然として claude.ai のみの機能 (リモート セッション、ディクテーション、使用法) が表示され、残ったログインで claude.ai を呼び出す問題を修正しました。
  • [VSCode] パネルがロードされた後、セッション リスト パネルの使用量メーターが空白のままになる問題を修正しました。最新の既知の使用法がすぐに表示されるようになりました
  • [VSCode] 「すべてのセッションでリモート コントロールを有効にする」トグルを修正し、オンまたはオフにすることは、新しいセッションだけでなく、すでに開いているセッションにも適用されるようにしました。
  • [VSCode] スクリーン リーダーのアナウンスを修正しました。フェンスまたは見出しの前の制御文字が音声から目に見える行を削除しなくなり、見出しにまたがる太字のマーカーが誤ってペアリングされなくなりました。
  • [VSCode] インラインではなくフィルター可能な「スラッシュ コマンド」ダイアログにスラッシュ コマンドをリストするようにアクション メニューを変更しました。どれかを選択すると実行されます。 MCP サーバーダイアログに同じフィルターボックスが追加されました
  • [VSCode] 「セッションの削除」を「セッションのアーカイブ」に変更しました。アーカイブされたセッションは、アーカイブ解除アクションを使用して、リストの下部にある折りたたみ可能な「アーカイブ セッション」グループに移動します。
