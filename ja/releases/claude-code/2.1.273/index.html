claude-code v2.1.273

パッチ 公開日2026年9月15日 出典anthropics/claude-code 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.273

何が変わったのか

  • LLM ゲートウェイ用に x-claude-code-request-class、x-claude-code-agent-type、x-claude-code-prev-tool-durations、x-claude-code-compaction、x-claude-code-context-compacted リクエスト ヘッダーを追加しました。 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 でオプトイン
  • MCP サーバーがセッション中に切断され、自動再接続が断念された場合に、/mcp を指す通知を追加しました。
  • クロード アプリから claude --remote-control または /remote-control で開始されたセッションのフォークを追加しました。フォークはコンピュータ上でバックグラウンド セッションとして実行されます
  • 権限チェッカーが permissions.blockReadsOutsideWorkingDirectories の下のプロンプトをスキップして完全に分析できない Bash コマンドと、バイパス モードで危険な rm を隠すサブシェルを修正しました
  • 組織がスキルをオフにした後も、claude.ai から同期されたスキルが利用可能なままになる問題を修正しました。それらは回復可能なゴミ箱に移動されるようになりました
  • サーバー管理の設定も存在する場合、MDM または managed-settings.json 経由で設定された allowManagedMcpServersOnly、deniedMcpServers、disableClaudeAiConnectors が無視される問題を修正
  • Bedrock、Vertex、Foundry、および Claude アプリ ゲートウェイ 403 で /login を実行するように指示する 401/403 エラーを修正しました。メッセージには、更新する資格情報の名前が表示されるか、ゲートウェイ管理者が示されます。
  • /login、/upgrade、/extra-usage が会話から以前の考えを破棄し、次のリクエストで完全なプロンプト キャッシュの書き換えが強制される問題を修正しました。
  • クラウドまたはリモート コントロール セッションでチャットに添付したファイルをアーティファクト ツールがアップロードするときに承認のために自動モードが停止する問題を修正しました。
  • リポジトリの .git ディレクトリが削除または移動された後、スタブ .git/info/exclude を再作成する長時間実行セッションを修正しました。
  • すでにシェルモードになっているときに最初に入力された ! を削除するメインプロンプトを修正し、! grep … のような否定されたコマンドを入力できるようにしました
  • macOS での読み取りが、ドラッグインされたスクリーンショット、またはシステムが 2 番目のパスで報告するファイルを拒否し、「許可がチェックされた後にシンボリックリンクの解像度が変更されました」を修正しました。
  • permissions.blockReadsOutsideWorkingDirectories を修正: リポジトリの設定によって選択されたメモリ ディレクトリは、プロンプトに読み込まれたり、呼び出されたり、インデックスが作成されたり、メモリ抽出で使用されなくなりました。
  • 最終的なストリーミング応答でトークンの使用が省略されているか、モデル ID が含まれていない場合、サブエージェントとバックグラウンド エージェントが失敗として報告され、結果が配信されない問題を修正しました。
  • コンテキスト メーターと自動コンパクト カウンティング アドバイザ ツールが実際のコンテキスト サイズの約 2 倍で回転する問題を修正しました。これにより、自動コンパクトが実際のウィンドウの約半分で起動するようになりました。
  • エージェントチームのチームメイトがすでに作業を終えており、エージェントパネルに表示されなくなったため、/tuiが再起動を拒否する問題を修正
  • .claude/scheduled_tasks.json が新しいワークツリーなどの別のフォルダーにコピーされた後、保存されたスケジュールされたタスクが間違ったセッションで実行される問題を修正しました。
  • 実行中にサブエージェントがバックグラウンドに移動された後 (例: CLAUDE_AUTO_BACKGROUND_TASKS)、サブエージェントの残りのメッセージと最終レポートがドロップされる SDK および --output-format stream-json 出力を修正しました。
  • SAML シングル サインオン ブロックを「管理者権限が必要」として報告する /install-github-app を修正しました
  • Claude Desktop、VS Code、または JetBrains セッションに接続されたリモート コントロール clients が、セッションのコンテキスト ウィンドウの使用を要求すると拒否される問題を修正しました。
  • 「PreCompact フックを実行中…」などの圧縮ステータス行に二重省略記号 (「……」) が表示されるスピナーを修正しました。
  • アーティファクトの読み取りまたは公開後にフロントエンド設計プラグインを示唆する誤検知のスピナー ヒントを修正しました
  • 権限チェッカーが分析できない Bash 行の読み取りおよび編集拒否ルールをチェックする 2.1.268 の変更を元に戻しました (eval、env -C)。 time -p make build のようなコマンドは拒否されずに再度プロンプトを表示します
  • 長いセッションでの応答性の向上: フックの進行状況とサブエージェントのアクティビティが更新のたびに会話全体を再処理することがなくなりました。
  • パブリッシュにアーティファクトが提供されないファイル タイプが含まれている場合のアーティファクト ツールのエラーを改善しました。クロードにはどのタイプが提供され、代わりに何をすべきかが通知され、ターミナルには 1 つのプレーンな行が表示されます。
  • アーティファクト ツールのページ読み取りを改善し、アーティファクト サービスがそのページに対して保持する機能とデータベース ルールを、公開できるすべてのユーザーに対して説明できるようにしました。
  • アーティファクト データベースの書き込みの改善: 更新により、ドキュメント全体を書き換えるのではなく、単一のフィールドを削除できるようになりました。
  • アーティファクトのパブリッシングの改善: claude.ai に到達した後に接続が切断されたパブリッシュは、失敗したり重複バージョンが作成されたりすることなく、安全に再送信されるようになりました。
  • IP 許可リスト、アプリのインストールの一時停止、または SAML シングル サインオンのクラウド セッション GitHub エラーを改善し、一般的なインストール ヒントの代わりに原因を表示するようにしました。
  • /autofix-pr の改善: gh pr view が失敗すると、一般的な終了コード行の代わりに gh 独自のエラー (サインイン、SAML、レート制限) が表示されるようになりました。
  • 一般的な警告ではなく、PR に対して GitHub Webhook 配信を設定できなかった理由 (リンクされた GitHub アカウントがないなど) を示す /autofix-pr を改善しました。
  • /web-setup エラーの改善: 拒否された GitHub トークンには考えられる理由と修正がリストされ、接続失敗には構成されたプロキシまたは TLS 証明書の問題が示されるようになりました。
  • セッション内 SSL 証明書とプロキシ接続エラーを改善し、エラー コードと修正対象を指定しました (untrusted 企業 CA の NODE_EXTRA_CA_CERTS など)。
  • クロード ログインの有効期限が切れたか取り消されたためにクラウド セッションを作成できない場合のエラーを改善しました。/login を実行するように指示されるようになりました。
  • MCP サーバーのサインインがセッション中に期限切れになったときに表示される、再認証方法を示すエラーを改善しました (/mcp)
  • Bedrock、Vertex、Foundry の自動モードを変更し、現時点ではデフォルトでローカル分類子を使用するようにしました。プラットフォームのサーバー側分類子を使用するように CLAUDE_CODE_AUTO_MODE_SERVER=1 を設定します
  • コストとトークンのメトリクスに実際のエージェント、スキル、プラグイン、MCP サーバー名も含めるように OTEL_LOG_TOOL_DETAILS=1 を変更しました。
  • Claude アカウントでのサインインを変更し、claude.ai プラグインへのアクセスも要求するようにしました。
  • 最後の API リクエストからのモデル動作パラメータ (モデル、システム プロンプト、ツール) のみを含むように /bug レポートと /feedback レポートを変更し、リクエスト メタデータと CLAUDE_CODE_EXTRA_BODY フィールドを省略しました。
  • [VSCode] 製品フィードバックが無効になっている組織に対して、「問題を報告」がまだ表示され、/bug / /feedback がレポート フォームを開く問題を修正しました。
  • [VSCode] Windows の電源投入が完了した後に表示される赤い「Claude Code process exited with code 4294967295」バナーを修正しました。
  • Windows: マップされたネットワーク ドライブが --add-dir で追加されたときの UNC パスのネットワーク パス許可チェックを改善しました。
  • [Claude Code on the web] 管理者が組織コネクタを削除して再度追加した後も、組織コネクタへのアクセスが失われ、古いコネクタを呼び出し続けるルーチンを修正しました。
  • [Claude Code on the web] 組織の設定からセルフホスト環境を作成するとサーバー エラーで失敗し、作成途中の環境が残る問題を修正しました。
  • [ウェブ上のクロード コード] 管理者の「クラウド セッションの共有」設定を、クロード コード ページではなくデータとプライバシーの下に表示されるように変更しました。データとプライバシーの管理者も管理できるようになりました。
  • [Claude Code on the web] 「保存されていない変更を破棄しますか?」を追加しました。 [新しいルーチン] ページまたは [ルーチンの編集] ダイアログの前に確認すると、入力したルーチン名、プロンプト、または編集内容が破棄されます。
  • [Claude Code on the web] クラウド環境を持たない新規ユーザーが Mac および Windows で表示するフルページのデスクトップ アプリ ダウンロード画面を削除しました。すぐにセットアップに進みます
  • [Web 上の Claude Code] ルーチンの詳細ページを改善しました: ブレッドクラムのメニューと名前変更、上部のオン/オフ スイッチと今すぐ実行、ルーチンの設定の横にある実行履歴
  • [Claude Tag] Enterprise Grid が切断されたがワークスペースの 1 つが接続されたままの場合、アプリを再インストールした後、Claude が数分間沈黙する問題を修正しました。
  • [Claude Tag] 組織共有のプライベート Slack チャネルに設定されたスケジュールされたタスクがサイレントに投稿されない問題を修正しました。彼らは現在、作成されたスレッドで実行され続けています
  • [Claude Tag] クロードがタスクの途中で古い Slack スレッドに返信すると、スレッドが最初から再起動され、まだプッシュされていない作業が失われる場合がある問題を修正しました。
  • [Claude Tag] アカウントトークンが更新された直後に、Claude が誤った「Claude Code 環境が見つかりませんでした」という通知を含むメッセージを時々ドロップする問題を修正しました。
  • [Claude Tag] 予算、貯蓄プラン、WAF クラシック、インポート/エクスポートなどのリージョンのないエンドポイントを拒否する AWS 接続を修正しました。 Global Accelerator リクエストが正しく署名されるようになりました
  • [Claude Tag] AWS 接続エラーの改善: リージョンのないホスト名など、リクエストに署名できない場合、単純なエラーではなく、その理由と修正方法がクロードに通知されます。
  • [Claude Tag] 小文字のトークン タイプを返すプロバイダーで失敗する OAuth client-credentials および JWT-bearer 接続を修正しました。リクエストは標準ベアラー スキームを送信するようになりました
  • [Claude Tag] Enterprise Grid 共有チャネル、Claude がまだ使用されていないチャネル、従来のプライベート チャネルでチャネル マネージャーの追加が拒否される問題を修正しました。
  • [Claude Tag] クロードが、要求されたときだけではなく、会話が依存するインシデント チャネルなど、関連するパブリック チャネルを単独で視聴し始めるように変更しました。
  • [Claude Tag] 管理者のメモリページに、メモリを保存している場合でもクロードが独自に設定した Slack チャンネルが表示されない問題を修正しました。管理者はそのメモリを開いて、編集、削除できるようになりました
  • [コードレビュー] 以前のレビューで「追加の発見」がリストされていた PR にベース ブランチをマージすると、完全な再レビューがトリガーされる問題を修正しました。これらのプッシュは、より軽いフォローアップレビューを受けるようになりました
  • [コード レビュー] @ メンション、コード スパンが複数行に折り返されている、またはバックティックされた HTML タグが原因で REVIEW.md 全体が無視される問題を修正しました。変更されたファイルにリンクする行のみが保留されます
  • [コードレビュー] 他のコードが変更される動作に依存している場合に、修正が機能し続ける必要があることを示す修正提案を改善しました。
  • [コード レビュー] 影響を受ける 2 番目の場所を指摘するレビュー コメントを改善し、その場所の問題を切り捨てられたスタブではなく完全な文で説明するようにしました。
  • [コード レビュー] /ultrareview --post を修正し、GitHub エラー後の再試行で結果コメントが 1 回または 2 回投稿されるのではなく、正確に 1 回投稿されるようになりました。コメントにはレビュー済みのコミットの名前が付けられます
  • [コードレビュー] 所有者または名前に capital 文字が含まれる GitHub リポジトリで、空のプッシュまたは内容が同一のプッシュが再レビューされる問題を修正しました。これらのプッシュはスキップされるようになりました
