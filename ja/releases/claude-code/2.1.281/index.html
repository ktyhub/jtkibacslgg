claude-code v2.1.281

クロードコード v2.1.281

何が変わったのか

  • blockReadsOutsideWorkingDirectories および disableBypassPermissionsMode を含む、desktop ポリシー ブロックの新しいクロード デスクトップ キーに対するクロード アプリ ゲートウェイのサポートを追加しました。
  • クロード アプリ ゲートウェイの Bedrock アップストリームに assume_role を追加しました。ゲートウェイは、必要に応じて別の AWS アカウントで、STS を通じて引き受ける IAM ロールとして Bedrock を呼び出します。オプションで開発者ごとに 1 つのセッションを実行します。
  • クロード アプリ ゲートウェイの Bedrock アップストリームに guardrail: {id, version} を追加し、Amazon Bedrock ガードレールを経由して送信されるすべてのリクエストに適用します (すべての Bedrock アップストリームに設定するか、何も設定しません)
  • クロード デスクトップおよび /login セッションのテレメトリに固定ラベルを付けるために、telemetry.resource_attributes をクロード アプリ ゲートウェイ構成に追加しました
  • すべてのコミットと PR 属性を非表示にするために settings.json に "attribution": false を追加しました。古い CLI バージョンは、それを保持する設定ファイルをスキップするため、バージョン間で共有されるファイルにオブジェクト形式を保持します。
  • 2026 年 7 月 28 日のプロトコル接続に MCP URL モードの引き出しを追加したため、サーバーはクロード コードにブラウザベースのフローを開くように要求できます。サーバーが完了を確認する方法がない場合、待機中のダイアログは画面上に残されません。
  • MCP サーバー チェックを claude plugin validate に追加しました。ロード時にサイレントに削除される .mcp.json エントリ、宣言されていない ${user_config.*} 参照、および安全でない URL を報告します。
  • 最近のセッションで自動モードが処理できる許可プロンプトの数を推定する自動モードの推奨事項を /insights に追加しました
  • /skills、/mcp、/plugin のインストール済みリストに、/workflows のような全画面モードのスクロールバーを追加しました。スクロールバーは、マウスがリスト上にあるときに表示され、cli クリックまたはドラッグできます。
  • API リクエストの再試行中にセッションが終了する可能性があるクラッシュ (「回復不能なインターフェイス エラー」) を修正しました
  • モデルが解析不可能なツール呼び出しと出力制限の切り捨てを交互に実行したときに、--max-turns を無視して無限に再試行できる可能性があるターンを修正しました
  • 再開されたセッションが以前のターンを変更された形式 (並列ツール呼び出しターン、サーバーが再接続中の MCP ツール呼び出しの入力またはツール検索結果、または読み込みターンが中断されたツール検索結果) で再送信する問題を修正しました。これにより、API が会話の前の推論をドロップする可能性がありました。
  • 非常に大規模なセッションを再開すると、最後の数メッセージのみが復元される場合がある問題を修正しました
  • 保留中の許可プロンプト中に再起動後にセッションが再開され、以前とは異なる履歴が送信され、その時点からプロンプトのキャッシュが壊れる問題を修正しました。
  • ツール呼び出し中に終了したセッションの再開を修正しました。クロードは呼び出しを確認し、その結果は不明であると言われるようになり、手動で再開しても非表示の「続行」メッセージが追加されなくなりました。
  • 以前のアドバイザーとのセッションの結果、API が毎ターン失敗する 1 つのリクエストを読み取れなくなり、以前の推論が繰り返し失われる問題を修正しました。歴史は一度修復されました
  • ツール検索がオフになっている間 (たとえば、プロキシやゲートウェイの背後にある場合)、MCP サーバーが会話中に切断した場合、または再開後にまだ接続している場合にプロンプト キャッシュが失われる問題を修正しました。
  • 警告なしで完了としてストリームを正常に閉じるプロキシまたはゲートウェイによって応答が短縮され、重複したストリーム イベントでツール呼び出しが 2 回実行される問題を修正しました。
  • プロキシが応答中にストリーム イベントをドロップすると、「コンテンツ ブロックが見つかりません」というエラーで応答が失敗する問題を修正しました。部分的な応答が保持されるようになり、Web 検索ではすでに到着した結果が保持されます。
  • ストリームの最終イベントの前に接続が切断されたときに、空の完了応答が 2 回要求される問題を修正しました
  • プロキシが後続の使用専用フレームを送信すると停止理由が失われる問題を修正しました
  • 最初の 5xx で失敗する CLAUDE_CODE_RETRY_WATCHDOG セッション、または 429/529 待機の実行後に接続が切断される問題、および 5xx からの長い Retry-After で上限なしでサイレントにスリープする問題を修正しました。
  • サーバーが Retry-After: 0 を送信したときに、高速モードでレート制限されたリクエストを連続して再試行する問題を修正しました。
  • 兄弟ツールの呼び出しが応答されずに実行されたままになったり、最終メッセージが表示されずにターンが終了したりする特大の画像を返すツールを修正しました
  • モデルが長すぎる名前でツールを呼び出した後、会話が「tool_use.name: 文字列は最大 200 文字である必要があります」で永続的にスタックする問題を修正しました。
  • クロード コードが自身のメモリ使用量を読み取れない場合 (ファイル記述子が不足している場合など)、ツール呼び出しが「メモリ使用量の取得に失敗しました」で失敗するか、実行後に失敗として報告される問題を修正しました。
  • 以前のアシスタント メッセージにプレーン文字列のコンテンツが含まれていた場合、--input-format stream-json セッション (エージェント SDK、VS Code 拡張機能) とスケジュールされたクラウド セッションが毎ターンエラーで失敗する問題を修正しました。
  • 非対話型セッション (-p、エージェント SDK) が開始されたディレクトリがセッション中に削除された後、次のターンで失敗する問題を修正しました。
  • ハンドシェイク中にホストが応答を停止した場合に、ホスト側 (SDK) MCP サーバーとのヘッドレス セッションが最初のメッセージで停止する問題を修正しました。リモートセッションは最大でも数秒待機するようになりました
  • MCP サーバーまたはプラグインが構成されていない場合、管理設定ネットワーク要求を待機する対話型起動を修正しました (約 80 ミリ秒、ネットワークに到達できない場合は 17 秒以上)
  • 3 MB を超える PDF を読んだり @ メンションしたりするときに、応答するまでに最大 2 分の遅延が発生する問題を修正しました。
  • 特定の PDF ページの読み取りが中断され、そのページのレンダリングが最大 2 分間実行されたままになる問題を修正しました。
  • 承認前に macOS の /.vol、/.nofollow、または /.resolve (ネットワーク マウントに到達できる) の下のパスを読み取る許可ダイアログと添付ファイルのチェックを修正しました。
  • コマンド置換出力のみをターゲットとする再帰的 rm (rm -rf "$(pwd)" など) が自動および --dangerously-skip-permissions モードでプロンプトなしで実行される問題を修正しました。 CLAUDE_CODE_DISABLE_SUBSTITUTION_RM_PROMPT=1 で実行しない限り、Bash 許可ルールでも要求されるようになりました。
  • ワイルドカード一致に拡張される NUL バイトを含む許可ルールを修正しました。このようなルールは何も一致しなくなりました
  • git rev-parse --git-dir と一致しないサンドボックス excludedCommands エントリ、シェル組み込みのような名前のプログラム、および [WIP] または # 行を含むコミット メッセージを修正しました。
  • CLAUDE_CODE_TMPDIR が設定されている場合、サンドボックス化された Bash コマンドが $TMPDIR に書き込めない問題を修正
  • ワークスペース trust プロンプトを通過していないディレクトリで、claude --bg がバックグラウンド セッションを開始し、そのプロジェクト フックを実行する問題を修正しました。最初に trust を要求するか、対話的に実行しない場合は終了するようになりました。
  • --setting-sources (および SDK settingSources) が生成されたセッションに転送されない問題を修正しました。チームメイト、/bg、claude agents セッション、および --worktree --tmux は親の制限で開始されるようになりました。
  • 読み取り、書き込み、編集、および NotebookEdit を修正しました。ヌル バイトを含むファイル パスは、ターン全体を終了するのではなく、明らかなエラーでツール呼び出しに失敗するようになりました。

  • 作業ディレクトリ内の --add-dir ディレクトリからの CLAUDE.md およびルール ファイルが、ヘッドレス セッションおよび SDK セッションでモデルに 2 回送信される問題を修正しました。
  • 許可プロンプトとサンドボックス ネットワーク アクセス プロンプトが重なって両方に応答した後、リモート セッションが「承認が必要」のままになり、古いプロンプトが表示される問題を修正
  • ワーカーが再起動する直前に終了したバックグラウンド エージェントについてクラウド セッションがクロードに通知しない問題を修正

  • 組織のポリシーが単にまだ読み込まれていない場合に、リモート コントロールが「組織のポリシーによって無効になっている」と報告される問題を修正しました。フェッチを再試行し、検証できなかったと表示されます
  • クロード デスクトップ、claude.ai、またはモバイル アプリから開くために claude remote-control が開始するリモート コントロール セッションにアーティファクト ツールが欠落している問題を修正しました。
