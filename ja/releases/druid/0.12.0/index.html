druid 0.12.0

マイナー 公開日2018年3月9日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.12.0 Druid 0.12.0 には、約 40 人の寄稿者による 100 を超えるパフォーマンスの改善、安定性の改善、バグ修正が含まれています。このリリースでは、Kafka インデックス サービスに大幅な改善が加えられています。 その他の主な新機能は次のとおりです。

  • 優先タスクロック
  • 自動セグメント管理の改善
  • アグリゲータ後のテスト統計
  • 数値分位点スケッチアグリゲーター
  • 基本認証拡張機能
  • クエリリクエストのキューイングの改善
  • 解析バッチのサポート
  • さまざまなパフォーマンスの改善
  • Druid SQL のさまざまな改善 変更点の完全なリストはここにあります: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0 このリリースのドキュメントは、http://druid.io/docs/0.12.0/ にあります。

ハイライト

Kafka のインデックス作成増分ハンドオフと分離されたパーティショニング

Kafka インデックス作成サービスは、増分ハンドオフをサポートするとともに、Kafka インデックス作成タスクによって作成されるセグメントの数を Kafka パーティションの数から分離するようになりました。詳細については、https://github.com/druid-io/druid/pull/4815#issuecomment-346155552 を参照してください。 #4815 で @pjain1 によって追加されました。

優先タスクのロック

Druid は、インデックス作成タスクのロックの優先順位をサポートするようになりました。インデックス作成タスクがデータソース + 間隔でロックを取得する必要がある場合、優先度の高いタスクが優先度の低いタスクをプリエンプトできるようになりました。詳細については、http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority を参照してください。 @jihoonson が https://github.com/druid-io/druid/pull/4550. で追加

自動セグメント管理の改善

保留中のセグメントの自動クリーンアップ

インデックス作成タスクは、メタデータ ストアの「pendingSegments」テーブルにエントリを作成します。 0.12.0 より前では、これらの一時エントリは自動的にクリーンアップされず、時間の経過とともにクラスターのパフォーマンスが低下する可能性がありました。 Druid 0.12.0 を使用すると、コーディネーターは保留中のセグメント テーブル内の未使用のエントリを自動的にクリーンアップできます。この機能は、コーディネーターのプロパティで druid.coordinator.kill.pendingSegments.on=true を設定することで有効になります。 #5149 で @jihoonson によって追加されました。

圧縮タスク

セグメントの圧縮 (指定された間隔内でセグメントのセットを結合して、より大きくてもセグメント数が少ないセットを作成する) は、Druid のバッチ取り込みの一般的な使用例です。 Druid 0.12.0 は、指定された間隔内のすべてのセグメントを 1 つのセグメントにマージする圧縮タスクをサポートするようになりました。詳細については、http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-taskを参照してください。 #4985 で @jihoonson によって追加されました。

集計後のテスト統計

新しい Z スコアおよび p 値検定統計ポストアグリゲーターが druid-stats 拡張機能に追加されました。詳細はhttp://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.htmlをご覧ください。 @chunghochen によって #4532 に追加されました。

数値分位数スケッチ アグリゲーター

数値分位数スケッチ アグリゲーターが druid-datasketches 拡張機能に追加されました。 #5002 で @AlexanderSaydakov によって追加されました。

基本認証拡張機能

Druid 0.12.0 には、基本 HTTP 認証とシンプルなロールベースのアクセス制御を提供する新しい認証/認可拡張機能が含まれています。詳細については、http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html を参照してください。 #5099 で @jon-wei によって追加されました。

クエリリクエストのキューイングの改善

現在、clients は、無制限の Jetty ワーカー プール キューに入れられるリクエストを送信しすぎて、誤ってブローカーに負荷をかける可能性があります。 Client は通常、client 側の特定のタイムアウト後に接続を閉じますが、ブローカーはこれらの要求の処理を継続し、応答していないように見えます。その間、clients は再試行を続け、すでに過負荷になっているブローカーにリクエストを追加し続けます。 ブローカー構成 および 履歴構成 に新しく導入されたプロパティ druid.server.http.queueSize および druid.server.http.enableRequestLimit を使用すると、ユーザーは、clients がブローカーやヒストリカルにクエリを圧倒するのを防ぐためにリクエストの拒否を構成できます。 #4540 で @himanshug によって追加されました。

解析バッチのサポート

カスタム取り込み解析拡張機能の開発者向けに、InputRowParsers が 1 つの入力行から複数の InputRow を返すことができるようになりました。これにより、Druid の外部での入力変換の必要性が減り、取り込みパイプラインが簡素化されます。 #5081 で @pjain1 によって追加されました。

パフォーマンスの向上

セグメント書き込み出力中

新しいセグメントを作成するとき、Druid は前処理されたデータの一部を一時バッファーに保存します。 0.12.0 より前は、これらのバッファは常にディスク上の一時ファイルに保存されていました。 0.12.0 では、@leventov による PR #4762 により、これらの一時バッファーをオフヒープ メモリに保存できるため、取り込み中のディスク I/O 操作の数が削減されます。これらのバッファーにオフヒープ メモリを使用できるようにするには、それに応じて druid.peon.defaultSegmentWriteOutMediumFactory プロパティを構成する必要があります。一時バッファーにオフヒープ メモリーを使用する場合は、より多くの直接メモリー使用量に対応するために -XX:MaxDirectMemorySize が増加していることを確認してください。 構成の詳細については、http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory を参照してください。

GroupBy の中間結果の並列マージ

@jihoonson による PR #4704 を使用すると、ディスクに溢れた中間 GroupBy 結果の並列マージに使用される多数の処理スレッドを構成できます。 0.12.0 より前は、このマージ ステップは常に単一のスレッド内で行われていました。 構成の詳細については、http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine を参照してください。

その他のパフォーマンスの改善

  • DataSegment メモリの最適化: #5094 by @leventov
  • IndexedInts.iterator() を削除: #4811 by @leventov
  • ExpressionSelectors: 最適化されたセレクターを追加: #5048 by @gianm

SQLの改善

以下の PR で @gianm によって、Druid SQL にさまざまな改善と機能が追加されました。

  • タイムフロア式の翻訳を改善: #5107
  • TIMESTAMPADD を追加: #5079
  • 未使用の集計を削除するルールを追加: #5049
  • CASE スタイルのフィルタリングされたカウントを個別にサポート: #5047
  • 「配列」結果形式とドキュメント結果形式を追加: #5032
  • 複雑なアグリゲータでの HaveSpec を修正: #5024
  • 文字列を日付/時刻リテラルに暗黙的にキャストするときの動作の改善: #5023
  • Avatica クエリ用のルーター接続バランサーを追加: #4983
  • 誤ったフィルターの単純化を修正: #4945
  • SQL クエリのルーター処理を修正: #4851

0.11.0 以前からのアップデート

アップグレード前に知っておくべき 0.11.0 と 0.12.0 の間の変更点については、以下を参照してください。 0.11.0 よりも前のバージョンから更新する場合は、関連する中間バージョンの release note で追加の注意事項を参照してください。

ロールバックの制限事項

0.12.0 にアップグレードした後は、https://github.com/druid-io/druid/pull/4762. に加えられた変更のため、0.11.0 より古いバージョンにダウングレードすることはできなくなります。ただし、バージョン 0.11.0 にロールバックすることは可能です。

com.metamx.java-util ライブラリの移行

Metamarkets java-util ライブラリが Druid に取り込まれました。その結果、次のパッケージ参照が変更されました。 com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics これは、druid.monitoring.monitors 構成に影響します。古い com.metamx.metrics.* パッケージにあるモニター クラスへの参照は、代わりに io.druid.java.metrics.* を参照するように更新する必要があります。 io.druid.java.util.metrics.JvmMonitor。 上記の com.metamx パッケージ内のクラスが log4j2.xml などの他の構成で参照されている場合、それらの参照も更新する必要があります。 拡張機能の開発者は、新しい Druid パッケージも使用できるようにコードを更新する必要があります。

カフェインキャッシュ拡張機能

Caffeine キャッシュ拡張機能は拡張機能からコア Druid に移動されました。さらに、Caffeine キャッシュがデフォルトのキャッシュ実装になりました。 druid-caffeine-cache が存在する場合は、0.12.0 にアップグレードするときに拡張子リストから削除してください。詳細については、https://github.com/druid-io/druid/pull/4810. をご覧ください。

Kafka インデックス サービスの変更

####earlyMessageRejectPeriod earlyMessageRejectPeriod 構成のセマンティクスが変更されました。メッセージ ウィンドウの境界を決定するときに、earlyMessageRejectPeriod が単なる (task start time) ではなく (task start time + task duration) に追加されるようになりました。詳細については、https://github.com/druid-io/druid/pull/4990 を参照してください。

ローリング アップグレード

0.12.0 では、Kafka スーパーバイザーと Kafka インデックス作成タスクの間でプロトコルの変更があり、ディスク上に保持されるメタデータ形式にもいくつかの変更があります。したがって、ローリング アップグレードをサポートするには、オーバーロードの前にすべての中間マネージャーを 最初に アップグレードする必要があります。この順序はアップグレードの標準的な順序とは異なることに注意してください。また、この順序は Kafka インデックス サービスを使用する場合にのみ必要であることにも注意してください。 Kafka インデックス サービスを使用していない場合、または Kafka スーパーバイザーのダウンタイムに対処できる場合は、任意の順序でアップグレードできます。 Overlord がアップグレードされるまでは、すべての Kafka インデックス作成タスクは (アップグレードされていても) 以前と同じように動作します。これは、切り離しや増分ハンドオフがないことを意味します。オーバーロードがアップグレードされると、アップグレードされたオーバーロードによって開始された新しいタスクが新機能をサポートするようになります。 詳細については、https://github.com/druid-io/druid/pull/4815を参照してください。

ロールバック

オーバーロードと中間マネージャーの両方がロールバックされると、適切に機能する新しいタスクのセットが開始されます。ただし、現在の一連のタスクはロールバック中に失敗する可能性があります。詳細については、#4815 を参照してください。

拡張機能開発者向けのインターフェースの変更

ColumnSelectorFactory API が変わりました。アグリゲーター拡張機能の作成者および ColumnSelectorFactory を使用するその他のユーザーは、それに応じてコードを更新する必要があります。詳細はhttps://github.com/druid-io/druid/pull/4886をご覧ください。 Aggregator.reset() メソッドは非推奨で使用されていないため、削除されました。詳細については、https://github.com/druid-io/druid/pull/5177 を参照してください。 DataSegmentPusher インターフェイスが変更され、push() メソッドに replaceExisting パラメーターが追加されました。詳細はhttps://github.com/druid-io/druid/pull/5187をご覧ください。 Escalator インターフェイスが変更され、createEscalatedJettyClient メソッドが削除されました。詳細はhttps://github.com/druid-io/druid/pull/5322をご覧ください。
