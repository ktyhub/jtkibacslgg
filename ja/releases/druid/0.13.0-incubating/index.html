druid 0.13.0-incubating

マイナー 公開日2018年12月12日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.13.0-incubating Druid 0.13.0-incubating には、81 人の寄稿者による 400 を超える新機能、パフォーマンス/安定性/ドキュメントの改善、バグ修正が含まれています。これは、Apache Incubator プログラムにおける Druid の最初のリリースです。主な新機能と改善点は次のとおりです。

  • ネイティブの並列バッチインデックス作成
  • 自動セグメント圧縮
  • システムスキーマテーブル
  • インデックス作成タスクのステータス、統計、エラーレポートの改善
  • SQL 互換の null 処理
  • 結果レベルのブローカーのキャッシュ
  • RDBMSからの取り込み
  • ブルームフィルターのサポート
  • 追加の SQL 結果形式
  • 追加のアグリゲーター (stringFirst/stringLast、ArrayOfDoublesSketch、HllSketch)
  • groupBy クエリでの複数のグループ化仕様のサポート
  • 相互 TLS サポート
  • HTTPベースのワーカー管理
  • ブローカーのバックプレッシャー
  • maxBytesInMemory 取り込みチューニング構成
  • マテリアライズド ビュー (コミュニティ拡張)
  • Influx Line Protocol のパーサー (コミュニティ拡張)
  • OpenTSDB エミッタ (コミュニティ拡張) 変更点の完全なリストはここにあります: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0 このリリースのドキュメントは次の場所にあります: http://druid.io/docs/0.13.0-incubating/

ハイライト

ネイティブの並列バッチインデックス作成

Hadoop への依存を必要とせずに、分割可能なソースの並列バッチ取り込みを管理する index_parallel スーパーバイザーを導入します。詳細については、http://druid.io/docs/latest/ingestion/native_tasks.html を参照してください。 注意: これは初期の単一フェーズ実装であり、入力データの分割を想定する方法に制限があります。特に、この機能の次回のイテレーションで追加される shuffle 実装がありません。詳細については、#5543 の提案を参照してください。 #5492 で @jihoonson によって追加されました。

自動セグメント圧縮

以前は、クエリのパフォーマンスを向上させるために小さなセグメントを最適なサイズのセグメントに圧縮するには、圧縮タスクまたは再インデックス付けタスクを送信して実行する必要がありました。これは多くの場合手動プロセスであるか、タスクの定期的な送信を処理するために外部スケジューラが必要でした。このパッチは、コーディネーター サービスによって管理される自動セグメント圧縮を実装します。 注意: これは初期実装であり、リアルタイム取り込みタスクとの相互運用性に制限があります。現在、インデックス作成タスクでは、同時操作による不整合を防ぐために、変更するタイムラインの部分のロックを取得する必要があります。この実装では、リアルタイムの取り込みが決して中断されないように優先度の低いロックを使用しますが、これはまた、リアルタイム タスクが圧縮中の時間間隔で継続的にロックを取得している場合、圧縮が進行しない可能性があることを意味します。これは、この機能の次のイテレーションでより詳細なロックを使用して改善される予定です。詳細については、#4479 の提案を参照してください。 この機能のドキュメント: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments @jihoonson によって #5102 に追加されました。

システムスキーマテーブル

提供および公開されたセグメント、クラスターのノード、および実行中および完了したインデックス作成タスクに関する情報を公開するテーブルを含むシステム スキーマを SQL インターフェイスに追加します。 注意: この実装には既知のオーバーヘッドの非効率性がいくつか含まれており、将来のパッチで解決される予定です。 この機能のドキュメント: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema #6094 で @surekhasaharan によって追加されました。

インデックス作成タスクのステータス、統計、エラーレポートの改善

以前は非常に不透明で、解析例外、タスクの失敗、および完了したタスクからの実際の出力の原因を特定することが困難であった、取り込み関連の API のパフォーマンスと詳細が改善されました。また、移動平均スループット統計を含む、改善された取り込みメトリック レポートも追加されます。 @surekhasaharan と @jon-wei によって #5801、#5418、#5748 に追加されました。

SQL 互換の null 処理

NULL 値を空の文字列またはゼロ値と同等ではなく欠損値として扱うことにより、Druid による NULL 値の処理が改善されました。これにより、Druid の SQL 互換性が高まり、ODBC/JDBC をサポートする外部 BI ツールとの統合が向上します。提案については #4349 を参照してください。 この機能を有効にするには、システム全体のプロパティ druid.generic.useDefaultValueForNull=false を設定する必要があります。 @nishantmonu51 によって #5278 と #5958 に追加されました。

結果レベルのブローカーのキャッシュ

従来のセグメントレベルのキャッシュと同時に動作できる結果レベルのキャッシュをブローカーに実装します。提案については #4843 を参照してください。 この機能のドキュメント: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching @a2l007 によって #5028 に追加されました。

RDBMS からの取り込み

RDBMS からの直接のデータ取り込みをサポートする sql Firehose を導入します。 @a2l007 によって #5441 に追加されました。

ブルームフィルターのサポート

Apache Hive などの外部システムによって生成されたブルーム フィルターを適用することにより、Druid クエリを最適化するためのサポートを追加します。将来的には、#6397 は、Druid クエリの結果としてブルーム フィルターの生成をサポートし、将来のクエリを最適化するために使用できるようになります。 @nishantmonu51 によって #6222 に追加されました。

追加の SQL 結果形式

行ベースの JSON および CSV の結果形式を追加し、さらに結果に含まれる列のリストを含む X-Druid-Column-Names および X-Druid-Column-Types 応答ヘッダーを追加します。 #6191 で @gianm によって追加されました。

'stringLast' および 'stringFirst' アグリゲーター

2 つの相補的なアグリゲーター、stringLast と stringFirst が導入されました。これらは文字列列を操作し、それぞれ最大と最小のタイムスタンプを持つ値を返します。 #5789 で @andresgomezfrr によって追加されました。

ArrayOfDoubles スケッチ

数値タプル スケッチのサポートを追加します。これは、一意のキーに関連付けられた double 値の配列を追加することで、カウント別の Theta スケッチの機能を拡張します。 #5148 で @AlexanderSaydakov によって追加されました。

Hllスケッチ

https://github.com/DataSketches. の HllSketch に基づくカウント別アグリゲータの構成可能な実装を追加 Druid のネイティブ HyperLogLogCollector と比較すると、精度、効率、速度が向上していることがわかります: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html #5712 で @AlexanderSaydakov によって追加されました。

groupBy クエリでの複数のグループ化仕様のサポート

subtotalsSpec groupBy パラメータのサポートを追加します。これにより、同じ列セットのサブセットごとにグループ化する複数のクエリを実行するときに、ブローカー レベルで中間結果を再利用することで Druid が効率的になります。詳細については、#5179 の提案を参照してください。 #5280 で @himanshug によって追加されました。

相互 TLS サポート

相互 TLS (サーバー証明書の検証 + client 証明書の検証) のサポートを追加します。参照: https://en.wikipedia.org/wiki/Mutual_authentication #6076 で @jon-wei によって追加されました。

HTTP ベースのワーカー管理

ZooKeeper に基づく以前の実装を置き換えるために、HTTP ベースのインデックス作成タスク管理実装を追加します。 Druid の ZooKeeper への依存を軽減し、最終的には排除するための一連の改善の一部です。提案については #4996 を参照してください。 #5104 で @himanshug によって追加されました。

ブローカーのバックプレッシャー

ブローカーがデータ サービング ノードにバックプレッシャーを適用できるようにして、clients による読み取りよりも早く結果が受信される場合に、メモリ不足でブローカーがクラッシュするのを防ぎます。 #6313 で @gianm によって追加されました。

「maxBytesInMemory」取り込みチューニング構成

以前は、インデックス作成タスクのメモリ管理の主要なチューニング パラメータは maxRowsInMemory 構成で、メモリの内容をディスクに書き出すしきい値を決定していました。行の「サイズ」は複数の要因に基づいて変化するため、これを適切に構成するのは困難でした。 maxBytesInMemory は、この構成を行ベースではなくバイトベースにします。 #5583 で @surekhasaharan によって追加されました。

マテリアライズドビュー

追加のストレージを犠牲にして、特定の状況でクエリのパフォーマンスを向上させることができるマテリアライズド ビューの作成をサポートします。詳細については、http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html を参照してください。 注意: これはコミュニティによって提供された拡張機能であり、Druid ディストリビューションには自動的には含まれません。これをいつコア拡張機能に昇格させるかを決定するためのフィードバックを歓迎します。詳細については、「コミュニティ拡張機能」(http://druid.io/docs/latest/development/extensions.html#community-extensions) を参照してください。 @zhangxinyu1 によって #5556 に追加されました。

流入ラインプロトコルのパーサー

Influx Line Protocol データ形式の取り込みのサポートを追加します。詳細については、「https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/」を参照してください。 注意: これはコミュニティによって提供された拡張機能であり、Druid ディストリビューションには自動的には含まれません。これをいつコア拡張機能に昇格させるかを決定するためのフィードバックを歓迎します。詳細については、「コミュニティ拡張機能」(http://druid.io/docs/latest/development/extensions.html#community-extensions) を参照してください。 #5440 で @njhartwell によって追加されました。

OpenTSDB エミッター

Druid メトリクスを OpenTSDB に出力するためのサポートを追加します。 注意: これはコミュニティによって提供された拡張機能であり、Druid ディストリビューションには自動的には含まれません。これをいつコア拡張機能に昇格させるかを決定するためのフィードバックを歓迎します。詳細については、「コミュニティ拡張機能」(http://druid.io/docs/latest/development/extensions.html#community-extensions) を参照してください。 #5380 で @QiuMM によって追加されました。

0.12.3以前からのアップデート

アップグレード前に知っておくべき 0.12.3 と 0.13.0 の間の変更点については、以下を参照してください。 0.12.3 よりも前のバージョンから更新する場合は、関連する中間バージョンの release note で追加の注意事項を参照してください。

MySQL メタデータ ストレージ拡張機能には JDBC ドライバーが含まれなくなりました

MySQL メタデータ ストレージ拡張機能は Druid ディストリビューションと一緒にパッケージ化されるようになりましたが、必要な MySQL JDBC ドライバーは含まれていません (ライセンス制限のため)。この拡張機能を使用するには、ドライバーを個別にダウンロードし、拡張機能のディレクトリに追加する必要があります。 詳細については、http://druid.io/docs/latest/development/extensions-core/mysql.html を参照してください。

S3 拡張には AWS リージョン設定が必要です

Jets3t から AWS SDK (#5382) に切り替えた結果、S3 拡張機能のユーザーはターゲット リージョンを明示的に設定する必要があります。これを行うには、JVM システム プロパティ aws.region または環境変数 AWS_REGION を設定します。 例として、システム プロパティを通じてリージョンを「us-east-1」に設定するには、次のようにします。

  • すべての Druid サービスの jvm.config ファイルに -Daws.region=us-east-1 を追加します。
  • プロパティが peon (ワーカー) プロセスに渡されるように、middleManager/runtime.properties の -Daws.region=us-east-1 を druid.indexer.runner.javaOpts に追加します。

取り込み仕様の変更

パッケージングの名前を io.druid から org.apache.druid に変更した結果、完全修飾クラス名でクラスを参照する取り込み仕様をそれに応じて変更する必要があります。 たとえば、Hadoop インデックス付きの Parquet 拡張機能を使用している場合、inputSpec の inputFormat フィールドを io.druid.data.input.parquet.DruidParquetInputFormat から org.apache.druid.data.input.parquet.DruidParquetInputFormat に変更する必要があります。

メトリクスの変更

新しい指標

  • task/action/log/time - タスクアクションを監査ログに記録するのにかかったミリ秒数 (#5714)
  • task/action/run/time - タスクアクションの実行にかかったミリ秒数 (#5714)
  • query/node/backpressure - バックプレッシャーが適用されているため、チャネルが読み取れないナノ秒 (#6335) (これはデフォルトでは有効になっておらず、発行するには QueryMetrics のカスタム実装が必要であることに注意してください)

新しい次元

  • taskId および taskType がタスク関連のメトリクスに追加されました (#5664)

その他

  • 時間が記録されていない場合、HttpPostEmitterMonitor は maxTime と minTime を発行しなくなりました (#6418)

ロールバックの制限

64 ビット doubles アグリゲータ

64 ビット double アグリゲーターがデフォルトで使用されるようになりました (#5478 を参照)。 64 ビット浮動小数点列のサポートは Druid 0.11.0 でリリースされたため、これが有効になっている場合、0.11.0 より古いバージョンはデータ セグメントを読み取ることができなくなります。 古い形式を無効にして保持するには、システム全体のプロパティ druid.indexing.doubleStorage=float を設定する必要があります。

ビットマップインデックスの無効化

0.13.0 は、列ごとにビットマップ インデックスを無効にするサポートを追加します。これにより、ビットマップ インデックスが値を追加しない場合にスペースを節約できます。これを行うには、ディメンション スキーマで「createBitmapIndex」フィールドを設定します。このオプションを使用して書き込まれたセグメントには、Druid の古いバージョンとの下位互換性がありません (#5402)。

動作の変更

Java パッケージ名の変更

Druid のパッケージ名はすべて io.druid から org.apache.druid に変更されました。これは、サービスの起動時に実行する必要がある Java メイン クラスの名前に影響します (現在は org.apache.druid.cli.Main です)。また、拡張機能やモニターのインストールと構成にも影響する可能性があります。

ParseSpec は取り込み仕様の必須フィールドになりました

デフォルトの ParseSpec (以前の DelimitedParseSpec) はなくなりました。取り込み仕様では、parseSpec を指定する必要があります。以前に parseSpec を提供しなかった場合は、既存の動作を維持するために "format": "tsv" を使用する必要があります (#6310)。

1 つの JDBC フレームで返されるデフォルトの最大行数に変更します

メモリ不足エラーを最小限に抑えるために、druid.sql.avatica.maxRowsPerFrame のデフォルト値が 100k から 5k に減りました (#5409)。

異なる時間範囲専用のブローカーにルーティングする場合のルーターの動作の変更

#5595 の結果、異なる時間範囲でのクエリ専用となる異なる層のブローカーが存在する構成では、ルーターが望ましくないブローカーを選択する可能性があります。議論については #1362 を参照してください。

Ruby TimestampSpec はミリ秒を無視しなくなりました

「ruby」形式の TimestampSpec を使用して解析されたタイムスタンプで、ミリ秒コンポーネントが切り捨てられなくなりました。このパーサーを使用していて、SECOND のクエリ粒度が必要な場合は、インデックス仕様で適切に設定されていることを確認してください (#6217)。

ZooKeeper タスク アナウンスのサイズが若干増加

データソース名が TaskAnnouncement に追加されたため、ZooKeeper に保存されるデータ量がタスクごとにわずかに増加します (#5511)。

フィルタリングされたアグリゲータへの「name」フィールドの追加

「filtered」タイプのアグリゲーターは「name」フィールドをサポートするようになりました。以前は、フィルターされたアグリゲーターは、ラップしたアグリゲーターの名前を継承していました。フィルターされたアグリゲーターとラップされたアグリゲーターの両方に「名前」フィールドを指定した場合は、フィルターされたアグリゲーターの名前が優先されます。フィルターされたアグリゲーターの名前が見つからないか空の場合は、ラップされたアグリゲーターの名前が使用されます (#6219)。

utf8mb4 が推奨されるメタデータ ストレージ文字セットになりました

アップグレード手順については、https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html. で説明されている ALTER DATABASE および ALTER TABLE 手順を使用してください。 動機と参考情報については、#5377 および #5411 を参照してください。

削除された構成プロパティ

  • druid.indexer.runner.tlsStartPort は削除されました (#6194)。
  • druid.indexer.runner.separateIngestionEndpoint は削除されました (#6263)。

拡張機能開発者向けのインターフェースの変更

  • パッケージ名が io.druid から org.apache.druid に変更されました。すべてのサードパーティ拡張機能は、META-INF/io.druid.initialization.DruidModule の名前を org.apache.druid.initialization.DruidModule に変更し、拡張機能のパッケージを適切に更新する必要があります (#6266)。
  • DataSegmentPuller インターフェースが削除されました (#5461)。
  • java-util の下の多くの関数が削除されました (#5461)。
  • Metadata クラスのコンストラクターが変更されました (#5613)。
  • 「spark2」Maven プロファイルが削除されました (#5581)。

API の非推奨

オーバーロード

  • /druid/indexer/v1/supervisor/{id}/shutdown エンドポイントは非推奨となり、/druid/indexer/v1/supervisor/{id}/terminate (#6272 および #6234) が使用されます。
  • /druid/indexer/v1/task/{taskId}/segments エンドポイントは非推奨になりました (#6368)。
  • /druid/indexer/v1/task/ID/status によって返される status フィールドは、statusCode (#6334) に代わって非推奨になりました。
  • インジェストチューニング構成の reportParseExceptions および ignoreInvalidRows パラメーターは非推奨となり、logParseExceptions および maxParseExceptions が使用されます (#5418)。

ブローカー

  • /druid/v2/datasources/{dataSourceName}/dimensions エンドポイントは非推奨になりました。代わりに、セグメント メタデータ クエリまたは INFORMATION_SCHEMA SQL テーブルを使用する必要があります (#6361)。
  • /druid/v2/datasources/{dataSourceName}/metrics エンドポイントは非推奨になりました。代わりに、セグメント メタデータ クエリまたは INFORMATION_SCHEMA SQL テーブルを使用する必要があります (#6361)。
