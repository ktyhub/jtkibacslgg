druid 0.14.0-incubating

マイナー 公開日2019年4月9日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.14.0-incubating Apache Druid (インキュベーション中) 0.14.0-incubating には、54 人の寄稿者による 200 を超える新機能、パフォーマンス/安定性/ドキュメントの改善、バグ修正が含まれています。主な新機能と改善点は次のとおりです。

  • 新しいウェブコンソール
  • Amazon Kinesis インデックスサービス
  • ヒストリカルの廃止モード
  • Broker でのパブリッシュされたセグメント キャッシュ
  • ブルームフィルターアグリゲーターと式
  • Apache Parquet 拡張機能を更新しました
  • ネストされた GroupBy クエリの強制プッシュダウン オプション
  • セグメントのハンドオフとドロップ ルールの処理の改善
  • Apache Hadoop 取り込みタスクが強制終了されたときに、MapReduce ジョブを自動的に強制終了します。
  • statsd エミッターの DogStatsD タグのサポート
  • すべてのルックアップ仕様を取得するための新しい API
  • 新しい圧縮オプション
  • より効率的なキャッシュコストセグメントバランス戦略 変更点の完全なリストはここにあります: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 このリリースのドキュメントは、http://druid.io/docs/0.14.0-incubating/ にあります。

ハイライト

新しい Web コンソール

Druid には、以前はコーディネーター コンソールとオーバーロード コンソールに分割されていた機能を提供する新しい Web コンソールがあります。 新しいコンソールを使用すると、ユーザーはデータソース、セグメント、タスク、データ プロセス (履歴および中間マネージャー)、およびコーディネーターの動的構成を管理できます。ユーザーは、コンソール内で SQL およびネイティブ Druid クエリを実行することもできます。 詳しくはhttp://druid.io/docs/0.14.0-incubating/operations/management-uis.htmlをご覧ください。 #6923 で @vogievetsky によって追加されました。

Kinesis インデックスサービス

Druid は、新しい druid-kinesis-indexing-service コア拡張機能によって提供される Kinesis ストリームからの取り込みをサポートするようになりました。 詳細はhttp://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.htmlをご覧ください。 #6431 で @jsun98 によって追加されました。

ヒストリカルの廃止モード

履歴プロセスを「廃止」モードにできるようになりました。このモードでは、コーディネーターは履歴プロセスをセグメント レプリケーションのターゲットとして考慮しなくなります。コーディネーターは、廃止予定の履歴からセグメントを移動することもあります。 これは、コーディネーターの動的構成によって制御されます。詳しくはhttp://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration.をご覧ください。 @egor-ryashin によって #6349 に追加されました。

ブローカー上の公開セグメント キャッシュ

Druid Broker は、コーディネーターのポーリングを介して公開されたセグメントのキャッシュを維持できるようになりました。これにより、sys.segments システム テーブルに対するメタデータ クエリの応答時間を大幅に改善できます。 詳細はhttp://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadataをご覧ください。 #6901 で @surekhasaharan によって追加されました

ブルームフィルターアグリゲーターと式

クエリ時にブルーム フィルターを構築するための新しいアグリゲーターと、Druid 式内でブルーム フィルター チェックを実行するためのサポートが druid-bloom-filter 拡張機能に追加されました。 http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.htmlをご覧ください。 #6904 と #6397 で @clintropolis によって追加されました

更新されたパーケット拡張機能

druid-extensions-parquet は contrib 拡張機能からコア拡張セットに移動され、フラット化と int96 値をサポートするようになりました。 詳細はhttp://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.htmlをご覧ください。 #6360 で @clintropolis によって追加されました

ネストされた GroupBy クエリの強制プッシュダウン オプション

ネストされた GroupBy クエリの外部クエリの実行を履歴プロセスにプッシュダウンできるようになりました。以前は、外部クエリは常にブローカー上で実行されていました。 詳細はhttps://github.com/apache/incubator-druid/pull/5471をご覧ください。 @samarthjain によって #5471 に追加されました。

セグメントのハンドオフと保持ルールの処理の改善

セグメントのハンドオフでは、データソースの保持ルールによって削除されるセグメントが無視されるようになり、問題 #5868 によって引き起こされる取り込みエラーが回避されます。 期間ロード ルールにデフォルトで将来が含まれるようになりました。 新しい「前に期間を削除」ルールが追加されました。詳細はhttp://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-ruleをご覧ください。 @QiuMM によって #6676、#6414、#6415 に追加されました。

Hadoop 取り込みタスクが強制終了されたときに MapReduce ジョブを自動的に強制終了する

Druid は、取り込みタスクが強制終了されたときに、Hadoop バッチ取り込みタスクによって作成された MapReduce ジョブを自動的に終了するようになりました。 #6828 で @ankit0811 によって追加されました。

statsd-emitter の DogStatsD タグのサポート

statsd-emitter 拡張機能は、DogStatsD スタイルのタグをサポートするようになりました。 http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.htmlを参照してください。 #6605 で @deiwin によって追加され、#6791 で @glasser によって追加された定数タグのサポートが追加されました。

すべてのルックアップ仕様を取得するための新しい API

すべての層のすべてのルックアップ仕様を取得するための新しい API が追加されました。詳細はhttp://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookupsをご覧ください。 @jihoonson によって #7025 に追加されました。

新しい圧縮オプション

自動圧縮で maxRowsPerSegment オプションがサポートされるようになりました。詳細はhttp://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segmentsをご覧ください。 圧縮タスクは新しい segmentGranularity オプションをサポートするようになり、圧縮されたセグメントのセグメント粒度を制御するための古い keepSegmentGranularity オプションは非推奨になりました。これらのプロパティの詳細については、http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html の segmentGranularity テーブルを参照してください。 @jihoonson によって #6758 と #6780 に追加されました。

より効率的なキャッシュコストセグメントのバランスを取る戦略

cachingCost コーディネーター セグメント バランシング戦略では、バランシング決定の履歴プロセスのみが考慮されるようになりました。以前は、この戦略では、セグメント レプリケーションのターゲットではないアクティブなワーカー タスクも不必要に考慮していました。 #6879 で @QiuMM によって追加されました。

新しいメトリクス:

  • 新しい割り当て率メトリック jvm/heapAlloc/bytes、#6710 で @egor-ryashin によって追加されました。
  • 新しいクエリ数メトリクス query/count、#6473 で @QiuMM によって追加されました。
  • SQL クエリ メトリック sqlQuery/bytes および sqlQuery/time。#6302 で @gaodayue によって追加されました。
  • Apache Kafka 取り込みラグ メトリクス ingest/kafka/maxLag および ingest/kafka/avgLag、#6587 で @QiuMM によって追加されました
  • タスク数メトリック task/success/count、task/failed/count、task/running/count、task/pending/count、task/waiting/count、#6657 で @QiuMM によって追加されました

拡張機能開発者向けの新しいインターフェース

リクエストログイベント

EmittingRequestLogger によって発行される RequestLogEvent 内のフィールドを制御できるようになりました。詳細は#6477を参照してください。 @leventov によって追加されました。

カスタム TLS 証明書チェック

カスタム TLS 証明書チェック用の拡張ポイントが追加されました。詳細はhttp://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checksをご覧ください。 #6432 で @jon-wei によって追加されました。

Kafka インデックス サービスは実験的ではなくなりました

Kafka Indexing Service 拡張機能は実験段階から外れました。

SQL の機能強化

dsql の機能強化

dsql コマンド ライン client は、CLI 履歴、基本的なオートコンプリート、およびクエリ コンテキストでのクエリ タイムアウトの指定をサポートするようになりました。 @gianm によって #6929 に追加されました。

SQL ID、リクエストログ、メトリクスを追加します。

SQL クエリには ID が付けられるようになり、SQL クエリの一部として実行されるネイティブ クエリには、ネイティブ クエリのリクエスト ログに関連付けられた SQL クエリ ID が記録されます。 SQL クエリがリクエスト ログに記録されるようになります。 2 つの新しいメトリクス、sqlQuery/time および sqlQuery/bytes が SQL クエリに対して出力されるようになりました。 詳細については、http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging および http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics を参照してください。 #6302 で @gaodayue によって追加されました

SQL アグリゲーターのサポートの追加

次のアグリゲータが SQL でサポートされるようになりました。

  • DataSketches HLL スケッチ
  • DataSketches シータ スケッチ
  • DataSketches 分位数スケッチ
  • ビンのヒストグラムを修正
  • ブルームフィルターアグリゲーター #6951 の @jon-wei と #6502 の @clintropolis によって追加されました

その他の SQL の機能強化

  • SQL: project-after-semijoin を使用したクエリのサポートを追加します。 #6756
  • SQL: 複数値ディメンションの選択のサポート。 #6462
  • SQL: システム テーブルで AVG をサポートします。 #601
  • SQL:「POSITION」関数を追加します。 #6596
  • SQL: INFORMATION_SCHEMA カタログ名を「druid」に設定します。 #6595
  • SQL: DruidSemiJoin のソート、sortProject の順序を修正しました。 #6769 @gianm によって追加されました。

0.13.0-incubating以前からのアップデート

アップグレード時の Kafka 取り込みのダウンタイム

#6958 で説明されている問題により、既存の Kafka インデックス作成タスクが、Overlord のローリング アップグレード中に不必要に終了される可能性があります。終了したタスクはオーバーロードによって再起動され、最初の再起動後に正しく機能します。

寄木細工のエクステンションの変更

druid-parquet-extensions 拡張機能は contrib から core に移動されました。 0.14.0-incubating を展開するときは、extensions-contrib ディレクトリに古いバージョンの Parquet 拡張機能が存在しないことを確認してください。 さらに、拡張機能には 2 つのスタイルの Parquet パーサーが含まれるようになりました。

  • parquet-avro: Parquet を Avro に変換し、Avro 表現を解析します。これは、0.14.0-incubating より前の既存のパーサーでした。
  • parquet: Parquet 形式を直接解析する新しいパーサー。この新しいパーサーのみが int96 値をサポートします。 0.14.0-incubating より前は、parquet タイプのパーサーを指定すると、タスクで Avro 変換パーサーが使用されていました。 0.14.0-incubating で、Avro 変換パーサーを引き続き使用するには、代わりに parquet-avro を使用するように取り込み仕様を更新する必要があります。 Parquet 入力を使用するタスクの inputSpec の inputFormat フィールドも、パーサーの選択と一致する必要があります。
  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat 詳細はhttp://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.htmlをご覧ください。

非 2.8.3 Hadoop で Druid を実行する

2.8.3 以外の Hadoop バージョンで Druid 0.14.0-incubating を使用する場合は、次の操作が必要になる場合があります。

  • Tip #3: Use specific versions of Hadoop libraries の http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html で説明されているように、Hadoop 依存関係座標をターゲット バージョンに設定します。
  • メイン Druid pom.xml の hadoop.compile.version を変更し、標準のビルド手順に従って、Hadoop のターゲット バージョンで Druid を再ビルドします。

その他の動作の変更

古いタスクのクリーンアップ

メタデータ ストレージ内の古いタスク エントリは、タスク ログとともに自動的にクリーンアップされるようになりました。詳細については、http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging および #6592 を参照してください。

自動処理バッファ サイズ設定

druid.processing.buffer.sizeBytes プロパティは、設定されていない場合、新しいデフォルト動作を持ちます。 Druid は、次の式を使用して処理バッファ サイズの値を自動的に選択するようになりました。

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

場所:

  • totalDirectMemory: -XX:MaxDirectMemorySize で指定された JVM の直接メモリ制限
  • numMergeBuffers: druid.processing.numMergeBuffers の値。
  • numProcessingThreads: druid.processing.numThreads の値。 Druid は、自動的に選択された処理バッファ サイズとして最大 1 GB を使用します。処理バッファ サイズは引き続き手動で指定できます。 詳細は#6588を参照してください。

保持ルールにデフォルトで将来が含まれるようになりました

新しい保持ルールにはデフォルトで将来が含まれるようになることに注意してください。詳細は#6414を参照してください。

プロパティの変更

セグメントの発表

Zookeeper または HTTP ベースのセグメント管理/検出の選択に使用される druid.announcer.type プロパティは、druid.serverview.type に移動されました。 0.14.0-incubating より前に http を使用していた場合は、新しい druid.serverview.type を使用するように構成を更新する必要があります。 詳細については、以下を参照してください。

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

SegmentWriteOutMediumFactory の JsonTypeInfo に欠落していたプロパティを修正

druid.peon.defaultSegmentWriteOutMediumFactory.@type プロパティが修正されました。プロパティは「@」を除いた druid.peon.defaultSegmentWriteOutMediumFactory.type になりました。 詳細は#6656を参照してください。

非推奨

近似ヒストグラム アグリゲーター

AccusimateHistogram アグリゲータは非推奨になりました。これは正式な誤差限界のない分布依存のアルゴリズムであり、精度に重大な問題があります。 DataSketches quantiles アグリゲータは、分位値とヒストグラムのユースケースの代わりに使用する必要があります。 ヒストグラムと分位数のアグリゲーター を参照してください。

カーディナリティ/HyperUnique アグリゲーター

Cardinality および HyperUnique アグリゲータは非推奨になり、DataSketches HLL アグリゲータと Theta Sketch アグリゲータが優先されます。これらのアグリゲーターは、より優れた精度とパフォーマンス特性を備えています。 詳細については、個別のアグリゲーターの数 を参照してください。

クエリチャンク期間

chunkPeriod クエリ コンテキスト構成は、関連する query/intervalChunk/time メトリックとともに非推奨になりました。詳細は#6591を参照してください。

keepSegmentGranularity 圧縮用

圧縮タスクの keepSegmentGranularity オプションは非推奨になりました。これらのプロパティの詳細については、#6758 および http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html の segmentGranularity テーブルを参照してください。

拡張機能開発者向けのインターフェースの変更

SegmentIdクラス

Druid は、セグメント ID を表すためにプレーン String の代わりに SegmentId クラスを使用するようになりました。詳細は#6370を参照してください。 @leventov によって追加されました。

druid-api、druid-common、java-util は druid-core に移動しました

druid-api、druid-common、java-util モジュールは druid-core に移動されました。プロジェクトがこれらのライブラリに依存している場合は、それに応じて依存関係を更新してください。 詳細は#6443を参照してください。
