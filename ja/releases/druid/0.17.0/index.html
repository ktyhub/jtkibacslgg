druid 0.17.0

マイナー 公開日2020年1月27日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.17.0 Apache Druid 0.17.0 には、52 人の寄稿者による 250 を超える新機能、パフォーマンスの強化、バグ修正、ドキュメントの大幅な改善が含まれています。 変更の完全なリスト と マイルストーンにタグ付けされたすべての項目 を確認してください。

ハイライト

バッチ取り込みの改善

Druid 0.17.0 には、ネイティブ バッチ インジェスト システムへの重要なアップデートが含まれています。このアップデートでは、非テキスト バイナリ形式をサポートする内部フレームワークが追加され、ORC と Parquet が初期サポートされます。さらに、ネイティブ バッチ タスクで HDFS からデータを読み取ることができるようになりました。 この再作業により、取り込みタスクでの取り込みソースとデータ形式の指定方法が変更されます。新しい機能を使用するには、InputSources と InputFormats に関するドキュメントを参照してください。 詳細については、次のドキュメントを参照してください。 https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

並列ネイティブ バッチ取り込みのための単一ディメンション範囲パーティショニング

並列インデックス タスクは、single_dim タイプのパーティション仕様をサポートするようになりました。これにより、単一ディメンションでの範囲ベースのパーティション化が可能になります。 詳細はhttps://druid.apache.org/docs/0.17.0/ingestion/native-batch.htmlをご覧ください。

圧縮の変更

並列インデックスタスク分割のヒント

並列インデックス作成タスクには、tuningConfig に新しい構成 splitHintSpec が追加され、オペレーターが各第 1 フェーズのサブタスクが読み取るデータ量を制御するためのヒントを提供できるようになりました。現在、Druid セグメントの再取り込みに使用される分割ヒント仕様タイプ SegmentsSplitHintSpec が 1 つあります。

並列自動圧縮

自動圧縮で並列インデックス作成タスクを使用できるようになり、圧縮のスループットが向上します。 並列処理のレベルを制御するために、自動圧縮tuningConfig には新しいパラメーター maxNumConcurrentSubTasks および splitHintSpec があります。 詳細はhttps://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configurationをご覧ください。 https://github.com/apache/incubator-druid/pull/8570

ステートフルな自動圧縮

自動圧縮では、partitionSpec を使用して以前の圧縮タスクによって行われた変更を追跡するようになりました。これにより、コーディネーターは冗長な圧縮操作を削減できるようになります。 詳細はhttps://github.com/apache/druid/issues/8489をご覧ください。 自動圧縮を有効にしている場合は、アップグレードする前に、「Druid 0.17.0 へのアップグレード」セクションの「ステートフル自動圧縮の変更」の情報を参照してください。

ブローカーでの並列クエリのマージ

Druid ブローカーは、複数のスレッドを使用してクエリ結果を並行してマージできるようになりました。 この新しい機能の構成方法の詳細については、構成リファレンス のブローカー セクションの druid.processing.merge.useParallelMergePool を参照してください。 並列マージはデフォルトで有効になっており (druid.processing.merge.useParallelMergePool プロパティによって制御されます)、ほとんどのユーザーは構成リファレンスで説明されている詳細構成プロパティを変更する必要はありません。 さらに、クエリ コンテキストを使用して、クエリごとにマージ並列処理を制御できます。新しいクエリ コンテキスト パラメーターに関する情報は、https://druid.apache.org/docs/0.17.0/querying/query-context.html. で見つけることができます。 https://github.com/apache/incubator-druid/pull/8578

SQL 互換の null 処理

0.17.0 では、Druid の SQL 互換の null 処理モードに関する公式ドキュメントを追加しました。 詳細については、https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling および https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling を参照してください。 これまで文書化されていなかったこのモードに存在していたいくつかのバグ、特に数値列での null 処理に関するバグが修正されました。 0.17.0 にアップグレードした後、クラスターをこの新しいモードに移行することを検討し始めることをお勧めします。 0.17.0 で修正された null 処理のバグの完全なリストは、https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+ にあります。

LDAP 拡張子

Druid は LDAP 認証をサポートするようになりました。 LDAP グループを Druid ロールにマッピングすることで、LDAP グループを使用した認可もサポートされます。

  • LDAP 認証は、LDAP タイプの認証情報バリデータを指定することによって処理されます。
  • LDAP を使用した承認は、LDAP タイプのロール プロバイダーを指定し、Druid 内で LDAP グループ -> Druid ロール マッピングを定義することによって処理されます。 LDAP 統合には、druid-basic-security コア拡張機能が必要です。詳細はhttps://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.htmlをご覧ください。 これは LDAP サポートを備えた最初のリリースであり、多種多様な LDAP エコシステムがあるため、一部の LDAP ユースケースと機能はまだサポートされていない可能性があります。この新しい機能の拡張が必要な​​場合は、問題を提出してください。 https://github.com/apache/incubator-druid/pull/6972

ドロップウィザードエミッタ

新しい Dropwizard メトリクス エミッターが contrib 拡張機能として追加されました。 現在サポートされている Dropwizard メトリック タイプは、カウンター、ゲージ、メーター、タイマー、およびヒストグラムです。これらのメトリクスは、コンソールまたは JMX レポーターを使用して出力できます。 詳細はhttps://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.htmlをご覧ください。 https://github.com/apache/incubator-druid/pull/7363

自己発見リソース

新しいエンドポイントのペアがすべての Druid サービスに追加され、Druid サービスが中央サービス検出メカニズム (現在 ZooKeeper) からサービスがクラスターに追加されたことの確認を受信したかどうかに関する情報を返します。これらのエンドポイントは、健全性/準備完了チェックとして役立ちます。 新しいエンドポイントは次のとおりです。

  • /status/selfDiscovered/status
  • /status/selfDiscovered 詳細については、ドルイド API リファレンス を参照してください。 https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

スーパーバイザー システム テーブル

タスクスーパーバイザー (Kafka または Kinesis スーパーバイザーなど) は、新しい sys.supervisors テーブルのシステムテーブルに記録されるようになりました。 詳細はhttps://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-tableをご覧ください。 https://github.com/apache/incubator-druid/pull/8547

遅延読み込みによる高速な歴史的開始

ヒストリカル用の新しいブール構成プロパティ druid.segmentCache.lazyLoadOnStart が追加されました。 この新しいプロパティにより、ヒストリカルではセグメントが最初にクエリされるまでセグメントのロードを延期できるため、多数のセグメントを持つクラスターのヒストリカルな起動時間を大幅に短縮できます。 詳細は「コンフィグレーションリファレンス」(https://druid.apache.org/docs/0.17.0/configuration/index.html)を参照してください。 https://github.com/apache/incubator-druid/pull/6988

セグメント キャッシュの分布変更の履歴

新しい歴史的プロパティ druid.segmentCache.locationSelectorStrategy が追加されました。 druid.segmentCache.locations で複数のセグメントの保管場所が指定されている場合、新しい locationSelectorStrategy プロパティーを使用すると、ユーザーはその場所を埋めるためにどのような戦略を使用するかを指定できます。現在サポートされているオプションは roundRobin および leastBytesUsed です。 詳細は「コンフィグレーションリファレンス」(https://druid.apache.org/docs/0.17.0/configuration/index.html)を参照してください。 https://github.com/apache/incubator-druid/pull/8038

新しい準備エンドポイント

新しいブローカー エンドポイント /druid/broker/v1/readiness が追加されました。 新しい履歴エンドポイント /druid/historical/v1/readiness が追加されました。 これらのエンドポイントは、既存の /druid/broker/v1/loadstatus および /druid/historical/v1/loadstatus エンドポイントに似ています。 これらは、認証/認可チェックを必要とせず、JSON 本文の代わりに 200 成功または 503 HTTP 応答コードのみを返すという点で異なります。 https://github.com/apache/incubator-druid/pull/8841

MiddleManager カテゴリに基づいたタスク割り当てのサポート

各 MiddleManager に対して「カテゴリ」名のプロパティを定義できるようになりました。カテゴリを意識した新しいワーカー選択戦略が追加され、ユーザーは設定されたカテゴリに基づいてタスクを MiddleManager に割り当てる方法を制御できるようになりました。 詳細については、構成リファレンス の druid.worker.category のドキュメントと次のリンクを参照してください。 https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

セキュリティ脆弱性の更新

セキュリティの脆弱性に対処するために、多数の依存関係が新しいバージョンに更新されました。 詳細は以下のPRをご覧ください。

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

ドルイド 0.17.0 へのアップグレード

ネイティブ クエリの選択が置き換えられました

非推奨の選択ネイティブ クエリ タイプは 0.17.0 で削除されました。 Select を使用するネイティブ クエリがある場合は、代わりに Scan を使用するように変更する必要があります。構文と出力形式の詳細については、スキャン クエリのドキュメント (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) を参照してください。 Select を使用する Druid SQL クエリの場合、変更は必要ありません。 SQL プランナーはすでに、Select クエリの内部で Scan クエリ タイプを使用しています。 https://github.com/apache/incubator-druid/pull/8739

古いコンソールは削除されました

従来のコーディネーターおよびオーバーロード コンソールは削除され、コーディネーターおよびオーバーロード上の新しい Web コンソールに置き換えられました。 https://github.com/apache/incubator-druid/pull/8838

Calcite 1.21 アップグレード、Druid SQL null 処理

Druid 0.17.0 は、Calcite をバージョン 1.21 に更新します。 Calcite のこの新しいバージョンでは、クエリを計画するときに SQL 準拠の null 処理動作を想定した追加の最適化を行うことができます。 Druid SQL を使用しており、null 処理動作に依存している場合は、https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling の情報を読み、アップグレードする前に Druid クラスターが SQL 準拠の null 処理モードで実行されていることを確認してください。 https://github.com/apache/incubator-druid/pull/8566

ロギングの調整

Druid 0.17.0 は、ライフサイクル、クエリ、取り込みログを整理しました。 変更の詳細なリストについては、https://github.com/apache/incubator-druid/pull/8889 を参照してください。外部統合の特定のログ メッセージに依存していた場合は、アップグレードする前に新しいログの変更を確認してください。 ログ メッセージの完全なセットは、ログ記録が DEBUG レベルに設定されている場合でも表示できます。パッケージごとの DEBUG ログを有効にする方法を示すテンプレート log4j2 構成ファイルは、conf/druid の下のサンプル クラスターの _common 構成フォルダーに提供されます。

ステートフルな自動圧縮の変更

0.17.0 の自動圧縮スケジュール ロジックは、古いバージョンには存在しない Druid のメタデータ ストア内の追加のセグメント パーティショニング情報を追跡します。この情報は、一連のセグメントがクラスターの現在の自動圧縮構成ですでに圧縮されているかどうかを判断するために使用されます。 この新しいメタデータが存在しない場合、セグメントのセットは常に初期圧縮のためにスケジュールされ、この新しいメタデータは圧縮後に作成されるため、自動圧縮設定が変更されていない場合、スケジューラーは後でセグメントをスキップできます。 この追加のセグメント パーティショニング メタデータは 0.17.0 より前には存在しないため、自動圧縮スケジューリング ロジックは、0.17.0 へのアップグレード後にデータ ソース内のすべてのセグメントを 1 回再圧縮します。 自動圧縮が有効になっている各データソースのセグメントのセット全体に対するこの再圧縮は、次のことを意味します。

  • アップグレード後には移行期間があり、通常の状態よりも多くの圧縮タスクの合計がキューに入れられます。
  • セグメント セット全体が再圧縮されると、ディープ ストレージの使用量が増加します (セグメントの古いセットは、明示的に削除しない限り、依然としてディープ ストレージに保持されます)。 ユーザーは、スケジュールされた圧縮タスクの一時的な増加と、ディープ ストレージの使用量への影響に注意することをお勧めします。古いセグメントの削除に関するドキュメントは https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data にあります。

targetCompactionSizeBytes プロパティが削除されました

targetCompactionSizeBytes プロパティは、圧縮タスクおよび自動圧縮構成から削除されました。自動圧縮では、maxRowsPerSegment が必須の構成になりました。非自動圧縮タスクの場合は、任意の partitionsSpec を使用できます。 https://github.com/apache/incubator-druid/pull/8573

コンパクションタスクのtuningConfig

#8570 によって導入された並列自動圧縮の変更により、手動で送信された圧縮タスクの仕様を更新して、tuningConfig セクションにインデックスの代わりに Index_Parallel タイプを使用する必要があります。これらの仕様変更は、クラスターを 0.17.0 にアップグレードした後に適用する必要があります。 既存の自動圧縮設定は更新後も変更されないままにすることができます。自動圧縮は、アップグレード後に並列処理を使用するように自動圧縮構成が更新されるまで、非並列圧縮タスクを作成します。 並列処理のレベルを制御するために、自動圧縮tuningConfig には新しいパラメーター maxNumConcurrentSubTasks および splitHintSpec があります。 詳細はhttps://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configurationをご覧ください。

圧縮タスク ioConfig

圧縮タスクにはタスク仕様で ioConfig が必要になりました。 詳細はZZPH100​​ZZをご覧ください。 ioConfig を既存の自動圧縮構成に追加する必要はありません。アップグレード後のコーディネーターは、ioConfig セクションを含むタスク仕様を自動的に作成します。 https://github.com/apache/incubator-druid/pull/8571

パーティション仕様フィールドの名前が変更されました

パーティション仕様の targetPartitionSize フィールドと maxSegmentSize フィールドは非推奨になりました。これらはそれぞれ targetNumRowsPerSegment および maxRowsPerSegment に名前が変更されました。 https://github.com/apache/incubator-druid/pull/8507

キャッシュメトリクスはデフォルトではオフです

キャッシュメトリクスはデフォルトで無効になりました。キャッシュ メトリックを有効にするには、"org.apache.druid.client.cache.CacheMonitor" を druid.monitoring.monitors プロパティに追加します。 https://github.com/apache/incubator-druid/pull/8561

スーパーバイザー API はタスク API と一致するように変更されました

スーパーバイザーのタスク仕様では、dataSchema、tuningConfig、および ioConfig セクションを spec フィールドのサブフィールドとして配置する必要があります。例については、https://github.com/apache/incubator-druid/pull/8810 を参照してください。 古い形式は 0.17.0 で引き続き受け入れられます。

セグメント API セマンティクスの変更

コーディネーターの /datasources/{dataSourceName}/segments エンドポイントは、表示されているセグメントのみではなく、指定された間隔で使用されているすべてのセグメント (影になっているセグメントを含む) を返すようになりました。 https://github.com/apache/incubator-druid/pull/8564

HttpEmitterConfig の基本認証用のパスワードプロバイダー

druid.emitter.http.basicAuthentication プロパティは、パスワード プロバイダー を受け入れるようになりました。 HTTP エミッターを使用している場合は、パスワード プロバイダーを使用するように構成を更新することをお勧めします。 https://github.com/apache/incubator-druid/pull/8618

複数値式の変換の変更

式で複数値の列を再利用しても、不必要なデカルト展開が発生しなくなります。詳細は以下のリンク先をご覧ください。 https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

ローリングアップグレード中の Kafka/Kinesis の取り込み

ローリング アップグレード中に、0.17.0 を実行しているタスクと古いバージョンを実行しているオーバーロードがあり、タスクがストリームからのデータの読み取りを進めたが、表示されたすべてのレコードを拒否した (たとえば、すべてが解析不可能だった) 場合、タスクが現在のストリーム オフセットでオーバーロードを更新すると、古いバージョンを実行しているオーバーロードで NullPointerExceptions が発生します。 以前は、この領域 (https://github.com/apache/incubator-druid/issues/8765) に、タスクが現在のオフセットをオーバーロードに伝達できないというバグがありました。この問題を修正するためにタスク/オーバーロード公開プロトコルが更新されましたが、古いオーバーロードはこのプロトコルの変更を認識しません。 この状態はかなりまれです。

デフォルトの Hadoop バージョンの変更

Druid 0.17.0 には、2.8.3 の代わりに Hadoop 2.8.5 ライブラリがバンドルされるようになりました。 druid.indexer.task.defaultHadoopCoordinates プロパティ、または Hadoop インジェスト仕様の hadoopDependencyCoordinates プロパティを介して構成内のバンドルされた 2.8.3 ライブラリを参照していた場合は、代わりにバンドルされた 2.8.5 ライブラリを指すようにこれらの参照を更新する必要があります。

ParseSpec.verify メソッドが削除されました

ParseSpec インターフェースの実装を提供するカスタム拡張機能を保守していた場合、verify メソッドは削除されており、カスタム実装ではメソッドの @Override アノテーションを削除する必要があります。 https://github.com/apache/druid/pull/8744

既知の問題

SQL 互換の NULL 処理モードでの長い列のフィルタリング

現在、SQL 互換の null 処理が有効になっている場合に、長い列の null 値に特定のフィルター タイプを適用する際のバグを認識しています (https://github.com/apache/druid/issues/9255)。 その他の null 処理の問題が発生した場合は、問題を報告してください。

Web コンソールでの取り込み仕様のプレビュー

Web コンソールのデータ ローダーで作成されたネイティブ バッチ インジェスト タスクに対して表示されるプレビュー仕様は、正しくフォーマットされていないため、コピーして手動で送信すると失敗します。ただし、データ ローダーを通じてこれらの仕様を送信すると、正しくフォーマットされた仕様が送信されます。 https://github.com/apache/druid/issues/9144

その他の既知の問題

未解決の問題の完全なリストについては、https://github.com/apache/druid/labels/Bug を参照してください。
