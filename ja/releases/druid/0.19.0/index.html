druid 0.19.0

マイナー 公開日2020年7月21日 出典apache/druid 英語原文

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.19.0 Apache Druid 0.19.0 には、約 200 の新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 51 人の寄稿者による追加のテスト カバレッジが含まれています。詳細については、変更の完全なリスト および マイルストーンにタグ付けされたすべて を参照してください。

<a name="19-new-features" href="#19-new-features">#</a> 新機能

<a name="19-vectorize-default" href="#19-vectorize-default">#</a> GroupBy および Timeseries のベクトル化クエリ エンジンがデフォルトで有効になっています

GroupBy および Timeseries クエリ用の ベクトル化されたクエリ エンジン は、オプトイン機能として Druid 0.16 に導入されました。それ以来、私たちはこれらのエンジンを広範囲にテストしてきましたが、これらの改善がより多くのユーザーに受け入れられる時期が来たと感じています。現時点ではすべてのクエリ エンジンがベクトル化されているわけではありませんが、この変更により、ベクトル化の対象となるクエリはすべてベクトル化されるようになることに注意してください。 druid.query.vectorize を false に設定すると、問題が発生した場合でも、この機能が無効になる可能性があります。 https://github.com/apache/druid/pull/10065

<a name="19-avro" href="#19-avro">#</a> Apache Avro オブジェクト コンテナ ファイルの Druid ネイティブ バッチ サポート

Druid 0.19.0 の新機能であるネイティブ バッチ インデックス作成は、Apache Avro Object Container Format エンコードされたファイルをサポートするようになり、外部 Hadoop クラスターを必要とせずに Avro データのバッチ取り込みが可能になります。詳細については、ドキュメント を参照してください。 https://github.com/apache/druid/pull/9671

<a name="19-sql-input-source" href="#19-sql-input-source">#</a> SQL データベースの Druid ネイティブ バッチ サポートを更新しました

「SqlInputSource」が Druid 0.19.0 に追加され、Druid 0.17 で初めて導入された新しいネイティブ バッチ インジェスト仕様と連携し、SqlFirehose は非推奨になりました。 「SqlFirehose」と同様に、現在は MySQL と PostgreSQL をサポートしており、これらの拡張機能のドライバーを使用します。これは比較的低レベルの取り込みタスクであり、オペレーターは、追加のために重複データが取り込まれないようにクエリを特別に作成するか、上書き時にデータのセット全体が置換されるようにクエリを実行することによって、正しいデータが取り込まれていることを手動で確認する必要があります。操作の詳細については、ドキュメント を参照してください。 https://github.com/apache/druid/pull/9449

<a name="19-ranger" href="#19-ranger">#</a> Apache Ranger ベースの認証

Druid 0.19.0 の新しい拡張機能は、Apache Ranger によってサポートされる Druid のアクセス制御を実装する Authorizer を追加します。この拡張機能が提供する基本的な機能の詳細については、[拡張機能のドキュメント]((https://druid.apache.org/docs/0.19.0/development/extensions-core/druid-ranger-security.html) および 認証と認可) を参照してください。 https://github.com/apache/druid/pull/9579

<a name="19-aliyun-oss" href="#19-aliyun-oss">#</a> Alibaba Object Storage Service のサポート

新しい「contrib」拡張機能が Alibaba Cloud Object Storage Service (OSS) に追加され、ディープ ストレージとバッチ インジェスト入力ソースとしての使用の両方を提供します。これは「contrib」拡張機能であるため、デフォルトではバイナリ配布にパッケージ化されません。クラスターでの使用方法の詳細については、コミュニティ拡張機能 を参照してください。 https://github.com/apache/druid/pull/9898

<a name="19-gce-autoscale" href="#19-gce-autoscale">#</a> Google Compute Engine の取り込みワーカーの自動スケーリング

0.19.0 に新たに追加された別の「contrib」拡張機能は、取り込みワーカーの自動スケーリングをサポートするために追加されました。これにより、Druid Overlord は、保留中のタスクやアイドル状態のワーカーがあるたびに、Google Compute Engine に対してワーカー インスタンス (MiddleManager または Indexers) をプロビジョニングまたは終了できるようになります。 Auto Scaling グループを使用せずにインスタンスを直接プロビジョニングおよび終了する Amazon Web Services の取り込み自動スケーリング拡張機能とは異なり、GCE オートスケーラーは マネージド インスタンス グループ を使用して、オペレーターが GCE でクラスターをプロビジョニングする方法とより厳密に連携します。他の「contrib」拡張機能と同様、デフォルトではバイナリ配布にパッケージ化されません。クラスターでの使用方法の詳細については、コミュニティ拡張機能 を参照してください。 https://github.com/apache/druid/pull/8987

<a name="19-regexp-like" href="#19-regexp-like">#</a> REGEXP_LIKE

新しい REGEXP_LIKE 関数が Druid SQL およびネイティブ式に追加されました。この関数は、パターンに正規表現を使用することを除いて、LIKE と同様に動作します。 https://github.com/apache/druid/pull/9893

<a name="19-web-lookup" href="#19-web-lookup">#</a> Web コンソールのルックアップ管理の改善

Druid 0.19 の Web コンソールには、ルックアップ テーブル管理インターフェイスに対するいくつかの便利な改善も含まれています。ルックアップの作成と編集は、JSON 仕様を入力するための生のテキスト エディタではなく、ユーザー入力を受け入れるフォームを使用して行われるようになりました。 <img width="682" alt="スクリーンショット 2020 年 4 月 2 日午前 1 14 38 分" src="https://user-images.githubusercontent.com/37322608/78221645-fa2b5080-7480-11ea-9824-c74e121575f3.png"> さらに、ルックアップの横にある虫眼鏡アイコンを cli クリックすると、そのルックアップの最初の 5000 個の値を表示できるようになりました。 <img width="1129" alt="2020 年 3 月 20 日午後 3 時 9 分 24 時のスクリーンショット" src="https://user-images.githubusercontent.com/37322608/77206532-cd5c5e00-6abc-11ea-9ea0-0680fa5de8cb.png"> https://github.com/apache/druid/pull/9549 https://github.com/apache/druid/pull/9587

<a name="19-datasource-loadstatus" href="#19-datasource-loadstatus">#</a> データソース「loadstatus」ごとの新しいコーディネーター API

コーディネーター API を使用すると、最新の公開済みセグメントがクエリに使用できるかどうかを簡単に判断できます。これは既存のコーディネーター 'loadstatus' API に似ていますが、データソース固有であり、間隔を指定でき、オプションでメタデータ ストアのスナップショットをライブ リフレッシュして最新の情報を取得できます。この API を使用して多数のセグメントをクエリする場合、特にメタデータの更新を強制する場合、大規模なクラスターでは「重い」呼び出しになる可能性があるため、オペレーターは依然として注意が必要であることに注意してください。 https://github.com/apache/druid/pull/9965

<a name="19-batch-append" href="#19-batch-append">#</a> 範囲およびハッシュ パーティショニングのネイティブ バッチ追加サポート

一部はバグ修正、一部は新機能です。Druid ネイティブ バッチは、時間チャンクが「ハッシュ」または「レンジ」分割アルゴリズムで分割されている場合に、既存の時間チャンクへの新しいデータの追加を (もう一度) サポートします。現在、追加されたセグメントは「動的」パーティショニングのみをサポートしており、古いバージョンにロールバックする場合、これらの追加されたセグメントはダウングレード後に Druid によって認識されないことに注意してください。以前のバージョンにロールバックするには、これらの追加されたセグメントを残りの時間チャンクとともに圧縮して、均一なパーティション分割スキームを持たせる必要があります。 https://github.com/apache/druid/pull/10033

<a name="19-bugs" href="#19-bugs">#</a> バグ修正

Druid 0.19.0 には 65 のバグ修正が含まれています。完全なリストはここ でご覧いただけます。

<a name="19-partition-non-atomic" href="#19-partition-non-atomic">#</a> バッチで取り込まれた「動的」パーティション化セグメントがアトミックにクエリ可能にならない問題を修正

Druid 0.19.0 は、バッチ取り込みタスクによって生成された「動的」パーティション化セグメントがパーティション全体の数を追跡していなかったという重要なクエリの正確性の問題を修正します。これは、これらのセグメントがオンラインになるときに、完全なセットとしてではなく、個々のセグメントとしてオンラインになることを意味します。つまり、タイム チャンク内で不完全なパーティション セットから結果をクエリできるスワップ期間が発生することになります。 https://github.com/apache/druid/pull/10025

<a name="19-partition-empty-buckets" href="#19-partition-empty-buckets">#</a> 空のバケットを持つ「ハッシュ」および「レンジ」パーティション セグメントをクエリできるように修正しました。

0.19.0 より前は、Druid にはハッシュまたは範囲パーティション分割を使用するときにバグがあり、取り込み後にバケットのいずれかが「空」になるようなデータ スキューがある場合、パーティションは「完全」とは認識されず、クエリ可能になりません。 Druid 0.19.0 は、パーティショニング仕様のスキーマを調整することでこの問題を修正します。 json 形式に対するこれらの変更は下位互換性を持つ必要がありますが、以前のバージョンにロールバックすると、これらのセグメントは再びクエリできなくなります。 https://github.com/apache/druid/pull/10012

<a name="19-bad-balancer" href="#19-bad-balancer">#</a> バランサーの動作が正しくありません

0.19.0 より前の Druid バージョンのバグにより、druid.server.maxSize が設定されていない場合に (誤った) コーディネーター操作が可能でした。このバグにより、すべてのヒストリカルにこの値が設定されていない場合、セグメントがロードされ、(実際にどのようなバランサー戦略が構成されているかに関係なく) クラスター内で効果的にランダムにバランスをとることが可能になります。このバグは修正されましたが、その結果、druid.server.maxSize をヒストリカルのセグメント キャッシュの場所のサイズの合計に設定する必要があります。そうしないと、セグメントがロードされません。 https://github.com/apache/druid/pull/10070

<a name="19-upgrading-from-previous" href="#19-upgrading-from-previous">#</a> Druid 0.19.0 へのアップグレード

0.18.1 から 0.19.0 にアップグレードする場合は、次の問題に注意してください。 0.18.1 よりも前のバージョンから更新する場合は、関連する中間バージョンの release note を参照してください。

<a name="19-server-size" href="#19-server-size">#</a> 履歴サーバーには「druid.server.maxSize」を設定する必要があります

コーディネーターのバグ修正 の副作用として、セグメントをロードするために druid.server.maxSize を設定する必要があります。この値は以前のバージョンでは正しく設定されているはずですが、クラスターをアップグレードする前にこの値が正しく設定されていることを確認してください。そうしないとセグメントがロードされません。 https://github.com/apache/druid/pull/10070

<a name="19-sys-segments-payload" href="#19-sys-segments-payload">#</a> システム テーブルの「sys.segments」列「payload」が削除され、「dimensions」、「metrics」、「shardSpec」に置き換えられました。

sys.segments テーブルから「ペイロード」列を削除すると、このテーブルに対するクエリがはるかに効率的になるはずです。また、このテーブルの最も有用なフィールドである「ディメンション」、「メトリクス」、および「shardSpec」のリストは分割されているため、引き続きクエリの処理に使用できます。 https://github.com/apache/druid/pull/9883

<a name="19-segment-load-threads" href="#19-segment-load-threads">#</a> セグメント読み込みスレッドのデフォルト数を変更しました

druid.segmentCache.numLoadingThreads 構成では、デフォルト値が「コア数」から「コア数」を 6 で割った値に変更されました。これにより、多数のセグメントをロードする際のヒストリカルの動作が初期状態より少し良くなり、クエリのパフォーマンスへの影響が制限されます。 https://github.com/apache/druid/pull/9856

<a name="19-broadcast-colocated" href="#19-broadcast-colocated">#</a> ブロードキャスト負荷ルールに「併置データソース」が含まれなくなりました

ブロードキャスト ロード ルールを利用してクラスタ間でより小さなデータソースを伝播し、結合操作を個々のセグメント処理にプッシュダウンできるようにするというアイデアに基づいて、より効率的な結合クエリを促進するための不完全な変更が 0.19.0 に追加されました。まだ完成した機能ではありませんが、これを実現するための変更の一環として、「ブロードキャスト」負荷ルールには、構成されたデータソースのセグメントを持つサーバーにのみセグメントをブロードキャストしようとする「併置データソース」の概念がなくなりました。これは非アトミックであるため、実際にはあまりうまく機能しませんでした。つまり、ブロードキャスト セグメントが、同じ場所に配置されたデータソースのロードやドロップよりも遅れるため、これを削除することにしました。 https://github.com/apache/druid/pull/9971

<a name="19-broadcast-broker-load" href="#19-broadcast-broker-load">#</a> ブローカーとリアルタイム タスクは、「ブロードキャスト」データソースからセグメントをロードするように構成できるようになりました

効率的な「ブロードキャスト結合」を導入するための前述の準備作業のもう 1 つの効果として、セグメント キャッシュが設定されている場合、ブローカーおよびリアルタイム インデックス作成タスクは「ブロードキャスト」ルールによってロードされたセグメントをロードするようになります。この機能は完全ではないため、0.19.0 でこれを実行する理由はほとんどなく、明示的に構成しない限り実行されません。 https://github.com/apache/druid/pull/9971

<a name="19-lpad-rpad" href="#19-lpad-rpad">#</a> lpad および rpad 機能の動作の変更

lpad および rpad 関数は、PostgreSQL と一貫して動作するようにするために、Druid のデフォルトの非 SQL 互換モードで動作がわずかに変更されました。新しい動作では、埋め込み式が空の文字列の場合、空の文字列が null として扱われて結果が null に強制されるのではなく、結果は (おそらくトリミングされた) 元の文字になります。 https://github.com/apache/druid/pull/10006

<a name="19-interfaces" href="#19-interfaces">#</a> カスタム Druid 式を提供する拡張機能は、equals メソッドと hashCode メソッドを実装することが期待されるようになりました。

Druid 0.19.0 の Expr インターフェイスへの変更では、ExprMacroTable 経由でカスタム式を提供する拡張機能が正しく機能するために、特に JOIN クエリで、クエリを最適に処理する方法を決定するフィルターと式の分析に依存する equals および hashCode メソッドも実装する必要があります。 https://github.com/apache/druid/pull/9830

<a name="19-known-issues" href="#19-known-issues">#</a> 既知の問題

未解決の問題の完全なリストについては、https://github.com/apache/druid/labels/Bug. を参照してください。
