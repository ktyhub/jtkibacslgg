#ドルイドドルイド-0.7.0

Druid 0.7.0 へのアップデート – 注意すべきこと

  • 新しい取り込み仕様 Druid 0.7.0 には、新しい取り込み仕様形式が必要です。 Druid 0.6.172 は、古い形式と新しい形式の両方の取り込みをサポートしており、古い形式から新しい形式に変換するスクリプトを備えています。このスクリプトは、Druid ノードの実行に使用されるのと同じ Main を使用して「tools ConvertSpec」で実行できます。 Druid クラスターを 0.6.172 に更新し、取り込み仕様を新しい形式に更新してから、Druid 0.7.0 に更新できます。クラスターを Druid 0.7.0 に直接更新する場合は、リアルタイム取り込みパイプラインが新しい仕様を理解していることを確認してください。
  • MySQL はデフォルトのメタデータ ストレージではなくなりました Druid は現在、デフォルトで Apache Derby を埋め込むようになりました。これは主にテスト容易性の目的で選択されました。ただし、運用環境で Derby を使用することはお勧めしません。テスト以外の場合は、MySQL または PostgreSQL メタデータ ストレージを使用してください。 メタデータ ストレージの構成パラメータ の名前が druid.db から druid.metadata.storage に変更され、Derby 以外を使用するには追加の druid.metadata.storage.type=<mysql|postgresql> が必要です。 convertProps ツールは、すべての 0.6.x プロパティを 0.7 プロパティに変換するのに役立ちます。
  • ドルイドでは大文字と小文字が区別されるようになりました Druid の列名では大文字と小文字が区別されるようになりました。以前は、クエリでは大文字と小文字を区別せず、データでは大文字と小文字を保持しようとしましたが、さまざまな大文字と小文字の問題に関連するバグが多数あったため、この変更を行うことにしました。 バージョン 0.6.x からアップグレードする場合:
    1. クエリ内の列の大文字と小文字がデータ内の列名の大文字と小文字が一致していることを確認し、それに応じてクエリを更新してください。
    2. 注意すべき非常に重要な点は、0.6 が取り込み時およびクエリ時に内部的にすべての列名を小文字にすることです。 0.7 では、これは当てはまりませんが、わかりやすくするために 0.7 では小文字の列名を使用することを強くお勧めします。
    3. 現在、データまたは取り込みスキーマの一部として大文字と小文字が混合された列名を持つデータを取り込んでいる場合:
      • TSV または CSV データの場合は、0.7.0 に更新するときにスキーマ内の列名を小文字にするだけです。
      • 大文字と小文字が混合されたフィールドを含む JSON データの場合、および列の名前を指定していない場合は、jsonLowerCase parseSpec を使用して、取り込み時にデータを小文字にし、下位互換性を維持できます。 他のすべての解析仕様では、 以前に大文字と小文字を混合して使用していた場合は、メトリック/アグリゲーター名。
  • バッチセグメントアナウンスがデフォルトになりました Druid は、デフォルトですべてのノードに対してバッチ セグメント アナウンスを使用するようになりました。すでに バッチ セグメント アナウンス を使用している場合は、準備完了です。 バッチ セグメント アナウンスメントを使用するようにまだ更新していない場合は、最初にバッチ アナウンスメントを使用するように現在の 0.6.x クラスターを更新する方法について フォーラムのこのガイド をお読みください。
  • Kafka 0.8.x を優先して Kafka 0.7.x を削除 Kafka 0.7 を使用している場合は、kafka-seven 拡張機能を手動で構築する必要があります。 Kafka 0.7 は Maven Central では使用できないため、ビルドではコメントアウトされています。 Kafka 0.8 (kafka-eight) 拡張子は影響を受けません。
  • コーディネーター エンドポイントの変更 多くのコーディネーター エンドポイントが変更されました。それらが何であるかについては、コーディネーターのドキュメント を参照してください。 特に：
  1. コーディネーターの /info が削除されました。
  2. 履歴ノードの /health が削除されました
  • com.metamx.metrics.SysMonitorには別のジャーが必要 現在、druid.monitoring.monitors 構成の一部として com.metamx.metrics.SysMonitor があり、それを保持したい場合は、SIGAR ライブラリ jar をクラスパスに追加する必要があります。 あるいは、sys/.* メトリックに依存しない場合は、単純に com.metamx.metrics.SysMonitor を削除することもできます。 現在、SIGAR は Maven Central で利用できないため、Druid アーティファクトを Maven Central に移動するには、SIGAR への直接の依存関係を削除する必要がありました。
  • アップデート手順 0.6.172 より古いバージョンの Druid を実行している場合は、まず 0.6.172 にアップグレードしてください。手順については、0.6.172 release notes を参照してください。 ダウンタイムなしでスムーズなローリング アップグレードを確実に行うには、ノードを次の順序で更新する必要があります。
    1. 履歴ノード
    2. インデックスサービス/リアルタイムノード
    3. ルーターノード (ある場合)、
    4. ブローカーノード
    5. コーディネーターノード

新機能

  • 長いメトリック列のサポート これまで、Druid はすべてのメトリクスを単精度浮動小数点値として保存していたため、longSum アグリゲーターを使用したクエリ (特に groupBy クエリ) で丸め誤差や予期せぬ結果が発生する可能性がありました。
  • プラグ可能なメタデータ ストレージ MySQL、PostgreSQL、および Derby (テスト用) がそのままサポートされるようになりました。 Derby は単一マスターのみをサポートするか、高可用性本番環境には使用しないでください。そのためには MySQL または PostgreSQL フェイルオーバーを使用してください。
  • 簡素化されたデータ取り込み API Druid のデータ取り込み API を完全にやり直します。
  • メトリック列の圧縮を LZF から LZ4 に切り替えます 初期パフォーマンス テストでは、通常のデータ セットでは 15% ～ 25% 高速化され、セグメントが約 3 ～ 5% 小さくなる可能性があることが示されています。
  • 構成可能な反転ビットマップ インデックス Druid は、デフォルトの Concise Bitmaps に加えて Roaring Bitmaps をサポートするようになりました。初期のパフォーマンス テストでは、セグメントが平均 20% 大きくなる代わりに、特定の種類のクエリでは Roaring が最大 20% 高速になる可能性があることが示されています。
  • 統合テスト Docker を使用して Druid クラスターを起動し、一連のインデックス作成およびクエリ テストを実行する一連の統合テストを追加しました。
  • 新しいドルイドコーディネーターコンソール 新しい Druid コンソールを導入しました。これにより、クラスターのステータスの概要がよりわかりやすく表示され、数十万のセグメントがある場合の拡張性がさらに向上します。このコンソールを拡張して、Druid クラスターの現在の状態に関する詳細情報を提供する予定です。
  • クエリ結果のコンテキスト 結果コンテキストは、クエリ ヘッダーでクエリ中にエラーを報告できます。現在、この機能は内部再試行に使用されていますが、より多くの情報を clients に報告できるように拡張したいと考えています。

改善点

  • クエリ速度の高速化 圧縮形式の高速化、列構造の小規模な最適化、複数の集計によるクエリの最適化、さらに groupBy クエリのパフォーマンスの多数の向上により、速度が大幅に向上しました。 全体として、一部のクエリは、新しいインデックス形式を使用すると最大 2 倍高速になります。
  • Maven Central のドルイドのアーティファクト Druid アーティファクトが Maven Central で利用可能 になり、独自のビルドとデプロイメントが容易になります。
  • 共通設定ファイル Druid には、すべてのグローバル プロパティとすべての外部依存関係を宣言できる common.runtime.properties が追加されました。これにより、複数のノード間で構成を繰り返すことがなくなり、Druid クラスターのセットアップの負担が少し軽減されることが期待されます。
  • デフォルトのホスト名、ポート、サービス名 すべてのノードのホスト名、ポート、およびサービス名がデフォルトであるため、デフォルトで十分であれば、事前に必要な設定が大幅に少なくなります。また、ポートの競合を気にせずに、単一マシン上ですべてのノード タイプを実行できることも意味します。
  • Druid の列名では大文字と小文字が区別されるようになりました 筐体のバグで死ぬ。大文字と小文字が混在する列があり、0.6.x を使用している場合は、0.7.0 に更新する危険性に注意してください。詳細については上記を参照してください。
  • クエリの再試行 Druid は、特定のクラスの失敗に対してクエリを自動的に再試行するようになりました。
  • バックグラウンド キャッシュ 特定の種類のクエリ、特に個別の (ハイパーログログ) カウントを伴うクエリの場合、これによりパフォーマンスが 20% 以上向上する可能性があります。 バックグラウンド キャッシュはデフォルトでは無効になっています。
  • コーディネーターのメモリ使用量の削減 コーディネーターのメモリ使用量を削減 (最大 50%)。これにより、頻繁な GC によりコーディネーターがリーダーシップを失うことがある問題が修正されます。
  • メトリクスを SSL エンドポイントに送信できるようになりました
  • 追加の AWS 認証情報のサポート、@gnethercutt に感謝します
  • リアルタイム取り込みのための追加の持続およびスロットル メトリクス これは、リアルタイムの取り込みがいつ調整されているか、および永続化にどれくらいの時間がかかっているかを診断するのに役立ちます。これらのメトリクスは、リアルタイム取り込みをスケールアップする時期を示す適切な指標となります。
  • ブローカー初期化エンドポイント ブローカーは、クエリの準備ができているかどうかを示すステータス エンドポイントを /druid/broker/v1/loadstatus に提供するようになり、ローリング アップグレードや再起動が容易になります。

バグ修正

  • 同じリアルタイム ノード上の同じデータソースの複数のシャードをサポートします。ありがとう@zhaown
  • HDFS タスク ログが期待どおりに機能するようになりました。ありがとう@flowbehappy。
  • ブローカーで発生する可能性のあるデッドロック状態が修正されました。
  • 結果を返す際の GZIP 圧縮に関するさまざまな修正。
  • druid.host は IPv6 アドレスもサポートするようになりました。

ドキュメント

  • 新しいチュートリアル。
  • 新しい取り込みドキュメント。
  • 新しい構成ドキュメント。
  • ルールドキュメントの改善。ありがとう@mrijke

既知の問題

  • 現時点では、異なるタイプのビットマップ インデックスを持つセグメントをマージすることはできないため、クラスター内に両方のタイプのインデックスがある場合は、druid.coordinator.merge.on を false に設定する必要があります。 「false」は設定のデフォルト値です。
  • https://github.com/druid-io/druid/issues/1045 同じ名前を使用する複雑な集計と事後集計を含む GoupBy クエリの問題
  • https://github.com/druid-io/druid-api/pull/38 取り込み仕様でlongSumを使用している場合、浮動小数点データがあると例外がスローされる可能性があります。
