druida druida-0.10.0

Druid 0.10.0 contém centenas de melhorias de desempenho, melhorias de estabilidade e correções de bugs de mais de 40 colaboradores. Os principais novos recursos incluem uma camada SQL integrada, dimensões numéricas, suporte à autenticação Kerberos, uma reformulação da tarefa "index", um novo filtro "like", colunas grandes, capacidade de executar o coordenador e o overlord como um único serviço, padrões de melhor desempenho e oito novas extensões. Se você estiver atualizando de uma versão anterior do Druid, consulte "Atualizando de 0.9.2 e versões anteriores" abaixo para obter notas de atualização, incluindo algumas alterações incompatíveis com versões anteriores. A lista completa de alterações está aqui: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.10.0 A documentação para esta versão está em: http://druid.io/docs/0.10.0/

Destaques

SQL integrado

Druid agora inclui um servidor SQL integrado desenvolvido com Apache Calcite. Druid fornece dois SQL APIs: HTTP POST e JDBC. Isso fornece uma alternativa ao JSON API nativo do Druid, que é mais familiar para novos desenvolvedores e que torna mais fácil a integração de aplicativos pré-existentes que falam SQL nativamente. Nem todos os recursos Druid e SQL são suportados pela camada SQL nesta versão inicial, mas pretendemos expandir ambos em versões futuras. O suporte SQL pode ser ativado definindo druid.sql.enable=true em sua configuração. Consulte http://druid.io/docs/0.10.0/querying/sql.html para obter detalhes e documentação. Adicionado em #3682 por @gianm.

Dimensões numéricas

Druid agora oferece suporte a dimensões numéricas no momento da ingestão e da consulta. Os usuários podem ingerir colunas longas e flutuantes como dimensões (ou seja, tratar as colunas numéricas como parte da chave de agrupamento de tempo de ingestão em vez de como agregadores, se o rollup estiver habilitado). Além disso, as consultas Druid agora podem aceitar qualquer coluna longa ou flutuante como dimensão para agrupamento ou filtragem. Existem compensações de desempenho entre colunas de string e numéricas. Colunas numéricas geralmente são mais rápidas de agrupar do que colunas de string. Colunas numéricas não têm índices, portanto geralmente são mais lentas para filtrar do que colunas de string. Consulte http://druid.io/docs/0.10.0/ingestion/schema-design.html#numeric-dimensions para documentação de ingestão e http://druid.io/docs/0.10.0/querying/dimensionspecs.html para documentação de consulta. Adicionado em #3838, #3966 e outros patches por @ jon-wei.

Suporte à autenticação Kerberos

Adicionada uma nova extensão chamada 'druid-kerberos' que adiciona suporte para autenticação de usuário para nós druidas usando Kerberos. Utiliza o mecanismo de negociação simples e protegido GSSAPI, SPNEGO(https://en.wikipedia.org/wiki/SPNEGO) para autenticação via HTTP. Consulte http://druid.io/docs/0.10.0/development/extensions-core/druid-kerberos.html para obter documentação sobre como configurar a autenticação Kerberos. Adicionado em #3853 por @nishantmonu51.

Renovação da tarefa de índice

A tarefa de indexação foi reescrita para melhorar o desempenho, especialmente para trabalhos que abrangem vários intervalos e que geravam muitos fragmentos. O segmentGranularity intervals agora pode ser determinado automaticamente e não precisa mais ser especificado, mas o tempo de ingestão pode ser reduzido se intervals e numShards forem fornecidos. Além disso, a tarefa de indexação agora oferece suporte a um sinalizador appendToExisting que faz com que os dados sejam indexados como um fragmento adicional da versão atual, em vez de como uma nova versão ofuscando a versão anterior. Consulte http://druid.io/docs/0.10.0/ingestion/tasks.html#index-task para documentação. Adicionado em #3611 por @dclim.

Curtir filtro

Druid agora inclui um filtro "like" que permite a filtragem no estilo SQL LIKE, como foo LIKE 'bar%'. A implementação é geralmente mais rápida que os filtros regex e é incentivada em relação aos filtros regex quando possível. Em particular, filtros semelhantes em prefixos como bar% são significativamente mais rápidos do que filtros regex equivalentes como ^bar.*. Consulte http://druid.io/docs/0.10.0/querying/filters.html#like-filter para documentação. Adicionado em #3642 por @gianm.

Colunas grandes

Druid agora oferece suporte a colunas individuais maiores que 2 GB. Esse recurso normalmente não é necessário, pois a orientação geral é que os segmentos geralmente devem ter de 500 MB a 1 GB de tamanho, mas é útil em situações em que uma coluna é muito maior que todas as outras (por exemplo, esboços grandes). Esta funcionalidade está disponível para todos os usuários Druidas e nenhuma configuração especial é necessária ao usar os tipos de colunas integrados. Se você desenvolveu um tipo de coluna métrica customizada como uma extensão Druid, poderá ativar o suporte a colunas grandes substituindo getSerializer em seu ComplexMetricsSerde. Adicionado em #3743 por @akashdw.

Opção de combinação Coordenador/Overlord

As implantações de Druidas agora podem ser simplificadas combinando as funções de Coordenador e Overlord no processo de Coordenador. Para fazer isso, defina druid.coordinator.asOverlord.enabled e druid.coordinator.asOverlord.overlordService apropriadamente em seus Coordenadores e então pare seus Overlords. O console Overlord estaria disponível no http://coordinator-host:port/console.html. Atualmente, este é um recurso experimental e está desativado por padrão. Pretendemos considerar tornar isso o padrão em uma versão futura do Druid. Consulte http://druid.io/docs/0.10.0/configuration/coordinator.html para documentação sobre este recurso e opções de configuração. Adicionado em #3711 por @himanshug.

Padrões de melhor desempenho

Esta versão altera duas configurações padrão para melhorar o desempenho imediato:

  • A opção buildV9Directly introduzida no Druid 0.9.0 agora está habilitada por padrão. Esta opção melhora o desempenho da indexação criando o formato de dados v9 diretamente, em vez de criar primeiro a v8 e depois converter para v9. Se necessário, você pode reverter para o código antigo definindo "buildV9Directly" como false em suas tarefas de indexação.
  • O mecanismo groupBy v2 introduzido no Druid 0.9.2 agora está habilitado por padrão. Este novo mecanismo groupBy foi reescrito desde o início para melhor desempenho e gerenciamento de memória. Se necessário, você pode reverter para o mecanismo antigo definindo "druid.groupBy.query.defaultStrategy" em seu runtime.properties ou "groupByStrategy" em seu contexto de consulta, como "v1". Consulte http://druid.io/docs/0.10.0/querying/groupbyquery.html para obter detalhes sobre as diferenças entre groupBy v1 e v2.

Atualizando do 0.9.2 e versões anteriores

Veja abaixo as alterações entre 0.9.2 e 0.10.0 que você deve conhecer antes de atualizar. Se você estiver atualizando de uma versão anterior ao 0.9.2, consulte release notes das versões intermediárias relevantes para obter notas adicionais.

Atualizações contínuas

O processo padrão de atualização do Druid descrito por http://druid.io/docs/0.10.0/operations/rolling-updates.html deve ser seguido para atualizações contínuas.

Consultar alterações do API

Observe que a seguinte consulta incompatível com versões anteriores API muda durante a atualização. Algumas consultas podem precisar ser ajustadas para continuarem a se comportar conforme o esperado.

  • Os recursos de consulta JavaScript agora estão desabilitados por padrão por motivos de segurança (#3818). Se você usar esses recursos, poderá reativá-los configurando druid.javascript.enabled=true nas propriedades de tempo de execução. Consulte http://druid.io/docs/0.10.0/development/javascript.html para obter detalhes, incluindo considerações de segurança.
  • Consultas GroupBy não permitem mais __time como nome de saída de uma dimensão, agregador ou pós-agregador (#3967).
  • Selecione query pagingSpecs agora assume como padrão o comportamento fromNext: true quando fromNext não é especificado (#3986). O comportamento permanece inalterado para consultas Select que tinham fromNext especificado. Se preferir o padrão antigo, você pode alterar isso através da propriedade de tempo de execução druid.query.select.enableFromNextDefault. Consulte http://druid.io/docs/0.10.0/querying/select-query.html para obter detalhes.
  • As consultas SegmentMetadata não incluem mais análise de "tamanho" por padrão (#3773). Você ainda pode solicitar a análise de "tamanho" adicionando "tamanho" a "análiseTipos" no momento da consulta.

Mudanças de implantação e configuração

Observe as seguintes alterações relacionadas à implantação durante a atualização.

  • Druid agora requer Java 8 para rodar (#3914). Se você estiver executando o Java 7, sugerimos atualizar primeiro o Java e depois o Druid.
  • Druid agora usa como padrão o mecanismo "v2" para groupBy em vez do mecanismo legado "v1". Como parte disso, os limites de uso de memória foram alterados de limites baseados em linhas para limites baseados em bytes, portanto, é possível que algumas consultas que atendiam aos limites de recursos anteriormente os excedam e falhem. Você pode evitar isso ajustando o novo mecanismo groupBy adequadamente. Se necessário, você pode reverter para o mecanismo antigo definindo "druid.groupBy.query.defaultStrategy" em seu runtime.properties ou "groupByStrategy" em seu contexto de consulta, como "v1". Consulte http://druid.io/docs/0.10.0/querying/groupbyquery.html para obter mais detalhes sobre as diferenças entre groupBy v1 e v2.<p>Este novo mecanismo groupBy foi reescrito do zero para melhor desempenho e gerenciamento de memória. A consulta API e os resultados são compatíveis entre os dois motores; no entanto, existem algumas diferenças do ponto de vista da configuração do cluster: (1) groupBy v2 usa principalmente memória fora do heap em vez de memória no heap; (2) requer um buffer de mesclagem para cada consulta simultânea; (3) se você configurou o cache para groupBy, ele deve estar nos históricos; e (4) não suporta chunkPeriod.
  • Druid agora tem um valor padrão diferente de zero para druid.processing.numMergeBuffers (#3953). Isto aumentará a quantidade de memória direta usada em sua configuração padrão. Essa alteração foi feita em conexão com a alteração do mecanismo groupBy padrão, uma vez que o novo mecanismo "v2" requer buffers de mesclagem. Se você estava usando groupBy v1 anteriormente, poderá compensar isso reduzindo seu heap JVM, já que groupBy v2 usa memória fora do heap em vez de memória on-heap.
  • Processos relacionados a consultas druidas (corretor, histórico, tarefas de indexação) agora alocam ansiosamente o número druid.processing.numThreads de instâncias DirectByteBuffer de tamanho druid.processing.buffer.sizeBytes para processamento de consultas na inicialização (#3628). Essa alocação era preguiçosa nas versões anteriores do Druid. Essa alteração não afeta o uso da memória de um cluster Druid de longa execução, mas significa que a memória para processamento de buffers deve estar disponível quando o Druid for inicializado.
  • Ao executar em fusos horários diferentes do UTC, o comportamento das constantes segmentGranularity predefinidas, como "dia", mudará durante a atualização. Anteriormente, isso geraria segmentos usando dias locais. No Druid 0.10.0, isso irá gerar segmentos usando dias UTC. Se você estava executando o Druid no fuso horário UTC, essa alteração não terá efeito. Observe que a execução do Druid em um fuso horário diferente do UTC não é oficialmente suportada (consulte http://druid.io/docs/0.10.0/configuration/index.html) e recomendamos sempre executar todos os processos em fusos horários UTC. Para criar segmentos de dia local usando Druid 0.10.0, você pode usar um segmentGranularity de horário local como:
"segmentGranularity" : {
     "type" : "period",
     "period" : "P1D",
     "timeZone" : "America/Los_Angeles"
}

Mudanças de extensão

  • As interfaces AggregatorFactory, BufferAggregator e PostAggregator foram alteradas (#3894, #3899, #3957, #4071). Se você implantou uma extensão personalizada que inclui AggregatorFactory ou PostAggregator, ela precisará ser recompilada. Todas as extensões integradas do Druid foram atualizadas para esta mudança.
  • Extensões direcionadas ao Druid 0.10.x devem ser compiladas com JDK 8.
