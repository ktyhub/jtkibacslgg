druida druida-0.14.0-incubating

Apache Druid (incubação) 0.14.0-incubating contém mais de 200 novos recursos, melhorias de desempenho/estabilidade/documentação e correções de bugs de 54 colaboradores. Os principais novos recursos e melhorias incluem:

  • Novo console web
  • Serviço de indexação Amazon Kinesis
  • Modo de descomissionamento para históricos
  • Cache de segmento publicado no Broker
  • Agregador e expressão de filtro Bloom
  • Extensão Apache Parquet atualizada
  • Opção de forçar push down para consultas GroupBy aninhadas
  • Melhor transferência de segmento e tratamento de regras de eliminação
  • Elimina automaticamente os trabalhos do MapReduce quando as tarefas de ingestão do Apache Hadoop são eliminadas
  • Suporte a tags DogStatsD para emissor statsd
  • Novo API para recuperar todas as especificações de pesquisa
  • Novas opções de compactação
  • Estratégia de balanceamento de segmento de cacheCost mais eficiente A lista completa de alterações está aqui: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 A documentação para esta versão está em: http://druid.io/docs/0.14.0-incubating/

Destaques

Novo console web

Druid tem um novo console web que fornece funcionalidades que anteriormente eram divididas entre os consoles coordenador e overlord. O novo console permite ao usuário gerenciar fontes de dados, segmentos, tarefas, processos de dados (Históricos e MiddleManagers) e configuração dinâmica do coordenador. O usuário também pode executar consultas SQL e Druid nativas no console. Para mais detalhes, consulte http://druid.io/docs/0.14.0-incubating/operations/management-uis.html Adicionado por @vogievetsky em #6923.

Serviço de indexação Kinesis

Druid agora oferece suporte à ingestão de streams do Kinesis, fornecida pela nova extensão principal druid-kinesis-indexing-service. Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html para obter detalhes. Adicionado por @jsun98 em #6431.

Modo de desativação para históricos

Os processos históricos agora podem ser colocados em modo de “descomissionamento”, onde o coordenador não considerará mais o processo histórico como um alvo para replicação do segmento. O coordenador também retirará segmentos do histórico de descomissionamento. Isto é controlado através da configuração dinâmica do Coordenador. Para mais detalhes, consulte http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration. Adicionado por @egor-ryashin em #6349.

Cache de segmento publicado no Broker

O Druid Broker agora tem a capacidade de manter um cache de segmentos publicados por meio de pesquisa no Coordenador, o que pode melhorar significativamente o tempo de resposta para consultas de metadados na tabela do sistema sys.segments. Consulte http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata para obter detalhes. Adicionado por @surekhasaharan em #6901

Agregador e expressão de filtro Bloom

Um novo agregador para construir filtros Bloom no momento da consulta e suporte para realizar verificações de filtros Bloom em expressões Druid foram adicionados à extensão druid-bloom-filter. Por favor consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html Adicionado por @clintropolis em #6904 e #6397

Extensão Parquet atualizada

druid-extensions-parquet foi movido para o conjunto de extensões principal das extensões de contribuição e agora suporta valores de nivelamento e int96. Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html para obter detalhes. Adicionado por @clintropolis em #6360

Forçar opção push down para consultas GroupBy aninhadas

A execução de consulta externa para consultas GroupBy aninhadas agora pode ser transferida para processos históricos; anteriormente, as consultas externas sempre seriam executadas no Broker. Consulte https://github.com/apache/incubator-druid/pull/5471 para obter detalhes. Adicionado por @samarthjain em #5471.

Melhor transferência de segmentos e tratamento de regras de retenção

A transferência de segmentos agora ignorará segmentos que seriam descartados pelas regras de retenção de uma fonte de dados, evitando falhas de ingestão causadas pelo problema nº 5868. As regras de carregamento do período agora incluirão o futuro por padrão. Uma nova regra "Período de suspensão anterior" foi adicionada. Consulte http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule para obter detalhes. Adicionado por @QiuMM em #6676, #6414 e #6415.

Elimina automaticamente os trabalhos do MapReduce quando as tarefas de ingestão do Hadoop são eliminadas

O Druid agora encerrará automaticamente os trabalhos MapReduce criados pelas tarefas de ingestão em lote do Hadoop quando a tarefa de ingestão for encerrada. Adicionado por @ankit0811 em #6828.

Suporte a tags DogStatsD para emissor de estatísticas

A extensão statsd-emitter agora suporta tags no estilo DogStatsD. Por favor veja http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html Adicionado por @deiwin em #6605, com suporte para tags constantes adicionadas por @glasser em #6791.

Novo API para recuperar todas as especificações de pesquisa

Foi adicionado um novo API para recuperar todas as especificações de pesquisa para todas as camadas. Consulte http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups para obter detalhes. Adicionado por @jihoonson em #7025.

Novas opções de compactação

A compactação automática agora suporta a opção maxRowsPerSegment. Consulte http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments para obter detalhes. A tarefa de compactação agora suporta uma nova opção segmentGranularity, descontinuando a opção keepSegmentGranularity mais antiga para controlar a granularidade de segmentos compactados. Consulte a tabela segmentGranularity em http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html para obter mais informações sobre essas propriedades. Adicionado por @jihoonson em #6758 e #6780.

Cache mais eficienteEstratégia de balanceamento de segmento de custo

A estratégia de balanceamento do segmento cachingCost Coordinator agora considerará apenas processos históricos para decisões de balanceamento. Anteriormente, a estratégia também consideraria desnecessariamente tarefas de trabalhadores ativos, que não são alvos para replicação de segmento. Adicionado por @QiuMM em #6879.

Novas métricas:

  • Nova métrica de taxa de alocação jvm/heapAlloc/bytes, adicionada por @egor-ryashin em #6710.
  • Nova métrica de contagem de consultas query/count, adicionada por @QiuMM em #6473.
  • Métricas de consulta SQL sqlQuery/bytes e sqlQuery/time, adicionadas por @gaodayue em #6302.
  • Métricas de atraso de ingestão Apache Kafka ingest/kafka/maxLag e ingest/kafka/avgLag, adicionadas por @QiuMM em #6587
  • Métricas de contagem de tarefas task/success/count, task/failed/count, task/running/count, task/pending/count, task/waiting/count, adicionadas por @QiuMM em #6657

Novas interfaces para desenvolvedores de extensões

RequestLogEvent

Agora é possível controlar os campos do RequestLogEvent, emitidos pelo EmittingRequestLogger. Consulte #6477 para obter detalhes. Adicionado por @leventov.

Verificações de certificado TLS personalizadas

Foi adicionado um ponto de extensão para verificações de certificados TLS personalizados. Consulte http://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checks para obter detalhes. Adicionado por @jon-wei em #6432.

O serviço de indexação Kafka não é mais experimental

A extensão Kafka Indexing Service saiu do status experimental.

Melhorias SQL

Melhorias no dsql

A linha de comando dsql client agora suporta histórico CLI, preenchimento automático básico e especificação de tempos limite de consulta no contexto de consulta. Adicionado em #6929 por @gianm.

Adicionar ID SQL, logs de solicitação e métricas

As consultas SQL agora têm um ID, e as consultas nativas executadas como parte de uma consulta SQL terão o ID da consulta SQL associado nos logs de solicitação da consulta nativa. As consultas SQL agora serão registradas nos logs de solicitação. Duas novas métricas, sqlQuery/time e sqlQuery/bytes, são agora emitidas para consultas SQL. Consulte http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging e http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics para obter detalhes. Adicionado por @gaodayue em #6302

Mais suporte para agregador SQL

Os seguintes agregadores agora são suportados em SQL:

  • Esboço DataSketches HLL
  • Esboço DataSketches Theta
  • Esboço de quantis DataSketches
  • Histograma de compartimentos fixos
  • Agregador de filtro Bloom Adicionado por @jon-wei em #6951 e @clintropolis em #6502

Outras melhorias de SQL

  • SQL: Adicione suporte para consultas com projeto após semijoin. #6756
  • SQL: Suporte para seleção de dimensões com vários valores. #6462
  • SQL: Suporte AVG em tabelas do sistema. #601
  • SQL: Adicionar função "POSIÇÃO". #6596
  • SQL: Defina o nome do catálogo INFORMATION_SCHEMA como "druid". #6595
  • SQL: Corrige a ordem de classificação, sortProject em DruidSemiJoin. #6769 Adicionado por @gianm.

Atualizando do 0.13.0-incubating e versões anteriores

Tempo de inatividade de ingestão do Kafka durante a atualização

Devido ao problema descrito em #6958, as tarefas existentes de indexação do Kafka podem ser encerradas desnecessariamente durante uma atualização contínua do Overlord. As tarefas encerradas serão reiniciadas pelo Overlord e funcionarão corretamente após a reinicialização inicial.

Alterações na extensão Parquet

A extensão druid-parquet-extensions foi movida de contrib para core. Ao implantar 0.14.0-incubating, certifique-se de que seu diretório extensions-contrib não possua versões mais antigas da extensão Parquet. Além disso, existem agora dois estilos de analisadores Parquet na extensão:

  • parquet-avro: Converte Parquet em Avro e depois analisa a representação Avro. Este era o analisador existente antes do 0.14.0-incubating.
  • parquet: Um novo analisador que analisa diretamente o formato Parquet. Somente este novo analisador suporta valores int96. Antes de 0.14.0-incubating, a especificação de um analisador do tipo parquet teria uma tarefa para usar o analisador de conversão Avro. No 0.14.0-incubating, para continuar usando o analisador de conversão Avro, você precisará atualizar suas especificações de ingestão para usar o parquet-avro. O campo inputFormat no inputSpec para tarefas que utilizam entrada Parquet também deve corresponder à escolha do analisador: -parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat -parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat Consulte http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html para obter detalhes.

Executando Druida com Hadoop não 2.8.3

Se você planeja usar o Druid 0.14.0-incubating com versões do Hadoop diferentes de 2.8.3, pode ser necessário fazer o seguinte:

  • Defina as coordenadas de dependência do Hadoop para sua versão de destino conforme descrito em http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html em Tip #3: Use specific versions of Hadoop libraries.
  • Reconstrua o Druid com sua versão alvo do Hadoop alterando hadoop.compile.version no Druid principal pom.xml e seguindo as instruções de construção padrão.

Outras mudanças de comportamento

Limpeza de tarefas antigas

As entradas de tarefas antigas no armazenamento de metadados agora serão limpas automaticamente junto com seus logs de tarefas. Consulte http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging e #6592 para obter detalhes.

Dimensionamento automático do buffer de processamento

A propriedade druid.processing.buffer.sizeBytes possui novo comportamento padrão caso não esteja configurada. O Druid agora escolherá automaticamente um valor para o tamanho do buffer de processamento usando a seguinte fórmula:

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

Onde:

  • totalDirectMemory: O limite de memória direta para o JVM especificado por -XX:MaxDirectMemorySize
  • numMergeBuffers: O valor de druid.processing.numMergeBuffers.
  • numProcessingThreads: O valor de druid.processing.numThreads. No máximo, o Druid usará 1 GB para o tamanho do buffer de processamento escolhido automaticamente. O tamanho do buffer de processamento ainda pode ser especificado manualmente. Consulte #6588 para obter detalhes.

As regras de retenção agora incluem o futuro por padrão

Esteja ciente de que as novas regras de retenção agora incluirão o futuro por padrão. Consulte #6414 para obter detalhes.

Mudanças de propriedade

Anúncio do segmento

A propriedade druid.announcer.type usada para escolher entre Zookeeper ou gerenciamento/descoberta de segmento baseado em HTTP foi movida para druid.serverview.type. Se você estava usando o http antes do 0.14.0-incubating, você precisará atualizar suas configurações para usar o novo druid.serverview.type. Consulte o seguinte para obter detalhes: -http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management -http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

corrigir propriedade ausente em JsonTypeInfo de SegmentWriteOutMediumFactory

A propriedade druid.peon.defaultSegmentWriteOutMediumFactory.@type foi corrigida. A propriedade agora é druid.peon.defaultSegmentWriteOutMediumFactory.type sem o “@”. Consulte #6656 para obter detalhes.

Depreciações

Agregador de histograma aproximado

O agregador proximatehistogram foi descontinuado; é um algoritmo dependente de distribuição sem limites formais de erro e tem problemas significativos de precisão. O agregador DataSketches quantiles deve ser usado para casos de uso de quantis e histogramas. Consulte Agregadores de histograma e quantis

Agregador de cardinalidade/hiperúnico

Os agregadores Cardinality e HyperUnique foram descontinuados em favor do agregador DataSketches HLL e do agregador Theta Sketch. Esses agregadores possuem melhores características de precisão e desempenho. Consulte Contar agregadores distintos para obter detalhes.

Período do bloco de consulta

A configuração do contexto de consulta chunkPeriod agora está obsoleta, juntamente com a métrica query/intervalChunk/time associada. Consulte #6591 para obter detalhes.

keepSegmentGranularity para compactação

A opção keepSegmentGranularity para tarefas de compactação foi descontinuada. Consulte #6758 e a tabela segmentGranularity em http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html para obter mais informações sobre essas propriedades.

Mudanças na interface para desenvolvedores de extensões

Classe SegmentId

Druid agora usa uma classe SegmentId em vez de Strings simples para representar IDs de segmento. Consulte #6370 para obter detalhes. Adicionado por @leventov.

druid-api, druid-common, java-util movidos para druid-core

Os módulos druid-api, druid-common, java-util foram movidos para druid-core. Atualize suas dependências adequadamente se o seu projeto dependesse dessas bibliotecas. Consulte #6443 para obter detalhes.
