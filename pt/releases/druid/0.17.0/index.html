druida druida-0.17.0

Apache Druid 0.17.0 contém mais de 250 novos recursos, melhorias de desempenho, correções de bugs e principais melhorias na documentação de 52 colaboradores. Confira a lista completa de alterações e tudo marcado com o marco.

Destaques

Melhorias na ingestão em lote

Druid 0.17.0 inclui uma atualização significativa para o sistema nativo de ingestão em lote. Esta atualização adiciona a estrutura interna para suportar formatos binários não textuais, com suporte inicial para ORC e ​​Parquet. Além disso, as tarefas em lote nativas agora podem ler dados do HDFS. Esse retrabalho altera a forma como a origem de ingestão e o formato de dados são especificados na tarefa de ingestão. Para usar os novos recursos, consulte a documentação sobre InputSources e InputFormats. Consulte a seguinte documentação para obter detalhes: https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

Particionamento de intervalo de dimensão única para ingestão de lote nativo paralelo

A tarefa de índice paralelo agora suporta a especificação de partições do tipo single_dim, que permite o particionamento baseado em intervalo em uma única dimensão. Consulte https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html para obter detalhes.

Mudanças de compactação

Dicas de divisão de tarefa de índice paralelo

A tarefa de indexação paralela agora possui uma nova configuração, splitHintSpec, no tuningConfig para permitir que os operadores forneçam dicas para controlar a quantidade de dados que cada subtarefa da primeira fase lê. Atualmente existe um tipo de especificação de dica dividida, SegmentsSplitHintSpec, usado para reingerir segmentos Druidas.

Compactação automática paralela

A compactação automática agora pode usar a tarefa de indexação paralela, permitindo maior rendimento de compactação. Para controlar o nível de paralelismo, a autocompactaçãotuningConfig conta com novos parâmetros, maxNumConcurrentSubTasks e splitHintSpec. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration para obter detalhes. https://github.com/apache/incubator-druid/pull/8570

Compactação automática com estado

A compactação automática agora usa o partitionSpec para rastrear alterações feitas por tarefas de compactação anteriores, permitindo ao coordenador reduzir operações de compactação redundantes. Consulte https://github.com/apache/druid/issues/8489 para obter detalhes. Se você tiver a compactação automática ativada, consulte as informações em "Alterações de compactação automática com estado" na seção "Atualizando para Druid 0.17.0" antes de atualizar.

Consulta paralela mesclada em corretores

O corretor Druid agora pode mesclar resultados de consulta de forma oportunista em paralelo usando vários threads. Consulte druid.processing.merge.useParallelMergePool na seção Broker da referência de configuração para obter detalhes sobre como configurar esse novo recurso. A mesclagem paralela é habilitada por padrão (controlada pela propriedade druid.processing.merge.useParallelMergePool) e a maioria dos usuários não deve precisar alterar nenhuma das propriedades de configuração avançadas descritas na referência de configuração. Além disso, o paralelismo de mesclagem pode ser controlado por consulta usando o contexto de consulta. Informações sobre os novos parâmetros de contexto de consulta podem ser encontradas em https://druid.apache.org/docs/0.17.0/querying/query-context.html. https://github.com/apache/incubator-druid/pull/8578

Tratamento nulo compatível com SQL

No 0.17.0, adicionamos documentação oficial para o modo de tratamento nulo compatível com SQL do Druid. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling e https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling para obter detalhes. Vários bugs que existiam neste modo anteriormente não documentado foram corrigidos, especialmente em torno do tratamento de nulos em colunas numéricas. Recomendamos que os usuários comecem a considerar a transição de seus clusters para este novo modo após atualizarem para 0.17.0. A lista completa de bugs de manipulação de nulos corrigidos em 0.17.0 pode ser encontrada em https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+

Extensão LDAP

Druid agora suporta autenticação LDAP. A autorização usando grupos LDAP também é suportada pelo mapeamento de grupos LDAP para funções Druid.

  • A autenticação LDAP é tratada especificando um validador de credenciais do tipo LDAP.
  • A autorização usando LDAP é tratada especificando um provedor de função do tipo LDAP e definindo mapeamentos de grupo LDAP->Druid dentro do Druid. A integração LDAP requer a extensão principal druid-basic-security. Consulte https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html para obter detalhes. Como esta é a primeira versão com suporte a LDAP e há uma grande variedade de ecossistemas LDAP, alguns casos de uso e recursos de LDAP podem ainda não ser suportados. Registre um problema se precisar de melhorias nesta nova funcionalidade. https://github.com/apache/incubator-druid/pull/6972

Emissor Dropwizard

Um novo emissor de métricas Dropwizard foi adicionado como uma extensão de contribuição. Os tipos de métricas do Dropwizard atualmente suportados são contador, medidor, medidor, cronômetro e histograma. Essas métricas podem ser emitidas usando um repórter Console ou JMX. Consulte https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html para obter detalhes. https://github.com/apache/incubator-druid/pull/7363

Recurso de autodescoberta

Um novo par de terminais foi adicionado a todos os serviços Druid que retornam informações sobre se o serviço Druid recebeu uma confirmação de que o serviço foi adicionado ao cluster, a partir do mecanismo central de descoberta de serviço (atualmente ZooKeeper). Esses endpoints podem ser úteis como verificações de integridade/prontidão. Os novos terminais são: -/status/selfDiscovered/status -/status/selfDiscovered Consulte o Druida referência API para obter detalhes. https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Tabela do sistema de supervisores

Os supervisores de tarefas (por exemplo, supervisores Kafka ou Kinesis) agora são registrados nas tabelas do sistema em uma nova tabela sys.supervisors. Consulte https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table para obter detalhes. https://github.com/apache/incubator-druid/pull/8547

Início histórico rápido com carregamento lento

Uma nova propriedade de configuração booleana para históricos, druid.segmentCache.lazyLoadOnStart, foi adicionada. Essa nova propriedade permite que os históricos adiem o carregamento de um segmento até a primeira vez que esse segmento é consultado, o que pode diminuir significativamente os tempos de inicialização do histórico para clusters com um grande número de segmentos. Consulte a referência de configuração para obter detalhes. https://github.com/apache/incubator-druid/pull/6988

Alteração na distribuição do cache de segmento histórico

Uma nova propriedade histórica, druid.segmentCache.locationSelectorStrategy, foi adicionada. Se houver vários locais de armazenamento de segmentos especificados em druid.segmentCache.locations, a nova propriedade locationSelectorStrategy permite ao usuário especificar qual estratégia será usada para preencher os locais. As opções atualmente suportadas são roundRobin e leastBytesUsed. Consulte a referência de configuração para obter detalhes. https://github.com/apache/incubator-druid/pull/8038

Novos endpoints de prontidão

Um novo endpoint do Broker foi adicionado: /druid/broker/v1/readiness. Um novo endpoint histórico foi adicionado: /druid/historical/v1/readiness. Esses terminais são semelhantes aos terminais /druid/broker/v1/loadstatus e /druid/historical/v1/loadstatus existentes. Eles diferem porque não exigem verificações de autenticação/autorização e, em vez de um corpo JSON, eles retornam apenas um código de resposta HTTP 200 bem-sucedido ou 503. https://github.com/apache/incubator-druid/pull/8841

Atribuição de tarefas de suporte com base nas categorias do MiddleManager

Agora é possível definir uma propriedade de nome de “categoria” para cada MiddleManager. Foram adicionadas novas estratégias de seleção de trabalhadores com reconhecimento de categoria, permitindo ao usuário controlar como as tarefas são atribuídas aos MiddleManagers com base nas categorias configuradas. Consulte a documentação do druid.worker.category na referência de configuração e nos links a seguir para obter mais detalhes: https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

Atualizações de vulnerabilidade de segurança

Um grande número de dependências foi atualizado para versões mais recentes para solucionar vulnerabilidades de segurança. Consulte os PRs abaixo para obter detalhes: -https://github.com/apache/incubator-druid/pull/8878 -https://github.com/apache/incubator-druid/pull/8980

Atualizando para Druida 0.17.0

A consulta nativa selecionada foi substituída

O tipo de consulta nativo Select obsoleto foi removido em 0.17.0. Se você tiver consultas nativas que usam Select, será necessário modificá-las para usar Scan. Consulte a documentação da consulta de varredura (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) para obter detalhes sobre sintaxe e formato de saída. Para consultas Druid SQL que usam Select, nenhuma alteração é necessária; o planejador SQL já usa o tipo de consulta Scan nos bastidores para consultas Select. https://github.com/apache/incubator-druid/pull/8739

Consoles antigos foram removidos

Os consoles legados do coordenador e do overlord foram removidos e substituídos pelo novo console da web no coordenador e no overlord. https://github.com/apache/incubator-druid/pull/8838

Atualização Calcite 1.21, tratamento nulo Druid SQL

Druida 0.17.0 atualiza Calcite para a versão 1.21. Esta versão mais recente do Calcite pode fazer otimizações adicionais que assumem um comportamento de tratamento nulo compatível com SQL ao planejar consultas. Se você usa Druid SQL e confia no comportamento de manipulação nula, leia as informações em https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling e certifique-se de que seu cluster Druid esteja sendo executado no modo de manipulação nula compatível com SQL antes de atualizar. https://github.com/apache/incubator-druid/pull/8566

Ajustes de registro

O Druid 0.17.0 organizou seu ciclo de vida, consultas e registro de ingestão. Consulte https://github.com/apache/incubator-druid/pull/8889 para obter uma lista detalhada de alterações. Se você dependia de mensagens de log específicas para integrações externas, revise as novas alterações de log antes de atualizar. O conjunto completo de mensagens de log ainda pode ser visto quando o log está definido para o nível DEBUG. Os arquivos de configuração do modelo log4j2 que mostram como ativar a criação de log DEBUG por pacote são fornecidos na pasta de configuração _common nos clusters de exemplo em conf/druid.

Mudanças de compactação automática com estado

A lógica de agendamento de compactação automática no 0.17.0 rastreia informações adicionais de particionamento de segmentos no armazenamento de metadados do Druid que não estão presentes em versões mais antigas. Essas informações são usadas para determinar se um conjunto de segmentos já foi compactado nas configurações atuais de compactação automática do cluster. Quando esses novos metadados não estiverem presentes, um conjunto de segmentos será sempre agendado para uma compactação inicial e esses novos metadados serão criados após serem compactados, permitindo ao escalonador ignorá-los posteriormente se a configuração da compactação automática não for alterada. Como esses metadados adicionais de particionamento de segmento não estão presentes antes de 0.17.0, a lógica de agendamento de compactação automática recompactará todos os segmentos dentro de uma fonte de dados uma vez após a atualização para 0.17.0. Essa recompactação em todo o conjunto de segmentos de cada fonte de dados com compactação automática habilitada significa que:

  • Haverá um período de transição após a atualização, onde mais tarefas totais de compactação serão enfileiradas do que em condições normais
  • O uso do armazenamento profundo aumentará à medida que todo o conjunto de segmentos for recompactado (o conjunto antigo de segmentos ainda será mantido no armazenamento profundo, a menos que seja explicitamente removido). Os usuários são aconselhados a estar cientes do aumento temporário nas tarefas de compactação programadas e do impacto no uso profundo do armazenamento. A documentação sobre remoção de segmentos antigos está localizada em https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

Propriedade targetCompactionSizeBytes removida

A propriedade targetCompactionSizeBytes foi removida da tarefa de compactação e da configuração de compactação automática. Para compactação automática, maxRowsPerSegment agora é uma configuração obrigatória. Para tarefas de compactação não automática, qualquer partitionsSpec pode ser usado. https://github.com/apache/incubator-druid/pull/8573

Tarefa de compactação tuningConfig

Devido às alterações de compactação automática paralela introduzidas por #8570, qualquer especificação de tarefa de compactação enviada manualmente precisa ser atualizada para usar um tipo index_parallel para a seção tuningConfig em vez de index. Essas alterações nas especificações devem ser aplicadas após o upgrade do cluster para 0.17.0. As configurações de compactação automática existentes podem permanecer inalteradas após a atualização; a compactação automática criará tarefas de compactação não paralelas até que as configurações da compactação automática sejam atualizadas para usar o paralelismo pós-atualização. Para controlar o nível de paralelismo, a autocompactaçãotuningConfig conta com novos parâmetros, maxNumConcurrentSubTasks e splitHintSpec. Consulte https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration para obter detalhes.

Tarefa de compactação ioConfig

A tarefa de compactação agora requer um ioConfig nas especificações da tarefa. Consulte https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig para obter detalhes. ioConfig não precisa ser adicionado às configurações de autocompactação existentes; o coordenador após a atualização criará automaticamente especificações de tarefa com seções ioConfig. https://github.com/apache/incubator-druid/pull/8571

Campos de especificação de partição renomeados

Os campos targetPartitionSize e maxSegmentSize nas especificações da partição foram descontinuados. Eles foram renomeados para targetNumRowsPerSegment e maxRowsPerSegment respectivamente. https://github.com/apache/incubator-druid/pull/8507

As métricas de cache estão desativadas por padrão

As métricas de cache agora estão desabilitadas por padrão. Para ativar métricas de cache, adicione "org.apache.druid.client.cache.CacheMonitor" à propriedade druid.monitoring.monitors. https://github.com/apache/incubator-druid/pull/8561

O Supervisor API foi alterado para ser consistente com a tarefa API

As especificações da tarefa do supervisor agora devem colocar as seções dataSchema, tuningConfig e ioConfig como subcampos de um campo spec. Consulte https://github.com/apache/incubator-druid/pull/8810 para obter exemplos. O formato antigo ainda é aceito no 0.17.0.

Mudança na semântica dos segmentos API

O endpoint /datasources/{dataSourceName}/segments no Coordenador agora retorna todos os segmentos usados (incluindo os sombreados) nos intervalos especificados, em vez de apenas os visíveis. https://github.com/apache/incubator-druid/pull/8564

Provedor de senha para autenticação básica de HttpEmitterConfig

A propriedade druid.emitter.http.basicAuthentication agora aceita um provedor de senha. Recomendamos atualizar suas configurações para usar um provedor de senha se estiver usando o emissor HTTP. https://github.com/apache/incubator-druid/pull/8618

Alteração na transformação da expressão de vários valores

A reutilização de colunas com valores múltiplos em expressões não resultará mais em explosões cartesianas desnecessárias. Consulte os links a seguir para obter detalhes. https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Ingestão de Kafka/Kinesis durante atualizações contínuas

Durante uma atualização contínua, se houver tarefas executando 0.17.0 e overlords executando versões mais antigas, e uma tarefa progrediu na leitura de dados de seu fluxo, mas rejeitou todos os registros que viu (por exemplo, todos não eram analisáveis), você verá NullPointerExceptions em overlords executando versões mais antigas quando a tarefa atualizar o overlord com seus deslocamentos de fluxo atuais. Anteriormente, havia um bug nesta área (https://github.com/apache/incubator-druid/issues/8765) onde tais tarefas não conseguiam comunicar seus deslocamentos atuais ao overlord. O protocolo de publicação de tarefa/overlord foi atualizado para corrigir isso, mas overlords mais antigos não reconhecem essa mudança de protocolo. Esta condição deve ser bastante rara.

Alteração da versão padrão do Hadoop

Druid 0.17.0 agora agrupa bibliotecas Hadoop 2.8.5 em vez de 2.8.3. Se você estivesse referenciando as bibliotecas 2.8.3 agrupadas em sua configuração por meio da propriedade druid.indexer.task.defaultHadoopCoordinates ou da propriedade hadoopDependencyCoordinates em suas especificações de ingestão do Hadoop, será necessário atualizar essas referências para apontar para as bibliotecas 2.8.5 agrupadas.

Método ParseSpec.verify removido

Se você estivesse mantendo uma extensão customizada que fornece uma implementação para a interface ParseSpec, o método verify foi removido e a anotação @Override no método precisará ser removida em quaisquer implementações customizadas. https://github.com/apache/druid/pull/8744

Problemas conhecidos

Filtragem em colunas longas no modo de tratamento nulo compatível com SQL

No momento, estamos cientes de um bug na aplicação de certos tipos de filtro em valores nulos de colunas longas quando o tratamento nulo compatível com SQL está habilitado (https://github.com/apache/druid/issues/9255). Registre um problema se encontrar qualquer outro problema de manipulação de nulos.

Visualização das especificações de ingestão no console da web

As especificações de visualização mostradas para tarefas de ingestão em lote nativas criadas no Data Loader do console web não estão formatadas corretamente e falharão se você copiá-las e enviá-las manualmente. No entanto, o envio dessas especificações por meio do Data Loader envia uma especificação formatada corretamente. https://github.com/apache/druid/issues/9144

Outros problemas conhecidos

Para obter uma lista completa de problemas em aberto, consulte https://github.com/apache/druid/labels/Bug
