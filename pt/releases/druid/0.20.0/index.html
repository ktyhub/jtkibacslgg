druida druida-0.20.0

Apache Druid 0.20.0 contém cerca de 160 novos recursos, correções de bugs, melhorias de desempenho, melhorias de documentação e cobertura de teste adicional de 36 colaboradores. Consulte a lista completa de alterações e tudo marcado para o marco para obter mais detalhes.

<a name="20-new-features" href="#20-new-features">#</a> Novos recursos

<a name="20-ingestion" href="#20-ingestion">#</a> Ingestão

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> Combinando InputSource

Uma nova combinação de InputSource foi adicionada, permitindo ao usuário combinar diversas fontes de entrada durante a ingestão. Consulte https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source para obter mais detalhes. https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Determina automaticamente numShards para particionamento de hash de ingestão paralela

Quando o particionamento hash é usado na ingestão paralela em lote, não é mais necessário especificar numShards na especificação da partição. O Druid agora pode determinar automaticamente vários fragmentos verificando os dados em uma nova fase de ingestão que determina as cardinalidades da chave de particionamento. https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Limites de contagem de arquivos de subtarefa para ingestão paralela em lote

O splitHintSpec baseado em tamanho agora oferece suporte a um novo parâmetro maxNumFiles, que limita quantos arquivos podem ser atribuídos a subtarefas individuais na ingestão paralela em lote. O splitHintSpec baseado em segmento usado para reingerir dados de segmentos Druidas existentes também possui um novo parâmetro maxNumSegments que funciona de forma semelhante. Consulte https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec para obter mais detalhes. https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Métricas de uso de slots de tarefas

Novas métricas de uso de slots de tarefas foram adicionadas. Consulte as entradas para as métricas taskSlot em https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service para obter mais detalhes. https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Compactação

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Suporte para todos os esquemas de particionamento para compactação automática

Uma especificação de particionamento agora pode ser definida para compactação automática, permitindo aos usuários reparticionar seus dados no momento da compactação. Consulte a documentação da nova propriedade partitionsSpec na compactação tuningConfig para mais detalhes: https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> Status de compactação automática API

Foi adicionado um novo coordenador API que mostra o status da compactação automática para uma fonte de dados. O novo API mostra se a compactação automática está habilitada para uma fonte de dados e um resumo do progresso da compactação. O console da web também foi atualizado para mostrar estas informações: https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png Consulte https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status para obter detalhes sobre o novo API e https://druid.apache.org/docs/latest/operations/metrics.html#coordination para obter informações sobre novas métricas de compactação relacionadas. https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Consultando

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Consultar remoção de segmento com particionamento de hash

Druid agora oferece suporte à remoção de segmentos em tempo de consulta (excluindo determinados segmentos como candidatos de leitura para uma consulta) para segmentos particionados por hash. Essa otimização se aplica quando todos os partitionDimensions especificados na especificação da partição hash durante o tempo de ingestão estão presentes no conjunto de filtros de uma consulta e os filtros na consulta filtram valores discretos do partitionDimensions (por exemplo, filtros seletores). A remoção de segmentos com particionamento de hash não é suportada com filtros não discretos, como filtros vinculados. Para usuários existentes com segmentos existentes, você precisará reingerir esses segmentos para aproveitar esse novo recurso, pois a remoção do segmento exige que um partitionFunction seja armazenado junto com os segmentos, o que não existe em segmentos criados por versões mais antigas do Druid. Não é necessário especificar partitionFunction explicitamente, pois o padrão é a mesma função de partição usada nas versões anteriores do Druid. Observe que os segmentos criados com um valor padrão partitionDimensions (partição por todas as dimensões + a coluna de tempo) não podem ser removidos desta maneira; os segmentos precisam ser criados com um partitionDimensions explícito. https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vetorização

Para habilitar recursos de vetorização, defina a propriedade druid.query.default.context.vectorizeVirtualColumns como true ou defina a propriedade vectorize no contexto de consulta. Consulte https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters para obter mais informações.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Suporte de vetorização para colunas virtuais de expressão

Colunas virtuais de expressão agora têm suporte para vetorização (dependendo das expressões usadas), o que resulta em uma melhoria de desempenho de 3 a 5x em alguns casos. Consulte https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support para obter detalhes sobre as expressões específicas que suportam vetorização. https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> Mais suporte de vetorização para agregadores

O suporte de vetorização foi adicionado para vários tipos de agregação: agregadores numéricos mínimo/máximo, agregadores de variação, agregadores ANY e agregadores da extensão druid-histogram. https://github.com/apache/druid/pull/10260 - mín/máx numérico https://github.com/apache/druid/pull/10304 - histograma https://github.com/apache/druid/pull/10338 - QUALQUER https://github.com/apache/druid/pull/10390 - variação Observamos uma melhoria de desempenho de cerca de 1,3x a 1,8x em alguns casos com a vetorização habilitada para o agregador mínimo, máximo e QUALQUER, e cerca de 1,04x a 1,07x com o agregador de histograma.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> Parâmetro offset para consultas GroupBy e Scan

Agora é possível definir um parâmetro offset para consultas GroupBy e Scan, que diz ao Druid para pular um número de linhas ao retornar resultados. Consulte https://druid.apache.org/docs/0.20.0/querying/limitspec.html e https://druid.apache.org/docs/0.20.0/querying/scan-query.html para obter detalhes. https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> Cláusula OFFSET para consultas SQL

Consultas Druid SQL agora suportam uma cláusula OFFSET. Consulte https://druid.apache.org/docs/0.20.0/querying/sql.html#offset para obter detalhes. https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Operadores de pesquisa de substring

Druid adicionou novos operadores de pesquisa de substring em sua linguagem de expressão e para consultas SQL. Consulte a documentação para funções de string CONTAINS_STRING e ICONTAINS_STRING para Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) e documentação para contains_string e icontains_string para a linguagem de expressão Druid (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions). Observamos uma melhoria de desempenho de cerca de 2,5x em alguns casos usando essas funções em vez de STRPOS. https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> Operador UNION ALL para consultas SQL

Consultas Druid SQL agora suportam o operador UNION ALL, que funde os resultados de múltiplas consultas. Consulte https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all para obter detalhes sobre quais formas de consulta são suportadas por este operador. https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Configurações de contexto de consulta padrão para todo o cluster

Agora é possível configurar propriedades de contexto de consulta padrão em todo o cluster incluindo uma configuração no formato druid.query.override.default.context.*, com * substituído pelo nome da propriedade. https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Outros recursos

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> Interface de regras de retenção aprimorada

A IU das regras de retenção no console da web foi aprimorada. Agora ele fornece sugestões e validação básica no menu suspenso do período, mostra as regras padrão do cluster e torna a edição das regras padrão mais acessível. https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Melhorias na extensão de cache Redis

A extensão de cache Redis agora suporta Cluster Redis, selecionando qual banco de dados será usado, conectando-se a servidores protegidos por senha e configurações de estilo de período para as propriedades expiration e timeout. https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Desativa o envio da versão do servidor nos cabeçalhos de resposta

Agora é possível desabilitar o envio de informações de versão do servidor nos cabeçalhos de resposta do Druid. Isto é controlado por uma nova propriedade druid.server.http.sendServerVersion, cujo padrão é true. https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Especifique propriedades de configuração baseadas em bytes com unidades

Druid agora oferece suporte a unidades para especificar propriedades de configuração baseadas em bytes, por exemplo:

druid.server.maxSize=300g

equivalente a

druid.server.maxSize=300000000000

Consulte https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html para obter mais detalhes. https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Correções de bugs

<a name="20-query-correctness" href="#20-query-correctness">#</a> Corrige problema de correção de consulta quando o histórico não tem cronograma de segmento

Druid 0.20.0 corrige um problema de correção de consulta quando um corretor emite uma consulta esperando que um histórico tenha determinados segmentos para uma fonte de dados, mas o histórico quando consultado não possui realmente nenhum segmento para essa fonte de dados (por exemplo, todos eles foram descarregados antes do histórico processar a consulta). Antes de 0.20.0, a consulta retornava com sucesso, mas sem os resultados dos segmentos que faltavam da maneira descrita anteriormente. No 0.20.0, as consultas agora falharão em tais situações. https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Corrigido problema que impedia o preenchimento do cache em nível de resultado

Druid 0.20.0 corrige um problema introduzido em 0.19.0 (https://github.com/apache/druid/issues/10337) que pode impedir que caches de consulta sejam preenchidos quando o cache em nível de resultado está habilitado. https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Correção para ordenação do agregador de variância

O agregador de variância usava anteriormente um comparador incorreto que comparava usando uma variável count interna do agregador em vez da variância. https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Corrige cache incorreto para consultas groupBy com especificações de limite

Druid 0.20.0 corrige problemas com consultas groupBy e cache, onde o limitSpec da consulta não era considerado na chave de cache, levando a resultados potencialmente incorretos se consultas idênticas, exceto o limitSpec, fossem emitidas. https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Correção para stringFirst e stringLast com rollup ativado

https://github.com/apache/druid/issues/7243 foi resolvido, os agregadores stringFirst e stringLast não causam mais exceção quando usados durante a ingestão com rollup habilitado. https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Atualizando para Druid 0.20.0

Esteja ciente das seguintes considerações ao atualizar de 0.19.0 para 0.20.0. Se você estiver atualizando de uma versão anterior à 0.19.0, consulte os release notes das versões intermediárias relevantes.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Padrão maxSize

druid.server.maxSize agora terá como padrão a soma dos valores maxSize definidos no druid.segmentCache.locations. O usuário ainda pode fornecer um valor personalizado para druid.server.maxSize que terá precedência sobre o valor padrão. https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Compactação e eliminação de alterações no ID da tarefa

As tarefas de compactação e eliminação emitidas pelo coordenador agora terão seus IDs de tarefa prefixados por coordinator-issued, enquanto as tarefas de eliminação emitidas pelo usuário serão prefixadas por api-issued. https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> Novos limites de tamanho para especificações de dicas de divisão de ingestão paralela

O splitHintSpec baseado em tamanho e segmento para ingestão de lote paralelo agora aplica um limite de arquivo/segmento padrão de 1.000 por subtarefa, controlado pelo maxNumFiles e maxNumSegments respectivamente. https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> Novos métodos PostAggregator e AggregatorFactory

Os usuários que desenvolveram uma extensão com implementações customizadas PostAggregator ou AggregatorFactory precisarão atualizar suas extensões, pois essas duas interfaces possuem novos métodos definidos em 0.20.0. PostAggregator agora possui um novo método:

  ValueType getType();

Para suportar informações de tipo em PostAggregator, AggregatorFactory também possui 2 novos métodos:

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Consulte https://github.com/apache/druid/pull/9638 para obter mais detalhes sobre as alterações da interface.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> Novos métodos relacionados ao Expr

Os usuários que desenvolveram uma extensão com implementações personalizadas do Expr precisarão atualizar suas extensões, pois o Expr e as interfaces relacionadas foram alteradas no 0.20.0. Consulte o PR abaixo para obter detalhes: https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> Métrica query/cpu/time mais precisa

No 0.20.0, a precisão da métrica query/cpu/time foi melhorada. Anteriormente, ele não considerava determinadas partes do trabalho durante o processamento da consulta, descritas com mais detalhes no PR a seguir: https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> Novas colunas de métricas do serviço de log de auditoria

Se você estiver usando o log de auditoria, esteja ciente de que novas colunas foram adicionadas à métrica do serviço de log de auditoria (comment, remote_address e created_date). Também foi adicionada uma coluna payload opcional, que pode ser habilitada configurando druid.audit.manager.includePayloadAsDimensionInMetric como true. https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext em logs de solicitação

Se você estiver usando o log de solicitação de consulta, os eventos de log de solicitação incluirão agora o sqlQueryContext para consultas SQL. https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> Estado adicional por segmento no armazenamento de metadados

Segmentos particionados por hash criados pelo Druida 0.20.0 agora terão dados partitionFunction adicionais no armazenamento de metadados. Além disso, as tarefas de compactação agora armazenarão informações adicionais por segmento no armazenamento de metadados, usado para rastrear o histórico de compactação. https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Problemas conhecidos

<a name="20-location-strat" href="#20-location-strat">#</a> Falha na injeção do druid.segmentCache.locationSelectorStrategy

A especificação de um valor para druid.segmentCache.locationSelectorStrategy evita que os serviços sejam iniciados devido a um erro de injeção. Consulte https://github.com/apache/druid/issues/10348 para obter mais detalhes.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Vazamento de recursos no amostrador de dados do console da web

Quando ocorre um tempo limite durante a amostragem de dados no console da web, os recursos internos criados para leitura da fonte de entrada não são fechados corretamente. Consulte https://github.com/apache/druid/pull/10467 para obter mais informações.
