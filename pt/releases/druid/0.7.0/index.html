Atualizando para Druida 0.7.0 – Coisas a serem observadas

  • Nova especificação de ingestão Druid 0.7.0 requer um novo formato de especificação de ingestão. Druid 0.6.172 suporta formatos de ingestão antigos e novos e possui scripts para converter do formato antigo para o novo. Este script pode ser executado com 'tools convertSpec' usando o mesmo Main usado para executar nós Druid. Você pode atualizar seu cluster Druid para 0.6.172, atualizar suas especificações de ingestão para o novo formato e, em seguida, atualizar para Druid 0.7.0. Se você atualizar seu cluster diretamente para Druid 0.7.0, certifique-se de que seu pipeline de ingestão em tempo real entenda a nova especificação.
  • MySQL não é mais o armazenamento de metadados padrão Druid agora tem como padrão incorporar o Apache Derby, que foi escolhido principalmente para fins de testabilidade. No entanto, não recomendamos o uso do Derby em produção. Para qualquer coisa que não seja teste, use o armazenamento de metadados MySQL ou PostgreSQL. Parâmetros de configuração para armazenamento de metadados foram renomeados de druid.db para druid.metadata.storage e um druid.metadata.storage.type=<mysql|postgresql> adicional é necessário para usar qualquer coisa diferente de Derby. A ferramenta convertProps pode ajudá-lo a converter todas as propriedades 0.6.x em propriedades 0.7.
  • Druida agora diferencia maiúsculas de minúsculas Os nomes das colunas druidas agora diferenciam maiúsculas de minúsculas. Anteriormente, tentamos não diferenciar maiúsculas de minúsculas para consultas e preservar maiúsculas de minúsculas para dados, mas decidimos fazer essa alteração porque havia vários bugs relacionados a vários problemas de caixa. Se você estiver atualizando da versão 0.6.x:
    1. Certifique-se de que a caixa da coluna em suas consultas corresponda à caixa dos nomes das colunas em seus dados e atualize suas consultas de acordo.
    2. Uma coisa muito importante a ser observada é que 0.6 coloca internamente em minúsculas todos os nomes de colunas no momento da ingestão e no momento da consulta. No 0.7, este não é mais o caso, no entanto, ainda recomendamos fortemente que você use nomes de colunas em letras minúsculas no 0.7 para simplificar.
    3. Se você estiver ingerindo dados com nomes de colunas com maiúsculas e minúsculas como parte de seus dados ou esquema de ingestão:
      • para dados TSV ou CSV, basta colocar os nomes das colunas em letras minúsculas no esquema ao atualizar para 0.7.0.
      • para dados JSON com campos de letras maiúsculas e minúsculas e se você não estava especificando os nomes das colunas, você pode usar o jsonLowerCase parseSpec para colocar os dados em letras minúsculas para você no momento da ingestão e manter a compatibilidade com versões anteriores. Para todas as outras especificações de análise, você precisará colocar em minúsculas o nomes de métricas/agregadores se você estava usando maiúsculas e minúsculas antes.
  • O anúncio do segmento em lote agora é o padrão Druid agora usa anúncio de segmento em lote por padrão para todos os nós. Se você já estiver usando anúncio de segmento em lote, estará tudo pronto. Se você ainda não atualizou para usar o anúncio de segmentos em lote, leia este guia no fórum sobre como atualizar seu cluster 0.6.x atual para usar o anúncio em lote primeiro.
  • Kafka 0.7.x removido em favor de Kafka 0.8.x Se estiver usando Kafka 0.7, você terá que construir a extensão kafka-seven manualmente. Está comentado na compilação, pois Kafka 0.7 não está disponível no Maven Central. A extensão Kafka 0.8 (kafka-eight) não é afetada.
  • Alterações no endpoint do coordenador Vários pontos de extremidade do coordenador foram alterados. Consulte a documentação do coordenador para saber o que são. Em particular:
  1. /info do coordenador foi removido.
  2. /health em nós históricos foi removido
  • É necessário um frasco separado para com.metamx.metrics.SysMonitor Se você atualmente tem com.metamx.metrics.SysMonitor como parte de sua configuração druid.monitoring.monitors e gostaria de mantê-lo, você terá que adicionar o jar da biblioteca SIGAR ao seu classpath. Alternativamente, você pode simplesmente remover com.metamx.metrics.SysMonitor se não confiar nas métricas sys/.*. Tivemos que remover a dependência direta do SIGAR para mover os artefatos Druidas para o Maven Central, já que o SIGAR não está disponível lá no momento.
  • Procedimento de atualização Se você estiver executando uma versão do Druid anterior a 0.6.172, atualize primeiro para 0.6.172. Consulte 0.6.172 release notes para obter instruções. Para garantir uma atualização contínua sem tempo de inatividade, os nós devem ser atualizados na seguinte ordem:
    1. nós históricos
    2. serviço de indexação/nós em tempo real
    3. nós do roteador (se houver),
    4. Nós do corretor
    5. nós coordenadores

Novos recursos

  • Suporte a colunas métricas longas Até agora, o Druid armazenava todas as métricas como valores de ponto flutuante de precisão única, o que poderia introduzir erros de arredondamento e resultados inesperados com consultas usando agregadores longSum, especialmente para consultas groupBy.
  • Armazenamento de metadados conectável MySQL, PostgreSQL e Derby (para teste) agora são suportados imediatamente. Derby suporta apenas master único ou não deve ser usado para produção de alta disponibilidade, use failover MySQL ou PostgreSQL para isso.
  • Ingestão de dados simplificada API refaça completamente a ingestão de dados do Druid API.
  • Alternar compactação para colunas métricas de LZF para LZ4 Os testes iniciais de desempenho mostram que ele pode ser entre 15% e 25% mais rápido e resulta em segmentos cerca de 3 a 5% menores em conjuntos de dados típicos.
  • Índices de bitmap invertidos configuráveis Druid agora suporta Roaring Bitmaps além dos Concise Bitmaps padrão. Os testes iniciais de desempenho mostram que o Roaring pode ser até 20% mais rápido para certos tipos de consultas, às custas de segmentos serem 20% maiores, em média.
  • Testes de integração Adicionamos um conjunto de testes de integração que usam Docker para ativar um cluster Druid para executar uma série de testes de indexação e consulta.
  • Novo console do Coordenador Druida Introduzimos um novo console Druid que deve fornecer uma melhor visão geral do status do seu cluster e ser um pouco mais escalonável se você tiver centenas de milhares de segmentos. Planejamos expandir este console para fornecer mais informações sobre o estado atual de um cluster Druida.
  • Contexto do resultado da consulta Os contextos de resultados podem reportar erros durante consultas nos cabeçalhos de consulta. No momento, estamos usando esse recurso para novas tentativas internas, mas esperamos expandi-lo para relatar mais informações ao clients.

Melhorias

  • Velocidades de consulta mais rápidas Muitas melhorias de velocidade graças ao formato de compactação mais rápido, pequenas otimizações na estrutura de colunas e otimizações de consultas com múltiplas agregações, bem como inúmeras melhorias de desempenho de consulta groupBy. No geral, algumas consultas podem ser até duas vezes mais rápidas usando o novo formato de índice.
  • Artefatos druidas no Maven Central Os artefatos druidas agora estão disponíveis no Maven Central para facilitar suas próprias compilações e implantações.
  • Arquivo de configuração comum Druid agora tem um common.runtime.properties onde você pode declarar todas as propriedades globais, bem como todas as suas dependências externas. Isso evita configurações repetidas em vários nós e esperançosamente tornará a configuração de um cluster Druida um pouco menos dolorosa.
  • Nomes de host, portas e nomes de serviço padrão Nomes de host, portas e nomes de serviço padrão para todos os nós significam que muito menos configuração será necessária antecipadamente se você estiver satisfeito com os padrões. Isso também significa que você pode executar todos os tipos de nós em uma única máquina sem se preocupar com conflitos de porta.
  • Os nomes das colunas Druid agora diferenciam maiúsculas de minúsculas Morte aos bugs do revestimento. Esteja ciente dos perigos de atualizar para 0.7.0 se você tiver colunas de maiúsculas e minúsculas mistas e estiver usando 0.6.x. Veja acima para mais detalhes.
  • Repetições de consulta O Druid agora tentará novamente consultas automaticamente para determinadas classes de falhas.
  • Cache em segundo plano Para determinados tipos de consultas, especialmente aquelas que envolvem contagens distintas (hiperloglog), isso pode melhorar o desempenho em mais de 20%. O cache em segundo plano está desabilitado por padrão.
  • Redução do uso de memória do coordenador Uso reduzido de memória do coordenador (em até 50%). Isso resolve um problema em que um coordenador às vezes perdia a liderança devido a GCs frequentes.
  • As métricas agora podem ser emitidas para endpoints SSL
  • Suporte adicional para credenciais da AWS, obrigado @gnethercutt
  • Métricas adicionais de persistência e limitação para ingestão em tempo real Isso deve ajudar a diagnosticar quando a ingestão em tempo real está sendo limitada e quanto tempo a persistência está demorando. Essas métricas fornecem uma boa indicação de quando é hora de aumentar a ingestão em tempo real.
  • Endpoint de inicialização do corretor Os corretores agora fornecem um endpoint de status em /druid/broker/v1/loadstatus para indicar se estão prontos para serem consultados, facilitando atualizações/reinicializações contínuas.

Correções de bugs

  • Suporte a vários fragmentos da mesma fonte de dados no mesmo nó em tempo real. Obrigado @zhaown
  • Os logs de tarefas do HDFS agora devem funcionar conforme esperado. Obrigado @flowbehappy.
  • Possível condição de deadlock corrigida no Broker.
  • Várias correções para compactação GZIP no retorno de resultados.
  • druid.host agora também deve suportar endereços IPv6.

Documentação

  • Novos tutoriais.
  • Nova documentação de ingestão.
  • Nova documentação de configuração.
  • Melhorias na documentação de regras. Obrigado @mrijke

Problemas conhecidos

  • Atualmente, não é possível mesclar segmentos com diferentes tipos de índices de bitmap, portanto, se você tiver os dois tipos de índices em seu cluster, deverá definir druid.coordinator.merge.on como falso. ‘false’ é o valor padrão da configuração.
  • Problema https://github.com/druid-io/druid/issues/1045 com consultas GoupBy com agregações complexas e pós-agregações usando o mesmo nome
  • https://github.com/druid-io/druid-api/pull/38 Se você estiver usando longSum em sua especificação de ingestão, ter dados de ponto flutuante pode gerar exceções.
